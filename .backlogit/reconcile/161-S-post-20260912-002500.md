## Step 5 — Lock release, and disclosed ordering deviation

**Disclosed deviation from the skill's Required Protocol**: the
`shipment-reconcile` skill's Post-Mode protocol specifies that the
shipment-record lock is retained through post-mode and released only at
this step (step 6), after the post-mode verification (steps 1–4) has run
under the lock. That ordering was not followed here: the lock
(`.backlogit/queue/.161-S.md.lock`) was released immediately following the
cascade invocation, in the original closure session (2026-09-11), via
`scripts/release_lock.ps1` (see the Cascade Close report's "Lock release"
section) — because at that time the cascade-close report's own inline
"Post-Mode" section was (incorrectly) treated as satisfying the post-mode
requirement, so no separate locked post-mode step was scheduled. This
dedicated report was only written afterward, during closure-PR review
remediation (2026-09-12), by which point the lock had already been
released and the shipment-record file had already relocated to
`.backlogit/archive/161-S.md` — re-acquiring a lock on the now-nonexistent
`.backlogit/queue/161-S.md` path is not meaningful, so strict compliance
with the "retain through post-mode" ordering is not achievable
retroactively.

**Why the verification above remains valid despite the deviation**: `git
log --oneline` for all 7 manifest archive files
(`.backlogit/archive/{153-F,153.001-T,153.002-T,153.003-T,153.004-T,
153.005-T,161-S}.md`) shows exactly one commit touching each after their
initial per-task archival — the single cascade-close closure commit
(`17534f1c`) — and no commit since. There has been no intervening mutation
to these files between the (already-released) lock and the Steps 1–4
verification performed above; the unlocked verification therefore reflects
the same state a locked verification would have observed.

**Follow-up**: future dedicated `mode: post` reconcile reports MUST run
under the retained lock per the skill's Required Protocol; this deviation
is disclosed here rather than silently normalized, and should not be
repeated. No lock sentinel remains at `.backlogit/queue/.161-S.md.lock` as
of this post-mode check. `backlogit sync` was run after the cascade
invocation to re-index the workspace (`CLOSURE_INDEX_SYNC_OK`).
