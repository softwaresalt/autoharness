Make AC2's fail-closed promise ENFORCEABLE IN THE ACTUAL RELEASE PATH (T14) by adding an unbypassable payload-composition gate to `.github/workflows/release.yml`.

WHY THIS EXISTS: AC2 promises that an unclassified tracked path FAILS THE BUILD. Hardening decision H1 chose "generated-and-asserted", which means the guarantee lives in a TEST. A test that nothing in the release path is required to run is not a gate - it is a hope. Without this task, a release could be built and published with the composition suite never executed, which is precisely the failure mode that produced the current untrimmed payload.

WHY IT IS A SEPARATE TASK (width isolation): editing a CI workflow is a different surface with a different blast radius and a different diagnosis path than editing packaging config. Folding it into the wheel-wiring task (160.006-T) would mix CI work with packaging work and push that task past the 2-hour rule.

WORKFLOW SHAPE AS IT ACTUALLY EXISTS: `.github/workflows/release.yml` has exactly ONE job (`release`). A separate gating job with a `needs:` edge is therefore NOT available without restructuring the workflow, and restructuring is OUT OF SCOPE for this shipment. The unbypassable form in a single-job workflow is an IN-JOB PREREQUISITE STEP.

DELIVERABLE - TWO GATE STEPS, NOT ONE (SPLIT IN CYCLE 6, FINDING 1). The cycle-5 deliverable required the composition suite to run BEFORE the build step, while verification V1 requires every composition assertion to UNPACK THE ACTUAL BUILT WHEEL. THOSE TWO CANNOT BOTH HOLD OF ONE STEP: at the moment a pre-build gate runs there is no wheel to unpack, so it either asserts against the source tree - violating V1 and therefore unable to detect a packaging defect, which is risk R1, the entire reason this shipment exists - or it builds its own wheel, violating the ordering claim AND inspecting an artifact that is NOT the one published. The contradiction is resolved by SPLITTING ON WHAT CAN BE KNOWN WHEN.

GATE A - PRE-BUILD SOURCE/STATIC GATE. Ordered strictly BEFORE the `uv build` step.
- Runs `python -m build_support.payload generate --channel all --check` (the command delivered by 160.014-T), where `all` means every channel the manifest's closed enum declares - after the cycle-5 de-scope (finding 1) that is WHEEL AND PLUGIN.
- Runs the SOURCE/STATIC half of the composition suite - exactly the assertions DECIDABLE WITHOUT AN ARTIFACT: manifest schema validation, the AC11 complete-classification check, the AC2 unclassified-tracked-path guard, the resolver's per-channel resolution and size report, the AC2d P1-P4 predicate, and the release.yml structural assertions.
- READ CONSUMER OF THE GENERATOR PARTITION: Gate A reads the AC3e partition 160.014-T prints to stdout and FAILS THE GATE when OVERWRITE union REMOVE is non-empty - that set is exactly the drift condition. The generator writes nothing under docs/audits/**; this gate consumes the stdout form.
- Running these first means a manifest/table drift fails the release BEFORE A SINGLE BYTE IS BUILT.

GATE B - POST-BUILD, PRE-PUBLISH ARTIFACT GATE. Ordered strictly AFTER `uv build` and strictly BEFORE the publish step.
- Runs the ARTIFACT half of the composition suite (V1): unpack the built wheel, resolve the plugin payload, and assert AC3 exclusions, AC4 completeness, AC8 size/count reporting, and AC9 Gate 4 cross-reference integrity INSIDE THE DELIVERED ARTIFACT.
- THE ARTIFACT INSPECTED IS THE ARTIFACT PUBLISHED - BY DIGEST IDENTITY, NOT BY REBUILDING. Gate B inspects the files ALREADY SITTING IN `dist/` that `uv build` produced. IT MUST NEVER BUILD ITS OWN WHEEL: a separately built wheel is a different artifact and proves nothing about the published one. It sets AUTOHARNESS_PAYLOAD_WHEEL to the `dist/*.whl` path so the artifact tests inspect exactly that file, and RECORDS THE SHA-256 OF EVERY `dist/*` MEMBER IT INSPECTED into the step log and $GITHUB_STEP_SUMMARY.
- WHAT THIS PROVES AND WHAT IT DOES NOT, STATED RATHER THAN IMPLIED: it proves the inspected artifact is byte-identical to the published artifact PROVIDED NO STEP BETWEEN GATE B AND PUBLISH WRITES INTO `dist/`. That proviso is ASSERTED, not assumed - see case 1 below. It does NOT prove PyPI stores what was uploaded; that is outside any gate this shipment can author.

BOTH GATES:
- MUST NOT carry `continue-on-error: true`.
- MUST NOT carry any `if:` expression that can skip them - no `if: always()`, no `if: success() || ...`, no workflow_dispatch bypass input.
- A failing gate fails the job: Gate A before anything is built, Gate B before anything is published.
