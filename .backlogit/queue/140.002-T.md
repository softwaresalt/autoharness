Amend the compound authoring template so newly authored learnings are born docline-conformant. Without this, the next compound doc reopens the gap that 140.001-T just closed.

**Plan:** `docs/plans/2026-08-21-docs-compound-docline-conformance-plan.md` Task 2

## Test-first requirement
Extend `tests/test_docs_compound_frontmatter_contract.py` (or add a sibling structural test) asserting that the Phase 3 frontmatter example in `templates/skills/compound/SKILL.md.tmpl` contains both `source:` and `doc_type:` keys. RED before, GREEN after.

## Steps
1. Amend the Phase 3 YAML frontmatter example in `templates/skills/compound/SKILL.md.tmpl` to include `source` and `doc_type`, using the value semantics confirmed in 140.001-T step 2. The current example specifies `title, description, problem_type, category, component, root_cause, resolution_type, severity, message, file_path, citations, tags` and has never specified these two.
2. `doc_type` guidance MUST state that the value is PATH-DERIVED and never a free-text choice, expressed as a **CAPABILITY-NEUTRAL AUTHORITY ORDER**. **The base template MUST NOT name any specific backlog tool or command** (amendment C3, review-fix cycle 4 — `compound` is a base Primitive 1 artifact that installs into workspaces with NO backlogit, so a hard-coded `backlogit docs classify` would be dead guidance there and would breach the environment-agnostic base-template rule). Write it as:

   > `doc_type` is PATH-DERIVED. Resolve it in this order:
   > 1. If the workspace's installed backlog/documentation tooling exposes a documentation-classification operation, that operation is authoritative for the path.
   > 2. Otherwise, the workspace's configured documentation path map is authoritative.
   > 3. If neither is configured, apply the directory convention: a document authored by this skill lives in the compound/learnings directory and is therefore `learning`.
   >
   > Never invent the value and never copy it from a neighbouring document.

   Rung 3 always yields a concrete answer, so NO unresolved customization point is left behind. In THIS workspace the rung-1 operation happens to be `backlogit docs classify <path>` and `backlogit docs scope` maps `docs/compound/` → `learning` — record that in the task record as the local resolution, but do NOT write the command into the template.
3. Add both fields to the skill's "Quality Criteria" list.
4. **STOP CONDITION.** Confirm `.github/skills/` still contains no `compound/` directory. At planning time it held only `install-harness`, `tune-harness`, `verify-harness`, `workspace-discovery`. If a dogfood counterpart has since appeared, STOP — a paired edit plus manifest checksum refresh is then required and this task's scope no longer holds.

## Acceptance criteria
- AC7. The template's Phase 3 example carries `source` and `doc_type`.
- AC8. The template still renders — no unresolved or malformed `{{...}}` introduced. The two new keys MUST NOT add a new template variable. (Reaffirmed in cycle 4: the capability-neutral authority order is PROSE, so it introduces no variable, requires no `install-harness` variable-table row, no `_derive_template_variables` change, and no registry key. See the rejected-alternatives note below.)
- AC8b (amendment C3, review-fix cycle 4). **Capability neutrality gate.** The amended `templates/skills/compound/SKILL.md.tmpl` contains NO occurrence of `backlogit`, nor of any other specific backlog-tool name or CLI command, anywhere in the `doc_type`/`source` guidance. Assert this MECHANICALLY in the structural test (a literal scan of the template for tool names), not by review. The guidance must remain fully actionable in a workspace where no backlog tooling is installed — rung 3 of the authority order is what guarantees that.

## Rejected alternatives (recorded, cycle 4)
- **New template variable** (e.g. `{{OP_DOC_CLASSIFY_CLI}}` sourced from the backlog registry, empty-string default per the existing `{{OP_*}}` family at `.github/skills/install-harness/SKILL.md:240-254`). REJECTED: it would require an `install-harness` variable-table row in BOTH the template and the installed `SKILL.md` (paired edit + `harness-manifest.yaml` checksum refresh — breaking AC10), a `_derive_template_variables` change (which is **142-F's** surface, a cross-feature width breach under P-003), and a registry schema key. It also directly contradicts AC8. The variable family remains the right pattern for genuinely tool-shaped values; `doc_type` is path-derived and needs no tool.
- **backlogit capability-pack overlay.** REJECTED: `.github/instructions/backlogit.instructions.md` does not currently cover documentation classification at all, so this would require editing both `templates/instructions/backlogit.instructions.md.tmpl` and its installed counterpart — again a paired edit plus manifest checksum, breaking AC10 and invalidating the plan's `requires_plan_hardening: no` rationale.
- AC9. `.github/skills/` contains no `compound/` directory — verified and recorded, not assumed.
- AC10. No `.autoharness/harness-manifest.yaml` entry changes (proves no dogfood counterpart was silently touched).
