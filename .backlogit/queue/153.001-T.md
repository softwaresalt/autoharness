Covers findings 1, 2, 3. acquire_lock.ps1 has no containment (Resolve-Path accepts absolute paths and ../ traversal); acquire_lock.sh L22 resolves symlinks via cd/pwd -P but never verifies containment; both resolve THROUGH links before computing the lock path, so a symlinked directory redirects lock creation outside the workspace (Constitution III and IV). DECISION (i): explicit workspace-root parameter, defaulting to git rev-parse --show-toplevel, with the resolved root itself validated. PLAN REVIEW FINDING 2 (P1): when the explicit parameter is absent AND the git-derived root is not an ancestor-or-equal of the scripts own installed location, FAIL CLOSED and demand the explicit parameter rather than guessing - otherwise a nested checkout silently resolves to a PARENT repository and widens containment. BINDING H2: enforce containment only after FULL symlink/junction resolution of BOTH the candidate path and the root, comparing fully-resolved real paths. BINDING H4: prefix-string containment is forbidden - /repo must not be treated as containing /repo-evil; use path-segment comparison. H5: PowerShell and POSIX variants implement identical semantics. TEMPLATE-FIRST (H1): edit templates/skills/file-lock/scripts/ only. Do not redesign the FileMode::CreateNew acquire race handling - it is correct. Source: 74C62374 findings 1-3.
