P4 T2 (PREPARE, inert). Implement src/autoharness/harness_read.py - ONE FILE. Size M, complexity high. Blocked by 181.001-T.

WHY A PRIMITIVE. A containment check followed by a separate open is a CHECK-THEN-OPEN RACE: the path that was validated is not provably the path that is read. This primitive removes the gap by making the HANDLE the unit of trust - every check is performed on an already-open handle, and the bytes are read from that same handle. It is the ONLY way this unit touches the filesystem; the resolver never calls open, Path.read_text, os.stat or os.listdir directly.

LOCAL BY DESIGN. 185-S / 179-F will later deliver a general safe-primitive substrate. NO EDGE ON 185-S IS CREATED OR IMPLIED - 187-S remains a dag-root and consolidation is future work for whichever unit ships second.

DELIVERS. (a) Roots canonicalized EXACTLY ONCE at entry with Path.resolve(strict=True); a root may itself lie behind a symlink, but BELOW a canonical root no component may be a link. (b) Lexical rejection before any handle is opened: absolute paths, drive letters, UNC and extended prefixes, environment-variable syntax, home expansion, any .. component, empty or . components, NUL and control characters, and reserved Windows device names - failure is PATH_LEXICALLY_REJECTED with no filesystem call performed. (c) POSIX traversal: os.open(root, O_RDONLY|O_DIRECTORY) once, then per intermediate component os.open(component, O_RDONLY|O_NOFOLLOW|O_DIRECTORY, dir_fd=parent_fd) and for the final component os.open(name, O_RDONLY|O_NOFOLLOW, dir_fd=parent_fd); every open is RELATIVE TO THE PARENT DIRECTORY FD so no path string is ever re-resolved by the kernel; os.fstat supplies (st_dev, st_ino, st_size, st_mtime_ns) and stat.S_ISREG must hold. (d) Windows traversal: CreateFileW with FILE_FLAG_OPEN_REPARSE_POINT|FILE_FLAG_BACKUP_SEMANTICS and FILE_SHARE_READ, opening the LINK ITSELF rather than its target; GetFileInformationByHandle rejects FILE_ATTRIBUTE_REPARSE_POINT; GetFinalPathNameByHandle(VOLUME_NAME_DOS) supplies the path the handle ACTUALLY points at, which is normalized and required to be component-wise contained under the canonical root; identity is (dwVolumeSerialNumber, nFileIndexHigh, nFileIndexLow, nFileSizeHigh, nFileSizeLow). (e) Containment is COMPONENT-WISE, never by string prefix. (f) Identity captured before and after the read and required equal. (g) The bounds table: 4 MiB per file enforced from the pre-read size, 32 MiB aggregate, 256 files, 512 shipment member IDs, 32 path components. (h) A platform adapter interface so both branches are injectable and deterministically testable.

FAIL, NEVER DEGRADE. If O_NOFOLLOW or dir_fd support is absent, if ctypes cannot bind CreateFileW or GetFinalPathNameByHandle, or if any required primitive raises NotImplementedError or AttributeError, the read fails PLATFORM_INVARIANT_UNAVAILABLE. THERE IS NO UNCHECKED FALLBACK READ ANYWHERE IN THIS UNIT.
