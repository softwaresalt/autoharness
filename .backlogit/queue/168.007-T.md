IMPLEMENTATION. Build the P-004 observation machinery that turns the RED suite in 168.005-T green. TWO PARTS. (A) validate_declared_harness_set() is the SOLE declaration-validation entry point: it runs the Draft-07 schema from 168.001-T, maps every jsonschema error to its token by the STRUCTURAL (absolute_path, validator) pair - NEVER by parsing message text - emitting P004_MARKER_MISPLACED naming an EntrySubject and P004_EMPTY_RED_SET naming the CollectionSubject, RAISES P004_DECLARATION_SCHEMA_ERROR and HALTS on any unmapped pair, and then evaluates the two relational rules the schema cannot express: within-list uniqueness (P004_DUPLICATE_DECLARATION) and cross-list disjointness (P004_SET_OVERLAP). (B) P004Result and the observation machinery: declared names are loaded INDEPENDENTLY, one per loadTestsFromName call; each returned suite is RECURSIVELY FLATTENED to leaf tests; load errors are attributed by a len(loader.errors) snapshot slice taken before and after each call; results are correlated to requested names through an id(test_object) identity map built at load time. NO POSITIONAL CORRESPONDENCE is used anywhere - loadTestsFromNames returns one SUITE per name rather than one test, so positional correlation is unsound in both the success and the failure case. P004Result reuses the INHERITED TestResult._exc_info_to_string formatting from the exc_info tuples handed to addFailure/addError, and OVERRIDES addSubTest so a subtest-only red path is never recorded as a pass.
DECLARATION-CONFORMANCE CHECK, SEPARATE FROM ATTRIBUTION: for every successfully loaded TestCase, assert loaded_test.id() == the requested test_id, emitting P004_DECLARED_ID_MISMATCH on inequality. This is enforced INDEPENDENTLY of the identity-map attribution above. Attribution answers "which declared name does this result belong to" and must stay identity-based so a _FailedTest placeholder is still attributed correctly; conformance answers "did the declaration name the test it claimed to name". Neither substitutes for the other, and collapsing them would let a declaration silently address a different test than it names.
TOTAL OUTCOME MATRIX: every declared class crossed with every observed outcome is defined, with no undefined cell. expectedFailure and unexpectedSuccess are DETERMINISTICALLY FAIL-CLOSED as P004_INCONCLUSIVE_OUTCOME - a declared expected_red test decorated @unittest.expectedFailure is reported by TestResult as an expected failure rather than a failure, and a declared expected_green_characterization test that unexpectedly succeeds is reported as an unexpected success; neither is silently folded into pass or into red.
TAGGED SUBJECT CONSTRUCTOR: every emitted token is constructed with exactly one subject - TestSubject, CollectionSubject, EntrySubject or DocumentSubject - so the subject kind is part of the token value and not inferred by the caller.
