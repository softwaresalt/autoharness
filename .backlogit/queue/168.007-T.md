Implement validate_declared_harness_set() and the P004Result observation boundary with its runner entry point in src/autoharness/, so the gate compares declared outcomes against PER-TEST observations rather than scanning merged runner output.

DECLARATION VALIDATION. validate_declared_harness_set(manifest) is the SOLE declaration-validation entry point and runs BEFORE the load step, failing closed so the runner never loads a declaration that did not pass. It executes in three ordered stages. (1) SHAPE: jsonschema.Draft7Validator(schema).iter_errors(manifest), consumed with sorted(..., key=jsonschema.exceptions.relevance) for deterministic ordering. Each ValidationError is mapped to a token by its STRUCTURAL (absolute_path, validator) pair - NEVER by parsing error.message, which is library-version dependent. Mapping: validator "required" missing marker at harness.expected_red[i] -> P004_MARKER_MISPLACED naming that item's test_id; validator "additionalProperties" for a surplus marker at harness.expected_green_characterization[i] -> P004_MARKER_MISPLACED naming that item's test_id; validator "minItems" at harness.expected_red -> P004_EMPTY_RED_SET (no identifier, the list is empty); validator "required" missing test_id, "type", or "minLength" in either list -> P004_MARKER_MISPLACED naming the JSON pointer to the offending item. The identifier is recovered by indexing the PARSED manifest with error.absolute_path. (2) UNMAPPED FAIL-CLOSED: a ValidationError whose (absolute_path, validator) pair matches no mapping row raises P004_DECLARATION_SCHEMA_ERROR, a hard error that halts and reports error.json_path and error.validator. It is deliberately NOT a tenth gate token; the gate token set stays at NINE. (3) RELATIONAL, only if stage 1 produced no tokens: within-list test_id uniqueness (P004_DUPLICATE_DECLARATION) and cross-list disjointness (P004_SET_OVERLAP). These two rules live here and nowhere else, because Draft-07 can express neither.

LOAD. Load EACH declared name INDEPENDENTLY via loader.loadTestsFromName(name) on a fresh TestLoader. Do NOT use loadTestsFromNames and do NOT use positional correspondence anywhere: loadTestsFromNames(names) is defined as suiteClass([loadTestsFromName(n) for n in names]), so its top-level members are one SUITE per input name and never one test per input name, and a resolvable name may expand to many tests - positional correlation is therefore unsound in BOTH the success and the failure case. For each name, SNAPSHOT len(loader.errors) immediately before the call and slice loader.errors[before:] immediately after, which is the only sound way to read TestLoader.errors: it is a FLAT LIST OF FORMATTED STRINGS appended in load order, with no key at all, so any keyed lookup or membership test against it is meaningless. RECURSIVELY FLATTEN the returned suite to leaf TestCase objects, never assuming depth 1. Build an id(test_object) -> requested_name IDENTITY MAP from the very objects about to be run. Do NOT assume unittest.loader._FailedTest.id() equals the requested name - it is not a guaranteed API - and never compare test.id() against the declared string to look a test up. Classify at load time, before anything runs: a name producing any load error, resolving to a _FailedTest, or resolving to ZERO tests is P004_MISSING_OBSERVATION; a name resolving to MORE THAN ONE test is P004_MISSING_OBSERVATION for the declared id plus P004_UNDECLARED_OBSERVATION for each surplus resolved id not itself declared.

RESULT. P004Result subclasses unittest.TextTestResult. addFailure(test, err) and addError(test, err) receive err as an EXC_INFO TUPLE (exc_type, exc_value, traceback), NOT a preformatted string; the per-test formatted traceback text is produced by the INHERITED TestResult._exc_info_to_string(err, test), and P004Result MUST reuse that inherited formatting rather than re-implementing traceback formatting. addSubTest(test, subtest, err) is a REQUIRED override: a unittest subtest failure is reported ONLY through addSubTest - the base TestResult never calls addFailure/addError for it, and a TestCase whose subtests all failed still reaches addSuccess - so omitting the override records a red harness test as success and emits a spurious P004_UNEXPECTED_GREEN, a silent false pass. Its contract: err is None means that subtest passed, record nothing and do not alter the parent's outcome; err is an exc_info tuple formatted by the same inherited _exc_info_to_string(err, subtest); attribution is by the PARENT test object via requested_of[id(test)], because the _SubTest proxy is created at run time and is not in the load-time identity map; the parent's outcome becomes failure (or error when the exception is not an AssertionError subclass) on the FIRST failing subtest; the parent's detail_text is the concatenation of every failing subtest's own formatted string in call order, each prefixed with that subtest's _subDescription(); and a test reaching addSuccess after at least one failing subtest keeps the failure outcome. Also override addSuccess, addSkip, addExpectedFailure and addUnexpectedSuccess so those outcomes are recorded in their own right and never folded into pass or fail; a skipped declared test is P004_MISSING_OBSERVATION.

COMPARE. Emit the observed outcome map keyed by REQUESTED NAME, test_id -> (outcome, detail_text), merging the load-time classifications, and perform the exact-set-equality comparison against the declared map in both directions. Marker matching runs against that test's OWN detail_text, so P004_MARKER_ABSENT names exactly one test.
