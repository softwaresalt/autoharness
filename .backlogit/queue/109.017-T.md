* The immediate post-claim invocation is the GLOBAL verification contract from 109.001-T, not a target-status-only check. When the target is not yet the sole active shipment it distinguishes TWO outcomes: (a) `CLAIM_NOT_OBSERVED` -- 109.021-T read-only retry-required token (non-zero, NON-`blocked`): pre-claim topology was valid but the claim is not yet observed (target still `queued`, zero active). This is NOT a terminal halt -- it triggers the bounded Ship-owned reclaim-and-reverify sequence below. (b) Genuine ambiguity -- any OTHER active shipment, a mismatched single active, or an inconsistent snapshot (`SHIPMENT_STATE_INCONSISTENT`) -- halts terminally with `CLAIM_VERIFY_FAILED`/remediation and NO reclaim.
* Bounded `CLAIM_NOT_OBSERVED` handling (Ship-owned; coordinates with 109.021-T detection-only contract and the existing Step 4a claim semantics; introduces NO CAS/lock/lease and asserts no atomic exclusion). On `CLAIM_NOT_OBSERVED` from the immediate post_claim gate, Ship performs at most ONE reclaim-and-reverify cycle, in this exact order: (1) Double-claim guard FIRST -- re-read the shipment own status via CLI (`backlogit shipment get <ID>`); if it is already `active` AND a re-run of the post_claim GLOBAL verification shows it is the sole active target, the original claim actually succeeded despite the token, so treat as converged (`CLAIM_VERIFY_OK`) and DO NOT reclaim; if two-or-more-active / mismatched-single / unexpected status / inconsistent snapshot, halt terminal `CLAIM_VERIFY_FAILED` with NO reclaim. (2) Only if still `queued` with zero active, re-run the full `--phase pre_claim` GLOBAL topology/readiness/zero-active checks; any non-zero pre_claim verdict is terminal fail-closed (never reclaim into an invalidated topology). (3) Perform the actual supported claim operation exactly once (`{{OP_CLAIM_SHIPMENT_MCP}}`, CLI fallback `backlogit shipment claim <ID>`) -- backlogit existing unlocked read/check/write claim, no atomic exclusion. (4) Re-run the immediate `--phase post_claim` GLOBAL verification: exit 0 / sole-active-target -> converged, proceed; a SECOND `CLAIM_NOT_OBSERVED` (bound exhausted) or any ambiguity -> terminal `CLAIM_VERIFY_FAILED`. The cycle runs at most once, reconciled with Step 4a existing single claim-retry (one claim attempt, not an unbounded loop).
