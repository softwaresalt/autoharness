PLAN UNIT U10 (plan revision 5). Domain: Python source. Posture: test-first.

FILES (2): src/autoharness/gates/closure_contract.py (EXTENDED), tests/test_closure_contract_path.py (NEW).

PURPOSE
The builder is the only part of the contract module that accepts caller-supplied identifiers and turns them into a filesystem path, so it carries an input-validation and containment obligation the rest of the module does not.

NORMATIVE SOURCE: plan revision 5, section "Contract Specification", items C1 (identifier grammars) and C4 (path construction and containment). Where this task body and the plan appear to differ, THE PLAN GOVERNS.

CHANGES
- validate_closure_id(value, *, field) -> str — FIELD-AWARE. field is "shipment_id" or "feature_id", and the value is checked against the corresponding grammar from C1. The validator CONSUMES those grammars and does not restate them, so builder and classifier cannot drift. Raises ClosureContractError naming the offending FIELD AND VALUE when the input is empty or whitespace, contains a path separator (/ or \), contains a traversal segment (. or ..), is absolute (/...), carries a drive designator (C:), is a UNC path (\\server\share), contains a null byte or control character, carries an internal hyphen in the ordinal segment, carries a LOWERCASE OR WRONG KIND LETTER, or otherwise fails its field's pattern.
- build_closure_path(closure_dir, shipment_id, feature_id, *, workspace_root) -> Path implementing C4 EXACTLY, in this order:
  1. Validate BOTH identifiers through validate_closure_id BEFORE any path join.
  2. RESOLVE THE WORKSPACE ROOT FIRST: root = Path(workspace_root).resolve(). This is the ONLY place the process CWD may participate at all, and only because the caller supplied a relative root.
  3. ANCHOR THE CLOSURE DIRECTORY: if closure_dir is RELATIVE, it is anchored as root / closure_dir and only then resolved. A RELATIVE closure_dir IS NEVER RESOLVED AGAINST THE PROCESS CWD. If closure_dir is absolute, it is resolved as given.
  4. Assert the resolved closure directory is INSIDE the resolved root; reject otherwise, naming the escaping path and the root. This rejects absolute out-of-root directories, relative directories that traverse out of the root, and symlink/junction targets outside the root (the check runs on the RESOLVED path, so a link is followed before the containment test).
  5. Render the canonical filename from the validated identifiers and resolve the output path.
  6. Assert the resolved OUTPUT path is inside the resolved root; reject otherwise.
  7. Assert output.parent equals the resolved closure directory.
  This is the ONLY construction path 167.007-T's composed test may use for canonical (R1) names.

SCOPE GUARD
No frontmatter parsing and no validity judgement. The builder NEVER creates a directory, NEVER writes a file, and NEVER touches docs/closure/ (D8).

TESTS (4) — bounded negative battery, all four parametrized
1. ACCEPTED-DOMAIN ROUND-TRIP, BOTH DIRECTIONS — parametrized over the complete accepted boundary set (numeric ordinal, alphanumeric ordinal, single-character ordinal, long ordinal). FORWARD: every accepted (shipment_id, feature_id) pair builds a path that classify_closure_candidates classifies as CANONICAL for that shipment, with the captured shipment_id EXACTLY EQUAL (NO case folding) to the input. REVERSE: every identifier pair R1 captures is accepted by validate_closure_id for its field. The two accepted domains are asserted to be THE SAME SET. (This bidirectional claim is made for R1 only; R2 is legacy-read-only and carries no such claim.)
2. PATH-ESCAPE INPUTS ARE REJECTED — parametrized over separators (a/b, a\b), traversal (.., ., ../x), absolute (/162-S), drive (C:162-S), UNC (\\srv\share). Each raises ClosureContractError naming the field.
3. GRAMMAR REJECTS — parametrized over empty, whitespace, a null byte, a leading/trailing/doubled hyphen, an internal-hyphen ordinal (16-2-S), a LOWERCASE KIND LETTER (162-s) on the write path, a cross-field kind letter (162-F as shipment_id, 154-S as feature_id), and a non-ASCII segment. Each raises ClosureContractError naming the field and the value.
4. WORKSPACE-ANCHORING AND CONTAINMENT MATRIX — THE WHOLE SCENARIO RUNS WITH THE PROCESS CWD SET TO A TEMPORARY DIRECTORY OUTSIDE THE WORKSPACE ROOT (monkeypatch.chdir), which is what makes the anchoring assertions meaningful. Parametrized over: a RELATIVE closure_dir (accepted, and the built path is asserted to lie under workspace_root and NOT under the CWD); an absolute in-root closure_dir (accepted); an absolute OUT-OF-ROOT closure_dir (REJECTED); a relative closure_dir that traverses out of the root (REJECTED); an in-root closure_dir reached through a symlink that stays inside the root (accepted); an in-root closure_dir whose target is a SYMLINK OR JUNCTION pointing outside the root (REJECTED); and a resolved output path landing outside the root (REJECTED). Each rejection names the escaping path and the workspace root. The symlink/junction rows are SKIPPED WITH AN EXPLICIT REASON on platforms where the test process cannot create them, and are NEVER silently passed.

ACCEPTANCE
- No code path resolves closure_dir against the process CWD.
- workspace_root is resolved before closure_dir is anchored.
- Scenario 4 demonstrably runs from a CWD that is not the workspace root.
- Touches NOTHING under docs/closure/ (D8).
