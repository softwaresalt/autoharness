SIZE: S. COMPLEXITY: medium. (Two independent axes; also emitted as structured backlog fields.) Shipment 1 (P0). Split out of 118.005-T by the F27 ruling so that the atomic-acquisition task and the lock-lifecycle task each stay inside the 2-hour box. Extend src/autoharness/supervise/locking.py with STALE-LOCK LIFECYCLE handling, built strictly on top of the atomic primitive established in 118.005-T and never as a substitute for it. Liveness uses PID PLUS PROCESS START-TIME so a recycled PID cannot be mistaken for the original holder. A stale lock (dead PID, or start-time mismatch) is NEVER silently reclaimed: it requires an explicit operator --force-unlock, which is exposed by the 120.006-T CLI option contract and is the only reachable remedy for a stranded lock. Crash-without-release leaves a stale lock that is DIAGNOSED, reported with an actionable message naming the holding PID and session id, and cleared only on explicit operator action. FAIL CLOSED (H2): when liveness cannot be determined, treat the lock as LIVE and refuse. Errors use the taxonomy from 118.003-T. Tests: dead-PID stale detection, start-time mismatch (recycled PID) rejection, force-unlock happy path, force-unlock refused against a LIVE lock, crash-without-release cleanup, and indeterminate-liveness -> REFUSED.
