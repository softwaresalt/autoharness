Extract the probe body into an importable helper so it is testable at all (an inline heredoc in YAML is untestable by construction; the workflow keeps calling it as a step and no behaviour moves). Assert SIX cases against INJECTED responses (C1-C3 from cycle 0; C4-C6 ADDED IN ORCHESTRATOR REVIEW-FIX CYCLE 1, FINDING 15). C1 - HTTPError 404 => probe PROCEEDS. C2 - 200 from pypi.org whose body identifies the REQUESTED version => NON-ZERO EXIT with the version AND the remedy in the message. C3 - URLError => PROPAGATES, never treated as "not present". C4 - WRONG-HOST REDIRECT: a 200 whose FINAL RESOLVED URL host is NOT pypi.org (a mirror or interception proxy) => RE-RAISED AS A TRANSPORT ERROR, explicitly NOT "present". Assert on the FINAL response URL after redirects, not on the requested URL. This is the case that would otherwise hard-fail a legitimate release, and binding H2a's host assertion is unverified without it. C5 - MALFORMED JSON: a 200 from pypi.org whose body is not decodable JSON, OR is valid JSON lacking info.version => RE-RAISED AS A TRANSPORT ERROR. Cover BOTH shapes as separate cases; H2a says "if the body cannot be parsed, treat it as a transport error" and without these that clause is prose. C6 - MISMATCHED VERSION: a 200 from pypi.org whose body identifies a version DIFFERENT from the one requested => probe PROCEEDS, because the requested version is not published. C2 AND C6 TOGETHER are what make H2a testable: a probe that merely checks "did the request succeed" passes C2 and FAILS C6.
