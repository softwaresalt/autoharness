THREE MANDATORY DELIVERABLES, all acceptance criteria, none deferrable:

(1) PUBLISH BOTH FILES. schemas/payload-manifest.schema.json (the live contract) AND the immutable versioned mirror schemas/payload-manifest/1.0.0.schema.json. This is the two-file convention observed on EVERY other versioned schema in this repository (harness-config, harness-manifest, workspace-profile, tool-telemetry-event, validation-gates). A top-level schema with NO versioned mirror is a conformance FAILURE.

    The schema declares, at 1.0.0:
    - `include` and `exclude` - the base path rule sets.
    - PER-CHANNEL OVERLAYS FOR ALL THREE CHANNELS - `wheel`, `sdist`, AND `plugin`. The channel key set is a CLOSED THREE-MEMBER ENUM: exactly wheel, sdist and plugin, no fourth member and no open-ended additionalProperties escape. A schema that permits an undeclared channel silently readmits an unclassified publication surface, which is the whole defect this shipment closes.
    - `generated_output_roots` (AC3d) - the list of paths that are OUTPUTS of the generation command rather than INPUTS to classification. Declared here so the resolver (160.004-T) and the classifier have a schema-backed key to read; its binding semantics are specified by 160.003-T and implemented by 160.004-T, not restated here.
    - the single `target_workspace_paths` key - the SOLE authored occurrence of those prefixes across EXECUTABLE AND CONFIGURATION SURFACES (see AC2d and 160.004-T's centralized classifier). Prose, documentation and test fixtures may name a prefix; executable and configuration surfaces may not re-derive it.

(2) REGISTER THE CONTRACT in src/autoharness/schema_contracts.py so the existing mutation detector covers payload-manifest from its FIRST release rather than after the first incident. This repository has THREE RECORDED OCCURRENCES of in-place schema mutation without a version bump (docs/compound/2026-08-30-157-s-149-f-schema-mutation-in-place-third-occurrence.md), and that learning records that the shorter, more dangerous fix path applies EXACTLY to CONTRACTS UNREGISTERED IN SCHEMA_CONTRACTS: an unregistered schema has NOTHING that detects a later in-place mutation, so a fourth occurrence would land silently.

(3) ASSERT THE PAIR. The test that FAILS if the live file and the 1.0.0 mirror diverge while the declared $id/version still reads 1.0.0. That assertion is precisely what was absent in all three prior occurrences.

CRITICAL: this is a NEW schema at 1.0.0. Do NOT mutate any existing schema in place.
