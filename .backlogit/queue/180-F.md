FOUNDATION (P3). ABSORBS the scope previously carried by 179-S. Make the verdict manifest the single authority for latest attempt and verdict, compatibly with the records that already exist. Delivers: a VERSIONED, TOTAL manifest normalizer that accepts all three live shapes - Family A attempt-roster (six manifests, 21 keys), Family B cycle-record (one manifest, 17 keys, governing 175-S), and Family C pre-review (null latest_attempt, empty attempts) - and emits a canonical record that is OPEN at the boundary and CLOSED at the core; strict canonical validation downstream of normalization only; and an ATOMIC review-result recorder built on the P2 atomic writer so the immutable artifact, the roster entry, the top-level selection fields and the plan source_history can never be partially written. Migrates ALL FOUR review-verdict consumer surfaces in ONE activation commit: templates/skills/harvest, templates/skills/plan-review, and both installed mirrors. Harvest is the load-bearing consumer - it reads an inline decision: PASS marker from the plan body today and never opens the manifest. SELF-HOSTING: this unit is authored and reviewed under the CURRENT inline-marker system; its activation commit is what switches the workspace onto the manifest system, and the new gate never admits its own plan. MANIFEST PARITY IS ATOMIC (decision D11, bound into the governing plan at revision 2; the EXACT manifest-parity contract - the enumerated activation arithmetic and the owned fail-closed verification step that replaces the generic verify-workspace command - is stated at PLAN REVISION 3, revision 4 binds that verification to the exact index snapshot the commit records, and revision 5 separates the pre-commit prechecks from the post-commit acceptance adjudication). Two of the four migrated consumer surfaces - .github/skills/harvest/SKILL.md and .github/skills/plan-review/SKILL.md - are MANIFEST-TRACKED INSTALLED ARTIFACTS; the two templates are not, because .autoharness/harness-manifest.yaml tracks no template. 180.010-T therefore refreshes EXACTLY TWO manifest artifacts: checksums IN ITS SINGLE ACTIVATION COMMIT AND THE SAME ROLLBACK UNIT, rewriting each to the sha256 of the installed file AS WRITTEN BY THAT COMMIT, and then VERIFIES CHECKSUM PARITY under an OWNED FAIL-CLOSED VERIFICATION CONTRACT BOUND TO THE EXACT INDEX SNAPSHOT THE COMMIT RECORDS - NOT the generic verify-workspace command, which reports whole-workspace install state read from the working tree rather than adjudicating a named staged digest against a named artifacts: entry and whose exit status is therefore not a checksum assertion. That contract runs AFTER ALL COMMIT MEMBERS ARE STAGED and BEFORE the commit is created, and it: (1) ASSERTS THE STAGED SET IS EXACTLY THE FIVE INTENDED COMMIT MEMBERS - git diff --cached --name-only equals that set, and a MISSING member, an EXTRA staged path or a DUPLICATE entry each fails; (2) REJECTS ANY UNSTAGED DIFFERENCE for those members - git diff --name-only restricted to them must be empty and none may be untracked, so the bytes verified are the bytes committed; (3) HASHES EACH TOUCHED INSTALLED ARTIFACT FROM THE INDEX, recomputing SHA-256 over the staged blob read as :<path> (git cat-file -p :.github/skills/harvest/SKILL.md, git cat-file -p :.github/skills/plan-review/SKILL.md), never a working-tree read; (4) PARSES THE MANIFEST FROM THE INDEX TOO, as :.autoharness/harness-manifest.yaml, so the entries compared against are the entries this commit records; (5) ADJUDICATES THE ENTRY SET TOTALLY - exactly one artifacts: entry matches each literal path, its primitive and template metadata are exactly as required and unchanged, and its checksum equals the recomputed digest byte-for-byte, with MISSING, EXTRA (any entry this commit adds or removes), DUPLICATE, METADATA-DIVERGENT and CHECKSUM-MISMATCHED each failing; this activation installs NO new artifact so no new entry is required here, and where a future activation does install one the same step asserts the new entry exists with exact path/template/primitive values before comparing its checksum; (6) RECORD THE INDEX IDENTITY AND FORBID RE-STAGING - record the index identity with git write-tree IMMEDIATELY AFTER (5) passes, then create the commit with NO INTERVENING INDEX MUTATION (no git add, git rm, git stash, checkout or restore); git commit -a and PATH ARGUMENTS to git commit are PROHIBITED, because both re-stage content after verification and would commit bytes the gate never adjudicated; (7) FAIL CLOSED BEFORE THE COMMIT EXISTS - steps (1)-(6) all run BEFORE the commit is created, so any failure among them, any unreadable input or any digest mismatch EXITS NON-ZERO AND THE COMMIT IS NOT CREATED, which is the whole of the pre-commit gate; and (8) ADJUDICATE ACCEPTANCE AFTER THE COMMIT IS CREATED - the commit is then created NORMALLY and this step DOES NOT PREVENT ITS CREATION and claims no such power; immediately afterwards compare git rev-parse HEAD^{tree} against the tree recorded in (6), and on a MISMATCH the commit records a tree the gate never adjudicated, so the activation is NOT ACCEPTED AND NOT PUBLISHABLE - it BLOCKS THE PUSH, blocks every downstream state token, verdict, manifest advance and handoff depending on this activation, and the LOCAL COMMIT MUST BE REVERTED OR CORRECTED AND THE WHOLE CONTRACT RE-RUN before any further step proceeds. THE COMMIT CONTAINS EXACTLY FIVE FILES AND MIGRATES FOUR CONSUMERS - templates/skills/harvest/SKILL.md.tmpl, templates/skills/plan-review/SKILL.md.tmpl, .github/skills/harvest/SKILL.md, .github/skills/plan-review/SKILL.md and .autoharness/harness-manifest.yaml: the refreshes are COMMIT MEMBERS, not consumer surfaces, so the consumer count stays FOUR, the mechanical consumer-inventory rule is unchanged, and no gate arity or fixture set moves. ROLLBACK COVERS ALL FIVE COMMIT MEMBERS: git revert of the single activation commit restores all four consumer surfaces AND both manifest checksums together.
