Re-scopes 936C68F3 part 2 (deliberation 013-DL Option C) from a CONSTRAINED operator-invoked forward-REPAIR mode to a REPORT-ONLY DETECTION + operator-remediation-guidance capability, per Copilot PR #304 review finding 1.

WHY RE-SCOPED (evidenced read-only against backlogit 1.8.0 source; C:\Source\GitHub\backlogit NOT mutated): the prior plan relied on a "forward re-claim (queued->active) via the existing atomic ClaimShipment (061-F)" as a shipment-RECORD-only repair of the queued-with-active-work inconsistency. Verified this is NOT achievable via any supported operation:
- ClaimShipment is NOT record-only. `internal/core/shipment_lifecycle.go` ClaimShipment transitions the shipment queued->active (MoveShipmentStatus) AND THEN iterates EVERY manifest member (NormalizeShipmentItems): it `loadArtifact`s each member and `setArtifactStatus(...Active)` for every member whose status is `queued`, cascading parent-feature status; a mid-flight member load/activation failure triggers `rollbackShipmentClaim` (all-or-nothing). A clean "record-only" flip is therefore impossible — a claim re-drives manifest-wide (re)activation with side effects.
- ClaimShipment is the ONLY queued->active transition and is STRICTLY SINGLE-SHOT: `isValidShipmentTransition` permits only queued->active and active->{shipped,abandoned}; active->active is rejected with `ErrShipmentConflict`; there is NO active->queued edge and NO record-only status-fix. There is also NO `blocked` shipment status in 1.8.0.
- Therefore the queued-with-active-work reparable state (a shipment whose claim was silently dropped while its MIXED-ROLE manifest kept progressing and completing) cannot be cleanly repaired by a supported record-only operation; re-claiming would (re)activate/cascade members rather than only correct the shipment record, and no other supported operation exists. Inventing direct frontmatter mutation, locks/CAS, or external backlogit changes is explicitly OUT OF SCOPE (operator constraint). TRUE AUTO-REPAIR IS THEREFORE DEFERRED.

RE-SCOPED SHIPPABLE SCOPE (REPORT-ONLY; read-only/additive; NO mutation authority):
1. STRENGTHEN DETECTION of the queued-with-active-work inconsistency in `templates/skills/shipment-reconcile/SKILL.md.tmpl` via a best-effort READ-ONLY inspection over EXISTING backlogit reads (`shipment list` + per-shipment/per-task status reads) plus a PER-TASK ALLOWED-STATE ROLE classification (used ONLY to DESCRIBE, never to gate a mutation), and EMIT a clear REPORT-ONLY diagnostic (offending shipment id, record status, per-task role + any per-item anomaly).
2. OPERATOR-REMEDIATION GUIDANCE: document the SUPPORTED manual remediation path the operator uses to resolve the inconsistency via backlogit's sanctioned lifecycle transitions ONLY — never an autoharness-issued mutation, never a fabricated active->queued rollback, never a blocked->queued transition.
3. Audit + telemetry for detection/report outcomes; verify/assertion-anchors + regression guard that pre/post/safe-close AND the detection path remain STRICTLY no-auto-mutation; docs.
