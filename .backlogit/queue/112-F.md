<!-- BEGIN:description -->
Implements deliberation 013-DL Option C (CONSTRAINED lift of shipment-reconcile's no-auto-repair stance). Adds a distinct, opt-in, operator-invoked `mode: repair-record-status` to templates/skills/shipment-reconcile/SKILL.md.tmpl that performs ONLY a FORWARD re-claim (queued->active) of a queued-with-active-work shipment, and ONLY when strict preconditions hold — else falls closed to the existing report-and-halt. The existing pre/post/safe-close paths remain STRICTLY no-auto-mutation. This mode is BEST-EFFORT DETECTION + fail-closed remediation, NOT prevention: it is NOT "provably safe", does NOT serialize concurrent claims, and does NOT provide atomic mutual exclusion (see the retained TOCTOU limitation below).

IMPL-PLAN (source of truth = 013-DL, incl. Addendum A + Addendum B):
- New isolated repair mode with preconditions: (i) a TARGET-AWARE READ-ONLY REPAIR-INSPECTION (per 013-DL Addendum A) over EXISTING backlogit reads requires ZERO active shipments AND that the target is the SOLE queued-with-active-work inconsistency — NOT the plain `autoharness gate pipeline-topology` invocation which is UNREACHABLE here (its detect-before-consistency scan halts on the target's own SHIPMENT_STATE_INCONSISTENT before the active-shipment invariant runs); any other active shipment or any non-target inconsistency => refuse (fail closed). This inspection is BEST-EFFORT DETECTION, NOT a lock/lease/serializer; (ii) record re-reads `queued` — the ONLY re-claimable shipment status; backlogit 1.8.0 has NO `blocked` shipment status (ShipmentStatus is only queued|active|shipped|abandoned) and no blocked->queued transition, so a shipment record with a non-lifecycle/legacy `blocked` status is MALFORMED LEGACY DATA => REFUSE + HALT for manual remediation, never a fabricated transition (H3); (iii) manifest tasks in a shape consistent with a silently-dropped claim, not torn/partial — verified by a PER-TASK ALLOWED-STATE ROLE classification (CORRECTED, publication-review P2 2026-08-06 / 013-DL Addendum D; FURTHER CORRECTED, publication-review P1 2026-08-06 / 013-DL Addendum E; FURTHER CORRECTED, publication-review P1 2026-08-06 / 013-DL Addendum F — TWO valid archived-completed representations): each manifest task must be a UNIQUE, NON-CONFLICTING record for its role, per how backlogit persists task state — a `queued` task is a UNIQUE LIVE QUEUE record (`status: queued`, no archive copy); an `active` task is a UNIQUE LIVE QUEUE record (`status: active`, no archive copy); a COMPLETED task is a UNIQUE ARCHIVE record in EITHER of backlogit's two valid archive representations — (a) `status: done` in `archive/` (explicit provenance NOT required) OR (b) `status: archived` + `archived_status: done` with valid `archived_from` provenance — with no conflicting live queue record. Allowed roles are EXACTLY {live-queued, live-active, archived-completed(done — either archive representation)}. FAIL CLOSED on ANY duplicate (id in both queue and archive), conflicting (queue status vs role mismatch, archive-alongside-queue, or a live `status: done` in the QUEUE), missing (no queue or archive file), malformed/absent provenance on a `status: archived` record (`archived_status: done`/`archived_from`), any OTHER archived status/provenance shape, orphan, out-of-role, or torn-partial anomaly. This is NOT a single-`expected_status` all-`matched` gate — that gate is UNREACHABLE for a queued-with-active-work TARGET, whose manifest tasks are MIXED-ROLE by definition (no one `expected_status` can make every task `matched`), so it would always refuse the exact state being repaired. Ambiguity refusal is unweakened: the torn/inconsistent signal is a per-item ANOMALY, not the mixedness of roles. (iv) backlogit reachable (CLI-preferred re-read); the forward re-claim executes ONLY through backlogit's EXISTING atomic all-or-nothing ClaimShipment (061-F) — NO new lock/lease/CAS. ClaimShipment atomicity is PER-SHIPMENT all-or-nothing (prevents TORN writes within one claim); it does NOT provide mutual exclusion between concurrent claims; and it is STRICTLY SINGLE-SHOT, NOT idempotent — a repeat claim on an already-`active` shipment is REJECTED with ErrShipmentConflict (isValidShipmentTransition treats active->active as invalid), which is exactly the double-claim guard that fails a racing/repeated second claim CLOSED rather than silently re-activating. (v) structured audit entry + telemetry on every attempt (attempted/succeeded/refused/degraded AND on post-claim two-active detection).
- TOCTOU RESIDUAL RISK (RETAINED, EXPLICIT — 013-DL / 109-F): the inspection and the ClaimShipment are SEPARATE, UNLOCKED operations. A concurrent claim can race in the window BETWEEN inspection and re-claim; the post-condition may only DETECT a second active shipment AFTER the target is already activated. This is the SAME already-accepted 109-F claim-path TOCTOU (best-effort detection, not prevention) and is neither introduced nor worsened by this mode. NEVER claim prevention, serialization, atomic exclusion, or "provably safe."
- Post-condition (DETECTION, not prevention): after the re-claim, re-verify the GLOBAL exactly-one-active-and-it-is-the-target invariant (extend the 109-F post-claim invariant; avoid self-refusal double-count). If a racing claim produced a SECOND active shipment, the post-condition DETECTS the two-active violation and FAILS CLOSED: emit audit+telemetry, HALT, and surface the inconsistency for OPERATOR remediation. The mode performs NO remediation mutation and MUST NOT attempt an active->queued rollback of the target (that transition is forbidden by backlogit 1.8.0 isValidShipmentTransition). Fail-closed manual remediation: the operator resolves the two-active state through backlogit's own sanctioned lifecycle transitions (e.g., completing/shipping or otherwise terminalizing one shipment) — never via an autoharness-issued active->queued rollback.
- Operator-only, gated behind explicit `--confirm`; Ship keeps report-and-halt unchanged.
- Permanently EXCLUDED: full automatic/silent self-repair; backward-repair (return tasks to queued) stays manual/operator.

ACCEPTABILITY DECISION (honest, re-review 2026-08-05): the constrained operator-invoked FORWARD repair REMAINS ACCEPTABLE with this residual TOCTOU risk. Rationale: (1) it is operator-invoked and single-shot in a deliberate single-active manual context, not automatic; (2) the residual two-active window is IDENTICAL in nature/scope to the already-accepted 109-F claim TOCTOU — the mode introduces NO NEW risk class beyond what every ClaimShipment already carries; (3) the post-condition DETECTS the race and FAILS CLOSED to audited operator remediation, bounding blast radius; (4) it never performs the forbidden active->queued rollback. Re-scoping to report-only was CONSIDERED and REJECTED because it would remove the operator's ability to perform the safe forward re-claim while providing NO safety gain (the underlying ClaimShipment TOCTOU is identical whether reached here or via a normal claim).

P-006 HARDENING CONCLUSION: Requires plan hardening = YES (safety-critical reconcile skill gains mutation authority). HARDENING RESOLUTIONS: (H1) ISOLATION — repair mode is a separate mode string, unreachable from pre/post/safe-close; those paths keep an explicit no-mutation assertion. (H2) TARGET POST-CONDITION (DETECTION, not prevention) — after the re-claim, re-verify the GLOBAL exactly-one-active==target invariant; this DETECTS a two-active state (and avoids self-refusal double-count) but does NOT prevent a concurrent claim from racing in. (H3) MALFORMED-STATUS HARD-EXCLUSION (RECAST third re-review 2026-08-05, 013-DL Addendum C) — the re-claimable status is `queued` only; backlogit 1.8.0 has NO `blocked` shipment status and NO blocked->queued transition, so a shipment record whose persisted status is not a valid lifecycle state (queued|active|shipped|abandoned) — e.g., a legacy `blocked` value — is classified as MALFORMED LEGACY DATA and REFUSED outright with a HALT for OPERATOR manual remediation; the mode NEVER fabricates a blocked->queued (or any) transition. (H4) ATOMICITY — reuse ClaimShipment PER-SHIPMENT all-or-nothing rollback (torn-write protection within ONE claim, NOT mutual exclusion between claims); no bespoke locking. (H5) AUDIT COMPLETENESS — audit+telemetry emitted on attempted/succeeded/REFUSE/DEGRADED AND on post-claim two-active detection, not only success. (H6) DEGRADED — backlogit unreachable => refuse + report-and-halt (never blind-mutate). (H7) TARGET-AWARE INSPECTION FAIL-CLOSED (added 2026-08-06 re-review, 013-DL Addendum A) — because `gate pipeline-topology` early-halts on the target's own SHIPMENT_STATE_INCONSISTENT before the active-shipment invariant, the mode uses its own read-only inspection over EXISTING backlogit reads that discriminates the SOLE-target reparable state and REFUSES on any other active shipment, any non-target inconsistency, or any ambiguity; no new gate/CLI code, no locks/CAS, forward-only via existing ClaimShipment. (H8) TOCTOU RESIDUAL RISK EXPLICIT (added 2026-08-05 second re-review, 013-DL Addendum B) — the inspection->re-claim window is an UNAVOIDABLE, RETAINED TOCTOU identical to 109-F; the mode DETECTS and FAILS CLOSED on post-claim two-active (audit + halt + operator remediation) with NO forbidden active->queued rollback of the target, and NEVER claims prevention/serialization/atomic exclusion/"provably safe"; REQUIRES a test that a concurrent claim racing between inspection and re-claim is detected by the post-condition and fails closed to operator remediation.
