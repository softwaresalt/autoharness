* A hook SKIPPED via `git --no-verify` runs no gate code and emits no telemetry — it is inherently unobservable locally and MUST NOT be claimed observable; CI is the independent (server-side) enforcement point that catches what a local skip would miss.
* --force never fail-opens a P0 topology violation without an audit record.

<!-- BEGIN:description -->
[Shipment A / core] Implement (a) post-operation re-verify semantics for claim that re-run the GLOBAL active-shipment invariant, not just the target's own state: after claim, re-read ALL shipment records (mirror 106-S CLAIM_VERIFY_FAILED via CLI re-read) and require EXACTLY ONE active shipment that IS the resolved target. Target active-and-sole -> proceed; target still queued -> ONE bounded retry ONLY after re-running the full topology/readiness revalidation including the A2 pre-claim ZERO-active precondition + detect-before scan; target blocked, any other active shipment present, two-or-more active, or a detected inconsistency -> CLAIM_VERIFY_FAILED (halt, no reclaim). (b) the audited operator-only --force bypass that appends a structured entry to .autoharness/gates/pipeline-topology-force-audit.log, and (c) a telemetry event emitted on EVERY gate RUN (pass/fail/forced) so an audited `--force` bypass is observable whenever the gate executes. NOTE: a hook SKIPPED via `git --no-verify` does NOT run the gate and therefore emits NO telemetry — such skips are inherently unobservable to local audit/telemetry (no local observer exists at skip time; the gate cannot record its own non-execution). The required CI backstop is the INDEPENDENT (server-side) enforcement point, NOT proof that the local hook ran.
