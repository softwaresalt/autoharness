Plan unit S5-U1b of docs/plans/2026-10-19-release-1-6-0-staged-chain-plan.md (depends on S5-U1 / 216.001-T; added after PR 543 Copilot review thread 1; deliberation 042-DL D-3 and AS-7; hardening H1). Extends src/autoharness/docs_only_check.py with the lifecycle class: paths under the backlog root are admitted ONLY as exactly <root>/queue/<id>.md or <root>/archive/<id>.md for the task, its parent feature or its shipment (IDs supplied by the caller and cross-checked against the task file), or a newly added <root>/checkpoints/*.json; for an item file the diff against the start-SHA version may change only allowlisted frontmatter keys (status, updated_at, commit, archived_from, archived_status, labels limited to adding/removing harness-verification-gated and harness-ready, custom_fields.scheduler_baseline_claim, custom_fields.harness_status) and the body must be byte-identical; any other backlog path (another item, a stash file, a body edit of the task's own file) is violation BACKLOG_PATH_NOT_LIFECYCLE; the item log under <root>/logs is git-ignored and out of the set. Rationale: P-011 guarantees a clean tree only before the claim; the claim and activation then change tracked backlog files, so without this class a valid docs-only task would be rejected, and a blanket backlog exemption would be unsafe. AC: (1) END-TO-END test in a temp git repo with a temp backlog root: claim writes (status/marker changes on task, feature, shipment) -> start-SHA comment (log only) -> docs edit to an owned file -> completion returns pass; (2) the same sequence still fails closed for an unrelated item edit, a stash edit, a body edit of the task's own file, a non-allowlisted frontmatter key change, a src/ edit and an edit to a non-owned docs file; (3) a new checkpoint file is admitted, a modified existing checkpoint is not; (4) unit tests green.
