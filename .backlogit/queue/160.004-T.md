It does NOT own green for wheel-composition, sdist-composition, plugin-composition, or release-path cases.

TEST-FIRST ORDERING: this task is BLOCKED BY 160.005-T (the RED-FIRST harness) AND BY 160.008-T. The 160.008-T edge is essential, not incidental: 160.008-T authors test_skill_docs_refs_resolve_to_workspace_not_payload, whose green owner is THIS task. All harness cases must exist and have been observed failing before any loader code is written.

PLACEMENT: this module lives in `build_support/`, which is itself EXCLUDED from the payload (classified explicitly by 160.003-T). It must NOT live in `src/autoharness/` - that would ship the packaging rules inside the very artifact they trim, a coupling inversion contradicting the feature's own minimalism goal.

RESPONSIBILITIES:
- Load and schema-validate the manifest.
- Resolve include/exclude globs plus per-channel overlays for the CLOSED THREE-CHANNEL SET {wheel, sdist, plugin} into a concrete file set. The sdist channel is not optional: `[tool.hatch.build.targets.sdist]` currently declares only `core-metadata-version`, so hatchling's default sweep packages the whole project and `uv build` publishes that untrimmed sdist alongside the wheel. A resolver that knows only two channels cannot trim the one that actually discloses the excluded set.
- APPLY GENERATED-OUTPUT-ROOT SELF-EXCLUSION (plan AC3d) - see below.
- Enumerate tracked paths and report any path in the input domain that is neither included nor explicitly excluded (drives the AC2/AC8 fail-closed guard).
- Report measured file count and byte size per channel (AC8).

GENERATED-OUTPUT-ROOT SELF-EXCLUSION LIVES IN THE RESOLVER, NOT THE GENERATOR (AC3d, binding). The manifest declares `generated_output_roots` - per channel, the directory the resolved payload is MATERIALIZED INTO (`plugin-payload/` for the plugin channel). BEFORE any classification runs, the resolver REMOVES every path under every declared output root from the tracked-path enumeration. Consequences the implementation must honour:
1. The removal is UNCONDITIONAL and applies to ALL THREE CHANNELS, so the plugin generator can never read its own output and the wheel and sdist never pick the tree up as source.
2. Removed paths are NEITHER classified NOR unclassified, so the AC2 unclassified-path failure is not triggered by generated content.
3. `generated_output_roots` is a DISTINCT key from `include`/`exclude`. The resolver must never treat an output root as an include rule and must never rely on rule ORDERING to make the exclusion "win".
4. THE EXCLUSION MUST NOT BE IMPLEMENTED INSIDE THE GENERATION COMMAND. Every other consumer of this resolver - the AC2 classification check, the per-channel size report, `--check` - would otherwise still see the output tree as input, and only the generator would be protected. The resolver is the single choke point.
WHY THIS MATTERS: if `plugin-payload/**` were an `include` rule, run two would resolve it as source and write it INSIDE `plugin-payload/`, producing `plugin-payload/plugin-payload/...`, and every further run would nest again - drift that regenerating can never clear, failing the release gate permanently. Exclusion from classifier INPUT does not affect PUBLICATION: `plugin-payload/` stays tracked, committed, and the `marketplace.json` `source` target (AC3c).

GENERATION COMMAND IS A SEPARATE TASK: hardening decision H1 makes the static `pyproject.toml` include tables and the `marketplace.json` payload declaration DERIVED artifacts. The single deterministic command that generates and drift-checks them - `python -m build_support.payload generate --channel {wheel|sdist|plugin|all}` and its `--check` mode, where `all` means all three - is delivered by 160.014-T, which CONSUMES this resolver. Keep the resolver's public surface stable and importable so that command can build on it; do NOT implement the generation/serialization path here (it would push this task past the 2-hour rule and mix resolution with codegen). This task delivers the RESOLVER; 160.014-T delivers the GENERATION COMMAND.

CENTRALIZED TARGET-WORKSPACE PATH CLASSIFICATION: expose ONE function, `build_support.payload.classify_target_workspace_path(path)`, which is the SOLE decision point for "does this docs/* reference resolve against the target workspace rather than the payload". It reads the manifest's single `target_workspace_paths` key (authored by 160.003-T) and MUST NOT re-list the docs/* prefixes in its own source. AC5's skill-reference test, AC9's Gate 4 allow-list, and the R2 false-positive rule all call THIS function.

  THE AC2d SINGLE-OCCURRENCE TEST IS SCOPED TO EXECUTABLE AND CONFIG SURFACES ONLY: build_support/**, src/**, tests/** EXCLUDING tests/fixtures/**, pyproject.toml, marketplace.json, .github/workflows/**, and the manifest itself. FIXTURE CARVE-OUT (extended review-fix cycle 4, finding 9): tests/fixtures/** IS EXCLUDED FROM THE SCAN SURFACE, so the surface is build_support/**, src/**, tests/** EXCLUDING tests/fixtures/**, pyproject.toml, marketplace.json, .github/workflows/**, and the manifest. THE CONTRADICTION THIS CLOSES: 160.018-T permits test fixtures to name a prefix while the scan covered tests/** WHOLESALE, so 160.001-T recording an accurate baseline inventory would have FAILED the drift test. THE GUARANTEE IS PRESERVED BY DERIVATION, NOT BY TEXTUAL ABSENCE: a SECOND assertion in the same case forbids ANY module under build_support/** or src/** - INCLUDING THE CLASSIFIER THIS TASK BUILDS - from obtaining target-workspace prefixes from a fixture, a test constant, or any source other than classify_target_workspace_path reading the manifest key. A fixture literal is INERT DATA; a fixture literal that something EXECUTABLE READS is a second source of truth, and that - not its existence - is the drift the rule stops. Both halves are asserted by test_target_workspace_prefixes_have_exactly_one_authored_occurrence (authored 160.005-T, green owner 160.003-T), so the carve-out is TESTED rather than assumed. Within those surfaces the rule is ABSOLUTE - exactly ONE authored occurrence, in the manifest. Documentation, plans, deliberations and backlog records are EXCLUDED from the test: an illustrative mention in prose cannot cause the drift the rule prevents, because nothing reads it. A repository-wide single-occurrence rule would be unsatisfiable, since the plan, the deliberation and the task records must all name the prefixes to be intelligible.
