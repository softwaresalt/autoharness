Implement the manifest loader/resolver that turns `.autoharness/payload-manifest.yaml` into a resolved per-channel file set, and the single centralized target-workspace path classifier.

GREEN RESPONSIBILITY (assigned by the RED harness 160.005-T): this task turns the RESOLVER-SCOPED cases green - test_manifest_is_sole_source_of_payload_paths (AC1), test_unclassified_tracked_path_fails_build (AC2/AC8, the V4 negative case), test_payload_size_reported (AC8). It does NOT own green for wheel-composition, plugin-composition, or release-path cases.

TEST-FIRST ORDERING: this task is BLOCKED BY the red harness (160.005-T). The harness cases must already exist and have been observed failing before any loader code is written.

PLACEMENT (plan-review finding P1-6): this module lives in `build_support/`, which is itself EXCLUDED from the payload (classified explicitly by 160.003-T). It must NOT live in `src/autoharness/` - that would ship the packaging rules inside the very artifact they trim, a coupling inversion contradicting the feature's own minimalism goal.

RESPONSIBILITIES:
- Load and schema-validate the manifest.
- Resolve include/exclude globs plus per-channel (wheel, plugin) overlays into a concrete file set.
- Enumerate tracked paths and report any path that is neither included nor explicitly excluded (drives the AC2/AC8 fail-closed guard).
- Report measured file count and byte size per channel (AC8).

GENERATION COMMAND IS A SEPARATE TASK (Orchestrator review-fix cycle 1, findings 6 and 7): hardening decision H1 makes the static `pyproject.toml` include table and the `marketplace.json` payload declaration DERIVED artifacts. The single deterministic command that generates and drift-checks them - `python -m build_support.payload generate --channel {wheel|plugin|all}` and its `--check` mode - is delivered by 160.014-T, which CONSUMES this resolver. Keep the resolver's public surface stable and importable so that command can build on it; do NOT implement the generation/serialization path here (it would push this task past the 2-hour rule and mix resolution with codegen).
CENTRALIZED TARGET-WORKSPACE PATH CLASSIFICATION (cycle 1, finding 6): expose ONE function, `build_support.payload.classify_target_workspace_path(path)`, which is the SOLE decision point for "does this docs/* reference resolve against the target workspace rather than the payload". It reads the manifest's single `target_workspace_paths` key (authored by 160.003-T). AC5's skill-reference test, AC9's Gate 4 allow-list, and the R2 false-positive rule all call THIS function. Re-implementing or re-listing the prefixes at any call site is prohibited; a test asserts exactly one authored occurrence of the prefix list in the repository.

ERROR HANDLING (plan-review finding P2-7): a malformed or schema-invalid manifest MUST fail closed with a specific, typed exception. It must never degrade to a permissive/default-inclusive payload - permissive failure reproduces the original defect.

TYPE SAFETY: explicit type signatures on public functions per Constitution Principle I (Safety-First Python).

SAFETY MODE (SHIP-10 plan H2): careful + freeze-scope. Writes are confined to `build_support/`. This task MUST NOT modify `src/autoharness/` (invariants I1/I2 - `_DATA_DIR` resolution order, `autoharness home`, `autoharness version` are read-only for this shipment). It does not wire either channel and does not generate the derived tables. NO-PUBLISH. Full mode text: docs/plans/2026-09-03-minimal-copilot-plugin-payload-plan.md section Plan Hardening -> H2.

ACCEPTANCE: AC1, AC2, AC8. Resolver output is deterministic and order-stable (same manifest in, same file set out, stable order, no environment-dependent values). The three resolver-scoped harness cases go from red to green and the transition is recorded.
