FILES (2): src/autoharness/gates/topology.py, tests/test_gates_topology.py.

PROBLEM BEING FIXED (D4)
closure_complete()'s bare `bool | None` conflates "no closure exists" with "a closure exists but I could not see it". That conflation is the defect's real operational cost: for six occurrences across two workspaces, operators were told closure evidence was MISSING while a complete, correct closure record sat in the expected directory. Compound learning lesson 8, "Unrecognised is loud", makes silent fall-through a defect in itself.

DELIVERABLES
1. _shipment_readiness_check (topology.py:1866-1882) consults closure_discovery(). Outcome mapping:
   - absent -> PREDECESSOR_CLOSURE_INCOMPLETE (token PRESERVED, so no existing consumer of the token breaks)
   - unrecognized -> NEW token PREDECESSOR_CLOSURE_UNRECOGNIZED, with the message naming THE CANDIDATE PATH(S) FOUND and THE CANONICAL PATTERN EXPECTED
   - recognized-but-invalid -> PREDECESSOR_CLOSURE_INCOMPLETE (existing behaviour, unchanged)
2. _shipment_readiness_details gains closure_discovery_outcome, closure_candidate_paths, and closure_expected_pattern. The existing `closure_complete` detail key is RETAINED with UNCHANGED semantics so the JSON payload stays backward compatible.

MANDATORY VERIFICATION (hardening H6 — resolves plan-review P2 finding F-4)
Adding PREDECESSOR_CLOSURE_UNRECOGNIZED widens the gate's PUBLIC token vocabulary. Grep the repository for every token-dispatch site over PREDECESSOR_CLOSURE_* (agents, skills, instructions, policies, scripts, tests) and confirm each either handles the new token explicitly OR fails closed on unknown tokens. A SILENT FALL-THROUGH SITE IS A BLOCKING FINDING FOR THIS TASK, not a follow-up — it would convert a vocabulary extension into an undetected behaviour change, which is the same generative failure as the defect under repair.

SCOPE GUARD
No gate is relaxed. PREDECESSOR_CLOSURE_UNRECOGNIZED is a BLOCKING token: it renames a failure, it never permits one (decision OQ-4). It is emitted ONLY when no RECOGNIZED candidate exists, so it is unambiguously blocking.

REACHABILITY (hardening H5)
The new outcome is reachable (a file named `162-S-notes.md` in docs/closure/) and escapable (rename to the canonical pattern). It is NOT a trap state.
