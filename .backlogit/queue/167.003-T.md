PLAN UNIT U3 (plan revision 5). Domain: Python source. Posture: test-first.

FILES (2): src/autoharness/gates/topology.py, tests/test_gates_topology.py.

PURPOSE
Make the gate say WHICH failure occurred: evidence absent, evidence present but unrecognized by name, or evidence recognized but invalid. Today all three collapse into PREDECESSOR_CLOSURE_INCOMPLETE, which is why the same defect has been re-diagnosed from scratch six times.

NORMATIVE SOURCE: plan revision 5, unit U3, and Contract Specification C3 (attribution).

CHANGES
- _shipment_readiness_check obtains structured discovery through a new module-level CAPABILITY ACCESSOR closure_discovery_for(readers, shipment_id) -> ClosureDiscovery | None, which duck-types the optional closure_discovery method introduced on FilesystemTopologyReaders in 167.002-T and returns None for any reader that does not expose it. When it returns None, the gate's behaviour is EXACTLY today's behaviour, so the TopologyReaders protocol and its implementers stay unmodified.
- When the outcome is `unrecognized`, emit the new token PREDECESSOR_CLOSURE_UNRECOGNIZED with a message naming THE ATTRIBUTED CANDIDATE PATH(S) FOUND AND THE CANONICAL PATTERN EXPECTED. `absent` and `recognized-but-invalid` continue to emit PREDECESSOR_CLOSURE_INCOMPLETE unchanged (D4).
- Because attribution is a DESIGNATED-POSITION PARSE (C3) — the shipment identifier is parsed from the position the anchored grammar reserves for it and that single parsed group is compared, never searched for elsewhere in the filename and never inside an R2 free-form suffix — a foreign shipment's record in the shared closure directory can NEVER produce this token for a genuinely absent shipment.
- _shipment_readiness_details gains closure_discovery_outcome, closure_candidate_paths, and closure_expected_pattern. The existing closure_complete detail key is RETAINED WITH UNCHANGED SEMANTICS so no existing consumer of the JSON payload breaks.

SCOPE GUARD
No gate is relaxed. PREDECESSOR_CLOSURE_UNRECOGNIZED is a BLOCKING token; it renames a failure, it never permits one. No protocol member is added in this unit. Touches NOTHING under docs/closure/ (D8).

TESTS (3)
1. An ATTRIBUTED unrecognized candidate produces the new token with the candidate path in `details`.
2. A reader that does NOT expose the capability produces EXACTLY today's behaviour and the original token.
3. The JSON payload still carries closure_complete.

ACCEPTANCE
- TopologyReaders protocol unchanged; _NullReaders unchanged; no existing test double modified.
- A foreign record whose free-form suffix contains the requested token does not trigger the new token.
