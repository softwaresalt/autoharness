BINDING H3: FAIL CLOSED if either file is unreadable or unparseable - a parity test that skips on a missing file is the same fail-open shape being removed. BINDING H3a (ADDED IN ORCHESTRATOR REVIEW-FIX CYCLE 1, FINDING 13) - KEY-SET CONTAINMENT IS NOT ENOUGH; TEMPLATE-OWNED MAPPINGS REQUIRE VALUE EQUALITY. H2 halts on a value-changed key, but H2 RUNS ONCE, inside 157.001-T's regeneration. A key-set-only parity test means that AFTER 157.001-T completes, a later edit silently changing mcp_tool: backlogit_create_item to something else keeps every key present and passes forever - the drift class this shipment exists to close would be detected on day one and never again. The parity test MUST therefore assert VALUE EQUALITY, not merely key presence, over the TEMPLATE-OWNED surface: (1) operations.*.mcp_tool - value equality (a wrong value fails at call time inside an agent run, never in CI); (2) operations.*.cli_command - value equality after normalizing interior whitespace (this is the declared CLI fallback that P-012 degraded mode depends on); (3) operations.*.params - value equality per key (a wrong param mapping silently writes the wrong field); (4) field_mapping.* and status_values.* - value equality (pure template-owned translation tables with no legitimate local meaning); (5) features.* - value equality PLUS an explicit no-true-to-false-flip assertion (a flag is a capability claim and a silently downgraded flag disarms a gate); (6) tool_name, tool_type, directory - value equality (identity; H7 already forbids changing tool names and this makes it testable).
BINDING H3b - THE PERMITTED WORKSPACE-OVERRIDE LIST IS EXPLICIT, ENUMERATED AND CLOSED. Value equality is useless if "workspace customization" is an open-ended excuse, and H2's P0 concern (blind regeneration destroying deliberate local customization) is real. Reconcile the two with an ALLOW-LIST OF OVERRIDE-ELIGIBLE FIELDS DECLARED IN THE TEST ITSELF. OVERRIDE-ELIGIBLE (installed MAY differ from template; the test reports the delta as INFO and PASSES): mcp_server.command, mcp_server.transport, cli.binary, and directory - the four fields that legitimately encode where THIS MACHINE finds the tool. NOT OVERRIDE-ELIGIBLE (installed MUST equal template; any difference FAILS): everything else in the value-equality list above. A field is override-eligible ONLY by appearing in that enumerated list; an unlisted difference is a FAILURE, never a tolerated customization - so widening the exemption becomes a VISIBLE EDIT to the allow-list under review, which is exactly the property H2's halt-for-review rule wants and cannot provide on its own once 157.001-T has finished. ASSERT THE ALLOW-LIST ITSELF: a fixture adding an unlisted differing field MUST FAIL, and a fixture differing only in an override-eligible field MUST PASS, so an accidental "allow everything" regression is caught in both directions. The parity test guarantees the question cannot be forgotten because the next drift fails a test instead of passing silently.
