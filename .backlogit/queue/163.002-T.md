Two assertion families plus the explicit-empty rule over the U1a fixture. AC: (1) ORDERING - a trace that reaches the cascade invocation with no pre-existing evidence record is REJECTED; a record whose collection_completed_at is absent, or is not STRICTLY BEFORE the cascade invocation timestamp, is REJECTED; (2) RECONSTRUCTION REJECTION - a trace producing a BYTE-IDENTICAL evidence record AFTER the mutation (the literal 159-S history) is REJECTED, and is rejected FOR THE ORDERING REASON, never for a content-mismatch reason. This is the load-bearing assertion: content equality is explicitly NOT sufficient, because 159-S's reconstruction WAS byte-identical and would pass any content comparison. A content-equality implementation MUST fail this test; (3) EXPLICIT-EMPTY - an evidence record with an empty validated set must record scan_performed: true with an explicit empty list; an omitted field is REJECTED, because an unrecorded empty scan is indistinguishable from a scan that never ran (the precise 159-S failure mode); (4) both new halt tokens asserted by name: RECONCILE_FAIL_PRECASCADE_EVIDENCE_MISSING and RECONCILE_FAIL_PRECASCADE_EVIDENCE_STALE, evaluated as two separately-labelled independently-failing conditions, never merged (merging two questions into one condition is the documented root cause of external defect B57F9E24); (5) RED only - no SKILL.md or template edits. Depends on U1a. Plan: docs/plans/2026-09-08-shipment-reconcile-step-0c-live-pre-mutation-evidence-plan.md U1b.
