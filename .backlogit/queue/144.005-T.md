## Deliverable (A1/R4 — flat module, NO new package)

`tests/_git_env.py` exporting:

```python
def consistent_git_env(base: Mapping[str, str] | None = None) -> dict[str, str]:
    """Return an environment mapping whose GIT_CONFIG_* triple is
    self-consistent: only (KEY_n, VALUE_n) pairs where BOTH are present are
    kept, survivors are renumbered contiguously from 0, and GIT_CONFIG_COUNT
    is set to the surviving count. Every other variable passes through
    unchanged."""
```

## A7 (BINDING) — exact shape only; never touch the other channels

Git has a SECOND, unrelated injection channel. Operate ONLY on the `GIT_CONFIG_COUNT` / `GIT_CONFIG_KEY_<n>` / `GIT_CONFIG_VALUE_<n>` triple, matched by EXACT name shape with an integer suffix. A prefix match on `GIT_CONFIG*` would silently disable them.

Pass through UNTOUCHED, with a dedicated pass-through test for EACH:
- `GIT_CONFIG_PARAMETERS`
- `GIT_CONFIG_GLOBAL`
- `GIT_CONFIG_SYSTEM`
- `GIT_CONFIG_NOSYSTEM`
- any other `GIT_CONFIG*` name

NEVER invent, default, or repair a malformed `GIT_CONFIG_COUNT` — a non-integer or negative count is returned UNCHANGED for git itself to reject.

## Binding properties, each individually tested

1. **Preservation** — every well-formed pair survives with key and value unchanged, in original relative order. `safe.bareRepository=explicit` and `credential.interactive=never` specifically MUST survive. This is the operator constraint "do not indiscriminately clear legitimate Git config injections".
2. **Narrowness (A7R, BINDING — SYMMETRIC; supersedes the original asymmetric wording)** — pair `n` is dropped **IF AND ONLY IF** `GIT_CONFIG_KEY_<n>` is ABSENT **OR** `GIT_CONFIG_VALUE_<n>` is ABSENT.

   The earlier wording ("only a pair whose `VALUE_n` is genuinely ABSENT is dropped") **contradicted this task's own deliverable**, which says only pairs where BOTH are present are kept. For a pair with `KEY_n` absent but `VALUE_n` present, the deliverable drops it while the old property 2 required keeping it — and keeping it would emit a `VALUE_n` with no matching `KEY_n` plus a `GIT_CONFIG_COUNT` that counts it, i.e. **the same malformed-triple class this normalizer exists to eliminate, in mirror image**.

   Git's contract is symmetric: for every `n` in `0 .. COUNT-1` it requires BOTH names. A missing key raises `missing config key GIT_CONFIG_KEY_<n>`; a missing value raises `missing config value GIT_CONFIG_VALUE_<n>`. Both are fatal and both end in `fatal: unable to parse command-line config`. The `9DD9E323` capture is the value-side INSTANCE of a two-sided rule, not the whole rule.

   ABSENT means the name is not present in the mapping at all. A pair whose key and value are BOTH present is KEPT, including when the value is present-but-empty on a platform that can represent it — **empty is not absent**, and that distinction is what stops the normalizer discarding a legitimate injection.

   Required SYMMETRIC test coverage (in addition to the existing value-absent case):
   - `KEY_n` absent, `VALUE_n` present -> pair DROPPED, survivors renumbered, `GIT_CONFIG_COUNT` reduced;
   - both absent -> pair DROPPED;
   - both present with an EMPTY value -> pair KEPT verbatim.

   Renumber-and-recount behavior is unchanged; only the survivor predicate becomes symmetric.
3. **Provable no-op** — when the input triple is already self-consistent, the returned mapping is `==` to the input, INCLUDING `GIT_CONFIG_COUNT` and key ordering. This is what makes the change a no-op on Linux and in CI, and it is ASSERTED, not assumed.
4. **No triple at all** — input without `GIT_CONFIG_COUNT` is returned unchanged.
5. **Malformed count** — non-integer or negative `GIT_CONFIG_COUNT` returned unchanged (A7).
6. **Purity** — the function never mutates `os.environ`.
