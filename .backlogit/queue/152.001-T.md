BINDING H2a - "VERSION PRESENT" MEANS THE BODY SAYS SO, FROM THE RIGHT HOST (made explicit in review-fix cycle 1). "Present" requires ALL of: the FINAL RESOLVED response host is pypi.org; the body decodes as JSON; the decoded body identifies THE REQUESTED VERSION. Host mismatch, undecodable body, or unexpected body shape => RE-RAISED TRANSPORT ERROR (never "present", never "absent").

BINDING H2b - A VERSION MISMATCH IS AN INTEGRITY ANOMALY, NOT EVIDENCE OF ABSENCE (this is the SINGLE authoritative statement of the mismatch outcome in this task; the cycle-1 "body decodes cleanly but names a DIFFERENT version => PROCEED" rule is WITHDRAWN and MUST NOT be reintroduced). The probe requests the EXACT-VERSION endpoint https://pypi.org/pypi/autoharness/{version}/json, which names the version IN THE PATH. A conforming PyPI can return only two things from that URL: 404 when the version does not exist, or 200 with a body identifying THAT version. A 200 whose decoded body names a DIFFERENT version is a response the protocol does not permit - it is POSITIVE EVIDENCE that something between the requester and PyPI is not behaving as PyPI (a cache serving a stale or mismatched object, a mirror synthesising responses, or an interception proxy). The REQUIRED OUTCOME is therefore RE-RAISE AS A TRANSPORT/INTEGRITY ERROR: the helper FAILS CLOSED, does NOT proceed, does NOT report "present", and publication does not occur. ABSENCE IS PROVED BY 404 AND NOTHING ELSE.
