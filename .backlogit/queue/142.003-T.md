Derive the role-route and escalation variables, preserving the PROSE-ONLY vs RAW-STORAGE split. This is the highest-consequence task in the feature.

**Plan:** `docs/plans/2026-08-21-verify-workspace-variable-derivation-plan.md` Task 1 (second half) + amendments B2, B6

## Variables in scope (~15)
RAW pass-through (classification `DERIVE-TO-EMPTY-STRING` when unset): `STAGE_FAMILY`, `STAGE_PROVIDER`, `STAGE_REASONING_EFFORT`, `SHIP_FAMILY`, `SHIP_PROVIDER`, `SHIP_REASONING_EFFORT`, `STAGE_ESCALATION_FAMILY`, `STAGE_ESCALATION_PROVIDER`, `STAGE_ESCALATION_REASONING_EFFORT`, `SHIP_ESCALATION_FAMILY`, `SHIP_ESCALATION_PROVIDER`, `SHIP_ESCALATION_REASONING_EFFORT`, `LEGACY_ESCALATION_FAMILY`, `LEGACY_ESCALATION_PROVIDER`, `LEGACY_ESCALATION_REASONING_EFFORT`.
RESOLVED (prose only): `ESCALATION_FAMILY`, `ESCALATION_PROVIDER`, `ESCALATION_REASONING_EFFORT`.
Also: `ANCHOR_REVIEW_FAMILY`, `ANCHOR_REVIEW_PROVIDER`, `ANCHOR_REVIEW_REASONING_EFFORT`.

## THE CRITICAL CONSTRAINT (C3 — the single highest-consequence error available in this feature)
`{{ESCALATION_*}}` is the ACTING-ROLE-COLLAPSED, RESOLVED value and renders `escalation-protocol.instructions.md` / agent-narrative PROSE ONLY. `{{LEGACY_ESCALATION_*}}`, `{{STAGE_ESCALATION_*}}` and `{{SHIP_ESCALATION_*}}` are RAW pass-through written verbatim into `harness-config.yaml.tmpl`'s flat and nested blocks.

Substituting the collapsed value into a raw slot copies a NESTED-ONLY override into the FLAT block on re-render, reproducing the H2 flat+nested ambiguity that PR #316 round 3 already fixed once — and would corrupt the escalation route agents resolve at session start.

**Amendment B6 extends this to the role routes themselves.** `templates/agents/_stage.agent.md.tmpl` frontmatter uses `{{TIER_3_*}}`, NOT `{{STAGE_*}}`. So `{{STAGE_*}}`/`{{SHIP_*}}` occur ONLY in `harness-config.yaml.tmpl` raw storage, whose own comment reads "Absent/empty sub-fields fall back to tier3 (stage) / tier2 (ship)". Deriving these WITH the tier fallback applied would materialise a role override the operator never declared — the same defect class, one level up. They are RAW: empty when unset, fallback NOT applied.

## Test-first requirement (amendment B2 — must be NEGATIVE as well as positive)
Given a workspace with a nested `stage.escalation` override and an UNSET flat `escalation`:
- assert the rendered flat block's three sub-fields are the EMPTY STRING, **and**
- assert they are specifically NOT EQUAL to the nested override's values.
A positive-only test would pass under the defect whenever the two happen to match.
Also assert the P-013.5 per-sub-field tier fallback holds for PROSE resolution (an absent `stage`/`ship` route resolves each sub-field from tier3/tier2, never from a hardcoded default and never from the current session model).

## Acceptance criteria
- AC-a. All ~18 role/escalation/anchor-review variables removed from T0a's expected set.
- AC-b (feature AC-F4). The NEGATIVE test above exists and passes.
- AC-c. A test proves that a workspace with a nested `stage.escalation` override and an empty flat `escalation` renders the flat block INERT (all-empty) — C3 enforced by test, not by comment.
- AC-d (C4). Round-trip: each of these renders into its documented slot in `templates/harness-config.yaml.tmpl` (lines 86–130).
- AC-e. `_render_template` UNCHANGED.
