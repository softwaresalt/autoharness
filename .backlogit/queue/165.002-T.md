3. Implement the four-state resolution (decision D1). Non-empty edges -> evaluate as today, provenance `explicit`. Empty edges -> DECLARED ROOT (label present) passes as `declared_root`; GENESIS passes as `genesis` ONLY under the narrow rule below; otherwise UNSEQUENCED blocks with token UNSEQUENCED_SHIPMENT and provenance `unsequenced`. States must be TOTAL and MUTUALLY EXCLUSIVE.

   GENESIS IS THE SOLE-RECORD RULE (PR review-fix cycle 2, thread PRRT_kwDORzpWpM6h3frF; this REPLACES the cycle-2 three-probe G2/G3/G4 formulation). Genesis holds ONLY when BOTH of these are true for the candidate shipment:
   G1. It declares no `blocks` edges and carries no `dag-root` label.
   G2. SOLE RECORD: the candidate is the ONLY shipment record that exists in the workspace, counting LIVE AND ARCHIVED records TOGETHER, REGARDLESS OF STATUS AND REGARDLESS OF PROVENANCE. Any other shipment record DISQUALIFIES genesis — whatever its status, recognized or not. The rule is STATUS-AGNOSTIC BY CONSTRUCTION: it never enumerates statuses, so it never needs revisiting when the status vocabulary changes.
   If G1 holds but G2 fails, the shipment is `unsequenced` and BLOCKS unless it carries `dag-root` (in which case it is `declared_root`).
   WHY THE THREE-PROBE FORM WAS A VERIFIED FAIL-OPEN. Cycle 2's G3 enumerated the disqualifying nonterminal states as "queued or active", while G2 covered only shipped-terminal records and G4 only abandoned ones. ANY value outside those three enumerations therefore fell through all three probes SIMULTANEOUSLY, so a workspace holding such a record alongside an edge-less undeclared candidate returned `genesis` — an unearned pass, in exactly the fail-open direction this feature exists to close. ENUMERATING STATUSES IS STRUCTURALLY FRAGILE: every value the vocabulary gains in future silently re-opens the same hole, and the fix would have to be remembered at that future moment. COUNTING RECORDS IS NOT: "exactly one shipment record exists in this workspace" is status-agnostic and cannot be widened by any later vocabulary change.
   CORRECTION TO THE CYCLE-2 ILLUSTRATION — `blocked` IS NOT A CURRENT ENUM MEMBER (PR review-fix cycle 3, staging PR #448, thread PRRT_kwDORzpWpM6h3ttS; the finding is VALID and ACCEPTED). Cycle 2 illustrated the hole with a `blocked` shipment and asserted "the shipment status enum is {`queued`, `blocked`, `active`, `shipped`, `abandoned`}". THAT ASSERTION IS FALSE and is RETRACTED. Verified at this HEAD: the gate's own reader defines `_VALID_LIVE_SHIPMENT_STATUSES = frozenset({"queued", "active", "shipped", "abandoned"})` (src/autoharness/gates/topology.py L35), and backlogit's core declares exactly FOUR `ShipmentStatus` constants — `queued`, `active`, `shipped`, `abandoned` — with `isValidShipmentTransition` returning false for anything else. `blocked` is MALFORMED LEGACY DATA on a shipment: historically writable because `backlogit move` accepted unvalidated status writes, and still advertised only because the `header-def` metadata catalog's shipment `status` enum is STALE at five values. See docs/compound/2026-05-07-backlogit-shipment-status-constraints.md.
   THE FAIL-OPEN CONCLUSION SURVIVES THE CORRECTION UNCHANGED — and is in fact WIDER than cycle 2 claimed. The hole was never specific to `blocked`: it admitted EVERY value outside the three enumerated probes, malformed legacy values and any future vocabulary addition alike. `blocked` remains the named regression fixture only because it is the malformed value this workspace can actually produce. The SOLE-RECORD replacement STANDS exactly as written.
   FAIL CLOSED ON ANY UNCLASSIFIABLE RECORD. A shipment record whose status is ABSENT, empty, whitespace-only, non-string, unparseable, or NOT A RECOGNIZED MEMBER of the current four-value vocabulary — including an archived record carrying an unrecognized `archived_status` — STILL COUNTS AS A DISQUALIFYING RECORD. Never skip it, never default it to a benign value, never treat it as absent. A record that cannot be classified is precisely the record whose sequencing significance is unknown; discarding it is the fail-open move and is FORBIDDEN. If the live or archived record set cannot be ENUMERATED at all, raise BacklogUnavailableError rather than concluding sole-extancy from a short or partial read.
   WHERE A `blocked` VALUE ACTUALLY LANDS — TWO DIFFERENT PATHS, DO NOT CONFLATE THEM (cycle 3, same thread).
   (i) A LIVE (queue-folder) shipment record carrying `status: blocked` NEVER REACHES four-state derivation AT ALL. The reader already fails closed on it: topology.py L553-563 raises BacklogUnavailableError("shipment record has a missing or unsupported status: 'blocked'") for any status outside `_VALID_LIVE_SHIPMENT_STATUSES`. That EXISTING malformed-input behaviour is PRESERVED EXACTLY — do NOT add a `blocked` branch, do NOT admit it into the recognized set, and do NOT let it fall through to `unsequenced`. A workspace holding a live `blocked` shipment fails the WHOLE evaluation closed, which is strictly stronger than "no genesis".
   (ii) An ARCHIVED record carrying `archived_status: blocked` DOES reach the count. `_archived_status` reads `archived_status` as an opaque lowercased string with no vocabulary validation, so the record is PRESENT, UNCLASSIFIABLE, and therefore DISQUALIFYING under the rule above. Genesis is denied by CARDINALITY, not by status interpretation; the candidate then resolves to `unsequenced` (or `declared_root` if it carries the label).
   Neither disposition is new behaviour: both follow directly from the status-agnostic cardinality rule plus the pre-existing reader contract. Neither may be softened, and the cardinality rule itself is UNCHANGED — every other record counts, regardless of status.
   GENESIS REMAINS CARDINALITY-1 AND SELF-LIQUIDATING: it cannot be true for two shipments at once, and it ceases to be available the moment a workspace holds a second shipment record of any kind. After that point every intended root must be DECLARED, and a later-numbered edge-less candidate blocks as `unsequenced` rather than passing by default.
   CASE COVERAGE required by test: (a) exactly one shipment record in the whole workspace -> `genesis` PASS; (b) several queued shipments, nothing ever shipped -> NO genesis for any of them, each blocks `unsequenced` unless declared; (c) shipped history present only as ARCHIVED records -> NO genesis; (d) only an abandoned shipment in history -> NO genesis; (e) a `blocked` shipment record present — SPLIT INTO TWO CASES, NOT ONE (cycle 3): (e1) a LIVE `blocked` record -> the evaluation RAISES BacklogUnavailableError at reader time per (i) above, reaching NO verdict at all and specifically NOT `unsequenced`; (e2) an ARCHIVED record with `archived_status: blocked` -> NO genesis by cardinality, and the candidate resolves to `unsequenced`; (f) an unclassifiable record present under each of the sub-cases above -> NO genesis, fail closed; (g) enumeration failure -> BacklogUnavailableError; (h) declared root in any of (b), (c), (d), (e2) or (f) -> `declared_root` PASS (case (e1) is EXCLUDED from (h): it raises at reader time before any classification, declared or not, and a fixture asserting `declared_root` there would be asserting a verdict the gate never produces).
