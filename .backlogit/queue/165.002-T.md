3. Implement the four-state resolution (decision D1). Non-empty edges -> evaluate as today, provenance `explicit`. Empty edges -> DECLARED ROOT (label present) passes as `declared_root`; GENESIS passes as `genesis` ONLY under the narrow rule below; otherwise UNSEQUENCED blocks with token UNSEQUENCED_SHIPMENT and provenance `unsequenced`. States must be TOTAL and MUTUALLY EXCLUSIVE.

   GENESIS IS NON-FAIL-OPEN AND NARROW (review-fix cycle 2, finding 2; this REPLACES the cycle-1 "no shipped-terminal shipment exists" rule, which was insufficient). Genesis holds ONLY when ALL of these are true for the candidate shipment:
   G1. It declares no `blocks` edges and carries no `dag-root` label.
   G2. NO shipped-terminal shipment exists anywhere in the workspace — LIVE or ARCHIVED (use `archived_status` / `archived_record_present` alongside `live_status`).
   G3. The candidate is the SOLE EXTANT NONTERMINAL shipment: no OTHER shipment record exists in a nonterminal state (queued or active), live or archived.
   G4. NO abandoned shipment record exists, live or archived. `abandoned` is terminal-but-not-shipped, so G2 alone would let it through; its presence nonetheless proves the workspace has already been sequenced, which disqualifies a bootstrap state.
   If G1 holds but ANY of G2/G3/G4 fails, the shipment is `unsequenced` and BLOCKS unless it carries `dag-root` (in which case it is `declared_root`).
   WHY ABSENCE OF SHIPPED HISTORY IS INSUFFICIENT, AND WHY LATER-NUMBERED CANDIDATES CANNOT SILENTLY PASS: a rule keyed only on "no shipped-terminal shipment exists" returns `genesis` for EVERY edge-less shipment in a workspace that has queued work but has not yet shipped anything. In such a workspace 169-S, 170-S, 171-S, 172-S and 173-S would ALL pass as `genesis` simultaneously — including candidates that are numerically and semantically downstream of other pending work — which is precisely the unearned-pass fail-open direction this feature exists to remove. Requiring SOLE EXTANCY makes `genesis` a cardinality-1 state: it cannot be true for two shipments at once, and it ceases to be available the moment a workspace holds a second shipment record of any kind. After that point, every intended root must be DECLARED, and a later-numbered edge-less candidate blocks as `unsequenced` rather than passing by default.
   CASE COVERAGE required by test: (a) fresh workspace, exactly one shipment, no other records -> `genesis` PASS; (b) several queued shipments, nothing ever shipped -> NO genesis for any of them; each blocks `unsequenced` unless declared; (c) shipped history present only as ARCHIVED records -> NO genesis (G2); (d) only an abandoned shipment in history -> NO genesis (G4); (e) declared root in any of (b)/(c)/(d) -> `declared_root` PASS.
   ONE SNAPSHOT: the G2/G3/G4 workspace-level facts are computed ONCE per evaluation from a single snapshot of shipment records and reused, never re-probed per shipment (see 165.005-T's shared-helper requirement).
