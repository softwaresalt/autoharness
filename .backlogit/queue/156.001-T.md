.github/skills/fix-ci/SKILL.md:13 renders a SENTINEL COMMENT STRING standing for "no gate is configured" into prose that then instructs the agent to verify that string is on PATH - an agent following it literally searches for a tool whose name is a comment. The defect is in the template authoring and variable-resolution layer, not the installed copy; patching the installed file would diverge it from its template and be silently reverted by the next install or tune run. Fix: when a gate is unconfigured, OMIT the entire clause - sentence, list item, and surrounding instruction - rather than substituting a placeholder into prose that presumes a gate exists. The sentinel string must never reach rendered output. PLAN REVIEW FINDING 1 (P1): omit at the SMALLEST ENCLOSING COMPLETE STRUCTURE (whole list item, whole sentence, or whole section) and add a rendered-markdown structural assertion - no empty list items, no headings with empty bodies - in any produced artifact, so omission does not leave dangling structure. NON-GOAL: no new quality gates; this changes how an UNCONFIGURED gate renders, not which gates exist. Source: D00CB293.
