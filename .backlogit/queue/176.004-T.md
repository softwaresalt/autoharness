Determine REQUIRED FINDING F7 (question Q7): what TOOL AUTHORITY the .mcp.json registration entry for an autoharness server grants. Three parts, and answering fewer does not answer it: (1) the LITERAL per-tool allowlist value, written exactly as it would be committed; (2) the PROJECTION RULE deriving that allowlist from the operation registry, stated as a rule rather than a one-time list, so a newly registered operation becomes or fails to become callable by rule; (3) the OBSERVED default for a registered-but-not-allowlisted operation, which must be NOT CALLABLE (fail closed) - and if the prototype shows any other default, that is itself the finding and is recorded as one. WILDCARD AUTHORITY IS REJECTED. "tools": ["*"] may be recommended only if this task records all three of: a specific capability no enumerated allowlist can express; the exact bound replacing enumeration, as a checkable predicate; and why that bound is not weaker than enumeration, in falsifiable terms. Absent all three, the recommendation is an enumerated allowlist and the wildcard is recorded as REJECTED WITH ITS REASON. A wildcard that is merely convenient, merely the prototype default, or merely consistent with the existing backlogit entry is rejected on each ground separately. CONTEXT: decision F8 records .mcp.json's "tools": ["*"] for the backlogit server as a current defect that 180-S removes in its activation commit; the operations behind this server write files (atomic write primitive) and execute subprocesses (fixed-argv primitive) per D1. FOLLOWS THE PROTOTYPE because the registered-but-not-allowlisted default is an OBSERVED property of a running registration, never a design preference; a preference with no observation is ABSENT, not ANSWERED. ELAPSED BOUND 45 min; on reaching it, record NOT-ANSWERED-FALLBACK with what was attempted and what blocked it. ACCEPTANCE EVIDENCE: the literal allowlist value, the projection rule, the observed default, and either the wildcard rejection with its reason or the three-part justification.
