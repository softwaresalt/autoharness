Add an optional top-level `detectors` block to **both** the pointer schema and the versioned schema, keeping them identical except `$id`, plus detector validation cases against the versioned (runtime-resolved) schema. Domain: schema contract. Files: 3.

<!-- BEGIN:acceptance-criteria -->
* **BOTH schema files carry the identical `detectors` block** — `schemas/validation-gates.schema.json` AND `schemas/validation-gates/1.0.0.schema.json`. A pointer-only edit is a FAILING outcome.
* `test_pointer_schema_mirrors_versioned_schema_except_id` **still passes** — the two documents are equal after popping `$id`, with the new block included.
* Each file keeps the `$id` matching its own path.
* **Detector validation cases run against the VERSIONED schema** (the document the runtime actually resolves): a valid `detectors` block validates; `mode: blocking` fails; an unknown per-node key fails (`additionalProperties: false`); a malformed `node_id` fails.
* The `detectors` block is entirely optional; an absent block means zero nodes and behavior identical to today.
* Existing `lifecycle_hooks` and `telemetry` blocks validate unchanged.
<!-- END:acceptance-criteria -->

<!-- BEGIN:description -->
Plan unit **U2**. Extend the validation-gates schema (v1.0.0) with a top-level **optional** `detectors` block: an array of node declarations with

* `node_id` — pattern-constrained to the D1 scheme `det:<domain>/<detector-id>@<version>`
* `applies_when` — `changed_paths_any`, `shipment_has_items_of_type`, `workspace_surfaces_any`, `always`
* `producer` — `kind` enum `pure|ast|coverage|api|command`, `ref`, `tool_version_dims`
* `validator` — `ref`, `consumes`
* `depends_on`
* `severity` enum `critical|high|medium|low`
* `mode` — **`const: report_only`**
* `remediation` — `class` enum, `hint`, `target_refs`, `authority` enum

`additionalProperties: false` inside each node object, so an unknown key is a **registry defect** rather than silent tolerance.

**FILES (3)**:
1. `schemas/validation-gates.schema.json` (pointer)
2. `schemas/validation-gates/1.0.0.schema.json` (versioned — **this is what the runtime loads**)
3. `tests/test_validation_gates_schema.py` (the schema's own contract test)

**Execution posture**: schema-first. No detector runtime code in this unit.
<!-- END:description -->

<!-- BEGIN:implementation-notes -->
**Decision D-2**: extend the existing schema rather than create a new file — `031-DL` R4 names it the declaration extension point, and its root is already `additionalProperties: true`, so the block is additive and back-compatible.

**Decision D-4**: `mode` as schema **`const`**, not merely a default. A default can be overridden by a config edit; a `const` makes `mode: blocking` a registry defect, so silent promotion (RK4/D7) is **structurally impossible** in S1.

**Decision D-10 (PR #414 cycle-1 correction, thread PRRT_kwDORzpWpM6dGx-N)**: this unit was previously scoped to ONE file, which was wrong in two independent ways:

1. **Runtime resolution order.** `resolve_validation_gates_schema_path()` (`src/autoharness/schema_contracts.py:511-532`) returns `schemas/validation-gates/1.0.0.schema.json` **first** and only falls back to the pointer if the versioned file is absent. The versioned file EXISTS in this repo. Editing only the pointer would leave **runtime validation completely unaware of `detectors`** while the pointer advertises support.
2. **The existing mirror test.** `tests/test_validation_gates_schema.py::test_pointer_schema_mirrors_versioned_schema_except_id` pops `$id` from both documents and asserts **full dict equality**. A pointer-only edit therefore **fails the existing suite outright**.

The two schema files are ONE atomic contract — never edit one without the other.

**Width isolation note**: the third file is the schema's **own contract test**, which already contains the parity assertion this change would otherwise break. Keeping them in one unit avoids shipping a knowingly red suite mid-shipment. No detector runtime logic belongs in this unit.

Note: `producer.kind: command` is schema-declared but **NOT implemented** in S1 (see U3) — declaring it keeps the enum stable without opening a subprocess surface.
