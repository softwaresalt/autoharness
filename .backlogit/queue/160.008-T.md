INSTALL-TIME PAYLOAD BOUNDARY cases (T9). Authored and observed against the BASELINE build, then re-observed against the trimmed build by the transition ledger (160.017-T).

SEQUENCING (machine-encoded, not prose). This task is BLOCKED BY 160.001-T (baseline capture), 160.005-T (RED-FIRST harness) and 160.016-T (CHARACTERIZATION harness). It BLOCKS 160.006-T (wheel wiring), 160.007-T (plugin wiring) AND 160.004-T (the resolver). A verification family that first exists after the behaviour it verifies cannot distinguish "this still works" from "this never worked" - there is no prior observation to compare against.

THE 160.004-T EDGE IS ESSENTIAL. This task authors test_skill_docs_refs_resolve_to_workspace_not_payload, whose GREEN OWNER IS 160.004-T. Without an edge forcing this task first, 160.004-T could implement `classify_target_workspace_path` before the case that must observe it red existed, and the red observation would be unobtainable. That edge was missing through review-fix cycles 1 and 2 and is now encoded.

TWO-CLASS CONTRACT (plan section Test strategy). Every case this task authors MUST DECLARE ITS CLASS IN THE TEST FILE ITSELF, PER CASE. THIS FAMILY IS MIXED - it has two CHARACTERIZATION cases and one RED-FIRST case - so there is NO family-wide class label and none may be introduced. A family label that contradicts the per-case truth is exactly the drift that made the plan and this record disagree.
- RED-FIRST: the case asserts behaviour that DOES NOT YET EXIST. Observed FAILING on the baseline before the implementing task begins, passing after. Required observation pair: (red on baseline, green after implementation).
- CHARACTERIZATION: the case asserts an EXISTING, PRESERVED behaviour that CORRECTLY PASSES ON THE BASELINE. Observed GREEN on the untrimmed baseline and GREEN AGAIN after trimming. A CHARACTERIZATION case is NOT required to be red and MUST NOT be weakened, inverted, or broken to manufacture one. Manufactured red is worse than no red: it destroys the signal for cases where red is real.
- If a CHARACTERIZATION case goes RED after the wiring tasks land, that is a REGRESSION CAUSED BY THE WIRING TASK, and the wiring task - not this one - is at fault.

BASELINE OBSERVATION IS A DELIVERABLE, not a side effect. Record, per case, the class and the observed baseline result, against the artifacts captured by 160.001-T (untrimmed wheel, untrimmed sdist, untrimmed plugin payload, recorded verify-workspace finding set, recorded install output inventory), loading the machine-readable half from tests/fixtures/payload-baseline/**. An observation with no recorded baseline reference cannot be replayed and does not satisfy this task.

SINGLE FAILURE DOMAIN: does an /install-harness run against a scratch workspace leak engine payload into that workspace? Nothing else. Tests run against the BUILT ARTIFACT, never the source tree (verification V1, risk R1).

THE THREE CASES, EACH WITH ITS OWN CLASS AND GREEN/PRESERVATION OWNER:

1. test_install_emits_only_generated_output (AC5, I3) - CLASS: CHARACTERIZATION. OBSERVED INITIAL STATE: GREEN on the baseline - /install-harness already emits only generated output, and that is the invariant trimming must not break, not a behaviour this shipment introduces. ASSERTS: a /install-harness run into a scratch workspace produces NO autoharness engine file copied verbatim - no engine .backlogit records, no engine docs/compound entries, no engine docs/decisions or docs/plans content - and the output is BYTE-IDENTICAL to the untrimmed baseline inventory captured by 160.001-T (invariant I3; byte-identity is the criterion, "equivalent" or "no meaningful difference" is not). PRESERVATION OWNER: 160.006-T / 160.019-T / 160.007-T.

2. test_no_engine_records_in_target_workspace (AC5) - CLASS: CHARACTERIZATION. OBSERVED INITIAL STATE: GREEN on the baseline. The installer GENERATES records into the target workspace; it never COPIES engine records, so a baseline scratch workspace is already clean. THE CLASS WAS CORRECTED IN REVIEW-FIX CYCLE 3: the plan previously labelled this RED-FIRST, which would have required breaking a correct installer to manufacture a red. ASSERTS: the scratch workspace contains no record traceable to the engine's own backlog by identity (not merely by directory name), so the case cannot be satisfied by an installer that copies engine records into a differently-named path. PRESERVATION OWNER: 160.006-T / 160.019-T / 160.007-T.

3. test_skill_docs_refs_resolve_to_workspace_not_payload (AC5, AC2d, risk R2) - CLASS: RED-FIRST. OBSERVED INITIAL STATE: RED, by IMPORT ERROR - `build_support.payload.classify_target_workspace_path` does not exist yet. THIS CASE IS DELIBERATELY AUTHORED AGAINST THE EXPECTED-ABSENT INTERFACE. Do NOT defer authoring it until 160.004-T has provided something to import: an unresolvable import IS the red observation, it is recorded as such, and authoring-on-absence is precisely what lets this task precede its green owner instead of trailing it. ASSERTS: skill references to the target-workspace docs prefixes resolve against the TARGET WORKSPACE path, not the packaged data dir. The case MUST obtain the prefix set BY CALLING `classify_target_workspace_path` and MUST NOT re-list the prefixes locally (AC2d single-occurrence rule, scoped to executable and config surfaces). Closes the false positive where a naive dependency scan reads these 77 references as required payload. GREEN OWNER: 160.004-T.
