CONTRACT (decision D1). Predecessors derive EXCLUSIVELY from ShipmentState.blocking_predecessor_ids. When that set is empty, exactly one of three states applies, each with its own provenance value: DECLARED ROOT (record carries the `dag-root` label) passes as `declared_root`; GENESIS passes as `genesis` under the narrow rule below; UNSEQUENCED blocks with token UNSEQUENCED_SHIPMENT and a message naming both remedies. Non-empty edge sets evaluate as `explicit`. The four states are total and mutually exclusive, and `predecessor_source` appears on every payload, blocked and passed alike.

GENESIS IS NARROW AND NON-FAIL-OPEN (review-fix cycle 2, finding 2 — this REPLACES the cycle-1 "no shipped-terminal shipment exists" rule). Genesis is granted only when the candidate declares no edges, carries no `dag-root`, AND: (G2) no shipped-terminal shipment exists anywhere, live or archived; (G3) the candidate is the SOLE EXTANT NONTERMINAL shipment record, live or archived; (G4) no abandoned shipment record exists anywhere. Absence of shipped history alone is INSUFFICIENT: in a workspace with several queued shipments and nothing yet shipped, that weaker rule returns genesis for EVERY edge-less shipment simultaneously — including later-numbered candidates downstream of other pending work — which is an unearned pass in exactly the fail-open direction this feature exists to close. Sole-extancy makes genesis a cardinality-1 state that cannot hold for two shipments at once and ceases to be available the moment a workspace holds a second shipment record of any kind. From that point on, every intended root must be DECLARED or it blocks as `unsequenced`. The three workspace-level facts are computed ONCE per evaluation from one snapshot and shared by both gates.

LABELS ARE FIRST-CLASS STATE WITH THEIR OWN VALIDATOR (review-fix cycle 2, finding 5; reaffirmed and sharpened in cycle 3, finding 8). `ShipmentState` RETAINS a VALIDATED IMMUTABLE `labels` TUPLE, and root classification DERIVES from that tuple rather than from an ad-hoc re-parse at each call site. The tuple is validated by a LABELS-SPECIFIC fail-closed validator — NOT the artifact-ID validator `_tuple_of_str`, whose `_ARTIFACT_ID_PATTERN` (`^\d+(?:\.\d+)*-[A-Z]+$`) rejects `dag-root` and would turn every labelled shipment record, INCLUDING 173-S ITSELF, into a hard BacklogUnavailableError. Fail-closed container/member discipline is preserved; label syntax replaces artifact-ID syntax; reader-level tests cover both polarities.

DIRECTIONAL-NUMERIC RESIDUE IS A BLOCKING FAILURE (review-fix cycle 3, finding 8). Any surviving numeric-adjacency influence on the CLAIM PATH is a BLOCKING FAILURE with NO DEFER HATCH: it may not be accepted as a residual risk, deferred to a follow-up, or waived at review.

WHY NOT A FLAT BLOCKING MODE (review-fix cycle 1, decision Finding 6): a flat `block` posture for edge-less shipments is NOT a legacy-compatibility mode. Legacy behaviour blocked only when a numerically lower unshipped shipment existed; a genuine root passed. A flat block deadlocks every legitimate DAG root with no in-contract escape. The declared-root state is what keeps intentional roots representable AND claimable while staying fail-closed.

ROOT DECLARATION AUTHORITY — NARROWED (review-fix cycle 3, finding 6). `dag-root` is a VERSION-CONTROLLED, REVIEW-GATED DECLARATION recorded in backlog data inside the repository trust boundary. It is AUDITABLE — visible in a diff, attributable to a commit, reviewable before merge — but it is NOT mechanically permission-enforced and it is NOT a security boundary. No artifact in this feature may claim that Ship self-declaring a root is technically impossible, mechanically prevented, or that there is "no escape hatch". The rule that only operator/Stage may apply `dag-root` is an AGENT-CONTRACT rule enforced by review and audit. This is an accepted, recorded residual risk, not a closed hole.

No `.autoharness/config.yaml` key, no root-schema change, no new versioned schema mirror, no schema_contracts.py work, no harness-config template change, no install/tune preservation, no dogfood config change, no config parity tests.

THE AUDIT PERSISTS NOTHING (review-fix cycle 3, finding 2). `--phase audit_sequencing` is a PURE READ-ONLY REPORT. It writes no durable ledger, creates no persisted audit artifact, records no future-remediation fields, and introduces no persistence subsystem into the gate. The gate owns NO write path. Every prior reference in this feature's artifacts to a "migration ledger" emitted by the audit is WITHDRAWN.

ROLLBACK IS DATA-ORDERED, NOT CODE-ONLY, AND THE LEDGER IS GIT (review-fix cycle 2 P2 finding 11, as REVISED by cycle 3 finding 13): migration mutates backlog data (`blocks` edges, `dag-root` labels) that a code revert cannot undo. The durable migration record is the VERSION-CONTROLLED OPERATOR COMMIT and its diff — reviewable, attributable, and already protected by repository history — not a gate-written ledger. Rollback reverts DATA FIRST by reverting the migration commit(s), THEN the engine; reverting code first leaves migrated data interpreted by a restored numeric engine, a state that existed in neither configuration. Where a migration was never committed, the rollback claim is NARROWED to manual reconstruction from backlog record history.
