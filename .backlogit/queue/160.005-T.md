CASE DETAIL:
- test_sdist_excludes_backlogit_explicitly / test_sdist_excludes_dev_directories - the sdist is the REAL disclosure surface. Its target declares only core-metadata-version, so the default sweep ships everything and `uv build` publishes it with the wheel. These cases are genuinely RED today, unlike their wheel counterparts.
- test_wheel_excludes_backlogit_explicitly is NOT authored here - it is already green on the baseline and is 160.016-T's CHARACTERIZATION case.
- test_payload_size_reported - report measured file count and byte size PER CHANNEL (wheel, sdist, plugin) so payload growth is observable in CI.
- test_unclassified_tracked_path_fails_build (V4) - inject a synthetic unclassified tracked path and assert the build FAILS. A fail-closed guard never observed failing is not known to be fail-closed.
- test_generated_output_root_excluded_from_classifier_inputs (AC3d) - assert NO path under ANY declared `generated_output_roots` entry appears in ANY channel's resolved input set, AND that the AC2 unclassified-path check does not flag generated content. Red today: neither the resolver nor the manifest key exists. This case is the guard against the recursion defect described below.
- test_plugin_generation_is_idempotent (AC2c, AC3d) - run `generate --channel plugin` TWICE against a scratch target and assert a BYTE-IDENTICAL tree and an IDENTICAL resolved input set on both runs. Distinct from test_generate_is_byte_deterministic_and_cross_platform, which pins OUTPUT stability; this pins INPUT stability after the generator has written output.
- test_plugin_payload_tree_is_self_excluded_and_flat (AC3d, AC3c) - assert the committed tree contains NO nested directory named `plugin-payload`, and that `generate --channel plugin --check` reports NO drift immediately after a regeneration. THIS IS THE CASE THAT PROVES THE DRIFT IS NOT PERMANENT: if `plugin-payload/**` were classified as a plugin INCLUDE input, each run would materialize the tree inside itself (`plugin-payload/plugin-payload/...`) and `--check` would report drift that regenerating only deepens.
- test_plugin_source_path_is_tracked_and_fetchable (AC3c) - assert marketplace.json `source` resolves to a path PRESENT IN A CONSUMER-FETCHABLE CHECKOUT. dist/.gitignore contains `*`, so a `source` under dist/ is unfetchable and the install simply fails. Assert the path is TRACKED, not merely that it exists locally.
- test_release_workflow_runs_payload_gate_before_publish (AC2b) - parse release.yml STRUCTURALLY (not by regex over raw text) and assert (i) a payload-composition gate step exists in the single `release` job, (ii) its step index is strictly LESS than both the build step index and the publish step index, (iii) no `continue-on-error: true`, (iv) no `if:` expression at all.
- test_release_gate_covers_all_three_channels (AC2b, AC3b) - assert the gate's channel argument resolves to wheel AND sdist AND plugin. A gate covering two of three channels is not a gate for the third. This case, together with test_manifest_validates_against_schema (whose schema declares a CLOSED channel enum), is what machine-enforces the closed three-channel set.
- test_generate_emits_expected_tables_to_a_scratch_target (AC2c) - asserts generation against a SCRATCH target. The COMMITTED-parity property is per-channel and owned by the wiring tasks (160.006-T, 160.019-T, 160.007-T), not by the generator, because the generator is forbidden to commit the tables it produces.
