PRODUCT UMBRELLA (childless) for Plan 1. Turn autoharness into a LOCAL, operator-driven supervisor / control-plane runtime for long-horizon Copilot CLI workloads. Copilot CLI is PRESERVED as the reasoning/agent-execution engine; autoharness owns lifecycle, policy, and supervision only and implements NO model action/observation reasoning loop. Move the orchestration policy currently duplicated and untested across start.ps1 and start.sh into tested, typed shared Python application services under src/autoharness/supervise/, with start.ps1 / start.sh reduced to compatibility shims over a new `autoharness run` CLI entry point. Scope: workspace bootstrap, sidecar lifecycle/preflight, child process/PTY management (ConPTY abstraction on Windows), session state machine, local structured commands/approvals, progress/events, cancellation, controlled restart/resume, logs/checkpoints, secret redaction, workspace/session locking, and recovery. Consumes stash 34D50F2D candidate (a) under the reconciled spike disposition (004-SP: CONDITIONAL PROCEED -> PROCEED under the clarified scope "supervising an external agent runtime is in scope; implementing a new agent runtime is not"). EXCLUDED / DEFERRED to Plan 2: Gradio, Microsoft devtunnel, remote UI/control, remote authentication, remote approvals, browser terminal streaming, and any remote service.

ROLE CHANGE (2026-08-10, plan-review cycle 3 of 3, F14 structural elimination). 117-F NO LONGER PARENTS ANY TASK. All 19 implementation tasks were re-parented, via the supported AdoptItem lifecycle operation, onto three ROOT per-shipment covering features — 118-F (S1), 119-F (S2), 120-F (S3) — each of which is FULLY COVERED by its own shipment manifest. 117-F is retained purely as the product-level record and grouping anchor, connected to the three implementation features by NON-HIERARCHICAL `related_to` semantic links. <!-- BEGIN:State-Machine -->
INIT -> LOCKING -> BOOTSTRAPPING -> PREFLIGHT -> RESOLVING -> LAUNCHING -> RUNNING -> {CANCELLING | RESTARTING | DRAINING} -> {EXITED | FAILED | REFUSED}. Transitions not in the legal-transition table are rejected with ErrorKind.ILLEGAL_TRANSITION; there are no implicit transitions. DRAINING is the only path from RUNNING to a terminal state and always flushes the journal, releases the lock, and reaps the child. REFUSED (lock contention) is a distinct terminal state from FAILED.
<!-- END:State-Machine -->
