<!-- BEGIN:State-Machine -->
INIT -> LOCKING -> BOOTSTRAPPING -> PREFLIGHT -> RESOLVING -> LAUNCHING -> RUNNING -> {CANCELLING | RESTARTING | DRAINING} -> {EXITED | FAILED | REFUSED | CANCELLED}. The terminal set is exactly these four states (operator ruling, 2026-08-12): CANCELLED is a DISTINCT fourth terminal, so an operator-cancelled session is never reported as EXITED; cancellation runs <phase> -> CANCELLING -> DRAINING -> CANCELLED. Transitions not in the legal-transition table are rejected with ErrorKind.ILLEGAL_TRANSITION; there are no implicit transitions. DRAINING is the only path from RUNNING to a terminal state and always flushes the journal, releases the lock, and reaps the child. REFUSED (lock contention) is a distinct terminal state from FAILED.
<!-- END:State-Machine -->
