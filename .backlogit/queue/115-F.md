<!-- BEGIN:description -->
Phase 2 of the DAG-visibility follow-up from spike 001-SP (stash 33CC445C), layered ADDITIVELY on the shipped Phase 1 substrate (110-F / 117-S, `autoharness gate dag-readiness`). Adds a deterministic, READ-ONLY, ADVISORY-ONLY resumption cursor answering the single question `ready_set` cannot: "what is the ONE shipment to pick up right now?"

VERIFIED GAP (read-only evidence, 2026-08-09): `compute_dag_readiness` (src/autoharness/gates/topology.py:1837) returns a lexically-sorted `ready_set` with NO cursor semantics and NO representation of in-flight work — an `active` shipment is never a ready candidate. After a crash/restart/context loss, a reader of `ready_set` alone can wrongly conclude a NEW shipment should be started while an `active` one is still in flight: exactly the P-001 single-active failure mode. Repo-wide grep confirms NO `next_eligible` implementation exists in autoharness, and none in external backlogit 1.8.0 (HEAD fd8d2c9d, internal/ scanned read-only, NOT mutated). Non-duplicative and not upstream-owned.

IMPL-PLAN (source of truth): docs/plans/2026-08-09-dag-next-eligible-resumption-advisory-plan.md. Deliberation: 014-DL (Option C).

RESOLUTION ORDER — SEVEN observable gate outcomes, evaluated in this order; ownership is SPLIT BY REACHABILITY: (1) DEGRADED backlog -> null/`degraded` — CLI-ONLY (115.002-T), synthesized deterministically in the `BacklogUnavailableError` handler BEFORE the analyzer runs, and NOT an analyzer branch; then, against the UNFILTERED enumeration, the analyzer's SIX branches (115.001-T): (2) cycle detected -> null/`cycle_detected`; (3) ambiguous live/archive provenance ANYWHERE -> null/`ambiguous_provenance` (anomaly-first, before any partitioning); (4) >1 `active` -> null/`multi_active_anomaly` (fail closed; pipeline-topology owns the BLOCK); (5) exactly 1 `active` -> THAT shipment is the cursor, reason `resume_active`; (6) 0 `active` -> deterministic head of `ready_set`, reason `ready_set_head`; (7) 0 `active` + empty ready_set -> null/`no_candidates`.

WHY THE SPLIT: `BacklogUnavailableError` is raised by `readers.list_shipments()`, so on that path the shipment enumeration never exists, `compute_dag_readiness` is never called, and no readiness result exists. Both analyzer inputs are absent exactly when degradation would be signalled, making a `degraded` analyzer branch UNREACHABLE BY CONSTRUCTION. An explicit `is_degraded` analyzer input was considered and REJECTED (it would let a caller assert degradation while passing successfully-read data). The analyzer's contract is "successfully-read data only".

DETERMINISTIC TIE-BREAK (BRANCH 6 `ready_set_head` ONLY — never branch 5 `resume_active`, which has exactly one `active` shipment and nothing to tie-break): sort candidates by DESC transitive `downstream_dependents` count (unblock the most work), then ASC shipment id. Ids are unique so the order is TOTAL — never ambiguous, never dependent on dict/filesystem iteration order. `downstream_dependents` is already computed by the same call; no new traversal.

OUTPUT SHAPE: `next_eligible_detail` is ALWAYS exactly `{"candidate_ids": [...], "offending_ids": [...]}` with BOTH keys present as ARRAYS on every path, including the degraded path where it is exactly `{"candidate_ids": [], "offending_ids": []}` — never the empty object `{}` and never null.

INTEROP CONTRACT: `next_eligible` is NOT guaranteed to be a member of `ready_set` (under `resume_active` the cursor is an `active` shipment and `ready_set` holds only live `queued`). Consumers MUST use `next_eligible_reason` as the discriminator and MUST NOT treat non-membership as an error.

ADVISORY-ONLY INVARIANT: the cursor RECOMMENDS. It never claims, activates, mutates, creates a branch/worktree, or authorizes a claim; a null cursor never authorizes a claim either. Ship's claim authority is untouched. P-001/P-016 fully preserved.

P-006 HARDENING CONCLUSION: Requires plan hardening = YES (field explicitly set, not absent). REQUIRED + DONE (H1-H6 incl. H3b and H4b) — elevated blast radius because the change edits gates/topology.py, the shared module backing the pipeline-topology gate (autoharness's P-001/P-016 enforcement surface), and because it reconciles a documented PERMANENT NON-GOAL (policy-adjacent).

OUT OF SCOPE / DEFERRED: agent-template weaving (Orchestrator/Stage/Ship consulting the cursor) and the consequent installed dogfood mirror refresh (the 111.007-T lesson) — deferred, re-triage only after the cursor ships and proves stable. Any scheduler, auto-claim, or parallel execution remains a PERMANENT NON-GOAL under P-001/P-016. No schema change, no template change, no new gate family, no exit-code change, no external/backlogit change.
