.githooks/pre-push.sh L29 guards the lint behind command -v markdownlint and L36-37 warn-and-skip, so the gate is absent on every machine without markdownlint-cli; there is no markdownlint CI job at all, so the hook is the only carrier and it fails open. PLAN REVIEW FINDING 1 (P0 - HARD PRECONDITION, ordered): (a) run the linter over the current tree and RECORD the violation count - measure, do not assume; (b) if non-zero, enforcement lands scoped as defined by S1 below, and a repository-wide run is added only once the count reaches zero. Turning it fail-closed repository-wide before the tree lints clean would make main permanently red and block this run's own portfolio. BINDING S1 - ONE SINGLE SHARED LINT SCOPE FOR CI AND HOOKS (NEW in review-fix cycle 2; this SUPERSEDES and REVISES cycle 1's H3, which is corrected in the plan in the same cycle). Cycle 1 was internally contradictory: H3 required CI to lint "the same glob with the same config as the hook (**/*.md)", while finding 1 required the CI job to be scoped to CHANGED FILES. Those two cannot both hold, and the contradiction is exactly the green-locally/red-in-CI failure H3 existed to prevent, only inverted. The single definition, binding on BOTH carriers: (i) SELECTOR - lint the set of Markdown files CHANGED relative to the merge-base with the default branch, filtered to *.md; (ii) CONFIG - .markdownlint.json, identical for both, with no per-carrier overrides; (iii) VERSION - one pinned markdownlint-cli version, identical for both, no unpinned global installs (finding 7); (iv) the CI PR job and the generated/local pre-push hook MUST derive the file set from that SAME selector definition, so a file that lints clean locally cannot fail in CI and vice versa; (v) the repository-wide **/*.md run is added to BOTH carriers SIMULTANEOUSLY, and only once the recorded violation count from (a) reaches zero - it is never enabled on one carrier alone. ACCEPTANCE MUST assert the equivalence directly: a test or check demonstrating that CI and the hook resolve the SAME file set for the SAME change, and that both use the same config path and the same pinned version. BINDING H1: the hook's fail-on-missing message must name the exact install command (npm install -g markdownlint-cli, at the pinned version) and the documented escape hatch (git push --no-verify) - a gate, not a wall. BINDING H2: the CI job lands before or with the hook change; if the hook starts failing while CI has no markdownlint job, enforcement lives only on developer machines, which is strictly worse than today for anyone who cannot install it. NON-GOAL: no new markdownlint rules and no change to .markdownlint.json. DOWNSTREAM: 155.004-T carries the generator/policy surfaces; 155.007-T and 155.008-T assert markdownlint cleanliness under THIS single scope definition. SIZE/COMPLEXITY (two-axis, ruleset ah-stage-sizing-v1): size M, complexity medium.
