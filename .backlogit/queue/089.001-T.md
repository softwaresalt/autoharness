Fix `resolve_workspace_root` (`experiments/088-compression-experiment/brainspace/workspace.py`,
~L151-167) so a dict payload whose `cwd` value is a truthy non-string (e.g.
`{"cwd": [...]}`) raises `WorkspaceContainmentError` instead of letting an
uncaught `TypeError` from `os.path.realpath()` crash the hook. `hook_cli.py`'s
existing `except WorkspaceContainmentError` clause (L47-55) already handles the
fail-safe `{}` passthrough — do not modify `hook_cli.py`; add an
`isinstance(payload_cwd, str)` guard in `resolve_workspace_root` before the
`_validate_related_to_process_cwd` call, raising `WorkspaceContainmentError`
for non-string values.

Scope: exactly 2 files — `brainspace/workspace.py` (fix) and
`tests/test_workspace_resolution.py` (tests). Do not touch `hook_cli.py` or add
a 3rd file (an end-to-end `hook_cli.py` subprocess test was deliberately
descoped by plan-review — see plan's P1-1 finding and P3-1 follow-up).
