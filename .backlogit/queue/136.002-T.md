SCOPE (narrow — read before sweeping)
This task owns exactly ONE hazard: a YAML frontmatter value written as an UNQUOTED PLAIN SCALAR whose text contains `: ` (colon followed by a space), which YAML then reads as a mapping key/value split. Nothing else.

METHOD
1. Parse each docs/**/*.md frontmatter block. A decode failure is a CANDIDATE, not a confirmed hit — a YAML decode error is NOT by itself evidence of this specific unquoted-colon hazard.
2. CONFIRM BEFORE EDITING: read the parser's reported error location (line/column) and the source line it points at, and verify that line is an unquoted plain scalar whose value contains `: `. Only a confirmed candidate is in scope for this task.
3. Correct a confirmed hit by quoting that value verbatim, and change nothing else.
4. Do not rely on a regex alone as ground truth — it both misses cases and produces false positives. Use a regex only to LOCATE the candidate line inside a file the parser has already flagged, never to DECIDE that a file is a hit.
5. ANY OTHER decode failure (tab indentation, duplicate key, malformed block scalar, unterminated quote, bad list or indentation, encoding fault, and so on) is OUT OF SCOPE. Leave that file byte-unmodified and capture it SEPARATELY as a deferred stash entry under P-021 C1, naming the file path, the parser error text, and the reported location. This is the same capture-only boundary the plan applies to newly surfaced docline findings.
