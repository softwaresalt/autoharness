Ten docs/ files carry silently truncated frontmatter values. The failure mode is distinct from and nastier than a decode failure: an unquoted YAML scalar containing SPACE-HASH triggers YAMLs comment rule, so the value is silently cut at the # and the document still parses - which is why tests/test_docs_frontmatter_decodes.py, which asserts the frontmatter DECODES, cannot see the class. None of the ten were introduced by the P-020 compaction that found them. BINDING H5: the repair is CONTENT-PRESERVING - quote the scalar so the full value survives; do not rewrite or shorten values and do not touch files outside the enumerated ten. Acceptance asserts the decoded value after repair equals the intended full value AND the file still decodes (finding 5). Extend the guard to detect truncation, with a negative test introducing a space-hash scalar. SCOPE BOUND (finding 6): an eleventh file the extended guard reveals is a P-021 capture, not this task.
