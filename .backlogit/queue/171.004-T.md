ASSEMBLY HALF ONLY. Implement manifest-driven review-input assembly: given a plan_id, read the active plan revision (171.001-T identity) and the latest-verdict manifest (171.003-T), and PRODUCE the typed input set handed to a review attempt. Selection is by explicit manifest pointer only; filename sorting, mtime and directory globbing are prohibited inputs.

THE EMITTED VALUE IS A TWO-BAND TYPED VALUE, ReviewInputSet(operative, context), not a flat list. operative holds EXACTLY ONE document - the one carrying plan_role: active, named by the manifest plan_path - never zero, never two, and never a review artifact. context holds every carried_forward_context[] artifact in manifest order, each as {artifact, reason}, and is the ONLY band in which a superseded, history or review-artifact document may legally appear. The context band is passed to the reviewer under an explicit non-authoritative label, and no verifier token is ever evaluated against its contents.

FLATTENING THE TWO BANDS INTO A SINGLE LIST IS A CONTRACT VIOLATION. The separation is what makes it structurally impossible for carried-forward context to become operative input, and the typed boundary exists so that flattening is a visible code change rather than an accident.

OWNERSHIP BOUNDARY WITH 171.013-T, NO OVERLAP: this task OWNS CONSTRUCTION of the input set and emits it as a typed value; it performs NO leak judgement and emits NO token. 171.013-T OWNS JUDGEMENT. Neither task may contain the other's logic. In particular this task MUST NOT silently drop a historical document it was handed, because that would hide the very defect 171.013-T exists to detect.
