Rewrite the P-004 Statement, Precondition, Postcondition and Violation Action in the POLICY TEMPLATE. THE QUANTIFIER IS HARNESS-SCOPED, NOT WHOLE-SUITE: the precondition is exact set equality between the shipment's DECLARED harness set and the OBSERVED per-test outcomes, not "every test function in the suite fails". THIRTEEN GATE TOKENS, each carrying a STRUCTURED SUBJECT: P004_UNEXPECTED_GREEN, P004_UNEXPECTED_RED, P004_MISSING_OBSERVATION, P004_UNDECLARED_OBSERVATION, P004_MARKER_ABSENT, P004_EMPTY_RED_SET, P004_SET_OVERLAP, P004_DUPLICATE_DECLARATION, P004_MARKER_MISPLACED, P004_INCONCLUSIVE_OUTCOME, P004_DECLARED_ID_MISMATCH, P004_HARNESS_SET_MISSING, P004_HARNESS_SET_STALE. P004_DECLARATION_SCHEMA_ERROR is a HARD HALT and deliberately NOT a fourteenth gate token. SUBJECT MODEL (replaces the impossible "every token names a test_id"): a token names exactly one of TestSubject (a single test_id), CollectionSubject (the declared set as a whole - P004_EMPTY_RED_SET has no test_id to name), EntrySubject (a declaration entry by index, for a malformed entry that may carry no test_id at all - P004_MARKER_MISPLACED), or DocumentSubject (the declaration document - P004_HARNESS_SET_MISSING, P004_HARNESS_SET_STALE). NORMATIVE NO-BYPASS STATEMENT: a bare `python -m unittest <ids>` invocation does NOT satisfy P-004. Satisfaction requires the single atomic public gate entrypoint, which produces a P004GateResult; merged runner output cannot attribute an outcome to a declared test_id and is therefore not a gate observation.
