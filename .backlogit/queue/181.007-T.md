P4 T4 (PREPARE). Implement the subcommand routing and JSON serializer in src/autoharness/cli.py - ONE FILE. Size S, complexity medium. Blocked by 181.006-T. Created at plan revision 11 as part of the mandated split of the oversized revision-10 PREPARE task.

RUNNABLE DEFAULT FORM. The form Ship prose, fixtures and operator documentation use is:

  autoharness harness resolve --workspace . --shipment 187-S --json

--autoharness-home IS OMITTED IN THE DEFAULT FORM. The home is resolved INTERNALLY by the CLI's existing precedence. The optional explicit flag --autoharness-home <path> exists for API callers, --help text and test fixtures ONLY; the angle-bracket notation is placeholder notation for documentation and MUST NEVER appear inside a quoted command in Ship agent prose, because the literal string <resolved-or-default> that revision 10 shipped is NOT RUNNABLE IN ANY SHELL. Fixtures assert the runnable default form.

EXIT CODES. 0 HARNESS_READY, 1 NO_HARNESS, 2 UNRESOLVED or invalid usage. The process exit status equals the emitted exit_code field ALWAYS; there is no path where they disagree. NO_HARNESS and UNRESOLVED both halt Ship before partition, but they remain DISTINCT states with distinct exit codes and distinct reason codes - they are never collapsed into one failure bucket.

JSON. The serializer emits every field of the plan's schema on EVERY outcome, including the invalid-usage outcome. Fields are never omitted; absent scalars are explicit null. Tuples are emitted as JSON arrays. Ordering is deterministic: declarations by ascending task_id, surfaces by ascending surface_id, diagnostics in generation order. Every path is redacted to a root-relative form with an explicit root marker; no absolute path, user directory or machine name is ever emitted. Without --json a short human summary goes to stdout and the same exit code is returned.

NO MCP SURFACE AND NO UNNAMED FOLLOW-ON. This unit's public boundary is the Python function plus this CLI. The typed-operation registry, OperationResult adapter and MCP parity are 184-S substrate, consumed later by the P-004 gate - NOT delivered here and NOT implied here.

TWO CALLERS, ONE IMPLEMENTATION. The future P-004 gate calls resolve_harness_surfaces DIRECTLY as a Python function and never shells out. Ship agent prose and human operators use this CLI. Both paths execute the same resolver, so an operator reproducing a Ship halt by hand gets byte-identical JSON.
