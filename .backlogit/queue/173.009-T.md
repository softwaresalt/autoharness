RECORD THE BACKLOGIT VERSION CONTRACT so every fixture assertion is bound to an identified binary rather than to whatever happens to be installed.

WHAT IS RECORDED:
1. THE PINNED CI VERSION, exactly as .github/workflows/ci.yml pins it.
2. THE PER-PLATFORM DIGEST TABLE, with a row per supported platform/architecture and its asset digest - AND THE UNPINNED-PLATFORM HALT RULE: a platform whose digest is not pinned MUST HALT rather than observe. The current CI pin covers LINUX-AMD64 ONLY; no Windows digest is pinned anywhere, so a Windows observation is not a permitted fallback, it is a halt.
3. THE EXACT ASSET COORDINATES: host, repository, tag, asset name, platform, architecture and digest. THE FULL COORDINATE TUPLE IS THE BINDING, NOT THE DIGEST ALONE - this is directly coupled security hardening, because a digest without its host/repository/tag/name/platform/architecture context does not identify where the bytes must come from, and a coordinate set without a digest does not identify which bytes. Each coordinate is verified independently and any mismatch halts.
4. THE OBSERVATION BASELINE: which behaviours were observed, against which version, with both the v1.9.0 observations and the 1.10.1+dirty corroboration carried forward rather than one discarded.
5. THE VERBATIM CI AND LOCAL CONFORMANCE COMMANDS for both the ordinary hermetic suite and the separately provisioned conformance gate, so either can be reproduced without guessing.
6. THE RE-OBSERVATION OBLIGATION WHEN THE PIN MOVES: advancing the pin invalidates the baseline and requires re-observation under the same approval-gated Part A0 preconditions. A fixture carried forward across a pin move without re-observation asserts against a binary nobody looked at.

THE FIXTURES ARE VERSION-AWARE AND FAIL LOUDLY on an undeclared binary version - never skip. A silent skip is how an external-evidence gate stops being evidence.
