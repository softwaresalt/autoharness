Surface deterministic predecessor provenance and the migration surfaces in `pipeline-topology` CLI output so operators and agents can audit WHY a shipment is claimable or blocked.

DELIVERABLES:
1. `--json` output exposes `predecessor_source` (one of `explicit` / `declared_root` / `genesis` / `unsequenced`) and the selected predecessor IDs on the `shipment_readiness` check, on BLOCKED and PASSED paths alike.
2. Human-readable output states the provenance alongside the outcome.
3. UNSEQUENCED_SHIPMENT rendering NAMES BOTH REMEDIES explicitly (record the real `blocks` edge, or declare the shipment a root). An operator reading only CLI output must be able to resolve the block without reading the source — a block with no visible exit is the deadlock defect this design corrects.
4. `--phase audit_sequencing` output (165.003-T) renders readably in both JSON and human modes.
5. Assertions added in `tests/test_gate_pipeline_topology_cli.py` covering each provenance value and the remedy text.

HARDENING H4: output changes must be ADDITIVE so existing agent consumers do not break. Do NOT rename or remove existing fields.

SIZE: S (~1h). COMPLEXITY: low (output surfacing over already-computed values).
