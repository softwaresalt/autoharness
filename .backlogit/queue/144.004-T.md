**LAYER 3 — regression guard.**

Plan: `docs/plans/2026-08-22-git-config-env-containment-plan.md` Task 4. Amendments A1, R4, R5 BINDING.

## Deliverable

A NEW test class in the EXISTING module `tests/test_test_suite_isolation_contract.py`, following that module's established shape (AST visitor + pinned allowlist + non-vacuity positive and negative cases + `path:line` failure message).

## Guard

Recursively over every `*.py` under `tests/`, an `ast.NodeVisitor` flags:

- any call to `patch.dict` / `mock.patch.dict` / `unittest.mock.patch.dict` whose first argument is `os.environ` (attribute access) or the string literal `'os.environ'`;
- any call to `os.environ.clear()` / `environ.clear()`.

**AST-structural, NOT a line regex** — per `docs/compound/2026-08-21-ast-based-structural-regression-guards-beat-line-regex.md`. It must match regardless of line wrapping, argument ordering, context-manager vs. decorator form, or import alias. A regex only encodes the textual shapes its author anticipated; this is the exact whack-a-mole failure that learning documents.

## R5 (BINDING) — allowlist naming, no confusion with the existing guard

`tests/test_test_suite_isolation_contract.py` ALREADY defines `ALLOWLIST` (pinned `frozenset()`) for the cwd-anchored-tempdir guard, asserted by `test_allowlist_is_exactly_expected`. A second guard with a NON-EMPTY allowlist in the same module invites a future editor to relax the wrong one.

- The new allowlist is named **`ENV_MUTATION_ALLOWLIST`** and is pinned to `frozenset({"_env_patch.py"})` (matched on `path.name`, matching the existing `ALLOWLIST` semantics — A1/R4).
- It is asserted exactly by its own **`test_env_mutation_allowlist_is_exactly_expected`**.
- The existing `ALLOWLIST` and `test_allowlist_is_exactly_expected` are left **BYTE-IDENTICAL** (covered by AIG-1 as an untouched-assertion check).

## Required companion tests

- `test_env_mutation_allowlist_is_exactly_expected` — pins `ENV_MUTATION_ALLOWLIST` so it cannot silently grow into a permanent escape hatch.
- Non-vacuity POSITIVE: a synthetic source string using EACH forbidden shape is detected — context-manager form, decorator form (`@patch.dict(os.environ, ...)`), aliased import, multi-line/split-argument call, string-literal `'os.environ'` first argument, and `os.environ.clear()`.
- Non-vacuity NEGATIVE: `patched_environ(...)` and `patch.dict(some_other_dict, ...)` are NOT flagged.
- The failure message NAMES every offending `path:line`.

## Acceptance

- Guard GREEN at head (after `144.003-T`).
- Guard provably FAILS if any migrated site is reverted (demonstrate against a synthetic source string; do not actually revert committed code).
- Existing `ALLOWLIST` and its test unchanged.
- Canonical gate (R3 PowerShell invocation) still green; `pytest` MUST NOT be substituted.
