Make template-variable resolution ARTIFACT/ROLE-AWARE at the render call site, so two artifacts that consume the SAME placeholder can receive DIFFERENT correct values — while `_render_template` stays pure `{{VAR}}` substitution (constraint C5, unchanged).

**Plan:** `docs/plans/2026-08-21-verify-workspace-variable-derivation-plan.md` Task 1b (+ amendment B8)
**Raised by:** Copilot review, PR #386 review-fix cycle 3, thread `PRRT_kwDORzpWpM6bTZTM`

## The defect (verified at exact call sites, not inferred)

* `src/autoharness/verify_workspace.py:4196` — `variables = _derive_template_variables(workspace_path, manifest, config, profile, registry)` is computed **ONCE**, OUTSIDE the artifact loop.
* `src/autoharness/verify_workspace.py:4340` — `stage_path.write_text(_render_template(source_content, variables), encoding="utf-8")` applies that **same single dict to EVERY artifact**.

So there is exactly one value of `{{ESCALATION_FAMILY}}` / `{{ESCALATION_PROVIDER}}` / `{{ESCALATION_REASONING_EFFORT}}` for the whole render pass. But BOTH agent templates consume that same collapsed triple:

* `templates/agents/_stage.agent.md.tmpl:946-947`
* `templates/agents/_ship.agent.md.tmpl:898-899`

And the escalation route is **per-role**: the Stage contract resolves `config.model_routing.stage.escalation` (nested per-role override, F02FD596) → legacy flat `config.model_routing.escalation` (DEPRECATED) → `model_routing.tier3` per-field; Ship resolves the `ship` equivalent → flat → its own tier. `{{ESCALATION_*}}` is defined in 142.003-T as the "ACTING-ROLE-COLLAPSED" value — but a single global dict has **no acting role**, so the collapse is unsatisfiable as currently plumbed.

**Severity is LATENT, not active, today.** `.autoharness/config.yaml` (lines 57-80) declares only the FLAT `escalation:` block (`gpt-5.6-sol`/`openai`/`high`) and no nested `stage.escalation` or `ship.escalation`, so both agents currently collapse to the same value and render correctly by coincidence. The defect ACTIVATES the moment an operator adds a nested per-role override — which the Stage contract documents as the PREFERRED form. A latent correctness bug that only appears once someone uses the documented feature is exactly the kind that must be fixed while the surface is open.

**Second reason role-awareness matters:** the ESCALATION_DEGRADED same-route guard is role-relative. Stage's route is `claude-opus-5` (== `tier3`); Ship's is `claude-sonnet-5` (== `tier2`). A shared collapsed value cannot express "degraded for Stage but genuine for Ship".

## Design constraints (NON-NEGOTIABLE)

1. **`_render_template` MUST NOT change** (C5, and 142.003-T AC-e). It stays pure `{{VAR}}` substitution over a supplied mapping. All role awareness happens BEFORE the call.
2. **Selection is by ARTIFACT IDENTITY, never by ambient state.** Derive the consuming role from the manifest artifact being rendered (its `path` / `template`, e.g. `.github/agents/_stage.agent.md` → role `stage`; `_ship.agent.md` → role `ship`). Never from the current session, the acting agent, or an env var.
3. **Only the COLLAPSED prose triple is role-scoped.** `{{ESCALATION_FAMILY}}`, `{{ESCALATION_PROVIDER}}`, `{{ESCALATION_REASONING_EFFORT}}` only. The RAW pass-through families (`{{LEGACY_ESCALATION_*}}`, `{{STAGE_ESCALATION_*}}`, `{{SHIP_ESCALATION_*}}`) remain GLOBAL and RAW and must be byte-identical in every artifact — C3 is preserved, not weakened. Re-scoping a raw slot per role would reintroduce the PR #316 round-3 flat+nested ambiguity.
4. **Artifacts with no role** (instructions, config, start scripts, AGENTS.md) get the BASE map unchanged. Default is base, never a guess.
5. **`escalation-protocol.instructions.md` is role-neutral** and keeps the base/legacy-flat collapsed value; do not silently give it a role.

## Steps
1. Introduce a pure composition helper, e.g. `_compose_artifact_variables(base_variables, artifact_role)` returning a NEW mapping = base overlaid with the role-scoped collapsed triple. It must not mutate `base_variables` (the same base is reused across all artifacts in the loop).
2. Introduce role resolution from artifact identity, e.g. `_resolve_artifact_role(artifact)` → `"stage" | "ship" | None`, driven by an explicit mapping table, not a substring guess.
3. Change ONLY the render call site at `verify_workspace.py:4340` to pass the composed mapping. Keep the single `_derive_template_variables` call at 4196 (one derivation, many compositions) so this stays O(1) in derivation cost.
4. Extend the derivation to compute, per role, the resolved escalation triple using the documented precedence: nested `model_routing.<role>.escalation` → flat `model_routing.escalation` → `tier3` per-field.

## Acceptance criteria
- AC7a. **The distinct Stage-vs-Ship override test exists and passes.** Given a config declaring `model_routing.stage.escalation` and `model_routing.ship.escalation` with DIFFERENT `model_family`/`model_provider`/`reasoning_effort`, the staged `.github/agents/_stage.agent.md` and `.github/agents/_ship.agent.md` render with the respective role's values, and the two rendered escalation triples are asserted **NOT EQUAL** to each other. An equality-only assertion would pass under the defect whenever the two happen to match.
- AC7b. With only the FLAT `escalation` declared (the CURRENT live workspace shape), both agents render the SAME flat value — proving this change is a strict generalisation and a no-op for today's config.
- AC7c. With NEITHER nested nor flat declared, each role falls back to `tier3` per-field, and the resulting same-route condition is representable per role.
- AC7d. `_render_template` is byte-identical to its pre-change form (assert by diff; no behavioural change).
- AC7e. The RAW families (`LEGACY_`/`STAGE_`/`SHIP_ESCALATION_*`) render byte-identically across every artifact — role composition did NOT leak into raw storage (C3 regression guard).
- AC7f. Artifacts with no resolved role render byte-identically to the pre-change output (base map unchanged).
- AC7g. `tests/test_scope_containment_policy_contract.py::test_clean_pairs_are_byte_identical_via_render_template` remains green; if any clean pair moves, both sides plus the manifest checksum are updated atomically (C6).
