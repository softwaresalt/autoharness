Resolve and validate every user-controlled Git ref before it reaches git, closing the argument-injection surface in discover_modified_files. Domain: code (security). Files: 1.

<!-- BEGIN:acceptance-criteria -->
* `resolve_commit_ref(ref)` runs `git rev-parse --verify --end-of-options <ref>^{commit}` and returns the resolved SHA **only** if it matches `^[0-9a-f]{40}$`; otherwise returns `None`.
* **Option-like refs are never treated as options.** `--output=/tmp/x`, `--upload-pack=...`, and any leading-dash value resolve to `None`. `--end-of-options` forces git to interpret the value as a ref.
* **No side effect on rejection**: resolution writes no file, mutates nothing, and does not invoke `git diff`.
* `discover_modified_files` accepts **only** validated full hex SHAs for `base`/`head`, and additionally uses `--end-of-options` / `--` separators internally as a backstop, so the module is safe even if a future caller forgets to pre-resolve.
* Applies to **every** user-controlled ref — head as well as base.
* Read-only: the resolver performs no repository mutation.
* Existing callers of `discover_modified_files` continue to behave identically (observable diff output unchanged).
<!-- END:acceptance-criteria -->

<!-- BEGIN:description -->
Plan unit **U8b**. Edit `src/autoharness/gates/discovery.py`.

**The vulnerability being closed**: `discover_modified_files` currently builds

```python
argv = ["git", "diff", "--name-only", f"{base}...{head}"]
```

(`src/autoharness/gates/discovery.py:61`) with **no option terminator**. Because `base` is user-controlled via `--base`, a value of `--output=/tmp/x` produces the argument `--output=/tmp/x...HEAD`, which `git diff` parses as its **`--output=<file>` option and writes a file** — directly contradicting this gate's read-only guarantee.

**Add** `resolve_commit_ref(ref) -> str | None`:

1. Run `git rev-parse --verify --end-of-options <ref>^{commit}`.
2. Accept the result **only** if it matches `^[0-9a-f]{40}$`.
3. Return `None` for anything else — unresolvable, ambiguous, or option-like.

**Harden** `discover_modified_files` itself: assert `base`/`head` are validated full hex SHAs, and add `--end-of-options` / `--` separators. This is defence in depth — the resolver is the primary control, this is the backstop.

**Execution posture**: test-first. Tested by U8c (option-like, invalid, symbolic, full-SHA pass-through).
<!-- END:description -->

**No dependencies** — this is a self-contained hardening of an existing module and does not need the detector contract. It is therefore schedulable FIRST in the serial order and unblocks both U4 (149.004-T) and U8 (149.008-T).

**Why a separate unit from U8**: U8 is width-isolated to the CLI (`src/autoharness/cli.py`, Files: 1). The resolver belongs in `gates/discovery.py` beside the vulnerable call, and it must protect **every** caller of discovery — not just the CLI path. Splitting keeps both units single-file and single-domain.

**Relationship to D-7**: D-7 already required resolving the base ref before calling `discover_modified_files`, but for a *correctness* reason — `discover_modified_files` never raises and returns `[]` on failure, so 'no files changed' and 'git broken' are indistinguishable (the FC1 trap). D-12 adds the *security* reason. One resolver satisfies both, which is why U4's applicability context also depends on this unit.

**Pre-existing-surface caution**: this is the one genuinely pre-existing shipped function touched by cycle 1. `--end-of-options` constrains only *option parsing* and cannot change the meaning of an already-valid ref, and existing callers pass internally-derived refs, so observable diff output is unchanged. U8c scenario 4 characterizes that pass-through explicitly.
