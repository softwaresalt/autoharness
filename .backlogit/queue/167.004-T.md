PLAN UNIT U4 (plan revision 5). Domain: Python CLI. Posture: test-first.

FILES (2): src/autoharness/cli.py, tests/test_cli_gate_closure_evidence.py (NEW).

PURPOSE
Move closure-evidence failure from a successor's gate back to the author's keyboard, with a write-time validator that accepts an artifact IF AND ONLY IF the read-time consumer would accept it (decision D6).

NORMATIVE SOURCE: plan revision 5, unit U4, and Contract Specification C5 (diagnostic contract).

CHANGES
- New subcommand: autoharness gate closure-evidence --path <file> [--shipment <id>] [--workspace <path>] [--json], added as ONE additional branch in the flat dispatcher at cli.py:369-389, plus its usage/help block alongside the existing pipeline-topology / dag-readiness blocks. --workspace is this command's WORKSPACE-ROOT CONTEXT and is the value passed as 167.010-T's required workspace_root argument whenever the command constructs or validates a closure path.
- Validation, in order:
  1. the resolved --path lies within the resolved --workspace root — 167.010-T's assert_path_within_workspace is imported and reused directly, not reimplemented, so a canonical-looking candidate reached from outside the workspace (an absolute out-of-root path, a traversal, or a symlink/junction resolving outside the root) is rejected BEFORE any of the checks below run;
  2. the filename matches the CANONICAL WRITE PATTERN from 167.001-T — a legacy-named artifact is a WRITE-TIME FAILURE, because recognition is read-side only (D3);
  3. the artifact satisfies the COMPLETE CONSUMER ACCEPTANCE PREDICATE;
  4. the artifact is discoverable for its declared shipment via classify_closure_candidates.
- SINGLE VALIDITY DEFINITION. Step 3 MUST call the existing consumer predicate topology._closure_artifact_complete (and, through it, _closure_conditions_satisfied) DIRECTLY, BY IMPORT. Re-implementing a scalar-enum check here is a DEFECT, not a simplification: such a check would accept a READY_WITH_CONDITIONS artifact with an unsatisfied or absent conditions: block that the consumer then rejects, so the write-time gate would certify an artifact the read-time gate blocks — a second, weaker definition of validity for the same contract. Reuse is IMPORT-ONLY; the predicate is NOT MODIFIED and remains byte-identical.
- DIAGNOSTIC GRANULARITY FOLLOWS C5. The authoritative predicate returns a BOOLEAN — it reports whether an artifact is acceptable, not why it was refused — so a field- or reason-specific frontmatter diagnostic could only come from a second implementation of the validity logic. Therefore:
  * Steps 1, 2, and 4, and an absent or unreadable --path, are CLI-OWNED checks and emit SPECIFIC diagnostics naming the offending path, workspace root, filename, or shipment.
  * Step 3 emits a GENERIC AUTHORITATIVE-PREDICATE REJECTION: it names the artifact path, names topology._closure_artifact_complete as the deciding authority, and quotes CLOSURE_PREDICATE_REQUIREMENT_DOC. It does NOT assert which field or which condition caused the refusal.
- Exit codes follow the established gate convention: 0 pass, 1 validation failure, 2 invalid input (an absent, unreadable, or workspace-escaping --path is invalid input).

SCOPE GUARD
Validation only. This command NEVER writes, renames, or repairs an artifact (D8). It is NOT wired into any pre-existing gate path.

TESTS (5)
1. Canonical filename + acceptable frontmatter passes with exit 0.
2. A legacy filename fails with exit 1 and the canonical pattern quoted.
3. An absent or unparseable path exits 2 naming the path.
4. A --path outside the resolved --workspace root — parametrized over an absolute out-of-root path, a traversal (../), and a symlink/junction that resolves outside the root (the symlink/junction row is skipped with an explicit reason on platforms where the test process cannot create them, and is never silently passed) — exits 2 naming the escaping path and the workspace root, reusing 167.010-T's assert_path_within_workspace rather than a second implementation.
5. The --json payload carries a failed_check discriminator with domain {workspace_containment, filename, frontmatter_predicate, discoverability, input} together with the path.

The semantic parity battery is 167.011-T, not this task.

ACCEPTANCE
- No independent membership test over closure_status or compaction_status values appears in cli.py.
- The frontmatter rejection message carries no field-level cause.
