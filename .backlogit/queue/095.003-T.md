<!-- BEGIN:description -->
Add a bounded retention window with a restated, achievable size bound. Keep at most _MAX_RETAINED_SEGMENTS (module constant, >=1) sealed segments; on rollover, prune the oldest generation(s) beyond the window. Pruning MUST NOT remove the segment sealed by the same rollover -- there is >= _MAX_RETAINED_SEGMENTS segments of slack between the newest sealed generation and the prune frontier, so an in-flight append that landed in the just-sealed segment survives within the window (ties the concurrency guarantee from 095.002-T together). Replay/conflict checks scan only still-retained segments. Restated byte bound (finding 5): a sealed segment is <= _MAX_SEGMENT_BYTES + one max record (sequential case); total retained <= (_MAX_RETAINED_SEGMENTS + 1) * (_MAX_SEGMENT_BYTES + one max record). Explicitly document + test the retention horizon: once the segment carrying an epoch_id is pruned, a later replay of that epoch_id can no longer be detected and is re-appended (acceptable -- JSONL is a best-effort mirror; SQLite is authoritative). Depends on 095.002-T. Files: src/autoharness/telemetry/jsonl_sink.py, tests/test_telemetry_jsonl_sink.py. <=3 files, <=5 functions, <=4 test scenarios. TDD.
<!-- END:description -->

<!-- BEGIN:acceptance-criteria -->
The sealed-segment count never exceeds _MAX_RETAINED_SEGMENTS and the oldest generation is pruned first. Total retained on-disk bytes are bounded by (_MAX_RETAINED_SEGMENTS + 1) * (_MAX_SEGMENT_BYTES + one max record) across repeated rollovers. Idempotent-replay and conflict detection still hold across all still-retained segments. The retention-horizon bound is asserted: an epoch whose segment has been pruned is re-appended (no false idempotency), not raised. The segment sealed by a rollover is never pruned in that same rollover, so a line written concurrently with the rollover survives at least one prune cycle. Existing tests still pass.
