<!-- BEGIN:acceptance-criteria -->
AC1 `compute_next_eligible` exists as a pure function performing NO I/O and NO backlogit/git mutation on ANY branch, including every anomaly branch (H4).
AC2 All 7 resolution branches implemented in the specified order, each returning a populated machine-readable reason; a null cursor with an empty/absent reason is a defect.
AC3 `reason` is exactly one of `resume_active`, `ready_set_head`, `no_candidates`, `multi_active_anomaly`, `ambiguous_provenance`, `cycle_detected`, `degraded` — no other value is ever emitted.
AC4 Detail payload always exposes BOTH `candidate_ids` and `offending_ids` keys (empty lists when not applicable) so consumers need no key-existence checks.
AC5 (H3) Two or more `active` shipments returns null / `multi_active_anomaly` with the offending ids — it MUST NOT pick a winner and MUST NOT fall through to the ready-set. Dedicated regression test.
AC6 (H3b) Ambiguous live/archive provenance returns null / `ambiguous_provenance`, checked BEFORE active/ready partitioning. Dedicated regression test INCLUDING the single-active-but-ambiguous case, which MUST report `ambiguous_provenance` and MUST NOT report `resume_active`. It is never folded into `multi_active_anomaly` or `no_candidates`.
AC7 (H5) Total-order determinism: a regression test feeds the same graph with shuffled input ordering and asserts an identical cursor, and covers a fan-out tie resolved by the ASC-id fallback.
AC8 (H1) The pre-existing tests/test_gates_dag_readiness.py and tests/test_gates_topology.py assertions pass UNMODIFIED; no existing symbol in topology.py is altered.
AC9 Unit tests cover every one of the 7 branches.
<!-- END:acceptance-criteria -->

<!-- BEGIN:description -->
WIDTH: analyzer/pure-logic ONLY. Files: src/autoharness/gates/topology.py + tests/test_gates_dag_readiness.py. Does NOT touch cli.py and does NOT touch docs (115.002-T / 115.003-T own those).

Add a NEW pure function `compute_next_eligible(shipments, readiness)` (plus a frozen `NextEligibleResult` dataclass with a `to_dict()`) beside the existing `compute_dag_readiness`. It consumes already-read `ShipmentState` values and the existing `DagReadinessResult` and performs NO I/O and NO mutation whatsoever.

RESOLUTION ORDER — evaluate against the FULL UNFILTERED shipment enumeration, in exactly this order: (1) DEGRADED (caller signals backlog unreachable) -> null / `degraded`; (2) `readiness.cycle_detected` -> null / `cycle_detected`; (3) ANY shipment with ambiguous live/archive provenance (reuse the EXISTING `_has_ambiguous_shipment_records`) -> null / `ambiguous_provenance` + offending ids; (4) more than one `active` shipment -> null / `multi_active_anomaly` + offending ids; (5) exactly one `active` shipment -> that id is the cursor, reason `resume_active`; (6) zero `active` -> tie-broken head of `readiness.ready_set`, reason `ready_set_head`; (7) zero `active` and empty ready_set -> null / `no_candidates`.

STRUCTURAL PATTERN (compound learning 2026-08-07-copilot-review-fix-introduces-new-filter-bug): enumerate UNFILTERED -> check anomalies FIRST -> only THEN partition into active/ready. Do NOT introduce any early narrowing filter; branches 3 and 4 must run before any active/ready partitioning so a corrupt or anomalous record can never be silently excluded.

TIE-BREAK (branch 6): sort by DESC `len(readiness.downstream_dependents[id])`, then ASC shipment id. Shipment ids are unique so the ordering is TOTAL — never ambiguous, never dependent on dict/filesystem iteration order. Reuse the already-computed `downstream_dependents`; add NO new graph traversal.

H1 NON-REGRESSION: `compute_dag_readiness`, the existing `DagReadinessResult` fields, `_dag_all_predecessors_finished`, `_shipment_map`, `_dag_successors`, `_dag_detect_cycle`, `_dag_downstream_dependents` and every symbol the pipeline-topology gate depends on MUST NOT be modified. This is strictly additive to the module.
