UPGRADE-PATH AND VERIFY-WORKSPACE PARITY CASES (T10). Authored and observed against the BASELINE build, then re-observed against the trimmed build by the transition ledger (160.017-T).

SEQUENCING (machine-encoded, not prose). This task is BLOCKED BY 160.001-T (baseline capture, T2a), 160.005-T (RED-FIRST harness) and 160.016-T (CHARACTERIZATION harness), and it BLOCKS 160.006-T and 160.007-T. A verification family that first exists after the behaviour it verifies cannot distinguish "this still works" from "this never worked".

TWO-CLASS CONTRACT (plan section Test strategy). Every case MUST DECLARE ITS CLASS IN THE TEST FILE ITSELF, PER CASE. THIS FAMILY IS MIXED - two CHARACTERIZATION cases and one RED-FIRST case - so there is NO family-wide class label and none may be introduced. A family label that contradicts the per-case truth is exactly the drift that made the plan and this record disagree.
- RED-FIRST: asserts behaviour that DOES NOT YET EXIST. Observed FAILING on the baseline, passing after implementation.
- CHARACTERIZATION: asserts an EXISTING, PRESERVED behaviour that CORRECTLY PASSES ON THE BASELINE. Observed GREEN on the untrimmed baseline and GREEN AGAIN after trimming. NOT required to be red, and MUST NOT be weakened or inverted to manufacture one.
- If a CHARACTERIZATION case goes RED after the wiring tasks land, that is a REGRESSION CAUSED BY THE WIRING TASK, and the wiring task - not this one - is at fault.

BASELINE OBSERVATION IS A DELIVERABLE, not a side effect. Record, per case, the class and the observed initial result against the artifacts captured by 160.001-T (T2a) - untrimmed wheel, untrimmed sdist, untrimmed plugin payload, recorded verify-workspace finding set, recorded `autoharness home`/`version` behaviour - loading the machine-readable half from tests/fixtures/payload-baseline/**. That baseline is a hard prerequisite, not a convenience.

Tests run against the BUILT ARTIFACT, never the source tree (verification V1, risk R1).

THE THREE CASES, EACH WITH ITS OWN CLASS AND GREEN/PRESERVATION OWNER:

1. test_verify_workspace_parity_trimmed_vs_baseline (AC6) - CLASS: CHARACTERIZATION. OBSERVED INITIAL STATE: GREEN on the baseline - the case is by construction a comparison against a recorded prior state, and comparing the baseline finding set with itself yields an empty difference. ASSERTS: install a scratch workspace from the build under test, run `autoharness verify-workspace`, and assert ZERO NEW findings versus the captured untrimmed baseline. Parity is asserted as a SET DIFFERENCE against the recorded baseline finding set, never as an absolute "no findings" claim - the untrimmed baseline may itself carry findings, and those are not this shipment's regressions. PRESERVATION OWNER: 160.006-T / 160.019-T / 160.007-T.

2. test_upgrade_from_1_5_0_leaves_no_orphans (AC6, risk R3, verification V3) - CLASS: RED-FIRST. OBSERVED INITIAL STATE: RED by MISSING ARTIFACT - the trimmed build to upgrade TO does not exist yet. THIS CASE CANNOT BE CHARACTERIZATION: orphans are created BY trimming, so there is no green-on-baseline observation to make; upgrading v1.5.0 to v1.5.0 leaves no orphans trivially and asserts nothing. ASSERTS: install v1.5.0 (untrimmed) into a scratch workspace, upgrade to the trimmed build, enumerate residual engine files, and assert the residual set is EMPTY or matches an explicitly enumerated expected set. An orphan is an engine file present after upgrade that the trimmed manifest does not classify as payload. GREEN OWNER: 160.006-T / 160.019-T / 160.007-T.

3. test_home_and_version_behave_identically (AC6, invariants I1, I2) - CLASS: CHARACTERIZATION. OBSERVED INITIAL STATE: GREEN on the baseline - `autoharness home` and `autoharness version` behave as 160.001-T recorded. THE CASE WAS NAMED IN REVIEW-FIX CYCLE 3: it previously existed only as an unnamed bullet, which made it invisible to the plan's case ledger and unverifiable by the transition ledger - an unnamed assertion has no owner and no recorded transition. ASSERTS: both commands behave identically pre- and post-change, against the recorded baseline behaviour. I1 and I2 are OBSERVED here, never modified. PRESERVATION OWNER: 160.006-T / 160.019-T / 160.007-T.
