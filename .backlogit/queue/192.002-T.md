3. Existing-record check table: invoking -> 7; post_close -> 2; plain --classify-only over pre_close -> 2 with record byte-identical, --replace-pre-close replaces it; mutating mode receives an existing cascade-selected pre_close record back instead of replacing it (R1).
4. Owner transition, takeover, and atomic write: transition succeeds for owning run_id, fails for a foreign one; a pre_close takeover with the correct takeover_from_run_id replaces the record and binds it to the new run_id, while a wrong takeover_from_run_id, a takeover over an invoking or post_close record, or a takeover writing a non-pre_close record is refused with the on-disk record byte-identical (Copilot PR #481 T6); atomic write leaves no partial file on simulated failure and refuses a symlink target.

<!-- BEGIN:description -->
Goal: evidence persistence for the shipment_close command: streaming capture, redaction application, per-pair lock, existing-record check, owner-bound atomic write.
Files: src/autoharness/shipment_close/__init__.py (EXIT_* constants only), src/autoharness/shipment_close/persist.py (new), tests/test_shipment_close_persist.py (new).
Key rules:
- Exit codes (R15): shipment_close/__init__.py holds ONLY the command's EXIT_* constants (A3 table: 0, 2, 3, 4, 5, 6, 7, 8) as their single definition; A1b, A3a, A3 and A3d import them; gates/cascade_evidence.py never defines or imports them.
- StreamCapture: counts bytes/lines, SHA-256 over every byte; retains a 64 KiB / 500-line tail window plus 4 KiB leading margin, and (stdout only) a never-persisted parse buffer <= 1 MiB; bytes past 1 MiB / 10,000 lines are drained and hashed but not retained (capture_truncated: true); stdout overflow -> parse_error: stdout exceeded capture cap (AS-F03).
- Redaction uses the A1 redact() (R6) - bearer/basic Authorization; credential pairs over one shared, case-insensitive key set (token, password, secret, api_key, apikey, access_token, refresh_token, client_secret) as key=value AND as a quoted JSON key with ':' and optional whitespace ("token": "...", "api_key":"...": value redacted through its closing quote, key kept; R17); gh[pousr]_ and github_pat_ tokens; sk- keys. Runs over the tail window before the excerpt is sliced (H-B4) and over every persisted free-text field (argv, tool.version_excerpt, parse_error, both excerpts, failures[]). Never over engine_semantics.reason, close_path_selection.reason, probed_version, probed_commit (R6).
- Per-pair lock (SL-F01): acquire_pair_lock(workspace, S, F, run_id) creates .autoharness/gates/cascade-close/{S}-{F}.lock with O_CREAT|O_EXCL (+O_NOFOLLOW where available) holding run_id, PID, started_at; every path component to the lock dir and docs/closure/evidence/ must be contained and a real directory (no symlink/junction/reparse), missing components mkdir'd one at a time and re-checked (SL-F06); held from the existing-record check through the final write, released in finally; an existing lock -> exit 7, never broken automatically.
- Existing-record check (first action under the lock): invoking -> exit 7; post_close -> exit 2 (already finalized). pre_close: plain --classify-only -> exit 2 no-clobber; --classify-only --replace-pre-close may replace (destructive, operator approval); mutating mode NEVER overwrites a pre_close record whose selected_close_path is cascade - it returns that record to A3 (R1) (only A3 step 4's exact-match re-stamp of run_id/captured_at may write over it, as a pre_close takeover); a safe_close-selected pre_close record may be replaced by the mutating mode (also a takeover). Returns the existing pre_close record (or None) so A3 never re-reads outside the lock.
- Owner transition (AS-F01): write_evidence_atomic(path, record, *, owner_run_id, takeover_from_run_id=None) allows only the owning run_id to move pre_close -> invoking -> post_close; refuses foreign writers and any transition out of post_close.
- Pre_close takeover (Copilot PR #481 T6): a pre_close record written by a --classify-only run carries that run's run_id, so a later mutating run is a foreign writer. The single narrowly authorized exception is an atomic compare-and-swap requested with takeover_from_run_id: under the pair lock write_evidence_atomic re-reads the on-disk record and proceeds only if it is phase pre_close AND its run_id == takeover_from_run_id, and the new record is phase pre_close with run_id == owner_run_id; otherwise it raises CascadeEvidenceError and leaves the on-disk record byte-identical. Never applies to invoking or post_close; a write without takeover_from_run_id over a different run_id is still refused. takeover_from_run_id is always the run_id of the record the existing-record check returned in the same lock hold. Exactly three callers may pass it: (1) A3 step 4 re-stamping a cascade-selected record, ONLY after A3 step 3's exact-match check passes and A3 confirms the *_to_record encodings differ only in run_id and captured_at; (2) the mutating mode replacing a safe_close-selected pre_close record; (3) operator-approved --classify-only --replace-pre-close. After a takeover the record carries the new run's run_id, so later invoking/post_close writes are ordinary owner transitions.
- Atomic write: same-dir temp file, flush+fsync, os.replace; refuses symlink/reparse targets and parents; Windows skips dir fsync and retries sharing-violation PermissionError at most 3 times with bounded backoff; temp removed in finally.
