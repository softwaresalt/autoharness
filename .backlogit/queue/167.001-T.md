CHANGES
- CANONICAL_CLOSURE_FILENAME_TEMPLATE — the single authoritative write pattern string (D2).
- CANONICAL_CLOSURE_PATTERN_DOC — DERIVED, NOT AUTHORED: computed from CANONICAL_CLOSURE_FILENAME_TEMPLATE by a pure function _render_pattern_doc(template), so the human-readable text the producer skills quote verbatim cannot be edited independently of the machine pattern. A duplicated literal here is a second source of truth and is a defect.
- CLOSURE_SHIPMENT_ID_PATTERN and CLOSURE_FEATURE_ID_PATTERN exactly as specified in C1. ONE CANONICAL IDENTIFIER DOMAIN: the write grammars are UPPERCASE-ONLY and CASE-SENSITIVE — kind letter S for shipments, F for features.
- RECOGNIZED_CLOSURE_PATTERNS — an ordered, CLOSED tuple of exactly the two compiled patterns specified in C2, with R1's identifier segments COMPOSED FROM C1's grammars rather than re-typed:
  * R1 (canonical, also the write pattern): uppercase-only; identifier comparison is EXACT, CASE-SENSITIVE whole-captured-group equality. R1's accepted domain and the path builder's accepted domain are the SAME SET in BOTH directions.
  * R2 (legacy, read-only): date-prefixed, shipment kind letter [Ss], free-form suffix; identifier comparison is CASE-FOLDED whole-captured-group equality. LOWERCASE TOLERANCE IS CONFINED TO R2. No bidirectional domain claim is made for R2; the only cross-pattern property asserted is one-directional and structurally provable — no builder output can ever match R2, because R2's second hyphen-delimited token must satisfy \d{2} while a builder name's second token is the literal kind letter.
- CLOSURE_PREDICATE_REQUIREMENT_DOC — the single contract-owned summary of the authoritative acceptance predicate's documented requirements, quoted by the CLI's generic rejection message (C5). Descriptive text only; it makes NO validity judgement.
- attribute_closure_candidate(filename, shipment_id) -> bool exactly as specified in C3. Attribution PARSES the shipment identifier from THE POSITION THE ANCHORED GRAMMAR RESERVES FOR IT and compares that single parsed group; try the R2 designated position first (immediately after the date prefix), else the R1 designated position (leading), else not attributed. THE REQUESTED IDENTIFIER IS NEVER SEARCHED FOR ANYWHERE ELSE IN A FILENAME, and in particular NEVER inside an R2 free-form suffix.
- classify_closure_candidates(closure_dir, shipment_id) -> ClosureDiscovery — frozen dataclass carrying canonical_matches, legacy_matches, unrecognized_candidates, and an outcome of absent | unrecognized | recognized, applying D5 ordering: the canonical partition wins outright when non-empty; within a partition, candidates are returned in deterministic sorted order. Candidate collection is gated by attribute_closure_candidate.
- CONSUMER_SITES — enumerated tuple of the runtime and producer sites deriving from this contract: the topology reader, the validation CLI, the two producer skill files, the two Ship agent files.
- CONTRACT_DEFINITION_SITE — this module's own repository-relative path, declared in-source, so U9's accepted set is derivable as (CONTRACT_DEFINITION_SITE,) + CONSUMER_SITES rather than a second narrative allowlist.
- RUNTIME_SCAN_ROOTS — the declared U9 scan scope: src/autoharness/, templates/skills/operational-closure/, templates/agents/, .github/skills/operational-closure/, .github/agents/. docs/ and tests/ are outside the scan scope by construction.

Path construction, workspace containment, and ID validation are U10's surface (167.010-T). Touches NOTHING under docs/closure/ (D8).
