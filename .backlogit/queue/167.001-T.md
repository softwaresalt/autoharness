PLAN UNIT U1. Domain: Python source. Posture: test-first.

FILES (2): src/autoharness/gates/closure_contract.py (NEW), tests/test_closure_contract.py (NEW).

DELIVERABLES
1. CANONICAL_CLOSURE_FILENAME_TEMPLATE — the single authoritative WRITE pattern string (D2): `{shipment_id}-{feature_id}-post-merge-closure.md` under the closure directory.
2. CANONICAL_CLOSURE_PATTERN_DOC — the exact human-readable pattern text the producer skill files MUST quote verbatim. 167.009-T compares the skill prose against this constant, so it is the anti-drift anchor.
3. RECOGNIZED_CLOSURE_PATTERNS — an ordered, CLOSED tuple of EXACTLY TWO compiled, fully anchored (\A...\Z) regexes (D3):
   R1 canonical: {shipment_id}-{suffix}-post-merge-closure.md
   R2 legacy:    {YYYY-MM-DD}-{shipment_id}-{suffix}-closure.md
   Both interpolate a re.escape'd shipment ID bounded by LITERAL `-` delimiters on both sides, matched case-insensitively ONLY on the ID segment. NEVER a substring search — this is the R2 mitigation against 16-S matching 162-S.
4. build_closure_path(closure_dir, shipment_id, feature_id) -> Path — the path builder the producer documentation directs authors to, and the ONLY construction path 167.007-T's composed test may use.
5. classify_closure_candidates(closure_dir, shipment_id) -> ClosureDiscovery — a frozen dataclass carrying canonical_matches, legacy_matches, unrecognized_candidates, and outcome in {absent, unrecognized, recognized}. Applies D5 ordering: the canonical partition wins outright when non-empty; within a partition candidates are returned in deterministic sorted order.
6. CONSUMER_SITES — an in-source enumerated tuple of EVERY site deriving from this contract (topology reader, validation CLI, both producer skill files, both Ship agent files), per compound lesson 4. 167.009-T asserts it is complete.

SCOPE GUARD
This module performs NO frontmatter parsing and makes NO validity judgement. It answers only "which files are candidates for this shipment, and how are they classified by NAME". Keeping name classification strictly separate from content validity is what lets the fail-closed validity predicate stay byte-unchanged (plan decision P-D3).

RATIONALE FOR A NEW MODULE (P-D1)
topology.py is a CONSUMER, not the definition. Placing the contract there would reproduce the "definition co-located with one consumer" structure that generated this defect. A sibling module matches the established gates/ precedent (shipment_closure.py, bootstrap_grant.py, sizing.py).

TESTS (4)
1. canonical / legacy / both / neither classification.
2. anchored-ID rejection of a foreign-ID filename.
3. deterministic ordering under multiple matches.
4. build_closure_path round-trips through classify_closure_candidates as CANONICAL.

ACCEPTANCE
- RECOGNIZED_CLOSURE_PATTERNS has EXACTLY two members and a test asserts that cardinality (hardening H1.4) — adding a third pattern must fail the suite and force a deliberate contract decision.
- No import of topology.py from this module (dependency direction is consumer -> contract, never the reverse).
- Touches NOTHING under docs/closure/.
