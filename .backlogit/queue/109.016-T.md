<!-- BEGIN:acceptance-criteria -->
* Given a covering feature spanning multiple serial shipments (e.g. 109-F -> 114-S/115-S/116-S), a sibling task that is in `.backlogit/archive/` BECAUSE its owning predecessor shipment reached a SUCCESSFUL TERMINAL state — the archived shipment record's terminal `archived_status` is `shipped` (or the normalized legacy `done`) — is EXCLUDED from the protected set and does NOT trip the baseline/verify-after cascade halt in the Ship safe-close closure procedure. Mere presence in `.backlogit/archive/` is NOT sufficient: only a successfully-shipped terminal state legitimizes the exclusion.
* A sibling task belonging to a NOT-yet-shipped shipment (still queued/active/blocked), an unassigned sibling still under the feature, OR a sibling whose owning shipment is archived in ANY non-shipped terminal state (e.g. `archived_status: abandoned`) REMAINS in the protected set and must stay in `.backlogit/queue/`; a genuine cross-cascade still halts with the P-005 violation (no P-001 bypass).
* Protected-set computation is sequence-aware AND terminal-status-aware: it distinguishes a legitimately released predecessor-sibling (owning archived shipment `archived_status: shipped` / normalized legacy `done`) from an illegitimately cascaded sibling (owning shipment not shipped — queued/active/blocked, unassigned, OR archived in a non-shipped terminal state such as `abandoned`). Every archived state that is not `shipped`/`done` remains PROTECTED.
* Deterministic test proves a 3-shipment serial sequence closes cleanly when predecessors are SHIPPED: 114-S closes (no predecessors archived), then 115-S safe-close PASSES with 114-S tasks archived under `archived_status: shipped`, then 116-S safe-close PASSES with 114-S+115-S tasks archived under `archived_status: shipped`. A companion NEGATIVE test proves that a sibling whose owning shipment is archived `abandoned` (non-shipped terminal) REMAINS protected and still trips the genuine-cascade halt.
* Change is confined to the Ship safe-close/`shipment-reconcile` protected-set contract in templates/agents/_ship.agent.md.tmpl and the installed .github/agents/_ship.agent.md; no backlogit source is mutated (external-guard boundary preserved).
<!-- END:acceptance-criteria -->

<!-- BEGIN:description -->
[Shipment A / core — sequencing prerequisite] The installed Ship safe-close `shipment-reconcile` contract (_ship.agent.md closure tasks b/c) computes the protected set as the covering feature plus EVERY sibling task not in the manifest, scanning BOTH .backlogit/queue/ and .backlogit/archive/, and requires every protected-set member to remain in .backlogit/queue/. For a covering feature split across serial shipments (109-F -> 114/115/116-S), this falsely flags a predecessor shipment's LEGITIMATELY archived tasks as an already-occurred cascade and halts, so 115-S and 116-S can never safe-close. Make the protected-set computation multi-shipment-per-feature sequence-aware AND terminal-status-aware: exclude a sibling task from the must-remain-queued protected set ONLY when its owning shipment record is archived with a successful terminal `archived_status` of `shipped` (or the normalized legacy `done`), while still protecting siblings of not-yet-shipped shipments AND siblings whose owning shipment is archived in any non-shipped terminal state (e.g. `abandoned`). MUST ship in 114-S (the first/core shipment) so the corrected contract is installed before 115-S/116-S close.
<!-- END:description -->
