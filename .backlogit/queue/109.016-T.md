<!-- BEGIN:acceptance-criteria -->
* CLOSE-CONTRACT (SHIP-THEN-VERIFY, NOT a pre-archive gate): backlogit_ship_shipment ATOMICALLY (from the caller's view) transitions the shipment active->shipped AND archives the released scope in one internal operation; `archived_status` is stamped by backlogit DURING archive (ArchiveItem) and does NOT exist on the record before archival, so a PRE-ARCHIVE `archived_status` check is IMPOSSIBLE and MUST NOT be attempted. Instead, on a SUCCESSFUL close the Ship safe-close procedure calls the SUPPORTED ship operation (backlogit_ship_shipment) for the CURRENT shipment ONLY (P-015 no cascade), then AFTER the call returns VERIFIES the resulting archived shipment record/provenance reads `archived_status: shipped` (or the normalized legacy `done`). If that terminal marker is absent or wrong (e.g. `active`/`abandoned`), Ship FAILS the closure and surfaces a remediation token — it does NOT hand-archive and does NOT invent a pre-archive gate. This POST-OPERATION verified marker is the RELIABLE signal the protected-set exclusion below depends on.
* Given a covering feature spanning multiple serial shipments (e.g. 109-F -> 114-S/115-S/116-S), a sibling task that is in `.backlogit/archive/` BECAUSE its owning predecessor shipment reached a SUCCESSFUL TERMINAL state — the archived shipment record's terminal `archived_status` is `shipped` (or the normalized legacy `done`) — is EXCLUDED from the protected set and does NOT trip the baseline/verify-after cascade halt in the Ship safe-close closure procedure. Mere presence in `.backlogit/archive/` is NOT sufficient: only a verified successfully-shipped terminal state legitimizes the exclusion.
* A sibling task belonging to a NOT-yet-shipped shipment (still queued/active/blocked), an unassigned sibling still under the feature, OR a sibling whose owning shipment is archived in ANY non-shipped terminal state (e.g. `archived_status: abandoned`) REMAINS in the protected set and must stay in `.backlogit/queue/`; a genuine cross-cascade still halts with the P-005 violation (no P-001 bypass).
* Protected-set computation is sequence-aware AND terminal-status-aware: it distinguishes a legitimately released predecessor-sibling (owning archived shipment `archived_status: shipped` / normalized legacy `done`) from an illegitimately cascaded sibling (owning shipment not shipped — queued/active/blocked, unassigned, OR archived in a non-shipped terminal state such as `abandoned`). Every archived state that is not `shipped`/`done` remains PROTECTED.
* Deterministic 114->115->116 test proves the 3-shipment serial sequence closes cleanly: each predecessor is closed via the SUPPORTED ship operation (backlogit_ship_shipment) which internally transitions to `shipped` and archives its tasks under `archived_status: shipped`, and Ship VERIFIES that marker AFTER the call returns; 114-S close archives its tasks `shipped`; 115-S safe-close then PASSES; 116-S safe-close then PASSES with 114-S+115-S tasks archived `shipped`. NEGATIVE cases: (a) a sibling whose owning shipment is archived `abandoned` (non-shipped terminal) REMAINS protected and still trips the genuine-cascade halt; (b) a shipment whose archived record post-operation reads `archived_status: active` (produced OUTSIDE the supported ship op — e.g. a direct archive of a still-active record, as evidenced by `.backlogit/archive/110-S.md`) is treated as NON-shipped: its siblings STAY protected and Ship's post-op verification FAILS the closure with a remediation token rather than trusting the marker. NO impossible pre-archive field verification is asserted.
* Change is confined to the Ship safe-close/`shipment-reconcile` protected-set + closure-sequence contract in templates/agents/_ship.agent.md.tmpl and the installed .github/agents/_ship.agent.md; no backlogit source is mutated (external-guard boundary preserved).

[Shipment A / core — sequencing prerequisite] The installed Ship safe-close `shipment-reconcile` contract (_ship.agent.md closure tasks b/c) computes the protected set as the covering feature plus EVERY sibling task not in the manifest, scanning BOTH .backlogit/queue/ and .backlogit/archive/, and requires every protected-set member to remain in .backlogit/queue/. For a covering feature split across serial shipments (109-F -> 114/115/116-S), this falsely flags a predecessor shipment's LEGITIMATELY archived tasks as an already-occurred cascade and halts, so 115-S and 116-S can never safe-close. Two coupled fixes: (1) CORRECT the closure contract so a SUCCESSFUL close uses the SUPPORTED ship operation (backlogit_ship_shipment) for the current shipment ONLY, which internally transitions active->shipped AND archives (stamping `archived_status` DURING archive), and THEN — AFTER the call returns — VERIFIES the resulting archived record reads `archived_status: shipped` (or normalized legacy `done`); a pre-archive `archived_status` check is IMPOSSIBLE (the field does not exist until archive) and is NOT attempted, and a post-op marker that is absent/`active`/`abandoned` FAILS the closure with remediation — so the protected-set exclusion can RELY on `archived_status: shipped` being a truthful POST-OPERATION signal; (2) make the protected-set computation multi-shipment-per-feature sequence-aware AND terminal-status-aware: exclude a sibling task from the must-remain-queued protected set ONLY when its owning shipment record is archived with a VERIFIED successful terminal `archived_status` of `shipped` (or the normalized legacy `done`), while still protecting siblings of not-yet-shipped shipments AND siblings whose owning shipment is archived in any non-shipped terminal state (e.g. `abandoned`). MUST ship in 114-S (the first/core shipment) so the corrected closure+protected-set contract is installed before 115-S/116-S close.

Ship-then-verify: the close procedure calls backlogit_ship_shipment (active -> shipped, which archives internally and stamps `archived_status` DURING archive at ArchiveItem) for the current shipment only, then re-reads the ARCHIVED record and VERIFIES its terminal `archived_status: shipped` (or normalized legacy `done`) AFTER the operation returns. There is NO pre-archive marker to check — backlogit stamps `archived_status` only at archive time — so a pre-archive gate is impossible and is not attempted. Evidence that archived != shipped today: `.backlogit/archive/110-S.md` carries `archived_status: active`, so mere archival is NOT proof of a successful release; Ship's POST-OPERATION verification closes that gap by rejecting any non-`shipped`/`done` archived marker. Owning-shipment resolution: a sibling task's owning shipment can be found by scanning shipment manifests (custom_fields.items) across .backlogit/queue/ and .backlogit/archive/. An archived shipment record whose manifest contains the sibling legitimizes exclusion ONLY when that record's terminal `archived_status` is `shipped` (or the normalized legacy `done`); read `archived_status` from the archived shipment frontmatter and do NOT treat mere presence in `.backlogit/archive/` as proof of a successful release. Preserve the existing genuine-cascade halt + git-restore recovery for siblings whose owning shipment is still queued/active/blocked, unassigned, OR archived in a non-shipped terminal state. Keep P-015 (never cascade backlogit_ship_shipment across sibling shipments) intact — the ship op is invoked ONLY for the shipment actually being closed, never cascaded to predecessors/successors. Add a deterministic fixture mirroring the 114/115/116 topology, a negative fixture with an `abandoned` archived predecessor whose siblings must remain protected, and a negative case asserting a post-operation archived marker of `active` (or `abandoned`) FAILS Ship's closure verification and keeps the siblings protected (no reliance on an impossible pre-archive gate).
