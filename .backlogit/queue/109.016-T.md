That op (backlogit `internal/core/shipment_lifecycle.go` `ShipShipment`, HEAD `fd8d2c9`) completes and archives the release scope (its manifest members) and, per covering-feature root, REQUEUES + DETACHES every unshipped non-release descendant — setting it back to `queued` and clearing its `parent_id` (`returnUnreleasedFeatureItems`), i.e. it returns the downstream 115-S/116-S tasks to unparented backlog rather than archiving them. A covering feature is marked done/archived ONLY when it is an explicit manifest member; a NON-MEMBER covering feature such as `109-F` (already removed from 114-S's manifest) is PRESERVED — snapshotted and restored via `restoreRolledUpNonMemberFeatures`, never left done/archived. It is P-015 forbidden for a partial-feature shipment because it would requeue/detach the downstream 115-S/116-S descendant tasks (orphaning them from `109-F` and breaking the serial 114->115->116 sequence) and archive the release-scope members outside the reconcile safe-close terminal-marker ordering — all before any post-call check runs. After manifest-scoped per-item closure, the shipment RECORD is closed by an ordered, non-cascading sequence: (1) move ONLY the shipment record to live `status: shipped` via `backlogit move <shipment_id> --status shipped` (the generic artifact status update that mutates only the shipment record — NOT the cascade op); (2) re-read and verify the shipment record's live `status: shipped`; (3) archive ONLY that shipment record via `backlogit archive <shipment_id>` (single artifact), which stamps `archived_status: shipped` from the live status; (4) re-read and verify the archived record's `archived_status: shipped`.
* TERMINAL-MARKER-BEFORE-ARCHIVE (the defect this task fixes): the current canonical safe-close archives the shipment record directly while it is still `active`, so the archived record gets `archived_status: active` (as `.backlogit/archive/110-S.md` / `103-S.md` demonstrate). Corrected safe-close inserts the move-to-`shipped` + live-status verification BEFORE the single-artifact archive, and the archived-provenance verification AFTER, so the shipment record always lands with `archived_status: shipped`.
* `archived_status` is created only by the single-artifact archive (step 3), so it cannot be verified before archival; the pre-archive marker to verify is the live `status: shipped`.
* SEQUENCE-AWARE PROTECTED SET: given a covering feature spanning multiple serial shipments, a sibling task is excluded from the protected set ONLY when its owning predecessor shipment record carries verified archived provenance `archived_status: shipped` (normalized legacy `done`).
