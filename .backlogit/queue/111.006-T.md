Update BOTH owner agent templates — `templates/agents/_stage.agent.md.tmpl` AND `templates/agents/_ship.agent.md.tmpl` — so each owner agent's OWN startup/recovery protocol implements the fail-closed crash-resumption lifecycle defined by C1/111.001-T + hardening H7/H8. This CHANGES the owner protocols themselves; it does NOT merely delegate to the Orchestrator routing (P1 finding: the existing Stage/Ship templates today fresh-start on an invalid checkpoint and resolve active checkpoints BEFORE a confirmed successful resume — both behaviors are removed here). 2. ZERO-CANDIDATE NORMAL STARTUP: at owner-agent session start, if the owning agent has NO active/unresolved recovery candidate of its own, it CONTINUES NORMAL WORK — NOT a failure and NOT an operator handoff (mirrors 111.001-T AC#1 zero-candidate no-op). 3. EXPLICIT OPERATOR FILENAME SELECTION when one or more of the agent's own candidates exist: never auto-pick; the operator selects a SINGLE checkpoint by filename. 4. OWNER VALIDATION: validate the selected checkpoint's CheckpointV1 `agent` ownership (`required,oneof=ship stage`) matches THIS agent's role — the Stage agent restores/resumes/prunes/RESOLVES ONLY `stage`-owned checkpoints; the Ship agent ONLY `ship`-owned; a checkpoint owned by the other role is NEVER restored, resumed, pruned, OR RESOLVED by this agent (CROSS-ROLE RESOLUTION is explicitly prohibited in addition to cross-role restore/resume/prune — preserves P-001 role separation). 5. OWNER-EXCLUSIVE restore/resume/prune performed by the owning agent only, after EXPLICIT OPERATOR CONFIRMATION (H1), and only after a valid unique selection + ownership match. 6. OWNER-SCOPED RESOLUTION, ONLY AFTER CONFIRMED SUCCESSFUL OWNER RESUME (H3): REPLACE the existing BULK/broad resolution behavior in BOTH owner protocols with an OWNER-SCOPED resolution that resolves ONLY the SINGLE explicitly operator-selected, ownership-matched checkpoint — never a bulk sweep of all/other active checkpoints, and never a checkpoint owned by the other role (cross-role RESOLUTION prohibited, per AC#4). Remove the existing behavior that resolves an active checkpoint before a confirmed successful resume — `resolve_checkpoint` is invoked strictly AFTER the owning agent confirms a successful resume of THAT selected checkpoint, never before, never on ambiguous/torn state, and never as an unscoped bulk resolution. 7. FAIL CLOSED, NO FRESH-START FALLBACK: an invalid / ambiguous / torn / malformed / unreadable checkpoint read => FAIL CLOSED to operator handoff; REMOVE the existing fresh-start-on-invalid-checkpoint behavior — the agent MUST NOT silently discard an invalid/ambiguous checkpoint and start a fresh session. A non-unique/ambiguous selection among EXISTING candidates or a missing/invalid/ambiguous `agent` ownership => fail closed AMONG EXISTING CANDIDATES (zero candidates never fails closed — see AC#2). 8. SINGLE-ACTIVE preserved (H2): owner resume picks up the SAME single-active cursor; no parallel resume, no new worktree (P-001/P-016). 9. WIDTH ISOLATION + WIRING: owner agent-template family (Stage + Ship agent templates) only — distinct from the orchestrator agent template authored in C1/111.001-T; the two owner templates install via the EXISTING first-party agent-template install path (no new install primitive/schema); verify/assertion-anchor coverage of these owner-template changes is owned by 111.003-T (C4).
