THE DEFECT
The closure-evidence PRODUCER and CONSUMER name the same artifact differently, and nothing in the repository holds them together.
- Producer skill template templates/skills/operational-closure/SKILL.md.tmpl:23 documents {{DOCS_CLOSURE}}/{YYYY-MM-DD}-{slug}-closure.md; the installed dogfood mirror .github/skills/operational-closure/SKILL.md:23 renders the same shape with the literal docs/closure. (The placeholder/literal difference is correct and is preserved — templates are the product.)
- The Ship agent template templates/agents/_ship.agent.md.tmpl:863 names the output DIRECTORY only, with no filename contract, and lists `compaction status` without `closure_status`; its installed mirror carries the same omission.
- The consumer FilesystemTopologyReaders.closure_complete (src/autoharness/gates/topology.py:718) globs docs/closure/{shipment_id}-*-post-merge-closure.md.
The two shapes cannot intersect, so conforming producer output is invisible to the gate, which emits PREDECESSOR_CLOSURE_INCOMPLETE. This has recurred SIX times and has been repaired per-artifact every time. Live consumer state confirms it: closure_complete("162-S") and closure_complete("174-S") both return None; closure_complete("173-S") returns True.

THE FIX
Replace per-artifact repair with ONE shared contract module that both sides consume, a write-time validator gate, and a composed producer->consumer test that fails if either side drifts again.
