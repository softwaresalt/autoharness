MANDATORY VALUE VALIDATION BEFORE THE EQUALITY (BINDING, ADDED IN REVIEW-FIX CYCLE 3, FINDING 3; PRESERVED VERBATIM ACROSS THE CYCLE-5 SEAM MOVE). size_composition is READ BACK FROM A TOOL, so the value is untrusted input and the equality is meaningless until its shape is proved. The clause set must state, before any comparison:
- unsized MUST be a NON-NEGATIVE INTEGER, and bool MUST BE EXCLUDED. In Python bool is a SUBCLASS of int, so isinstance(False, int) is True and False == 0 is True: an unvalidated predicate PASSES on False and lets an entirely un-analysed shipment through under the appearance of a clean result. The type check MUST be of the form "is an int AND is not a bool", never a bare isinstance(x, int).
- histogram MUST be a MAPPING (an EMPTY mapping is valid - see B3). H4 requires the gate to read BOTH unsized AND histogram; a gate that never validates histogram is not reading it.
- NEVER COERCE. No int(x), no float comparison, no truthiness fallback, no "default to 0", no "treat missing as zero". Coercion converts a fail-closed condition into a silent pass, which is the exact fail-open shape this shipment exists to remove.
- EVERY fail-closed rejection MUST report the SPECIFIC validation failure - TYPE, RANGE, or SHAPE - naming the field and the observed value. A generic "size composition invalid" message cannot distinguish a broken tool from an unsized shipment, and the operator remedies for those two differ.

AUTHORSHIP (BINDING, CORRECTED IN EXTENDED REVIEW-FIX CYCLE 4, FINDING 2; REINFORCED IN CYCLE 5, FINDING 9): THIS TASK AUTHORS NO BOUNDARY CASE AND NO TEST. All eleven cases B1-B11 are AUTHORED IN 158.002-T against the unmodified tree, BEFORE this task changes anything, and this task CONSUMES them. The eleven are restated below because they are this task's CLAUSE CONTRACT - the text the Stage instruction must exhibit - not because this task writes their assertions. Any assertion found to have been authored here instead FAILS acceptance, because a case written by its own implementer is green on arrival and can never have been observed red. A DIRECT blocks edge 158.003-T -> 158.002-T is declared (in addition to the transitive path through 158.001-T) so the ordering is machine-checked.
B1 - unsized: 0 (int) with a NON-EMPTY histogram => PASS. The ordinary success case.
B2 - unsized: 1 (int) with a NON-EMPTY histogram => FAIL, and the failure message MUST NAME THE UNSIZED MEMBER IDs. A failure that says only "unsized members present" forces a manual hunt through the shipment; naming the IDs is what makes the gate actionable.
B3 - unsized: 0 (int) with an EMPTY histogram (a shipment with no task members) => PASS. An empty shipment is NOT an unsized one. Emptiness is a different defect and is deliberately NOT gated here; failing it would block a legitimately empty assembly for a reason this gate has no authority over. NOTE the contrast with B11: an EMPTY MAPPING passes, an ABSENT OR MALFORMED histogram fails closed.
B4 - the unsized FIELD IS ABSENT from the rollup => FAIL CLOSED, named SHAPE error. AN ABSENT FIELD IS NOT ZERO. A missing key means the rollup could not be computed or the tool did not report it, which is precisely when the gate knows least and must refuse; reading it as passing would let an entire un-analysed shipment through under the appearance of a clean result.
B5 - unsized: 0 (int) with ruleset_version: null => PASS (binding H4). A null ruleset version is not a sizing defect and does not trip this gate.
B6 - unsized: false (bool) => FAIL CLOSED, named TYPE error. THIS IS THE MOST DANGEROUS MALFORMED VALUE IN THE SET: bool subclasses int, so False == 0 evaluates True and an unvalidated predicate PASSES. The clause must require rejection on TYPE before the equality is evaluated, and require the message to name the type. unsized: true must be rejected by the SAME type check, not incidentally by True == 1 - both bool values are named, so an implementation that only special-cases False is caught.
B7 - unsized: 0.0 (float) => FAIL CLOSED, named TYPE error. 0.0 == 0 evaluates True, so a float also passes an unvalidated predicate while proving nothing about an integer member count.
B8 - unsized: "0" (string) => FAIL CLOSED, named TYPE error. MUST NOT be coerced with int(). A producer emitting strings is a producer whose contract is not the one this gate reads, and silently accepting it hides that.
B9 - unsized: null => FAIL CLOSED, named TYPE error. A null is an explicit "not computed" - exactly the condition under which the gate must refuse rather than assume.
B10 - unsized: -1 (negative int) => FAIL CLOSED, named RANGE error. A negative count is impossible and indicates a broken rollup. Note that -1 == 0 is False, so a naive predicate would fail this case for the WRONG REASON and with an unusable message; the range check is what makes the diagnosis correct.
B11 - histogram ABSENT, or present but NOT A MAPPING (list, string, null, or scalar) => FAIL CLOSED, named SHAPE error. Distinct from B3 in both directions: an EMPTY MAPPING is a valid rollup of an empty shipment and PASSES; an ABSENT or MALFORMED histogram means the rollup could not be computed and must be REFUSED. The absent case and at least one non-mapping case are separate deterministic clauses.

WHY THE CLAUSE SET IS PARTITIONED THIS WAY: B3 and B4 are the two cases a naive `if unsized:` TRUTHINESS check gets wrong in OPPOSITE directions - truthiness treats B4's missing key as falsy and PASSES it (fail-open, the dangerous direction), while a careless emptiness guard FAILS B3. B6, B7 and B8 are the cases a naive `unsized == 0` EQUALITY check gets wrong - each compares equal to zero (or coerces to it) without BEING a non-negative integer count. B9 and B10 are values whose rejection must be ATTRIBUTED CORRECTLY rather than happening accidentally. B11 closes the histogram half of H4. None may be dropped as an edge case: together they are the complete failure surface the predicate actually has.
