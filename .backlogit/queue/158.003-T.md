DELIVERABLE: at shipment-assembly time, read the shipment's size_composition rollup BACK FROM THE TOOL after assembly and FAIL the assembly WHEN AND ONLY WHEN the unsized-only predicate trips.

BUDGET PREDICATE (THE WHOLE OF IT): size_composition.unsized == 0, evaluated ONLY AFTER the read-back value has been VALIDATED. There is NO aggregate size or complexity threshold, NO declared budget value, and NO composition-exceeds-budget branch. CORRECTED IN REVIEW-FIX CYCLE 2, FINDING 9: this task previously also required failing "when the composition exceeds the declared budget", language that survived from an earlier draft. The plan WITHDREW that clause and decided the unsized-only predicate deliberately; no budget is declared anywhere in this shipment, so "the declared budget" referred to nothing. An implementer following it would have had to INVENT a threshold - a number with no owner, no derivation and no review - and would then have been gating shipments on a fabricated value while believing it was specified. Implement the equality and nothing else; if a future shipment wants an aggregate budget, that is a new decision with a declared value, not an inference from this text.

MANDATORY VALUE VALIDATION BEFORE THE EQUALITY (BINDING, ADDED IN REVIEW-FIX CYCLE 3, FINDING 3). size_composition is READ BACK FROM A TOOL, so the value is untrusted input and the equality is meaningless until its shape is proved. Before comparing anything:
- unsized MUST be a NON-NEGATIVE INTEGER, and bool MUST BE EXCLUDED. In Python bool is a SUBCLASS of int, so isinstance(False, int) is True and False == 0 is True: an unvalidated predicate PASSES on False and lets an entirely un-analysed shipment through under the appearance of a clean result. The type check MUST be of the form "is an int AND is not a bool", never a bare isinstance(x, int).
- histogram MUST be a MAPPING (an EMPTY mapping is valid - see B3). H4 requires the gate to read BOTH unsized AND histogram; a gate that never validates histogram is not reading it.
- NEVER COERCE. No int(x), no float comparison, no truthiness fallback, no "default to 0", no "treat missing as zero". Coercion converts a fail-closed condition into a silent pass, which is the exact fail-open shape this shipment exists to remove.
- EVERY fail-closed rejection MUST report the SPECIFIC validation failure - TYPE, RANGE, or SHAPE - naming the field and the observed value. A generic "size composition invalid" message cannot distinguish a broken tool from an unsized shipment, and the operator remedies for those two differ.

REQUIRED BOUNDARY CASES - ALL ELEVEN, B1 THROUGH B11, EXACTLY AS THE PLAN DECLARES THEM. B1-B5 were added in review-fix cycle 2 (finding 9); B6-B11 are the TYPE-VALIDITY BAND added in review-fix cycle 3 (finding 3). Each case is DETERMINISTIC: a fixed injected rollup value in, a fixed named outcome out - no sampling, no environment dependence, no ordering dependence.
B1 - unsized: 0 (int) with a NON-EMPTY histogram => PASS. The ordinary success case.
B2 - unsized: 1 (int) with a NON-EMPTY histogram => FAIL, and the failure message MUST NAME THE UNSIZED MEMBER IDs. A failure that says only "unsized members present" forces a manual hunt through the shipment; naming the IDs is what makes the gate actionable.
B3 - unsized: 0 (int) with an EMPTY histogram (a shipment with no task members) => PASS. An empty shipment is NOT an unsized one. Emptiness is a different defect and is deliberately NOT gated here; failing it would block a legitimately empty assembly for a reason this gate has no authority over. NOTE the contrast with B11: an EMPTY MAPPING passes, an ABSENT OR MALFORMED histogram fails closed.
B4 - the unsized FIELD IS ABSENT from the rollup => FAIL CLOSED, named SHAPE error. AN ABSENT FIELD IS NOT ZERO. A missing key means the rollup could not be computed or the tool did not report it, which is precisely when the gate knows least and must refuse; reading it as passing would let an entire un-analysed shipment through under the appearance of a clean result.
B5 - unsized: 0 (int) with ruleset_version: null => PASS (binding H4). A null ruleset version is not a sizing defect and does not trip this gate.
B6 - unsized: false (bool) => FAIL CLOSED, named TYPE error. THIS IS THE MOST DANGEROUS MALFORMED VALUE IN THE SET: bool subclasses int, so False == 0 evaluates True and an unvalidated predicate PASSES. Assert the gate rejects it on TYPE before the equality is evaluated, and assert the message names the type. unsized: true must be rejected by the SAME type check, not incidentally by True == 1 - assert both bool values, so an implementation that only special-cases False is caught.
B7 - unsized: 0.0 (float) => FAIL CLOSED, named TYPE error. 0.0 == 0 evaluates True, so a float also passes an unvalidated predicate while proving nothing about an integer member count.
B8 - unsized: "0" (string) => FAIL CLOSED, named TYPE error. MUST NOT be coerced with int(). A producer emitting strings is a producer whose contract is not the one this gate reads, and silently accepting it hides that.
B9 - unsized: null => FAIL CLOSED, named TYPE error. A null is an explicit "not computed" - exactly the condition under which the gate must refuse rather than assume.
B10 - unsized: -1 (negative int) => FAIL CLOSED, named RANGE error. A negative count is impossible and indicates a broken rollup. Note that -1 == 0 is False, so a naive predicate would fail this case for the WRONG REASON and with an unusable message; the range check is what makes the diagnosis correct.
B11 - histogram ABSENT, or present but NOT A MAPPING (list, string, null, or scalar) => FAIL CLOSED, named SHAPE error. Distinct from B3 in both directions: an EMPTY MAPPING is a valid rollup of an empty shipment and PASSES; an ABSENT or MALFORMED histogram means the rollup could not be computed and must be REFUSED. Cover the absent case and at least one non-mapping case as separate deterministic cases.

WHY THE CASE SET IS PARTITIONED THIS WAY: B3 and B4 are the two cases a naive `if unsized:` TRUTHINESS check gets wrong in OPPOSITE directions - truthiness treats B4's missing key as falsy and PASSES it (fail-open, the dangerous direction), while a careless emptiness guard FAILS B3. B6, B7 and B8 are the cases a naive `unsized == 0` EQUALITY check gets wrong - each compares equal to zero (or coerces to it) without BEING a non-negative integer count. B9 and B10 are values whose rejection must be ATTRIBUTED CORRECTLY rather than happening accidentally. B11 closes the histogram half of H4. None of these may be dropped as an edge case: together they are the complete failure surface the predicate actually has.

This is the genuine MACHINE gate of this shipment - it reads state back from the tool and no amount of agent goodwill can fake it.
