Surface metric-quality provenance (estimated vs observed) in eval-summary derived ratios instead of treating all denominators as equally trustworthy (source: stash D194A24B, 3EFC51DE).

Files (3): src/autoharness/telemetry/aggregation.py, src/autoharness/eval/summary.py, tests/test_eval_summary.py

Current state (two coupled defects): eval/summary.py has no general mechanism surfacing whether an economics metric was estimated vs observed in its output -- only one special-case exists for context_area_tokens (summary.py:161). gap_rate (summary.py:143: float | str = UNAVAILABLE if expected == 0 else missing / expected) ignores metric_quality entirely, and _derived_ratio (aggregation.py:118-121) is likewise not quality-aware -- it only guards against None values / zero denominators, not against a denominator whose provenance is "estimated".

TDD (red->green): add two tests to test_eval_summary.py (both fail first). (1) test_gap_rate_flags_estimated_denominator_provenance: a metric history where the denominator's quality is "estimated" (not "observed") asserts the summary output surfaces a provenance marker (quality field alongside gap_rate) distinguishing it from a genuinely observed ratio. (2) test_gap_rate_unavailable_when_numerator_unavailable: 3EFC51DE's concrete case -- a usable denominator (expected_tool_count=1) with an "unavailable" numerator (missing_expected_tool_count=0 marked unavailable) must surface "unavailable" provenance, NOT a bare 0.0. Then: extend _derived_ratio in aggregation.py to accept/propagate a quality indicator for BOTH its numerator and denominator operands (a denominator-only design still returns 0.0 for the unavailable-numerator case and does not fix 3EFC51DE), and update summary.py's gap_rate computation (and any other _derived_ratio consumers sharing the same gap) to surface that provenance in the returned summary structure, generalizing the existing context_area_tokens special-case rather than duplicating it.

Acceptance criteria:
- eval-summary output for gap_rate (and other _derived_ratio-based metrics) includes a provenance/quality indicator derived from BOTH numerator and denominator operands.
- An unavailable (or estimated) numerator degrades the ratio provenance (e.g. expected=1 with an unavailable missing-count numerator surfaces "unavailable", not a bare 0.0).
- Existing context_area_tokens special-case behavior is preserved or generalized into the same mechanism (no regression).
- Ratios with fully-observed numerator and denominator are unaffected (no provenance noise added for the common case where nothing is estimated).
- Verification: python -m pytest tests/test_eval_summary.py -v
