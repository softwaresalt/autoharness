Add exactly one deterministic regression test that enforces a root-level tracked-JSON allowlist. This is the ONLY recurrence-prevention control for feature 133-F, and it doubles as the standing verification that the three deleted artifacts stay absent and that no legitimate root file was lost.

DEPENDS ON 133.001-T. This test asserts the three artifacts are ABSENT, so it MUST land after the deletion or CI goes transiently red (review finding F6, P1).

DELIVERABLE: one new file, tests/test_repo_root_artifacts.py.

REQUIRED BEHAVIOUR:
- A stdlib unittest.TestCase. The canonical gate for this repository is
  PYTHONPATH=src python -m unittest discover -s tests
  Root pytest is NOT canonical here; it wanders into vendored references/* and fails collection. See docs/compound/097-S-canonical-unittest-gate.md.
- Resolve the repository root as the parent of the tests/ directory containing __file__. Do NOT rely on the current working directory (review finding F8, P2).
- Shell out to "git ls-files -z -- *.json" with that repository root as cwd.
- Filter the result to DEPTH-0 entries only, that is, reject any path containing "/". Git pathspec wildcards match across "/", so an unfiltered "*.json" returns nested matches including vendored references/* content (review finding F7, P2).
- Assert the resulting set equals EXACTLY: {".mcp.json", "plugin.json"}.
- On failure, name the offending path or paths in the assertion message so the diagnostic is actionable.
- Call skipTest if git is unavailable or the tree is not a git checkout, so the suite stays deterministic offline.

WHY AN ALLOWLIST TEST AND NOT A .gitignore RULE:
The source stash entry suggested "a gitignore rule or a CI check". The CI check was selected and the ignore rule was DELIBERATELY REJECTED (plan section 4, review finding F12). Do NOT add a .gitignore rule as part of this task. Rationale:
- An ignore rule matching three literal names has strictly weaker coverage than the allowlist; the next ad-hoc dump named verify.json or out2.json bypasses it entirely.
- An ignore rule fails SILENTLY, files just vanish from git add, whereas this test fails loudly and names the offender.
- .gitignore never untracks already-tracked files, so it contributes nothing to the actual defect.
- It would silently suppress a hypothetical legitimate future root JSON file.
Broad *.json ignores are explicitly prohibited. No ignore rule is added at all.

ALLOWLIST JUSTIFICATION:
- .mcp.json is the canonical shared MCP workspace config and is intentionally tracked (see the explicit comment in .gitignore).
- plugin.json is the plugin manifest, name "autoharness", version 1.4.11.

DETERMINISTIC ACCEPTANCE CRITERIA:
1. tests/test_repo_root_artifacts.py exists and is discovered by "PYTHONPATH=src python -m unittest discover -s tests".
2. The full unittest suite passes, with the new test PASSING (not skipped) in a normal git checkout.
3. Temporarily restoring any one of the three deleted files, for example "git show 24777b44:out.json > out.json && git add out.json", makes the new test FAIL and names that path. Revert the restoration afterwards. This proves the control actually fires rather than passing vacuously.
4. No .gitignore modification is present in the diff.
5. The diff adds exactly one file and modifies no existing file.

CI NOTE, NO WORKFLOW EDIT REQUIRED: .github/workflows/ci.yml's "changes" job is a fail-closed denylist excluding only docs/**, .backlogit/** and .autoharness/**. Root *.json and tests/** fall outside those exclusions, so code == true and the test job runs. Do NOT modify ci.yml.
