Document the new gate contract and the migration procedure for workspaces that relied on unstated numeric sequencing.

DELIVERABLES:
1. Gate documentation in `docs/` describing: explicit-DAG predecessor derivation; the four derivation states and their `predecessor_source` values (`explicit`, `declared_root`, `genesis`, `unsequenced`); the UNSEQUENCED_SHIPMENT token; and the root-declaration surface (the `dag-root` label on a shipment record) including WHO may apply it — operator/Stage only, never Ship self-declaring to unblock its own claim.
2. GENESIS IS NARROW — DOCUMENT IT PRECISELY (review-fix cycle 2, finding 2). State the full rule: genesis requires no edges, no `dag-root`, NO shipped-terminal shipment anywhere (live OR archived), the candidate being the SOLE EXTANT NONTERMINAL shipment, and NO abandoned record anywhere. State plainly WHY absence of shipped history alone is insufficient: in a workspace with several queued shipments and nothing yet shipped, a "no shipped history" rule would return genesis for EVERY one of them at once, including later-numbered candidates downstream of other pending work — an unearned pass in exactly the fail-open direction this change exists to close. State the practical consequence for operators: a fresh install's FIRST shipment passes as `genesis` and cannot deadlock, but the SECOND shipment onward must either declare a real `blocks` edge or carry `dag-root`.
3. MIGRATION GUIDE built around the `audit_sequencing` phase (165.003-T): run the audit, review every edge-less shipment, then for each one either record the real `blocks` edge or declare it a root. State plainly that in a workspace disqualified from genesis an un-audited edge-less shipment BLOCKS as `unsequenced` — the intended fail-closed posture — and that the block names both remedies.
4. Document the REMOVED behaviour (numeric adjacency) and why it was retired, citing the three prior defect cycles in docs/compound/ and the directional-numeric root cause they share.
5. Explain that NO configuration key exists for this contract (decision D2): the posture is per-shipment declared intent in backlog data, so there is nothing to configure, no schema version to track, and nothing for install/tune to preserve.
6. ROLLBACK POSTURE — CORRECTED AND ORDERED (review-fix cycle 2, P2 finding 11; this REPLACES the cycle-1 claim that a code revert suffices). A code-only rollback DOES NOT restore the pre-migration workspace. Migration mutates BACKLOG DATA: `blocks` edges added and `dag-root` labels applied during the audit persist after the engine is reverted, and the reverted numeric engine will then interpret those edges as real explicit predecessors — potentially blocking claims that the pre-migration engine allowed. Document:
   a. WHAT IS AND IS NOT REVERSIBLE BY CODE ALONE: the derivation logic, the `predecessor_source` output field (additive, safe for older consumers to ignore), the `audit_sequencing` phase, and the UNSEQUENCED_SHIPMENT token are all code-reversible with no orphaned configuration, because no configuration was introduced. Migrated edges and root labels are NOT.
   b. THE MIGRATION LEDGER is the record that makes data rollback possible. It captures each shipment's PRE-MIGRATION edge set and label set, so the prior state can be restored exactly rather than guessed.
   c. ORDERING IS MANDATORY: revert BACKLOG DATA FIRST using the ledger (remove edges and `dag-root` labels that the migration added, restoring the recorded pre-migration state), THEN revert the ENGINE. Reverting code first leaves migrated data being interpreted by the restored numeric engine — a state that existed in neither the before nor the after configuration, and the most likely source of a confusing mid-rollback block.
   d. If no ledger exists for a given workspace (it was migrated by hand rather than via the audit), say so plainly: data rollback for that workspace is manual and must be reconstructed from backlog record history, and the rollback claim is correspondingly NARROWED — it is not automatic.
7. Cross-reference the decision, this plan, and the original intake bug report (docs/bugs/2026-09-11-autoharness-pipeline-topology-numeric-predecessor-bug.md, committed as the durable source artifact). Reference ONLY committed artifacts.
