Document the new gate contract and the migration procedure for workspaces that relied on unstated numeric sequencing.

DELIVERABLES:
1. Gate documentation in `docs/` describing: explicit-DAG predecessor derivation; the four derivation states and their `predecessor_source` values (`explicit`, `declared_root`, `genesis`, `unsequenced`); the UNSEQUENCED_SHIPMENT token; and the root-declaration surface (the `dag-root` label on a shipment record) including WHO may apply it — operator/Stage only, never Ship self-declaring to unblock its own claim.
2. MIGRATION GUIDE built around the `audit_sequencing` phase (165.003-T): run the audit, review every edge-less shipment, then for each one either record the real `blocks` edge or declare it a root. State plainly that in a workspace WITH shipping history an un-audited edge-less shipment BLOCKS as `unsequenced` — this is the intended fail-closed posture, and the block names both remedies. State equally plainly that a brand-new workspace with no shipping history passes as `genesis`, so a fresh install cannot deadlock on its first claim.
3. Document the REMOVED behaviour (numeric adjacency) and why it was retired, citing the three prior defect cycles in docs/compound/ and the directional-numeric root cause they share.
4. Explain that NO configuration key exists for this contract (decision D2): the posture is per-shipment declared intent in backlog data, so there is nothing to configure, no schema version to track, and nothing for install/tune to preserve.
5. Rollback posture (H4): declaring roots and adding edges are reversible backlog operations; provenance fields are additive and safe for older consumers to ignore; a full engine revert leaves no orphaned configuration because none was introduced.
6. Cross-reference the decision and the plan. Reference ONLY committed artifacts — no link to any uncommitted working document.
