<!-- BEGIN:acceptance-criteria -->
* `autoharness gate pipeline-topology --help` prints usage including the `--shipment <SHIPMENT_ID>` target flag and the `--phase <pre_claim|post_claim|lifecycle|ambient>` flag.
* --json/--mode/--force/--shipment/--phase parse; unknown args -> exit 2.
* SHIPMENT-SCOPED CONTRACT: in a shipment-scoped operation (agent-mode pre-claim / route-eligibility / cursor-advance, and any explicit scoped invocation), `--shipment <SHIPMENT_ID>` is REQUIRED; a missing/empty target -> exit 2 (invalid), fail-closed, never fail-open.
* NON-SHIPMENT CONTEXT: hook/ci ambient invocations parse WITHOUT `--shipment` and run target-independent invariants; when a target is resolvable (see A4 resolution rule) it is consumed, otherwise ambient-only checks run fail-closed.
* The parsed target shipment ID is carried on the gate domain-input object consumed by the readiness/ownership/re-verify checks (A4/A3a/A5).
* The gate domain-input also carries an EXPLICIT `phase` driving the A2 phase-aware active-shipment invariant, with the four values `pre_claim|post_claim|lifecycle|ambient`: pre_claim = ZERO-active; post_claim AND lifecycle = exactly-one-same-target; ambient = AT-MOST-ONE-active validating the resolved target when one exists (zero-active passes so ordinary no-claim work is non-blocking; exactly-one-active passes ONLY when it is the resolved target; exactly-one-not-target/unresolved or two-or-more blocks). THE SOURCE OF THE PHASE IS MODE-SCOPED: in shipment-scoped agent mode the phase is supplied ONLY by the explicit `--phase` CLI flag and MUST be one of the shipment-scoped values `pre_claim|post_claim|lifecycle` — REQUIRED, NEVER inferred from mode or claim state; a missing/empty/invalid value — INCLUDING the non-scoped `ambient` — -> exit 2 (invalid), fail-closed. Hook/ci ambient contexts (which run target-independent invariants) instead resolve an OMITTED phase deterministically to `ambient` (NOT `lifecycle`) without a human-supplied flag, so ordinary zero-active commits/CI pass while two-or-more active or a mismatched single active still blocks. The parsed/resolved phase is carried on the gate domain-input consumed by A2 (109.005-T) and the post-claim GLOBAL re-verify (109.001-T).
* Skeleton returns exit 0 with a structured (JSON-capable) report object that echoes the resolved target shipment (or null for ambient-only) and the resolved phase.
* Follows existing gates.gate dispatch conventions; no import of install/tune modules.
