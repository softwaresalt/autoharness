The render loop already composes per-artifact variables for role artifacts (_resolve_artifact_role + _compose_artifact_variables). Add the equivalent SITE OVERLAY: for an artifact at .github/agents/**/<id>.agent.md whose agent:<id> site has a binding, overlay that artifact's four route variables (TIER_<N>_FAMILY, TIER_<N>_PROVIDER, TIER_<N>_REASONING_EFFORT, TIER_<N>_CONTEXT_TIER, N = the site's default tier) with the resolver's output so the in-memory render of a bound agent equals what install and tune write. An artifact with no resolved site, and every pipeline artifact, gets the base map back UNCHANGED (same 'no resolved role means base map' constraint as the role overlay). config.overrides precedence mirrors the role overlay. The overlay applies at BOTH seams that render an agent from a template: the staged render loop (manifest artifacts[], managed-rendered) and the in-memory community render in _fc_rendered_candidate (managed-community). A community agent is not in artifacts[], so the staged loop never renders it, and without the second seam the candidate behind a reinstall-community proposal would carry the tier default instead of the bound route (PR #513 thread PRRT_kwDORzpWpM6rmKbh). N = the registry's default_tier (B2, 208.002-T). A workspace-authored agent is not a manifest artifact, has no template render and default_tier=None, so it receives no overlay; neither does a managed site whose tier is unresolved (SiteRegistry.unresolved), because its template names no single tier to overlay. Without this unit a bound agent could never satisfy both the render-parity check and the B7 drift check. Test scenarios: a bound agent renders with the binding's values; a bound managed-community agent's in-memory candidate render carries the binding's values; every unbound agent, community agents included, renders byte-identically to the pre-change render (invariant I9); config.overrides precedence; pipeline agents unchanged.
