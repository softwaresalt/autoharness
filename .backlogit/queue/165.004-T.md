Author the advisory-parity test matrix for `dag-readiness` versus `pipeline-topology --phase pre_claim`. Characterization for behaviour that already agrees; STRICT EXPECTED-FAILURE for the new parity requirements. THIS TASK ENDS GREEN — 165.005-T flips the expected-failure markers.

MOTIVATING DIVERGENCE (reproduced in-workspace, decision Finding 3): `dag-readiness` places `163-S` in `ready_set` while `pre_claim` blocks it. Both gates AGREE on the edge `163-S -> 162-S`; they diverge because `_dag_all_predecessors_finished` (L1873) tests only shipped-terminal status and does not model the closure-evidence dimension at all.

THE MATRIX IS TOTAL (review-fix cycle 1, finding 4). Advisory behaviour must be DEFINED AND TESTED for EVERY derivation state, not just the explicit one. For each of the four states — `explicit`, `declared_root`, `genesis`, `unsequenced` — crossed with the closure-evidence dimension, assert that advisory output and `pre_claim` CANNOT CONTRADICT each other:
P1. A `unsequenced`-blocked shipment MUST NEVER appear in `ready_set` and MUST NEVER be reported `next_eligible` while `pre_claim` blocks it. This is the specific gap called out in review: a policy-blocked root must not be advertised as the next thing to claim.
P2. A `declared_root` MUST NEVER be reported advisory-blocked while `pre_claim` passes it — parity fails in BOTH directions, not just the permissive one.
P3. A `genesis`-state shipment is reported consistently with `pre_claim`'s pass.
P4. A shipment whose explicit predecessor is shipped-terminal but lacks RECOGNIZED closure evidence MUST NOT read as ready while `pre_claim` blocks it.
P5. Advisory output is EXPLICITLY LABELLED advisory / non-authorizing.
P6. `next_eligible` output is disambiguated so it cannot be read as claim authorization.
P7. `dag-readiness` NEVER authorizes a claim under ANY configuration or state.

COMPOSED-STATE-MACHINE FRAMING (docs/compound/2026-09-06-composed-workflow-protocol-state-machine-validation.md): the two gates are a producer/consumer pair. Each can pass its own unit tests while the COMPOSITION is broken — which is exactly the observed defect. Test the composition, not the halves.

NON-VACUOUS FIXTURES (docs/compound/2026-08-09-next-eligible-detail-scoping-and-vacuous-tiebreak-tests.md): every asserted state must be reachable and distinguishable in its fixture; an ordering/eligibility assertion whose fixture cannot distinguish outcomes passes vacuously and is not coverage.
