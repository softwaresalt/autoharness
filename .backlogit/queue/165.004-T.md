Author the advisory-parity test matrix for `dag-readiness` versus `pipeline-topology --phase pre_claim`. Characterization for behaviour that already agrees; CONSTRAINED RED (via the `expect_red` helper specified in 165.001-T) for the new parity requirements. THIS TASK ENDS GREEN — 165.005-T flips the RED expectations to ordinary assertions.

SCOPE: PREDECESSOR-STATE PARITY ONLY (review-fix cycle 3, finding 5 — this REPLACES the cycle-2 "closure narrowed to the explicit state" instruction). This matrix covers PARITY OF THE FOUR DERIVATION STATES — `explicit`, `declared_root`, `genesis`, `unsequenced` — AND NOTHING ELSE.

CLOSURE EVIDENCE IS REMOVED FROM THIS TASK ENTIRELY. This task does NOT discover, read, evaluate, or assert parity over closure evidence in ANY state, and NO acceptance criterion here references it. Cycle 2 narrowed the closure dimension to the `explicit` state; cycle 3 REMOVES it. Closure-evidence producer/consumer behaviour — including any composed producer/consumer test — belongs EXCLUSIVELY to stash FD0CCB42. Keeping even ONE closure cell in this shipment would re-import a surface decision D4 descoped, and would make 173-S a shipped CONSUMER of the very naming contract FD0CCB42 must be free to redefine, forcing that work to negotiate compatibility with a dependent it never agreed to. `pre_claim`'s own pre-existing per-explicit-predecessor closure check is UNTOUCHED and stays exactly where it is; it is pinned only by the characterization lock in 165.001-T (C2).

MOTIVATING DIVERGENCE (reproduced in-workspace, decision Finding 3): `dag-readiness` and `pre_claim` disagree because `_dag_all_predecessors_finished` (L1873) and `compute_dag_readiness` (L1968) model predecessor resolution independently of the authoritative path. THIS TASK'S REMEDY IS STATE PARITY: both gates must derive the SAME predecessor state from the SAME shared derivation helper. (The historical 163-S symptom also involved closure-evidence naming; that half is FD0CCB42's and is NOT asserted here.)

MATRIX SHAPE — TOTAL OVER THE FOUR DERIVATION STATES:
- `explicit` — a shipment WITH edges resolves to the same predecessor state in both gates. Tested with the predecessor UNSHIPPED and with the predecessor SHIPPED-TERMINAL. The assertion is on the DERIVED STATE and on `ready_set`/`next_eligible` membership — NEVER on closure evidence. This is the only state carrying more than one case, because it is the only state with a predecessor whose shipped-status can vary.
- `declared_root` — tested ONCE.
- `genesis` — tested ONCE.
- `unsequenced` — tested ONCE.
Plus the genesis-narrowness parity cases (P3b below, two disqualifier shapes). Parity is TOTAL over the four states; it is not multiplied by any dimension.

ASSERTIONS:
P1. A `unsequenced`-blocked shipment MUST NEVER appear in `ready_set` and MUST NEVER be reported `next_eligible` while `pre_claim` blocks it. This is the specific gap called out in review: a policy-blocked root must not be advertised as the next thing to claim.
P2. A `declared_root` MUST NEVER be reported advisory-blocked while `pre_claim` passes it — parity fails in BOTH directions, not just the permissive one.
P3. A `genesis`-state shipment is reported consistently with `pre_claim`'s pass. Use a genesis-VALID fixture — under the SOLE-RECORD rule (PR review-fix cycle 2, thread PRRT_kwDORzpWpM6h3frF) that means the candidate is the ONLY shipment record in the workspace, live and archived counted together, with NO other record of ANY status. A fixture built on "nothing shipped yet" alone, or on the retired G2/G3/G4 three-probe reading, is NOT genesis and would silently assert the wrong state.
P3b. GENESIS NARROWNESS PARITY: in a workspace disqualified from genesis, an edge-less undeclared candidate is `unsequenced` in BOTH gates. Assert this over TWO disqualifier shapes, not one: (i) a second QUEUED shipment record present; and (ii) an ARCHIVED record carrying `archived_status: blocked` — an unclassifiable value that the retired three-probe rule admitted entirely, which is the regression the cycle-2 finding found. Both must be `unsequenced` in both gates. CYCLE-3 CORRECTION (thread PRRT_kwDORzpWpM6h3ttS): shape (ii) was previously written as a LIVE `blocked` record on the premise that `blocked` is a shipment status. It is NOT — it is malformed legacy data, and a LIVE `blocked` record raises BacklogUnavailableError at reader time in BOTH gates rather than deriving `unsequenced`, so it cannot serve as a parity fixture for a derived state. The parity fixture is the ARCHIVED form. Separately assert that the LIVE form fails closed IDENTICALLY in both gates — the malformed-input path must not diverge between `pre_claim` and `dag-readiness` either. This guards against `dag-readiness` keeping the old broad genesis notion, or the old status-enumerating notion, after `pre_claim` adopts the sole-record rule.
P4. EXPLICIT-STATE PARITY: a shipment with explicit edges derives the SAME state in both gates, asserted with the predecessor unshipped and with it shipped-terminal. Assert on derived state and eligibility membership only.
P5. Advisory output is EXPLICITLY LABELLED advisory / non-authorizing.
P6. `next_eligible` output is disambiguated so it cannot be read as claim authorization.
P7. `dag-readiness` NEVER authorizes a claim under ANY configuration or state.

CONSTRAINED RED MECHANISM (PR review-fix cycle 2, thread PRRT_kwDORzpWpM6h3frC — REPLACES the cycle-3 "CONSTRAINED XFAIL REASONS" instruction). Canonical CI is `python -m unittest discover -s tests`, where a pytest `xfail` marker is INERT and `unittest.expectedFailure` cannot constrain WHY a test failed. Every RED expectation here MUST use the `expect_red(raises=..., message_contains=..., reason=...)` helper specified in 165.001-T: only the named exception type and normalized message count as the known RED; ANY other exception FAILS the test; an XPASS FAILS the test. A fixture error, a collection error, or an unknown-phase error MUST NOT satisfy RED. Where the helper is awkward for a particular case, that case may instead be authored in the SAME task as its implementation with the RED observation recorded in the disposition notes. THIS TASK ENDS GREEN either way.

Each can pass its own unit tests while the COMPOSITION is broken — which is exactly the observed defect. Test the composition, not the halves.

NON-VACUOUS FIXTURES (docs/compound/2026-08-09-next-eligible-detail-scoping-and-vacuous-tiebreak-tests.md): every asserted state must be reachable and distinguishable in its fixture; an ordering/eligibility assertion whose fixture cannot distinguish outcomes passes vacuously and is not coverage.
