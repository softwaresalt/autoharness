Author the advisory-parity test matrix for `dag-readiness` versus `pipeline-topology --phase pre_claim`. Characterization for behaviour that already agrees; STRICT EXPECTED-FAILURE for the new parity requirements. THIS TASK ENDS GREEN — 165.005-T flips the expected-failure markers.

MOTIVATING DIVERGENCE (reproduced in-workspace, decision Finding 3): `dag-readiness` places `163-S` in `ready_set` while `pre_claim` blocks it. Both gates AGREE on the edge `163-S -> 162-S`; they diverge because `_dag_all_predecessors_finished` (L1873) tests only shipped-terminal status and does not model the closure-evidence dimension at all.

MATRIX SHAPE — TOTAL OVER STATES, NARROW ON CLOSURE (review-fix cycle 2, P2 finding 10; this REPLACES the cycle-1 "four states CROSSED WITH the closure dimension" instruction). The closure-evidence dimension is only MEANINGFUL for the `explicit` state: closure evidence is evaluated per explicit predecessor, and the other three states have NO predecessor to evaluate closure against. Crossing them with closure variants would produce fixtures in which the closure dimension cannot change the outcome — vacuous cells that inflate the matrix while proving nothing, which is exactly the failure mode docs/compound/2026-08-09-next-eligible-detail-scoping-and-vacuous-tiebreak-tests.md records. Therefore:
- `explicit` state: test ACROSS the closure-evidence variants (predecessor not shipped; predecessor shipped-terminal WITH recognized closure evidence; predecessor shipped-terminal WITHOUT recognized closure evidence).
- `declared_root`, `genesis`, `unsequenced`: test ONCE EACH for derivation/advisory parity. No closure cross-product.
Parity is still TOTAL over the four derivation states — every state is covered — it is simply not multiplied by a dimension that cannot apply to it.

ASSERTIONS:
P1. A `unsequenced`-blocked shipment MUST NEVER appear in `ready_set` and MUST NEVER be reported `next_eligible` while `pre_claim` blocks it. This is the specific gap called out in review: a policy-blocked root must not be advertised as the next thing to claim.
P2. A `declared_root` MUST NEVER be reported advisory-blocked while `pre_claim` passes it — parity fails in BOTH directions, not just the permissive one.
P3. A `genesis`-state shipment is reported consistently with `pre_claim`'s pass. Use a genesis-VALID fixture (the candidate is the sole extant shipment record, no shipped-terminal and no abandoned history, live or archived) — the narrow rule of review-fix cycle 2 finding 2. A fixture built on "nothing shipped yet" alone is NOT genesis and would silently assert the wrong state.
P3b. GENESIS NARROWNESS PARITY (one case): in a workspace disqualified from genesis (a second extant nonterminal shipment exists), an edge-less undeclared candidate is `unsequenced` in BOTH gates. This guards against `dag-readiness` keeping the old broad genesis notion after `pre_claim` narrows it.
P4. `explicit` + shipped-terminal predecessor + NO recognized closure evidence: MUST NOT read as ready while `pre_claim` blocks it. (This is the motivating 163-S shape.)
P5. Advisory output is EXPLICITLY LABELLED advisory / non-authorizing.
P6. `next_eligible` output is disambiguated so it cannot be read as claim authorization.
P7. `dag-readiness` NEVER authorizes a claim under ANY configuration or state.

COMPOSED-STATE-MACHINE FRAMING (docs/compound/2026-09-06-composed-workflow-protocol-state-machine-validation.md): the two gates are a producer/consumer pair. Each can pass its own unit tests while the COMPOSITION is broken — which is exactly the observed defect. Test the composition, not the halves.

NON-VACUOUS FIXTURES (docs/compound/2026-08-09-next-eligible-detail-scoping-and-vacuous-tiebreak-tests.md): every asserted state must be reachable and distinguishable in its fixture; an ordering/eligibility assertion whose fixture cannot distinguish outcomes passes vacuously and is not coverage. This is also the reason the closure cross-product is narrowed above rather than expanded.
