ESTABLISH THE SUITE PARTITION so that external conformance evidence never makes ordinary canonical unittest discovery fail.

THE PROBLEM THIS REMOVES: the four refusal fixtures observe the behaviour of an EXTERNAL BINARY. If they live in the ordinary discovery root, then after the approval-gated workspace binary is cleaned up, a plain PYTHONPATH=src python -m unittest discover -s tests RED-FAILS for a reason that has nothing to do with this repository's code. That converts a routine local or CI run into a false failure and, worse, trains readers to ignore red.

THE PARTITION:
1. Create tests_conformance/ OUTSIDE the ordinary discovery root. The four hermetic refusal fixtures (173.001-T through 173.004-T) and the T0 baseline live there.
2. ASSERT that PYTHONPATH=src python -m unittest discover -s tests EXITS 0 on a clean checkout WITH NO PROVISIONED BINARY. The ordinary suite stays HERMETIC - it depends on no external executable, no network, and no provisioning step.
3. ASSERT the conformance suite FAILS LOUDLY rather than SKIPPING when the binary is absent. A silent skip is how an external-evidence gate stops being evidence: it passes green while observing nothing. Absence of the binary is a provisioning failure and must be reported as one.
4. Add the SEPARATE REQUIRED CI JOB that provisions the pinned, digest-verified binary REPRODUCIBLY and runs the conformance command. It is a required gate - the conformance evidence is not optional - but it is a DISTINCT job, so its provisioning requirements never leak into the ordinary unit-test job.
5. DOCUMENT the verbatim CI command and the verbatim local command for both suites, so a developer can reproduce either without guessing.

Entry point: no dependencies. Blocks 173.001-T, 173.002-T, 173.003-T, 173.004-T and 173.009-T. Scope: tests/, tests_conformance/ and .github/workflows/ci.yml.
