Implement the Git branch SHORT-NAME validator: rules V1-V11 plus the standalone option-like invariant. V1 empty/whitespace-only; V2 begins with '-'; V3 is exactly '-' or all '-'; V4 begins/ends with '/' or contains '//'; V5 begins/ends with '.' or contains '..'; V6 contains an ASCII control char (\\x00-\\x1F, \\x7F) or a space; V7 contains any of ~ ^ : ? * [ backslash; V8 ends with .lock or any /-delimited component ends with .lock; V9 any /-delimited component begins with '.'; V10 is exactly '@' or contains the sequence '@{'; V11 ends with '.'. EQUIVALENCE CLAIM CORRECTED IN REVISION 4 -- do not implement or assert an identical accept/reject set against `git check-ref-format --branch`. The truthful relationship is a STRICT SUPERSET OF REJECTIONS with one enumerated divergence class: (i) every value this validator ACCEPTS is also accepted by `git check-ref-format --branch`; (ii) every value `git check-ref-format --branch` REJECTS is also rejected here; (iii) the enumerated divergence set D is the @{...} revision-suffix family, including the @{-N} previous-checkout shorthand, which `git check-ref-format --branch` ACCEPTS and RESOLVES but which this workspace path contract DELIBERATELY REJECTS under V10, because @{-N} is a context-dependent revision expression evaluated against the reflog rather than a durable branch identity, and a gate that persists it into an expected-branch list would record an expectation whose meaning changes with checkout history. Normalization is explicitly NOT chosen; rejection is. The equivalence corpus therefore asserts (i), (ii) and the exact membership of D in both directions, and fails on any value that diverges outside D. Separately, V2/V3 option-like rejection is asserted as its OWN invariant, not derived from git's behaviour, because `git check-ref-format --branch` cannot unambiguously receive a leading-hyphen argument at all. Where the local git binary is unavailable the corpus SKIPS LOUDLY rather than passing vacuously, and the frozen expected-outcome corpus is asserted regardless.
