Implement the Git branch SHORT-NAME validator: rules V1-V11 plus the standalone option-like invariant. V1 empty/whitespace-only; V2 begins with '-'; V3 is exactly '-' or all '-'; V4 begins/ends with '/' or contains '//'; V5 begins/ends with '.' or contains '..'; V6 contains an ASCII control char (\x00-\x1F, \x7F) or a space; V7 contains any of ~ ^ : ? * [ backslash; V8 ends with .lock or any /-delimited component ends with .lock; V9 any /-delimited component begins with '.'; V10 is exactly '@' or contains the sequence '@{'; V11 ends with '.'.

DO NOT implement or assert an identical accept/reject set against `git check-ref-format --branch`. The truthful relationship is a STRICT SUPERSET OF REJECTIONS with ONE enumerated divergence set D: (i) every value this validator ACCEPTS is also accepted by git; (ii) every value git REJECTS is also rejected here; (iii) D contains EXACTLY TWO SHAPES and nothing else - (1) the bare @, which git check-ref-format --branch accepts and echoes back, and (2) @{-N} for N >= 1 that actually RESOLVES in the invoking repository. Both are deliberately rejected here under V10, because a context-dependent revision expression evaluated against the reflog is not a durable branch identity and a gate that persisted it into an expected-branch list would record an expectation whose meaning changes with checkout history. Normalization is explicitly NOT chosen; rejection is.

The WIDER @{...} family is a SHARED REJECTION, not a divergence, and must be asserted as such. Measured against git 2.55.0.windows.5: check-ref-format --branch first runs interpret_branch_name, which expands ONLY the @{-N} previous-checkout form, then runs check_refname_format, whose "cannot contain @{" rule rejects everything else. foo@{1}, main@{0}, a@{b}, @{u}, @{upstream}, foo@{upstream} and @{-0} therefore ALL EXIT 128, agreeing with V10. Do not implement or assert any wider @{...} divergence: doing so would make the superset assertion false in the direction it exists to guarantee.

Because @{-N} acceptance is repository-state-dependent, the @{-N} arm of the corpus MUST run inside a HERMETIC FIXTURE REPOSITORY whose scripted checkout history makes specific N values known-resolvable, and must probe only those values there. Probing @{-N} against the ambient repository reflog is PROHIBITED: the result would depend on the checkout history of whoever runs the suite. Unresolvable @{-N} values are asserted as shared rejections.

The equivalence corpus asserts (i), (ii), and the exact membership of D in both directions, and fails on any value that diverges outside D. Separately, V2/V3 option-like rejection is asserted as its OWN invariant, not derived from git's behaviour, because `git check-ref-format --branch` cannot unambiguously receive a leading-hyphen argument at all. Where the local git binary is unavailable the corpus SKIPS LOUDLY rather than passing vacuously, and the frozen expected-outcome corpus is asserted regardless.
