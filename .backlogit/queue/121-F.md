Implementation plan for Plan 2 V1, grounded in docs/design-docs/2026-08-09-deferred-gradio-devtunnel-remote-control-plan.md and Plan 1 event/journal seams (119.004-T, 119.005-T, 120.008-T). Deliver one combined remote Observe + Steer surface over the local Copilot supervisor: status, phase, progress, redacted output stream, journal tail, pause, resume, cancel, and request-checkpoint. Preserve local authority with loopback-only binding, a closed structured command vocabulary, no raw/general-purpose component exposure, local journal as sole source of truth, stateless remote clients, and clear failure when devtunnel is unavailable. Q3 is explicitly devtunnel authenticated access control alone for V1; application-layer identity verification is a future follow-up and must not be silently added. Approve and Privileged tiers remain local-only and browser terminal streaming is permanently out of scope. Plan 2 is independent of Plan 1 and must not be added to the Plan 1 dependency graph.

<!-- BEGIN:dod -->
- Implementation spike resolves the framework within the Q1 non-negotiables.
- Plan 1 event/journal contracts are mapped as integration seams without changing Plan 1.
- Observe data is redacted and journal-authoritative; clients are stateless.
- Steer commands are closed, structured, bounded, and idempotency/state-machine behavior is specified.
- Loopback-only binding and devtunnel lifecycle/teardown are specified.
- Devtunnel unavailability produces a clear prerequisite/configuration failure.
- Approve and Privileged remain local-only; browser terminal streaming remains permanently out of scope.
- P-006 hardening and plan-review pass before implementation tasks are harvested.

<!-- END:dod -->

<!-- BEGIN:goals -->
- Provide one bounded V1 implementation plan for Observe + Steer, not separate observe-only work.
- Select the UI framework only through an implementation spike, while enforcing loopback-only bind, closed structured commands, and no raw/general-purpose component exposure.
- Reuse Plan 1 event and journal seams without creating a second remote retention store.
- Preserve the four-tier Observe/Steer/Approve/Privileged taxonomy while exposing only Observe and Steer remotely in V1.
- Treat devtunnel-only authentication as the accepted V1 security decision and record application-layer verification as future work.

Scope: status, phase, progress, redacted output stream, journal tail, pause/resume/cancel/request-checkpoint.
Excluded: remote approvals, remote privileged actions, browser terminal streaming, corporate-network fallback/preflight, separate remote retention, arbitrary command execution, and any new agent reasoning loop.
