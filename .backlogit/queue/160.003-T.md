GENERATED OUTPUT ROOTS ARE A SEPARATE KEY FROM INCLUDE/EXCLUDE (plan AC3d). The manifest declares `generated_output_roots`, naming per channel the directory the resolved payload is MATERIALIZED INTO. For the plugin channel that is `plugin-payload/`.

  `plugin-payload/**` IS DECLARED IN `generated_output_roots` AND IS NOT AN `include` RULE IN ANY CHANNEL. This is a correction of a real defect, not a re-wording. Classifying it as "INCLUDE in the plugin channel" makes the plugin generator's own output part of its next run's INPUT: run two resolves `plugin-payload/**` as source and writes it INSIDE `plugin-payload/`, producing `plugin-payload/plugin-payload/...`; run three nests again. `generate --check` then reports drift that regenerating can NEVER clear, because every regeneration deepens the tree - PERMANENT DRIFT failing the release gate on every subsequent run. Prose saying the tree is "excluded from itself" cannot fix an `include` rule that says otherwise; the manifest must express the distinction STRUCTURALLY.

  BINDING SEMANTICS THIS MANIFEST MUST ENCODE:
  1. Paths under a declared output root are REMOVED FROM THE TRACKED-PATH ENUMERATION BEFORE any classification runs. They are therefore NEITHER classified NOR unclassified, so AC2's unclassified-path build failure is NOT triggered by generated content, and the generator can never read its own output.
  2. The removal is UNCONDITIONAL AND APPLIES TO ALL THREE CHANNELS. That is also what keeps the tree out of the wheel and the sdist - it is a derived duplicate of payload content, not source. No separate wheel/sdist exclude rule is needed or permitted for it.
  3. EXCLUSION FROM CLASSIFIER INPUT IS NOT EXCLUSION FROM PUBLICATION. `plugin-payload/` remains TRACKED and COMMITTED and remains the directory `marketplace.json`'s `source` points at (AC3c). Input role and output role are independent properties of the same path; conflating them is exactly what produced the defective classification.
  4. The plugin channel's payload is the resolved SOURCE file set written into the output root. A channel whose resolved source set is empty produces an EMPTY output root; it never falls back to shipping whatever the output root already contains.
  PROHIBITED: adding `plugin-payload/**` (or any declared output root) to an `include` rule in any channel; relying on rule ORDERING to make an exclusion "win"; or leaving the self-exclusion to the generator instead of the resolver - the latter would leave every other resolver consumer (the AC2 classification check, the size report, `--check`) still seeing the output tree as input.
  SPIKE DEPENDENCE: `plugin-payload/` exists only under spike branch (b) (160.002-T). Under branch (a) the `generated_output_roots` entry names a surface that is never materialized and the key is inert; under branch (c) the shipment halts to the operator before this classification is exercised.
  dist/** REMAINS A PLAIN EXCLUDE, NOT AN OUTPUT ROOT. dist/.gitignore contains `*`, so nothing under dist/ is tracked or present in a consumer checkout. A gitignored build-output directory is not a publishable `source` and is never a payload source.
