IMPLEMENTATION. Build the SINGLE ATOMIC PUBLIC ENTRYPOINT for the P-004 gate: run_p004_gate(shipment_id) in src/autoharness/gates/p004.py, exposed as the CLI surface autoharness gate p004 --shipment &lt;id&gt; [--json] in src/autoharness/cli.py. ONE BOUNDARY OWNS THE WHOLE SEQUENCE: load the shipment-scoped declaration, validate it, load the declared names, run them under P004Result (including addSubTest), compare declared against observed by exact set equality, emit the thirteen gate tokens with their structured subjects, and serialize a P004GateResult. There is NO partial entry: no caller may load without validating, run without P004Result, or compare without the declaration. NO BYPASS: a bare `python -m unittest <ids>` invocation produces NO P004GateResult and therefore does NOT satisfy P-004. That is stated normatively in the policy text (168.002-T/168.003-T) and asserted end-to-end in the GREEN task (168.008-T). Vanilla unittest output is not a gate observation, because merged runner output cannot attribute an outcome to a declared test_id. P004GateResult JSON carries: shipment_id, manifest_digest, gate_result (PASS or FAIL), tokens[] where each token names its structured subject (TestSubject with test_id, CollectionSubject, EntrySubject with entry_index, or DocumentSubject), declared_expected_red[], declared_expected_green_characterization[], observed[], and the per-test outcome table. AGENT-FACING PARITY: where terminal execution is unavailable, the equivalent agent-facing contract is a P004_GATE_REQUEST block carrying the same inputs and returning the same P004GateResult JSON shape, so an agent surface and a terminal surface cannot diverge.
