BLOCKING SPIKE (plan-review finding P0-1). Establish how the Copilot plugin channel payload can actually be constrained before any plugin wiring begins.

The plan assumes the plugin payload can be trimmed, but the only observed mechanism is `.github/plugin/marketplace.json`'s `source: "."`, and no evidence establishes that Copilot CLI supports an exclusion or allowlist for plugin sources.

Determine which branch holds:
(a) marketplace source supports an exclusion/allowlist mechanism -> wire directly in the plugin-channel task (160.007-T); or
(b) it does not -> 160.007-T must instead BUILD a payload directory (dist/plugin/) from the manifest and repoint `source` at it, which changes that task's shape and adds a build step.

ACCEPTANCE: documented finding naming the mechanism, with evidence (Copilot CLI plugin docs/behavior), and a decision recorded for branch (a) or (b). NO SOURCE CHANGES.

BRANCH (b) CONSEQUENCES THE SPIKE MUST RECORD IF IT SELECTS (b): dist/plugin/** must be classified EXCLUDE in the manifest (160.003-T) and gitignored; the materialization step must invoke the single generation command from 160.004-T rather than reimplementing resolution; and the AC2b release-path gate (160.006-T) must cover the plugin channel via `generate --channel all --check`.

BLOCKS: 160.007-T must not begin until this resolves. Proceeding on assumption (a) without evidence risks discovering mid-implementation that the plugin half of the feature is infeasible as written.

This task IS the de-risking step for its own high complexity.
