Adds a crash-resumption + context-pruning-on-restore protocol as autoharness PRODUCT-TEMPLATE ORCHESTRATION PROSE driving the EXISTING backlogit-checkpoint + agent-engram substrate. No external binary changes; no runtime engine; single-active preserved.

IMPL-PLAN (source of truth = spike 002-SP):
- Orchestrator agent template: crash-resumption protocol — at session start enumerate ACTIVE/unresolved recovery candidates (backlogit list_checkpoints status=active). ZERO-CANDIDATE CASE: if NO active recovery candidate exists there is nothing to recover and normal orchestration CONTINUES (NOT a failure, NOT an operator handoff). ONLY WHEN one or more valid recovery candidates exist does the contract engage: MORE THAN ONE checkpoint may be active concurrently across agents (a `stage`-owned and a `ship`-owned checkpoint can both be active), so the Orchestrator REQUIRES EXPLICIT OPERATOR SELECTION of a SINGLE checkpoint by filename (NO auto-pick), then VALIDATES the selected checkpoint's CheckpointV1 `agent` ownership (`required,oneof=ship stage`) and ROUTES restore/resume/prune EXCLUSIVELY to that owning agent (stage-owned => Stage subagent only; ship-owned => Ship subagent only) — the Orchestrator NEVER executes Stage/Ship-owned restore/resume/prune work itself directly (P-001 role separation). FAIL CLOSED (AMONG EXISTING CANDIDATES only; zero candidates is the no-recovery-needed continuation, never a fail-closed trigger) on a non-unique selection or missing/invalid/ambiguous `agent` ownership => operator handoff, no restore. -> classify a POTENTIALLY-interrupted session -> REQUIRE EXPLICIT OPERATOR CONFIRMATION before ANY restore/prune (NO automatic resume; NO dead-session auto-recovery — checkpoint schema V1 has no heartbeat/session-lock/lease and only created_at/updated_at, so age alone cannot prove a session dead, and 002-SP excluded new checkpoint-schema/runtime plumbing) -> ONLY on operator confirmation restore recorded state_dump (get_checkpoint) and resume the recorded SINGLE-ACTIVE cursor, else operator handoff on any ambiguity/torn state -> resolve_checkpoint ONLY after confirmed successful resume.
- Supporting checkpoint-recovery / prune-on-restore protocol authored as a section in the backlogit capability-pack overlay instruction template (`templates/instructions/backlogit.instructions.md.tmpl`): bounded read-select-summarize over restored checkpoint/engram state; drop superseded action-observation history; ties to existing context-efficiency instruction / P-020 substrate. Because that overlay is NOT currently installed in the dogfood/self-install workspace (no manifest artifact, no `.github/instructions/backlogit.instructions.md`), a SEPARATE install/tune task (111.005-T) adds install-harness + tune-harness wiring to install it to `.github/instructions/backlogit.instructions.md` whenever the backlogit pack is active and to record it as a STANDARD FIRST-PARTY manifest artifact with a SINGLE `artifacts[].checksum` (the same contract used by the agent-engram/agent-intercom/graphtor-docs overlays) — NOT the community-template installed_checksum/source_checksum pair. Verification (111.003-T) is targeted SECTION-PRESENCE + standard artifact-checksum coherence; NO installed-vs-source dual-checksum drift comparison (unsupported).
- OWNER AGENT PROTOCOLS (publication-review P1 2026-08-06, owner-agent recovery conflict): BOTH owner agent templates — the Stage agent template (`templates/agents/_stage.agent.md.tmpl`) AND the Ship agent template (`templates/agents/_ship.agent.md.tmpl`) — are updated (task C5/111.006-T) so each owner agent's OWN startup/recovery protocol adopts the fail-closed lifecycle: ZERO-CANDIDATE NORMAL STARTUP; EXPLICIT OPERATOR FILENAME SELECTION when its own candidates exist; CheckpointV1 `agent`-ownership validation against the agent's own role (Stage restores/resumes/prunes only `stage`-owned; Ship only `ship`-owned); OWNER-EXCLUSIVE restore/resume/prune after EXPLICIT OPERATOR CONFIRMATION; resolve_checkpoint ONLY after a CONFIRMED SUCCESSFUL owner resume; and FAIL CLOSED with NO FRESH-START FALLBACK on invalid/ambiguous/torn/malformed checkpoint reads. This REMOVES the pre-existing owner-template behaviors that fresh-start on an invalid checkpoint and resolve active checkpoints BEFORE a confirmed successful resume. This CHANGES the owner protocols themselves — NOT mere delegation to the Orchestrator routing in C1/111.001-T.
- Explicit degraded-mode fallbacks (backlogit/engram unreachable => NO auto-resume, operator handoff), mirroring Tool-Availability-Gate + ENGRAM_DEGRADED patterns.
