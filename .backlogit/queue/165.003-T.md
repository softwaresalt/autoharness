Add the read-only sequencing AUDIT phase that migrates workspaces off previously-implicit numeric sequencing (decision D3). This replaces the first-round "migrate the numeric test class" task; that test disposition moved INTO 165.002-T so it is atomic with the production change and no task ever ends red.

WHY THIS EXISTS: retiring numeric inference without an audit would leave operators unable to tell which of their edge-less shipments were relying on implicit sequencing. The audit is the migration contract — it replaces a silent default with an explicit, one-time, operator-driven reconciliation.

THIS PHASE IS A PURE READ-ONLY REPORT (review-fix cycle 3, finding 2 — this REPLACES the cycle-2 migration-ledger requirement; NARROWED in PR review-fix cycle 1, thread PRRT_kwDORzpWpM6h3Tgi). It computes from the workspace it reads and emits output. Every durable-ledger write, every future-remediation field, and every persistence claim from cycle 2 is REMOVED: the phase PERFORMS NO BACKLOG MUTATION of any kind (no item, feature, shipment, manifest, status, label, or dependency write) and PERFORMS NO MIGRATION-STATE OR LEDGER WRITE (no durable migration record, no persisted audit artifact, no state file, no new file format, no persistence subsystem in the gate). It owns no durable artifact.

ABSOLUTE "NO-WRITE" IS FALSE AND IS RETRACTED (PR review-fix cycle 1, thread PRRT_kwDORzpWpM6h3Tgi — finding ACCEPTED). The cycle-3 wording claimed the phase "WRITES NOTHING, PERSISTS NOTHING". That is not achievable and was never true of any `pipeline-topology` phase: `_gate_pipeline_topology_command` (src/autoharness/cli.py) calls `_emit_pipeline_topology_telemetry` UNCONDITIONALLY on EVERY run, which appends a structured tool-telemetry event to the workspace telemetry journal whenever telemetry is enabled in the workspace config. An `audit_sequencing` run will emit that event exactly like `pre_claim`, `post_claim`, `lifecycle`, and `ambient` do.

WHAT IS ALLOWED: the ORDINARY, PRE-EXISTING `pipeline-topology` telemetry emission, unchanged. It is OBSERVATIONAL ONLY and MUST REMAIN FAIL-OPEN — the existing `except Exception` handler returns a warning and never alters the gate's behaviour or exit code, and this task must not narrow, harden, or make load-bearing that fail-open contract. This phase adds NO new telemetry field, NO new journal, and NO new emission site; it simply inherits the emission every phase already performs. Telemetry is NOT a migration record and MUST NOT be read back by the audit or by anything else as authorization or state.

THE MIGRATION RECORD IS STILL THE VERSION-CONTROLLED COMMIT (unchanged): operators migrate by editing backlog records with ordinary backlogit commands, and those records are version-controlled. The resulting MIGRATION COMMITS AND THEIR DIFFS are the external migration record and the rollback evidence.

IMPLEMENTATION (src/autoharness/gates/topology.py):
1. Register a new phase `audit_sequencing` in `VALID_PHASES` (L31) ONLY. Do NOT add it to `SCOPED_PHASES` (L32) and do NOT give it a phase status requirement: the audit is workspace-wide, not target-scoped. LEARNING APPLIED (docs/compound/2026-08-18-lifecycle-gate-must-precede-safe-close-mutation.md): phase status preconditions carry ordering meaning; a new phase must not disturb the `lifecycle` phase's active-target invariant.
2. The phase is READ-ONLY, NON-AUTHORIZING, and NEVER BLOCKS. It cannot authorize a claim and cannot fail a gate.
3. For every EDGE-LESS shipment report: its derived state (`declared_root` / `genesis` / `unsequenced`), the RAW numerically-adjacent candidate the retired heuristic WOULD have inferred, and the REMEDIATION OPTIONS AVAILABLE (record the real `blocks` edge, or declare the shipment a root). Where the state is `unsequenced`, also report WHICH genesis disqualifier applied (G2 archived/live shipped history, G3 a second extant nonterminal shipment, G4 an abandoned record), so the operator can see why a workspace that has never shipped is nevertheless not genesis.
   DO NOT record "the remediation the operator chose". That decision has NOT HAPPENED at audit time, so the field could only ever hold a guess or an empty slot. Report the options; do not claim an outcome.
4. Re-home `_prior_shipment_id` (L1433-1469) as this report's ONLY consumer. It is never a claim input again.

MANDATORY — DO NOT INHERIT THE SUPPRESSION PREDICATE (hardening F6): the audit must report the RAW numeric-adjacency candidate WITHOUT the reverse-dependency suppression logic at L1458. That predicate is the source of all three recorded defect cycles and of the non-uniform silent fail-open; in an ADVISORY report it would silently HIDE candidates the operator needs to see.

FLIP THE INHERITED STRICT-XFAIL AUDIT EXPECTATIONS (review-fix cycle 2, finding 6 — MANDATORY, NOT OPTIONAL). 165.002-T re-expresses the historical `ImplicitNumericPredecessorTests` directional cases as RAW numeric-candidate expectations over THIS audit surface's OUTPUT, written there as STRICT expected-failure because the surface does not yet exist. THIS TASK FLIPS THEM to ordinary passing assertions. They are the durable form of the retired heuristic's encoded knowledge, and they are stated as the NEGATION of suppression:
- the no-declared-reverse-dependency fixture yields a reported raw candidate;
- the unrelated-dependencies fixture yields a reported raw candidate;
- the MULTI-HOP reverse-dependency fixture — where suppression would have hidden the candidate entirely — STILL yields a reported raw candidate;
- the higher-numbered forward-dependent fixture still yields a reported raw candidate.
If any of these cannot be flipped green, the audit has inherited the suppression predicate and this task is NOT done. Note that `_prior_shipment_id` retains its suppression logic internally; this task must consume the RAW adjacency computation, not the suppressed result — extract or bypass as needed, but do not pin the suppressed behaviour as an expectation anywhere.

NO LEDGER, NO PERSISTENCE SUBSYSTEM (review-fix cycle 3, finding 2). Cycle 2 required a "durable, machine-readable, append-only MIGRATION LEDGER". That requirement is WITHDRAWN IN FULL. Building it would have given a phase whose DEFINING PROPERTY is that it does not mutate its OWN WRITE PATH and its OWN durable file format, and would have created a SECOND SOURCE OF TRUTH about backlog state that can itself drift from the backlog it describes — the same producer/consumer drift class this feature exists to remove, reintroduced one level up.
THE MIGRATION RECORD ALREADY EXISTS AND NEEDS NO INVENTION: operators migrate by editing backlog records with ordinary backlogit commands, and those records are VERSION-CONTROLLED. The resulting MIGRATION COMMITS AND THEIR DIFFS are the external migration record and the rollback evidence — durable, reviewable, attributable, reversible by ordinary git operations, and already trusted for every other change in the repository. The audit does not duplicate a record git already keeps. Rollback ordering is documented in 165.009-T.

TESTS: audit output per state; the disqualifier reporting in item 3; raw-candidate reporting under the suppression configuration (the flipped expectations above); the audit never blocks and never authorizes; adding the phase does not alter `lifecycle`/`pre_claim`/`post_claim`/`ambient` behaviour.

NO-MUTATION TESTS — SCOPED, NOT ABSOLUTE (PR review-fix cycle 1, thread PRRT_kwDORzpWpM6h3Tgi). Assert that an `audit_sequencing` run performs NO BACKLOG MUTATION and NO MIGRATION-STATE/LEDGER WRITE:
- no `.backlogit/` (or configured backlog root) file is created, modified, or deleted — queue, archive, manifests, and index alike;
- no item status, label, dependency, or shipment manifest changes across the run;
- no migration-state, ledger, or persisted-audit artifact is created anywhere;
- the audit's output is a function of the workspace it read, with no read-back of anything it wrote.
DO NOT ASSERT "zero filesystem writes" or "no file is created or modified by an audit run". That assertion is FALSE by construction — the unconditional `pipeline-topology` telemetry emission appends to the telemetry journal on every run when telemetry is enabled — and a test encoding it would fail on a telemetry-enabled workspace or, worse, drive an implementer to suppress telemetry for this phase and break parity with every other phase. Instead: with telemetry ENABLED, assert the telemetry event IS emitted and that the audit output and exit code are IDENTICAL to a telemetry-disabled run; and assert a telemetry failure during an audit run changes neither output nor exit code (fail-open preserved).
