=== DURABLE, REBUILDABLE BASELINE EVIDENCE (BINDING; ADDED IN REVIEW-FIX CYCLE 5, FINDING 11) ===

The baseline is CONSUMED BY the CHARACTERIZATION half of the shipment - principally T3b and 160.016-T - LONG AFTER this task runs, on a tree that has since changed. A baseline pinned to "the current HEAD" or to "the wheel I built" is therefore not a baseline at all: HEAD moves, and an unrecorded build is unreproducible. NO WHEEL OR PLUGIN BINARY IS COMMITTED - committing build artifacts is forbidden. What is committed is the EVIDENCE THAT LETS ANY LATER RUN REBUILD AND COMPARE:

  (E1) MEMBER INVENTORIES WITH PER-MEMBER HASHES. For BOTH the wheel and the resolved plugin payload, record for EVERY member: the archive-relative path, the byte size, and the SHA-256 of the member's content. Record ALSO an AGGREGATE DIGEST, computed with the PLAN'S SINGLE CANONICAL DEFINITION AND NO OTHER (cycle 8, item 10): SHA-256 over the newline-joined, PATH-LEXICOGRAPHICALLY-SORTED `(path, size, sha256)` TRIPLES, with an ASCII unit separator (U+001F) between the three fields of a triple, and paths normalized to forward slashes and encoded UTF-8. SIZE IS PART OF THE DIGEST INPUT, not merely a recorded column. This is the ONLY aggregate-digest contract in this shipment; every consumer - 160.012-T's baseline reconciliation and 160.017-T's `artifact_ref` - recomputes it EXACTLY THIS WAY, so a single value proves whole-inventory equality and a mismatch can be localized to the differing member rather than reported as an opaque "baseline changed". NO VARIANT FORM (path-only, path+hash, unsorted, differently separated) MAY BE INTRODUCED ANYWHERE.

  (E2) THE EXACT IMMUTABLE SOURCE COMMIT. Record the FULL 40-CHARACTER COMMIT SHA the baseline was built from, plus the branch name and any tag, and state explicitly that the SHA - not the branch, not "HEAD" - is the authoritative reference. A branch name is a MUTABLE POINTER; a consumer resolving it later gets a different tree and a false mismatch, which is worse than no baseline because it fails loudly for the wrong reason. Every downstream assertion cites the SHA.

  (E3) A DETERMINISTIC REBUILD RECIPE - THIS TASK'S OWN REPRODUCIBILITY RECORD ONLY. Record the EXACT command line that produced each artifact (build backend and version, front-end command and version, target name, output directory) in a form that can be copy-executed, together with the ENVIRONMENT DIMENSIONS that can legitimately change the output: Python interpreter version and implementation, operating system and architecture, locale/encoding, source-date/timestamp handling, and the resolved versions of the build backend and any build dependency. A later consumer that reproduces a DIFFERENT inventory must be able to tell "the payload changed" from "I built it on a different interpreter" - without the recorded dimensions those two are indistinguishable and every diff becomes unactionable. E3 IS A RECORDED FACT, NOT AN EXECUTABLE INPUT TO ANOTHER TASK. THREE EARLIER FORMULATIONS ARE WITHDRAWN AND MUST NOT BE REINTRODUCED: (a) E3 is NOT the input to any hermetic upgrade case - the "HERMETIC UPGRADE CASE (cycle 7)" was withdrawn in full; (b) NO baseline wheel is rebuilt here or anywhere as an input to 160.012-T (T10) - T10 consumes E1/E2/E3 as RECORDED FACTS and performs no baseline rebuild; (c) NO OS temporary directory is used - `tempfile.TemporaryDirectory()` and every equivalent OS-temp API are PROHIBITED for generated, test, and upgrade scratch alike, and the only permitted scratch root is the single workspace-contained `dist/.autoharness-scratch/<run-id>/`.
