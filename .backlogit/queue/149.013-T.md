Security tests for option-safe Git ref resolution: option-like refs, invalid refs, valid symbolic refs, and full-SHA pass-through, plus re-characterization of the existing discovery AND gate suites against U8b's new input contract. Domain: tests. Files: 3.

<!-- BEGIN:acceptance-criteria -->
* **The no-side-effect assertion is the gating one**: after a rejected `--output=<tmp>` base, the test asserts the would-be output file **does not exist**. Without this assertion the P0 argument-injection mitigation is unproven.
* Option-like refs produce the invalid-input exit class (exit 2), not a silent empty diff.
* Invalid refs are rejected with the same class; no `git diff` is invoked.
* Valid symbolic refs resolve to a full 40-char hex SHA.
* An already-full SHA resolves to itself, and `discover_modified_files` is shown to receive only validated hex SHAs.
* **The existing discovery suite is green under the new contract** (PR #414 cycle-2 correction, thread `PRRT_kwDORzpWpM6dVQdY`): `tests/test_gates_discovery.py` is updated so that the canonical Q5 gate passes. Specifically:
  * the three `discover_modified_files("main", "HEAD", ...)` call sites (lines **32, 40, 49**) pass **validated 40-hex SHAs** instead of symbolic refs;
  * the exact-argv assertion (line **45**) is updated to the new option-safe argv, including the `--end-of-options` / `--` separators;
  * the two graceful-degradation tests (not-a-repo, git-missing) still assert `[]` + a warning — that behaviour is deliberately **unchanged**, and this is asserted rather than assumed;
  * `parse_diff_output` tests are untouched — that function has no ref surface.
* **`tests/test_gates_gate.py` is reconciled (D-17, cycle-3 thread
  `PRRT_kwDORzpWpM6dVfzg`)** — bounded to **two** edits and **one** addition:
  * `test_check_uses_injected_discover` (line ~90) is re-characterized: the
    injected discover must be shown to receive **validated 40-hex SHAs**, not the
    raw `"main"`/`"HEAD"` text it pins today.
  * `test_check_no_gates_returns_empty_report` (line ~86) is asserted
    **unchanged** — a symbolic `base="main"` with `enabled=False` must still
    return an empty report **without** resolving, proving the early return
    precedes resolution.
  * **One new assertion**: `check()` with an unresolvable/option-like `base`
    rejects with the invalid-input class, invokes **no** `git diff`, and writes
    **no** file.
* **Symbolic-ref behaviour is characterized explicitly, not left implicit**: symbolic-ref resolution lives in `resolve_commit_ref` (scenario 3) and **not** in `discover_modified_files`, which now rejects any non-hex `base`/`head`. A test asserts that rejection so the boundary cannot silently regress.
* No network access.

<!-- BEGIN:description -->
Plan unit **U8c**. Create `tests/test_gate_ref_safety.py`; re-characterize `tests/test_gates_discovery.py` and `tests/test_gates_gate.py`.

**4 scenarios**:

1. **Option-like refs are rejected with no side effect** — `--output=<tmp>`, `--upload-pack=...`, and a leading-dash ref each resolve to `None`, produce the invalid-input exit class, and — asserted explicitly — leave **no file created at the would-be output path**.
2. **Invalid refs** (nonexistent branch, nonexistent SHA) are rejected with the invalid-input class and no `git diff` invocation.
3. **Valid symbolic refs** (`HEAD`, `HEAD~1`, a branch name, a tag) resolve to a full 40-char hex SHA.
4. **Full-SHA pass-through** — an already-full 40-hex SHA resolves to itself unchanged, and `discover_modified_files` receives only validated hex SHAs.

**Plus: existing-suite reconciliation** (not a fifth scenario -- a mechanical
update to an existing file, required because U8b changes the input contract of a
function that file already pins):

* Edit `tests/test_gates_discovery.py` to pass validated 40-hex SHAs and to
  assert the new option-safe argv, per the acceptance criteria above.
* Add one assertion that a **symbolic** ref passed directly to
  `discover_modified_files` is now rejected -- this is the characterization the
  cycle-2 review asked for.

**Depends on U8b.**

This suite is what makes the cycle-1 P0 disposition (thread `PRRT_kwDORzpWpM6dGx_a`) valid. Scenario 1's filesystem assertion is not decorative: the whole finding is that a read-only gate could be induced to **write a file**, so proving absence of that file is the actual proof of mitigation. Asserting only the exit code would leave the vulnerability untested.

**Why not folded into U11**: U11 already carries 4 scenarios (ART-01 fixture, RK1 retro-validation, --json exit-0-on-failed, --base honored). Adding 4 more would put 8 scenarios in one unit and breach both the plan's max-4-scenario granularity budget and the 2-hour rule.

Use a temp directory for the would-be output path so the test cannot pollute the repository even if the mitigation regresses.

**Why the existing-suite update lives here and not in U8b** (cycle-2, thread
`PRRT_kwDORzpWpM6dVQdY`): U8b is width-isolated to `src/autoharness/gates/discovery.py`
(code domain, Files: 1). `tests/test_gates_discovery.py` is a **test** artifact, so
folding it into U8b would breach width isolation. It belongs to the unit that already
owns the tests for this contract. Files rises 1 -> 2, still inside the plan's max-3-files
budget, and the scenario count stays at 4 -- the reconciliation is a mechanical
re-characterization of four existing assertions, not new test design, so the 2-hour rule
still holds at size S.

must land together (or U8c immediately after U8b within the same working session). The
