Stop defaulting quality-report metrics to "observed" when no quality label was ever recorded (source: stash 59E6CD50).

Files (2): src/autoharness/telemetry/report.py, tests/test_telemetry_reports.py

Current state: _quality (report.py:98-115) defaults worst to "observed" whenever worst is None, unless the metric field name is in _unavailable_metrics (report.py:51-60), which only flags fields whose VALUE is None/"unavailable" -- it does not distinguish "no quality label was ever attached" from "quality label was attached and is genuinely observed". This makes reports overstate confidence for metrics that were never quality-annotated.

TDD (red->green): add test_quality_reports_unknown_when_no_label_recorded to test_telemetry_reports.py constructing a metric history with zero quality-label entries, asserting _quality returns an explicit "unknown" (or equivalent unavailable) marker rather than "observed" (fails first). Then change _quality's None-handling: only default to "observed" when the metric has recorded numeric values but truly no quality entries were ever expected (i.e., preserve current behavior for fields already in _unavailable_metrics), and introduce a distinct "unknown" return value for the case where no quality label was ever recorded, propagated through the report renderer.

Acceptance criteria:
- Metrics with zero recorded quality labels report "unknown" (or equivalent), not "observed".
- Metrics with at least one real "observed" quality label continue to report "observed".
- Existing _unavailable_metrics-driven behavior for None/"unavailable" values is unchanged.
