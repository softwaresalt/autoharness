Encode the PR-body concision contract (design decision D5 -- the direct answer to the operator's opening sentence, "I don't need a ten point checklist in the PR body") across templates/skills/pr-lifecycle/SKILL.md.tmpl + .github/skills/pr-lifecycle/SKILL.md and templates/instructions/pull-request.instructions.md.tmpl + .github/instructions/pull-request.instructions.md.

CONTRACT: a PR body carries ONLY (a) the audit verdict, (b) a pointer to the committed audit evidence record, and (c) any deferred follow-up IDs. The verbose category list NEVER appears in a PR body.

EXPLICIT PROHIBITION REQUIRED (hardening finding H5): state the prohibition affirmatively rather than merely omitting the checklist. PR #440 pasted the ten-point checklist into its PR body precisely because nothing forbade it; an omission does not prevent recurrence, only a stated rule does.

ALSO WIRE D6: the PR body is a MUTABLE surface and therefore the correct owner of CURRENT-HEAD readiness claims, whereas committed evidence records only immutable last-code-affecting or explicitly named observed state. This split is what prevents the PR #439 self-referential reviewed_head fixed-point loop from recurring.
