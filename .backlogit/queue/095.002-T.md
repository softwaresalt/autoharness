<!-- BEGIN:description -->
Add size-based rollover on write: when the active segment would exceed the configured max_segment_bytes, seal it to a monotonically-named, sortable segment file (e.g. execution_epochs.jsonl.N) colocated with the active file and start a fresh active segment. Rollover MUST be race-tolerant and non-raising: under concurrent writers, a rename race (target already sealed, or source already rotated by another writer) must not corrupt data or raise -- the writer re-resolves the current active segment and appends there. Default max_segment_bytes is large enough that the existing suite never rolls. Depends on 095.001-T (cross-segment replay). Files: src/autoharness/telemetry/jsonl_sink.py, tests/test_telemetry_jsonl_sink.py. <=3 files, <=5 functions, <=4 test scenarios. TDD.
<!-- END:description -->

<!-- BEGIN:acceptance-criteria -->
With a low test threshold, appending past max_segment_bytes rolls over: the prior active segment is sealed under a monotonic name and a fresh active segment is created. With the default (high) threshold, the existing small-scale writes stay single-file and existing behavior is preserved. Concurrent writers rolling over simultaneously neither corrupt data nor raise; every appended line lands intact as valid JSON in the current active segment after rollover. Cross-segment replay from 095.001-T continues to hold after a rollover.
