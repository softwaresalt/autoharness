<!-- BEGIN:description -->
Add size-based rollover on write under the sink's single-writer-per-path contract. When the active segment reaches _MAX_SEGMENT_BYTES (module constant), seal it by renaming to max(existing sealed generation)+1 (execution_epochs.jsonl.NNNNN) -- a name that does not already exist, so the rename never clobbers a sealed segment -- then create a fresh active segment. An oversized single record (encoded line > threshold) is still written INTACT as one line to its own segment (never split). Writer model (PR #249 round 2, DEFINITIVE -- Option B): the production caller (eval/runner.py run_matrix) drives telemetry sequentially in one process, so the sink is single-writer-per-path; sealed segments are immutable BY CONSTRUCTION -- the writer per-epoch sequence is preflight -> [rename active -> gen N, create fresh active, prune] -> append, and each append is a synchronous open(O_APPEND)->write->close with no handle held across the rename, so the writer never appends to a segment after sealing it. No interprocess lock is needed and none is added. Concurrent multi-PROCESS writers to the same path are explicitly OUT OF CONTRACT. Atomic single-line append is retained as defense-in-depth (an accidental duplicate line is reconciled on read), NOT elevated to a rollover guarantee. Default _MAX_SEGMENT_BYTES is large enough that the existing suite never rolls; tests patch the constant to a low value. Depends on 095.001-T. Files: src/autoharness/telemetry/jsonl_sink.py, tests/test_telemetry_jsonl_sink.py. <=3 files, <=5 functions, <=4 test scenarios. TDD.
<!-- END:description -->

<!-- BEGIN:acceptance-criteria -->
With a patched low threshold, appending past _MAX_SEGMENT_BYTES rolls over: the prior active segment is sealed under the next generation name (max existing sealed generation + 1) and a fresh active segment is created. The next-generation name never targets an existing sealed segment (no-clobber by construction). With the default (high) threshold, existing small-scale writes stay single-segment and existing behavior is preserved, including the existing multi-thread line-integrity test. Sealed-segment immutability holds: after a rollover, subsequent appends target only the new active segment and the sealed segment bytes are unchanged. An oversized single record larger than the threshold is written intact to its own segment. Cross-segment replay from 095.001-T continues to hold after a rollover. No concurrent-multi-process-writer rollover behavior is claimed or tested (out of contract).
