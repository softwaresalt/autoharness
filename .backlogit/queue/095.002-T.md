<!-- BEGIN:description -->
Add size-based rollover on write with a scoped, tested concurrency guarantee. When the active segment reaches _MAX_SEGMENT_BYTES (module constant), seal it by renaming to the next generation (execution_epochs.jsonl.NNNNN) and create a fresh active segment. An oversized single record (encoded line > threshold) is still written INTACT as one line to its own segment (never split). Rollover MUST be race-tolerant and non-raising: on rename contention (generation already sealed by another writer, or source already rotated) it must not corrupt data or raise -- the writer re-resolves the current active segment and appends there. Encode and test the ACTUAL guarantee (do not over-claim losslessness): every append is one atomic intact line; an in-flight append racing a rollover lands intact in the just-sealed OR the fresh active segment. Default _MAX_SEGMENT_BYTES is large enough that the existing suite never rolls; tests patch the constant to a low value. Depends on 095.001-T. Files: src/autoharness/telemetry/jsonl_sink.py, tests/test_telemetry_jsonl_sink.py. <=3 files, <=5 functions, <=4 test scenarios. TDD.
<!-- END:description -->

<!-- BEGIN:acceptance-criteria -->
With a patched low threshold, appending past _MAX_SEGMENT_BYTES rolls over: the prior active segment is sealed under the next generation name and a fresh active segment is created. With the default (high) threshold, existing small-scale writes stay single-file and existing behavior is preserved. Concurrent writers rolling over simultaneously neither corrupt data nor raise; every produced line is valid, complete JSON and lands intact in either the sealed or the fresh active segment (none lost while retained). An oversized single record larger than the threshold is written intact to its own segment. Cross-segment replay from 095.001-T continues to hold after a rollover.
