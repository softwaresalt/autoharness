Makes the workspace shipment record the single authoritative source for the implementation branch, with a validated TWO-RUNG precedence ladder (explicit_contract then title_alias, no third rung) and a branch-name validator implementing V1-V11 plus a standalone option-like invariant that rejects leading-hyphen and option-shaped values.

RELATIONSHIP TO git check-ref-format --branch (truthful, and NOT an identity claim): a STRICT SUPERSET OF REJECTIONS with ONE enumerated divergence set D containing EXACTLY TWO SHAPES. (i) Every value this validator ACCEPTS is also accepted by git. (ii) Every value git REJECTS is also rejected here. (iii) D = { the bare @ } union { @{-N} for N >= 1 that actually RESOLVES in the invoking repository } - these two, and only these two, are accepted by git and deliberately rejected here under V10, because a context-dependent revision expression evaluated against the reflog is not a durable branch identity and a gate that persisted it would record an expectation whose meaning changes with checkout history. Normalization was considered and explicitly NOT chosen.

The WIDER @{...} family is a SHARED REJECTION, never a divergence: git check-ref-format --branch runs interpret_branch_name, which expands ONLY the @{-N} previous-checkout form, and then check_refname_format, whose "cannot contain @{" rule rejects everything else. foo@{1}, main@{0}, a@{b}, @{u}, @{upstream}, foo@{upstream} and @{-0} all exit 128, agreeing with V10. Classifying them as divergences would make the superset assertion false in the direction it is supposed to guarantee.

Because @{-N} resolution is repository-state-dependent, its divergence arm MUST be asserted inside a HERMETIC FIXTURE REPOSITORY with a scripted checkout history making specific N values known-resolvable. Probing @{-N} against the ambient repository reflog is PROHIBITED.
