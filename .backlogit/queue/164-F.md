Promote the ten-category documentation consistency audit from an ephemeral PR-body checklist into a durable, technology-agnostic harness capability applied on EVERY shipment in EVERY installed workspace. Operator intake (stash 8F2FD1F6, 2026-09-09, verbatim): "I don't need a ten point checklist in the PR body, I need it as a compound learning that gets applied by the harness on every shipment regardless of workspace in which the harness is installed." Motivated by PR #440 (checklist recorded in the PR body then deleted before merge) and PR #439 (self-referential reviewed_head fixed-point loop).

KEY CONSTRAINT (verified 2026-09-09): no mechanism propagates docs/compound/ content into an installed workspace -- templates/skills/compound/ authors only into the target's own initially-empty docs/compound/. The requirement therefore splits across two vectors: MEMORY (docs/compound/, this repo only, records why the audit exists) and BEHAVIOUR (normative template surfaces, every workspace, carries the audit itself). Conflating them yields a plan that cannot deliver.

INSTALLS: (1) one normative technology-agnostic instruction template shipment-documentation-audit.instructions.md.tmpl as the SINGLE SOURCE OF TRUTH for the ten categories, plus its dogfood mirror; (2) in-place consolidation of the existing compound taxonomy learning (categories 5/6/8/9 folded in, PR #439/#440 evidence added, delivery-paradox recorded) rather than a competing entry; (3) universalized Evidence Consistency Reviewer persona trigger (conditional/dogfood-path -> every-shipment/technology-agnostic); (4) Ship agent pre-readiness audit weave with P-021 routing; (5) pr-lifecycle + pull-request PR-body concision contract (verdict + evidence pointer + deferred follow-up IDs only, checklist explicitly prohibited); (6) operational-closure weave; (7) dogfood mirror parity and harness manifest checksum refresh; (8) deterministic verification across three target technology profiles.

TEN CATEGORIES: 1 lifecycle/temporal; 2 status consistency across frontmatter/headings/conditions/summaries/follow-ups/verdicts; 3 immutable evidence semantics (last_code_affecting_head vs current PR HEAD, no self-referential SHA claims); 4 PR/commit/branch/task/shipment identity; 5 quantitative consistency (NEW); 6 ownership/role attribution (NEW); 7 path/cross-reference integrity incl. moved/archived/compacted files and relocation stubs; 8 scope/distribution wording (NEW); 9 frontmatter schema consistency with canonical NEIGHBOURING artifacts (NEW); 10 stale TODO/pending/conditional language after conditions are satisfied.

RELATIONSHIP TO 162-F / 170-S (CRITICAL, NOT A DUPLICATE): 170-S already builds a CONDITIONAL Evidence Consistency Reviewer persona with a 10-point branch-tree-only rubric (162.004-T), review-skill Step 1.5 retrieval, mechanical delta checks, and dogfood parity tests. This feature is the UNIVERSALIZATION + COMPLETION layer strictly ON TOP of that substrate and is sequenced BEHIND 170-S. It MUST NOT re-author the persona, re-open 170-S's PASS plan-review verdict, or restate its rubric. Overlapping-surface collision (Ship agent, review persona, pr-lifecycle) is the primary execution risk; tasks touching those surfaces must re-read them as 170-S actually left them rather than as the plan predicts.

DESIGN DECISIONS: D1 categories authored once, all other surfaces reference and never restate (restating manufactures the cross-surface drift the audit exists to catch); D2 audit obligation unconditional per shipment with an explicit "no documentation surface touched" outcome still recorded; D3 technology-agnostic predicates only; D4 consolidate the compound learning in place; D5 PR bodies carry outcome only; D6 anti-self-referential readiness -- mutable PR body/external gates own current-HEAD readiness while committed evidence records only immutable last-code-affecting or named observed state; D7 P-021 integration (in-scope fixed before readiness, out-of-scope captured before disposition); D8 no new template variables, verified negatively.
