CHANNEL RESOLVER CONTRACT TESTS. Split out of 160.008-T in Orchestrator review-fix cycle 1 (finding 7 sizing, finding 5 channel contradiction). This task owns the two SEPARATE resolver contracts that AC6 previously conflated into a single "all three install methods" claim.

WHY THE OLD AC6 WAS WRONG: AC6 required Python `_DATA_DIR` resolution to work for pip, clone AND plugin. The plugin channel EXCLUDES `src/` and `pyproject.toml`, so a plugin-only install has NO Python package and therefore NO `_DATA_DIR` at all. The old criterion demanded a Python resolver in a channel that by construction has no Python. The contracts are now split.

CONTRACT A - PYTHON-CHANNEL RESOLVER (AC6a). Applies to the PIP and CLONE/EDITABLE install methods ONLY, i.e. exactly the environments where the `autoharness` Python distribution is importable.
- test_data_dir_resolution_pip_install - `_DATA_DIR` (cli.py:14-21) resolves `templates/` and `schemas/` from the installed wheel's packaged data directory.
- test_data_dir_resolution_clone_editable - the clone/editable fallback to repo root resolves `templates/` and `schemas/`.
- NEGATIVE ASSERTION A1: the Python-channel contract MUST NOT require any plugin-root artifact. Assert resolution succeeds with `plugin.json` and `.github/plugin/marketplace.json` absent from the environment.
- The `_DATA_DIR` resolution ORDER is invariant I1/I2 and is OBSERVED here, never modified (freeze-scope).

CONTRACT B - PLUGIN-ROOT RESOLVER (AC6b). Applies to the PLUGIN channel ONLY: no Python CLI on PATH, no `src/`, no `pyproject.toml` in the payload.
- test_plugin_root_resolves_templates_and_schemas - `templates/` and `schemas/` resolve relative to the INSTALLED PLUGIN ROOT (the directory the marketplace payload materializes), with no Python import involved.
- test_plugin_version_resolves_from_plugin_manifest - version resolves from `plugin.json` / `.github/plugin/marketplace.json` per AC10, not from `pyproject.toml` or `src/autoharness/__init__.py`.
- NEGATIVE ASSERTION B1: assert NO import of the `autoharness` Python package occurs on this path, and that the contract holds with no Python interpreter-visible `autoharness` distribution installed.
- NEGATIVE ASSERTION B2: assert `src/`, `pyproject.toml`, and any `_DATA_DIR`-bearing package are ABSENT from the resolved plugin payload. Their presence is a payload-composition regression, not a convenience.

CONTRACT DISJOINTNESS (mandatory): a single test must assert that the two contracts are DISJOINT by channel - no environment is expected to satisfy both, and neither contract is a fallback for the other. This is the assertion that prevents AC6a and AC6b silently re-merging into the old contradictory single claim.

SCOPE BOUNDARY: install-time payload boundary assertions are 160.008-T; upgrade/parity is 160.012-T; the registration support matrix is 160.009-T. This task covers RESOLUTION ONLY.

Test fixtures create isolated environments under a gitignored temporary path and MUST NOT mutate the developer's installed interpreter, the real `~/.autoharness/`, or any tracked file. NO-PUBLISH.
