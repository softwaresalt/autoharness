P-021 C5
Name the archive operation as the allowed, manifest-derived post-merge Step 7 retirement.

H2 (P1) DRAFTING HAZARD — READ BEFORE EDITING
C5 deliberately names removal AND archival as SEPARATELY prohibited DISCRETIONARY dispositions, because archival also takes a Stage-owned deferred entry out of Stage's triage queue; a prohibition naming only removal would leave the same loss reachable by another verb. After this rename the clause will say the ALLOWED exception is archival AND that DISCRETIONARY archival is prohibited. That is correct and intended, but it reads as tension and will invite a "simplifying" edit that deletes the discretionary prohibition. DO NOT SIMPLIFY.
- The DISCRETIONARY qualifier must remain attached to BOTH verbs.
- The manifest-derived exception must remain explicitly scoped to the post-merge Step 7 path.
- A reviewer proposing removal of the archival prohibition is to be refused with a pointer to hardening section H2.

BACKLOG REGISTRY
Keep the stash_remove mapping PRESENT but marked deprecated; ensure stash_archive is the operation THIS REGISTRY resolves to for the Ship post-merge stash-retirement path, expressed as MCP primary backlogit_stash_archive with a PARAMETERIZED CLI fallback. Note the starting state: the stash_archive mapping already declares mcp_tool and params.stash_id but declares NO cli_command at all, so this task ADDS the cli_command key rather than editing an existing one.

REQUIRED EXACT VALUE (P1 — read before writing the mapping)
The cli_command MUST be written verbatim as:
    cli_command: "backlogit stash archive {{stash_id}}"
A bare `backlogit stash archive` with no stash identifier is INVALID and MUST NOT be written. Verified against the installed CLI: `backlogit stash archive --help` declares `Usage: backlogit stash archive <stash-id>` — exactly one REQUIRED positional stash identifier, with no flag form and no default. A bare command is therefore unexecutable, and a P-012 degraded-mode consumer that logs or runs the declared fallback verbatim (`TOOL_DEGRADED: {tool_name} — CLI fallback: {cli_command}`) would emit a command that cannot run, silently defeating the fallback leg the migration exists to establish.

Registry convention is to embed operation parameters as `{{...}}` placeholders directly in cli_command — see `stash` -> `backlogit stash add --text {{text}}`, `get_task` -> `backlogit get {{id}}`, `move_task` -> `backlogit move {{id}} --status {{status}}`. The placeholder name MUST be exactly `{{stash_id}}` so it resolves against the mapping's existing `params.stash_id` key; any other spelling leaves the parameter unbound.

The subject of this requirement is the registry file's own mapping — not any wording inside the Ship agent contract, which this task does not touch. This exact-value requirement is the AUTHORITY for the registry cli_command. Where other migration artifacts (the 137-F feature description, 137.003-T, the hardening addendum, the deliberation, and the staging memory record) name `backlogit stash archive` in bare form, they are describing the CLI SUBCOMMAND's existence or contrasting it with the deprecated `stash remove` alias — they are not quoting a registry value — and are correct as written; they do not license a bare cli_command here.

H5 (P2): do NOT delete stash_remove. The MCP tool is still exposed and still functions, and the CLI retains `stash remove` as an alias of `stash archive`. Deleting the mapping would state the operation does not exist, which is false. The registry's job is to describe the tool truthfully, including its deprecated surface. Marking it deprecated is descriptive only — the registry MUST NOT resolve any Ship execution path to stash_remove.

ACCEPTANCE
- C5 still prohibits discretionary removal AND discretionary archival.
- The manifest-derived post-merge exception still reads as allowed.
- Registry still describes both operations; stash_remove marked deprecated and NOT resolved by any prescriptive execution path.
- The registry's stash_archive mapping names backlogit_stash_archive as MCP primary and declares its CLI fallback as the exact string `backlogit stash archive {{stash_id}}`. VERIFY LITERALLY: the `{{stash_id}}` placeholder is present in the cli_command value, and it matches the mapping's `params.stash_id` key so the identifier is passed through to the command. A cli_command of bare `backlogit stash archive`, or one using any placeholder name other than `{{stash_id}}`, FAILS this criterion. This criterion is evaluated against templates/backlog/registries/backlogit.registry.yaml ONLY. The Ship agent contract's own archive wording is 137.003-T's acceptance criterion, not this task's, and MUST NOT be asserted here — asserting it would manufacture a false dependency on 137.003-T.
