P-021 C5
Name the archive operation as the allowed, manifest-derived post-merge Step 7 retirement.

H2 (P1) DRAFTING HAZARD — READ BEFORE EDITING
C5 deliberately names removal AND archival as SEPARATELY prohibited DISCRETIONARY dispositions, because archival also takes a Stage-owned deferred entry out of Stage's triage queue; a prohibition naming only removal would leave the same loss reachable by another verb. After this rename the clause will say the ALLOWED exception is archival AND that DISCRETIONARY archival is prohibited. That is correct and intended, but it reads as tension and will invite a "simplifying" edit that deletes the discretionary prohibition. DO NOT SIMPLIFY.
- The DISCRETIONARY qualifier must remain attached to BOTH verbs.
- The manifest-derived exception must remain explicitly scoped to the post-merge Step 7 path.
- A reviewer proposing removal of the archival prohibition is to be refused with a pointer to hardening section H2.

BACKLOG REGISTRY
Keep the stash_remove mapping PRESENT but marked deprecated; ensure stash_archive is the operation the Ship contract resolves to.
H5 (P2): do NOT delete stash_remove. The MCP tool is still exposed and still functions — only the CLI subcommand is gone. Deleting the mapping would state the operation does not exist, which is false. The registry's job is to describe the tool truthfully, including its deprecated surface.

ACCEPTANCE
- C5 still prohibits discretionary removal AND discretionary archival.
- The manifest-derived post-merge exception still reads as allowed.
- Registry still resolves both operations; stash_remove marked deprecated.
