Reliability hotfix for a P1 gate-correctness defect that is UNFIXED on main as of 747193fe. src/autoharness/gates/topology.py::_prior_shipment_id (line 1345, introduced by PR #357 / commit 0568f044 during shipment 139-S) suppresses the numeric-adjacency implicit-predecessor fallback whenever ANY shipment declares the target as a dependency, with no directionality filter. A numerically HIGHER shipment declaring the target (e.g. 113-S depends on 112-S) is the NORMAL forward-order case the heuristic exists to support, not a reverse-edge anomaly. The over-broad check therefore silently ALLOWS claiming a shipment that should have been blocked by PREDECESSOR_NOT_SHIPPED -- a silent fail-OPEN in a safety gate. Fix: restrict the suppression to numerically LOWER declaring shipments only, per the fix verified during 139-S post-merge closure (94/94 topology tests, 113/113 subtests, 1550 full-suite passes) and recorded verbatim in the compound doc; plus one regression test. This is the THIRD correction to the same predicate (skip-violator -> any-direction -> directional), so P-006 hardening was performed (H1-H9) despite the small diff. Multi-persona adversarial review: PASS, 0 unresolved P0 / 0 unresolved P1 (6 findings; 2 P1 resolved, 2 P2 resolved, 1 P2 resolved for this PR, 1 P3 accepted+deferred). Sequenced ahead of 138-S by an explicit blocks edge because abandoning 138-S requires a claim, which executes the pre_claim topology gate.
