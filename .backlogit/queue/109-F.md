<!-- BEGIN:description -->
Covering feature for E3C25E6D (deliberation 012-DL, informing spike 001-SP). Add a fail-closed `autoharness gate pipeline-topology` that mechanically enforces the serial Stage->Ship, single implementation branch/worktree workflow (P-001/P-016) instead of relying on agent prose. This is the mechanical enforcement layer on top of the 060-F/061-S prose policy + partial Ship intake gate.

AUTHORITY BOUNDARY: persisted backlogit shipment status is authoritative evidence, not a lease or exclusion primitive. ClaimShipment is an unlocked read/check/write with per-shipment all-or-nothing persistence/rollback for its own activation path, but no CAS, lock, lease, or serialization exists at any local or cross-machine scope. Same-checkout and divergent-checkout claims remain TOCTOU-exposed. The gate is a read-only detector/validator of persisted state plus local git branch/worktree topology; it provides pre/post detection and fail-closed remediation, never atomic exclusion, and never mutates backlogit transitions. A centralized exclusion service is out of scope.

The gate verifies four topology invariants around topology-sensitive operations: (1) phase-aware active-shipment state — pre_claim requires zero active; post_claim/lifecycle requires exactly one active and the selected target; (2) dependency/prior readiness requires predecessor state `shipped` live or archived provenance `archived_status: shipped|done` AND completed required closure including P-020; (3) branch-to-selected-shipment ownership; (4) exactly one implementation worktree locally, honoring only the explicit Stage spike exception. Branch/worktree creation occurs before claim under P-011, so Ship gates pre_claim before branch/worktree, gates pre_claim again immediately before claim, then performs an immediate post_claim global verification after claim.

* `autoharness gate pipeline-topology` implemented fail-closed with `--json`, `--mode`, `--force`, required agent-scoped `--shipment <ID>`, and explicit `--phase <pre_claim|post_claim|lifecycle>`; documented exits 0 pass / 1 blocked / 2 invalid.
* Deterministic core tests cover all four invariants, explicit target/phase handling, pre_claim zero-active, post_claim/lifecycle exactly-one-same-target, detect-before, and post-claim global verification.
* Dependency/prior readiness accepts only live `shipped` OR archived provenance `archived_status: shipped|done`, AND separately requires complete closure including P-020. `abandoned`, live queued/active/blocked, archived active/queued/blocked/abandoned, generic archived state, missing provenance, or incomplete closure blocks; positive and negative tests cover the full matrix.
* No artifact claims exclusion: persisted status is authoritative evidence only; backlogit and the gate provide no CAS, lock, lease, or serialization at any scope. Local and cross-machine TOCTOU limitations and machine-local worktree visibility are documented.
* pre-commit + pre-push hook templates (.sh + .ps1), opt-in install/tune/verify integration, and verify_workspace assertions added.
* Ship template ordering is structurally enforced: pre_claim gate before branch/worktree creation; pre_claim gate immediately before claim; claim; immediate post_claim GLOBAL verification over all shipments; then lifecycle gates before build, PR, and closure. Branch/worktree is never labeled post_claim. Orchestrator route/cursor checks remain pre_claim.
* Safe-close treats `backlogit_ship_shipment` as potentially partially mutating, not atomic. After success OR error Ship re-reads both live and archived state/provenance. Only a successful return plus one coherent archived `archived_status: shipped|done` record and no contradictory live residue may proceed; errors, partial mutation, ambiguity, or non-shipped provenance fail closed with remediation.
* Shipment-reconcile protected-set computation excludes predecessor siblings only after that verified coherent successful archived result; all non-shipped/missing/ambiguous cases remain protected. Deterministic 114->115->116 success tests and partial-mutation/error negatives are required.
* Serial sequencing keeps dependency-gated successors queued from creation and suppresses them via blocks edges; no blocked->queued transition is attempted. 109.019-T ships in 114-S and requires post-closure instruction reload before successor selection.
* Required-vs-advisory CI detect-at-sync backstop implemented with staged rollout; it is not exclusion.
* `--force` writes the force-audit log; every executed gate run emits telemetry, while `git --no-verify` non-execution remains locally unobservable.
* No parallel scheduler introduced; DAG adoption remains deferred (001-SP).
