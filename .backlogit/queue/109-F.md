<!-- BEGIN:description -->
Covering feature for E3C25E6D (deliberation 012-DL, informing spike 001-SP). Add a fail-closed `autoharness gate pipeline-topology` that MECHANICALLY enforces the serial Stage->Ship, single implementation branch/worktree workflow (P-001/P-016) instead of relying on agent prose. This is the mechanical enforcement layer on top of the 060-F/061-S prose policy + partial Ship intake gate — distinct, not duplicative.

AUTHORITY BOUNDARY (per 012-DL): backlogit is the authoritative shipment claim/status store, but its ClaimShipment (queued->active) is NOT a compare-and-swap, lock, or lease: it is an UNLOCKED read/check/write whose ONLY guarantee is PER-SHIPMENT ALL-OR-NOTHING PERSISTENCE WITH ROLLBACK (no torn/partial activation). It does NOT serialize concurrent claims at ANY scope — same-checkout concurrent claims race (LOCAL TOCTOU) and divergent not-yet-synced checkouts can each read zero-active and both claim (CROSS-MACHINE TOCTOU), the conflict surfacing only at git sync/CI. The gate is a fail-closed READER/VALIDATOR of that state + LOCAL git branch/worktree topology; it NEVER mutates backlogit internal transition rules (external-guard pattern). At-most-one-active-shipment is NOT serialized by backlogit at any scope; the gate provides ONLY pre/post DETECTION + fail-closed remediation (degraded to detect-at-sync/CI + fail-closed-on-ambiguity), NOT atomic exclusion or an invented remote lease; a true workspace-global lock / centralized remote lease is explicitly out of scope / future work. Do not mutate C:/Source/GitHub/backlogit.

The gate verifies four topology invariants before topology-sensitive ops (shipment claim, branch/worktree creation, build, push, PR, closure): (1) a PHASE-AWARE active-shipment invariant evaluated against backlogit state in the current synchronized checkout — PRE-CLAIM requires ZERO active shipments; POST-CLAIM/later-lifecycle allows exactly one active shipment and only when it is the resolved target (DETECTION-ONLY; NOT serialized locally or cross-machine, per the limitation above); (2) queue/dependency + prior-closure readiness; (3) branch-to-claimed-shipment ownership (three-case per P-011); (4) exactly one implementation WORKTREE (machine-local), honoring only the explicit time-boxed Stage spike/research exception (P-016).
