<!-- BEGIN:description -->
Covering feature for E3C25E6D (deliberation 012-DL, informing spike 001-SP). Add a fail-closed `autoharness gate pipeline-topology` that MECHANICALLY enforces the serial Stage->Ship, single implementation branch/worktree workflow (P-001/P-016) instead of relying on agent prose. This is the mechanical enforcement layer on top of the 060-F/061-S prose policy + partial Ship intake gate — distinct, not duplicative.

AUTHORITY BOUNDARY (per 012-DL): backlogit is the authoritative cross-machine shared lease for shipment claim/status; the gate is a fail-closed READER/VALIDATOR of backlogit status + LOCAL git branch/worktree topology. The gate NEVER mutates backlogit internal transition rules (external-guard pattern). Do not mutate C:/Source/GitHub/backlogit.

The gate verifies four topology invariants before topology-sensitive ops (shipment claim, branch/worktree creation, build, push, PR, closure): (1) at most one ACTIVE shipment (global, via backlogit); (2) queue/dependency + prior-closure readiness; (3) branch-to-claimed-shipment ownership (three-case per P-011); (4) exactly one implementation WORKTREE (machine-local), honoring only the explicit time-boxed Stage spike/research exception (P-016).

* Gate INVOCATION wired into the Ship agent template before every promised topology-sensitive op (shipment claim, branch/worktree creation, build, PR, closure) AND into the Orchestrator agent template (route-to-Ship pre-claim eligibility + cursor-advance), each with structural acceptance assertions (109.017-T / 109.018-T). Git hooks cover commit/push; agent integration covers the agent-orchestrated points.
* Every shipment-scoped claim/routing gate invocation passes the EXPLICIT target shipment ID: Ship passes the shipment being claimed/operated on at each lifecycle point; the Orchestrator passes the candidate/successor shipment at route-to-Ship and cursor-advance; non-shipment hook/ci contexts use a deterministic implicit target-resolution contract (currently-claimed shipment / current-branch slug, ambient-only when none resolves) WITHOUT weakening fail-closed agent mode.
* Shipment-reconcile safe-close protected-set computation is multi-shipment-per-feature sequence-aware AND terminal-status-aware: the serial 114-S -> 115-S -> 116-S lifecycle closes cleanly by excluding ONLY predecessor sibling tasks whose owning shipment is archived with a successful terminal `archived_status: shipped` (or normalized legacy `done`); siblings whose owning shipment is not-yet-shipped OR archived in any non-shipped terminal state (e.g. `abandoned`) stay protected, and genuine cross-cascades still halt (109.016-T, ships in 114-S so the corrected contract is installed before 115-S/116-S close).
