*** PA-1 — ActionRisk: CRITICAL. REQUIRES EXPLICIT OPERATOR APPROVAL BEFORE EXECUTION. ***

This task ARMS AN IRREVERSIBLE PUBLISH. Pushing the tag triggers .github/workflows/release.yml (trigger: tags v*), which builds, publishes to PyPI, and creates the GitHub Release UNATTENDED. PyPI is immutable — once 1.5.0 is uploaded, that version is permanently consumed and can never be re-uploaded.

PRECONDITION — do this ONLY AFTER the PR is merged to main (150.008-T records the MERGE COMMIT SHA).

PRE-PUSH ASSERTIONS (all must pass; this is the LAST REVERSIBLE MOMENT):
1. The PR is MERGED to main and main is green.
2. Tag name minus the leading "v" EXACTLY equals pyproject.toml's version (release.yml L39 rejects a mismatch, but assert it locally first — a rejected tag still burns a tag name and creates confusing history).
3. A non-empty "## 1.5.0 - <date>" section exists in CHANGELOG.md on main (release.yml L67 aborts otherwise).
4. *** DRY-RUN EVIDENCE MUST BE BOUND TO THE EXACT MERGE COMMIT (added under the operator-authorized bounded cycle 4). ***
   150.006-T (dry run A) and 150.007-T (dry run B) execute BEFORE the PR is opened. 150.008-T then permits review-fix pushes, and the merge commit may additionally incorporate a newer base. An earlier PASS therefore attests a tree that is NOT necessarily the tree being tagged.
   Before tagging, do ONE of:
     (a) RE-RUN dry run A and dry run B against the EXACT merge commit SHA; or
     (b) confirm the EVIDENCE SHA recorded by 150.006-T and 150.007-T EQUALS the merge commit SHA — and RE-RUN on ANY mismatch.
   WHY THIS MATTERS: these are the release's UNIQUE package-integrity and markdown/verification gates. CI does NOT perform the wheel force-include destination checks (all ten mappings), the isolated-install version/home/bundled-data probes, or the fail-closed markdown gate. Without this re-bind, the tag can be pushed against a tree whose packaged templates/docs passed only CI's narrower checks — and the publish that follows is IRREVERSIBLE.
   STOP if either dry run FAILS on the merge commit. Do not tag.
5. *** 1.5.0 MUST BE ABSENT FROM PyPI. *** Probe https://pypi.org/pypi/autoharness/1.5.0/json and REQUIRE a 404.
   - 200 (version exists) -> STOP. DO NOT TAG. Escalate.
   - Probe unreachable/ambiguous -> FAIL CLOSED. STOP. DO NOT TAG.
   WHY THIS ASSERTION LIVES HERE: the release workflow does NOT enforce it. release.yml L102-L106 merely PRINTS "already on PyPI; publish will skip existing files on reruns" and EXITS 0, and L112 publishes with skip-existing: true. An unattended run would skip the upload, SMOKE-TEST THE PRE-EXISTING PACKAGE (which passes), and CREATE/UPDATE A GITHUB RELEASE around artifacts this build did not produce — reporting overall success. Workflow hardening is deferred to stash 8E10B13B.
6. EXPLICIT OPERATOR GO/NO-GO OBTAINED AND RECORDED (after assertions 1-5 pass).

STEPS:
1. Create an ANNOTATED tag v1.5.0 on the merge commit.
2. Push the tag to origin.

Gate-ordering rationale (docs/compound/2026-08-18-lifecycle-gate-must-precede-safe-close-mutation.md): ALL gates must pass BEFORE the terminal irreversible mutation, and they must have been evaluated against THE TREE BEING TAGGED. Do not push the tag to "see if it works".

STOP CONDITIONS:
- Version mismatch -> STOP before pushing.
- No 1.5.0 changelog section -> STOP.
- Dry-run evidence not bound to the merge commit, or a rerun fails -> STOP.
- 1.5.0 already present on PyPI, or probe ambiguous -> STOP (fail closed).
- Operator approval not obtained -> STOP.
