Close the autoharness-owned half of the checkpoint resume_hint gap in three parts, landing in the order policy -> producers -> validation.

PART 3 FIRST - HISTORICAL-RECORD COMPATIBILITY POLICY, TOTAL AND DETERMINISTIC. Every pre-existing schema_version: 1 record lacking a usable resume_hint lands in exactly one of two outcomes, decided by status alone: status: resolved yields the REPORTED, NON-BLOCKING CHECKPOINT_LEGACY_HINTLESS_RESOLVED, enumerated by filename and excluded from the candidate set; status: active yields the CONCRETE, BLOCKING CHECKPOINT_ACTIVE_HINTLESS and fails closed to operator handoff. An active record is NEVER grandfathered, and there is no unspecified third branch. The two rules are separate and neither widens the other. NO MIGRATION MECHANISM SHIPS and no committed checkpoint file is ever rewritten.

PART 1 - PRODUCER GUARANTEE. Every harness checkpoint producer emits a top-level resume_hint specific enough to support a later recovery decision, explicitly including the minimal end-of-session completion checkpoint. Part 1b additionally updates the authoritative Checkpoint Payload Contract ATOMICALLY across .github/instructions/backlogit.instructions.md and templates/instructions/backlogit.instructions.md.tmpl so the raw backlogit create call is no longer advertised as a permitted harness producer path, with install-manifest checksums regenerated for every modified tracked file.

PART 2 LAST - DETERMINISTIC VALIDATION. The boundary is the EXECUTABLE ADAPTER COMMAND autoharness checkpoint create, which producers invoke instead of the raw backlogit create operation. A package-local Python function cannot enforce anything against Markdown agent templates that call backlogit directly; because the adapter is a command, "did this template invoke the gate?" is a decidable property of the template text. Validation is strictly PRE-WRITE: on a failing harness outcome the adapter exits non-zero and writes nothing. validate_checkpoint_payload(payload, origin) is the single predicate, with origin partitioning the four tokens structurally.
