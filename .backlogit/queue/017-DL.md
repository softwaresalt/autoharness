# Tune stale startup-script contract migration

## Problem Frame

<!-- BEGIN:problem-frame -->
Auto-Tune can report an installed target workspace start.ps1/start.sh as unchanged when the file still implements the obsolete pre-shim inline orchestration contract. The current templates already emit thin compatibility shims delegating to autoharness run, and the repository-root scripts were already migrated by shipped Plan 1. The remaining work is to add target-workspace drift detection and non-destructive migration behavior without re-planning or changing the shipped startup templates or self-install scripts.
<!-- END:problem-frame -->

## Options

<!-- BEGIN:options -->
1. Add only a structural Tune rule that recognizes the current thin-shim markers and legacy inline orchestration markers; treat missing, current, legacy, and ambiguous/customized files separately. 2. Add a new explicit startup-script contract identifier/version to the manifest/profile and compare it during Tune, with structural validation as a fallback for manifests from older installs. 3. Regenerate every startup script on every tune so all workspaces converge, at the cost of overwriting operator customizations.
<!-- END:options -->

## Chosen Direction

<!-- BEGIN:chosen-direction -->
Use option 2 with option 1 as the compatibility detector: define a named startup-script contract/version tied to the canonical templates, have Tune classify manifest/version state plus file structure, and use generate-when-absent or backup-and-refresh-when-stale behavior. Preserve operator-added sections by extracting and reattaching supported customization blocks; ambiguous content must be surfaced for review rather than silently discarded. Keep install-harness and current startup templates unchanged unless implementation evidence proves shared metadata wiring is required. Scope is target workspaces only; repository-root start.ps1/start.sh and shipped Plan 1 remain out of scope.
<!-- END:chosen-direction -->

## Open Questions

<!-- BEGIN:open-questions -->
The implementation must define exact PowerShell and POSIX markers, the contract-version storage location and backward-compatible default, the safe boundary for preserving Claude Code/Codex/custom sections, and deterministic tests for unchanged-manifest legacy files, current files, missing files, and ambiguous customizations. Because this is a migration rule that can rewrite installed target artifacts, plan hardening is required before review.
<!-- END:open-questions -->
