<!-- BEGIN:description -->
Covering feature for stash 7D1E2F1A: add a rotation + retention policy to the telemetry JSONL sink so the execution_epochs.jsonl mirror stops growing unbounded beside the authoritative SQLite store. Follow-up deliberately deferred from shipment 097-S / feature 092-F (PR #241) to keep that shipment width-isolated. Hardened 2026-07-29 per PR #249 Copilot review (round 1: 6 findings; round 3: pivot to a best-effort concurrent-writer mirror + no-replace rollover model, findings A + B; P-006 formally applied).

Design (see plan docs/plans/2026-07-29-telemetry-jsonl-sink-rotation-retention-plan.md): size-based segment rollover with a bounded retained-segment window. Rotation thresholds are NON-CONFIGURABLE module constants in jsonl_sink.py (_MAX_SEGMENT_BYTES, _MAX_RETAINED_SEGMENTS), NOT runtime config -- exposing them as config would require editing four telemetry schemas (additionalProperties:false), config.py, and record.py with a schema-version bump (finding 2). Sealed segments carry a monotonic zero-padded generation (execution_epochs.jsonl.NNNNN); the active segment is the base name. That single generation identity is shared by the preflight token, rollover, and pruning (finding 6). Existing preflight/replay checks (scan_epoch_digest/find_epoch_digest) are extended to scan active + retained sealed segments so idempotent-replay and TelemetryConflictError conflict detection hold across rotated segments, within a documented retention horizon (a replay whose segment was pruned may re-append). The reader read-path (reader.py) is extended to read active + retained sealed segments so rotated history survives reads (finding 3).

Writer model (PR #249 round 3, DEFINITIVE -- Option A): the sink is a BEST-EFFORT, CONCURRENT-WRITER-SAFE human-readable mirror; SQLite is authoritative and duplicate/late mirror lines are reconciled on read (epoch_id dedupe + SQLite-over-JSONL precedence). This is the sink existing documented contract (cli.py:934/1003 telemetry record is a second public writer entry point besides run_matrix; jsonl_sink.py:96-104 says a line is a single atomic write safe for concurrent writers; jsonl_sink.py:161-171 says concurrent duplicate lines are benign by design and reconciled on read, not by locking). Rotation PRESERVES this contract rather than swapping in a single-writer model or over-claiming immutability: (1) sealing uses a NO-REPLACE atomic generation claim (os.link/O_EXCL/CREATE_NEW; loser retries next generation) so a concurrent rollover never clobbers a sealed segment, WITHOUT a global lock (finding A); (2) sealed segments are NOT claimed immutable -- a late O_APPEND into a just-sealed segment is acceptable and reconciled on read (finding B); (3) pruning removes only sealed segments beyond the window, never the active segment and never authoritative SQLite data. Rotation is on by default; the default _MAX_SEGMENT_BYTES is large enough that the existing suite never rolls (existing single-segment behavior preserved). The only mirror loss is retention pruning (SQLite remains authoritative).

Scope: telemetry subsystem only -- src/autoharness/telemetry/jsonl_sink.py and reader.py plus their tests. No changes to epoch.py, record.py, config.py, aggregation, schemas, CLI, or templates. reader.py is a review-driven scope expansion within the telemetry subsystem (finding 3). Canonical test gate: PYTHONPATH=src python -m unittest discover -s tests.

<!-- BEGIN:acceptance-criteria -->
Unbounded growth is prevented: size-based rollover seals the active segment to the next generation when it reaches _MAX_SEGMENT_BYTES and starts a fresh active segment. Retention is bounded: at most _MAX_RETAINED_SEGMENTS sealed segments are retained (oldest sealed generation pruned first; the active segment is never pruned). Restated achievable size bound (finding 5): a single oversized record is written intact to its own segment; a sealed segment is <= _MAX_SEGMENT_BYTES + one max record; total retained bytes <= (_MAX_RETAINED_SEGMENTS + 1) * (_MAX_SEGMENT_BYTES + one max record). The sink existing preflight/replay checks still hold across rotated segments: idempotent-replay and TelemetryConflictError consider matches in the active + all retained sealed segments; the preflight token carries the active-segment generation identity so an offset is reused only for the same generation (rollover between preflight and append forces a full rescan -- finding 6); documented exception is the retention horizon (pruned-segment mirror epochs may re-append; SQLite authoritative). Writer model (findings A + B, round 3): the sink is a best-effort concurrent-writer-safe mirror with SQLite authoritative and reconcile-on-read; sealing uses a no-replace generation claim so a concurrent rollover never clobbers an already-sealed segment (simultaneous-collision test: both sealed segments preserved, zero whole-segment loss); sealed segments are NOT claimed byte-immutable -- a late line into a sealed segment is reconciled on read (reader test); no global write lock is introduced. The reader read-path returns records from active + retained sealed segments after rollover with no history loss, preserving dedupe/precedence/malformed-line skipping (finding 3). Rotation thresholds are module constants, not configuration (finding 2). Traceability: covering feature 095-F, tasks 095.001-T..095.004-T, shipment 100-S (finding 1). All existing tests in tests/test_telemetry_jsonl_sink.py pass unchanged; new tests cover rollover, simultaneous seal-collision (no-replace), retention/pruning, cross-segment replay, preflight-generation invalidation, late-line-into-sealed reconciliation, and reader-across-segments. Full-suite gate PYTHONPATH=src python -m unittest discover -s tests is green.
