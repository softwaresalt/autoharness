Covering feature for stash 7D1E2F1A: add a rotation + retention policy to the telemetry JSONL sink so the execution_epochs.jsonl mirror stops growing unbounded beside the authoritative SQLite store. Follow-up deliberately deferred from shipment 097-S / feature 092-F (PR #241) to keep that shipment width-isolated. Hardened 2026-07-29 per PR #249 Copilot review (round 1: 6 findings; round 2: convergence on the single-writer concurrency model, findings A + B; P-006 formally applied).

Design (see plan docs/plans/2026-07-29-telemetry-jsonl-sink-rotation-retention-plan.md): size-based segment rollover with a bounded retained-segment window. Rotation thresholds are NON-CONFIGURABLE module constants in jsonl_sink.py (_MAX_SEGMENT_BYTES, _MAX_RETAINED_SEGMENTS), NOT runtime config -- exposing them as config would require editing four telemetry schemas (additionalProperties:false), config.py, and record.py with a schema-version bump (finding 2). Sealed segments carry a monotonic zero-padded generation (execution_epochs.jsonl.NNNNN); the active segment is the base name. That single generation identity is shared by the preflight token, rollover, and pruning (finding 6). Existing preflight/replay checks (scan_epoch_digest/find_epoch_digest) are extended to scan active + retained sealed segments so idempotent-replay and TelemetryConflictError conflict detection hold across rotated segments, within a documented retention horizon (a replay whose segment was pruned may re-append). The reader read-path (reader.py) is extended to read active + retained sealed segments so rotated history survives reads (finding 3).

Rotation is on by default; the default _MAX_SEGMENT_BYTES is large enough that the existing suite never rolls (existing single-segment behavior preserved). Writer model (PR #249 round 2, DEFINITIVE -- Option B): the production caller (eval/runner.py run_matrix) drives telemetry sequentially in one process, so the sink is single-writer-per-path. Under that contract sealed segments are immutable BY CONSTRUCTION (the single writer never appends to a segment after sealing it; no O_APPEND handle is held across the rename) and rollover needs no interprocess lock; rollover seals to max(existing sealed generation)+1 so a rename never clobbers a sealed segment. Concurrent multi-PROCESS writers to the same path are explicitly OUT OF CONTRACT; atomic single-line append is retained as defense-in-depth (accidental duplicates reconciled on read), not a rollover guarantee. The only loss is retention pruning (SQLite remains authoritative).

Scope: telemetry subsystem only -- src/autoharness/telemetry/jsonl_sink.py and reader.py plus their tests. No changes to epoch.py, record.py, config.py, aggregation, schemas, CLI, or templates. reader.py is a review-driven scope expansion within the telemetry subsystem (finding 3). Canonical test gate: PYTHONPATH=src python -m unittest discover -s tests.

<!-- BEGIN:acceptance-criteria -->
Unbounded growth is prevented: size-based rollover seals the active segment to the next generation when it reaches _MAX_SEGMENT_BYTES and starts a fresh active segment. Retention is bounded: at most _MAX_RETAINED_SEGMENTS sealed segments are retained (oldest generation pruned first). Restated achievable size bound (finding 5): a single oversized record is written intact to its own segment; a sealed segment is <= _MAX_SEGMENT_BYTES + one max record; total retained bytes <= (_MAX_RETAINED_SEGMENTS + 1) * (_MAX_SEGMENT_BYTES + one max record). The sink existing preflight/replay checks still hold across rotated segments: idempotent-replay and TelemetryConflictError consider matches in the active + all retained sealed segments; the preflight token carries the active-segment generation identity so an offset is reused only for the same generation (rollover between preflight and append forces a full rescan -- finding 6); documented exception is the retention horizon (pruned-segment epochs may re-append). Writer model (findings A + B, round 2): the sink is single-writer-per-path; sealed segments are immutable by construction and the next-generation name never clobbers an existing sealed segment; concurrent multi-process writers to one path are explicitly out of contract and not claimed or tested. The reader read-path returns records from active + retained sealed segments after rollover with no history loss, preserving dedupe/precedence/malformed-line skipping (finding 3). Rotation thresholds are module constants, not configuration (finding 2). Traceability: covering feature 095-F, tasks 095.001-T..095.004-T, shipment 100-S (finding 1). All existing tests in tests/test_telemetry_jsonl_sink.py pass unchanged; new tests cover rollover, retention/pruning, cross-segment replay, preflight-generation invalidation, sealed-segment immutability, and reader-across-segments. Full-suite gate PYTHONPATH=src python -m unittest discover -s tests is green.
