<!-- BEGIN:description -->
Covering feature for stash 7D1E2F1A: add a rotation + retention policy to the telemetry JSONL sink (src/autoharness/telemetry/jsonl_sink.py), which currently appends ExecutionEpoch records to a single execution_epochs.jsonl mirror with no rollover, no retention window, and no compaction, so the mirror grows unbounded beside the authoritative SQLite store. Follow-up deliberately deferred from shipment 097-S / feature 092-F (PR #241) to keep that shipment width-isolated.

Design decision (see plan): size-based segment rollover with a bounded retained-segment window, and the sink's existing preflight/replay checks (scan_epoch_digest / find_epoch_digest) extended to scan the active segment plus all retained sealed segments so idempotent-replay and TelemetryConflictError conflict detection still hold across rotated segments. Sealed segments are immutable append-only files (preserving the first-write-immutable contract); compaction and age-based rollover were rejected as more complex and less deterministic. Rotation is on by default with a default max_segment_bytes large enough that the existing test suite never rolls (existing single-file behavior preserved). Total disk usage is bounded by (max_retained_segments + 1) * max_segment_bytes.

Width-isolated to jsonl_sink.py + its test module. No changes to epoch.py, record.py, aggregation, schemas, CLI, or templates. Plan: docs/plans/2026-07-29-telemetry-jsonl-sink-rotation-retention-plan.md. P-006 hardening not required (single Python module, additive, config-gated; no schema/CLI-distribution/template blast radius). Canonical test gate: PYTHONPATH=src python -m unittest discover -s tests; targeted module tests/test_telemetry_jsonl_sink.py.
<!-- END:description -->

<!-- BEGIN:acceptance-criteria -->
Unbounded growth is prevented: size-based rollover triggers when the active segment reaches the configured max_segment_bytes, sealing it and starting a fresh active segment. Retention is bounded: at most max_retained_segments sealed segments are retained (oldest pruned first), so total on-disk bytes are bounded by (max_retained_segments + 1) * max_segment_bytes. The sink's existing preflight/replay checks still hold across rotated segments: idempotent-replay and TelemetryConflictError conflict detection consider matches in the active segment and all retained sealed segments; the documented exception is that guarantees hold only within the retention horizon (a replay whose segment was pruned may be re-appended). All existing tests in tests/test_telemetry_jsonl_sink.py still pass unchanged, and new tests cover rollover, retention/pruning, and cross-segment replay. Full-suite gate PYTHONPATH=src python -m unittest discover -s tests is green.
