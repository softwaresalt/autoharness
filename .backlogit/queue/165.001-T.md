GENESIS EXPECTATIONS — NARROW, NON-FAIL-OPEN RULE (review-fix cycle 2, finding 2; REPLACES the cycle-1 single "no shipped-terminal shipment" assertion). Genesis requires ALL of: G1 no edges and no `dag-root`; G2 no shipped-terminal shipment anywhere, live OR archived; G3 the candidate is the SOLE EXTANT NONTERMINAL shipment (no other queued/active record, live or archived); G4 no abandoned record anywhere. Assert EACH disqualifier independently so no single fixture can carry the whole rule vacuously:
N5a. GENESIS PASS — fresh workspace holding EXACTLY ONE shipment record and nothing else: passes with `predecessor_source: "genesis"`.
N5b. NO GENESIS FROM ARCHIVED SHIPPED HISTORY (G2) — a workspace whose only shipped-terminal shipments exist as ARCHIVED records is NOT genesis; an edge-less undeclared shipment there blocks as `unsequenced`. The probe must read `archived_status`/`archived_record_present`, never only live queue records; otherwise archiving or pruning history silently re-enters genesis and converts a block into a pass.
N5c. NO GENESIS WITH MULTIPLE PENDING SHIPMENTS AND NO SHIPPED HISTORY (G3) — a workspace holding several QUEUED shipments and nothing ever shipped: NONE of them is genesis. Assert this over at least two distinct candidates including a LATER-NUMBERED one, so the fixture proves a later-numbered edge-less candidate cannot silently pass. This is the specific fail-open a "no shipped history" rule would allow — every pending shipment passing genesis simultaneously.
N5d. NO GENESIS FROM ABANDONED-ONLY HISTORY (G4) — a workspace whose only prior shipment record is `abandoned` (terminal but NOT shipped) is NOT genesis. Without G4, the G2 probe alone would admit it.
N5e. DECLARED ROOT STILL PASSES IN EVERY NON-GENESIS WORKSPACE — the same fixtures as N5b/N5c/N5d, with `dag-root` on the candidate, pass as `declared_root`. This proves the narrow genesis rule does not deadlock intentional roots.
N6. Unsequenced shipment (no edges, no declaration, workspace disqualified from genesis by any of G2/G3/G4) blocks with token UNSEQUENCED_SHIPMENT, and the message NAMES BOTH remedies (add the real `blocks` edge, or declare the shipment a root).
