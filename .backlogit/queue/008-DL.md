# 088 failure-content-in-success decline: reconcile spec + close detector coverage gap

## Problem Frame

<!-- BEGIN:problem-frame -->
The 088-F throwaway compression prototype must NEVER compress a SUCCESSFUL postToolUse.textResultForLlm that embeds failure evidence (non-zero exit code, stderr, stack trace, or gate verdict) — collapsing such a line into the compressor's omitted middle is evidence loss. Investigation finding: the decline detector (brainspace/policy.py classify_decline_reason -> FAILURE_BEARING_SUCCESS with _FAILURE_BEARING_PATTERNS) AND its negative-control tests (test_policy_decline_cases.py::test_failure_bearing_success_declines, test_hook_decide_then_stash.py::test_failure_bearing_output_declines_before_store, corpus control, benchmark report) were ALREADY implemented and SHIPPED in 088.004-T (commit 118bf21, 2026-07-25), after this stash entry was written (~07-24). Two residuals from the stash entry remain genuinely open: (1) SPEC DRIFT — the compression plan (docs/plans/2026-07-15-...-plan.md, last touched 07-23) 088.004-T Task-detail bullet + Plan Hardening section were never reconciled to enumerate the failure-bearing-SUCCESS invariant (they only list secret/gate/stack-trace/operator decline cases and 'confirm failure outputs [postToolUseFailure] are untouched'); and (2) COVERAGE GAP — the detector's failure-signal patterns are colon-anchored (exit code:\s*[1-9]), so common non-colon phrasings ('exit code 1', 'exited with code 1', make 'Error 1'/'*** [t] Error 1', 'npm ERR!', JetBrains 'Process finished with exit code 1') are NOT detected; classify_decline_reason returns None and _compress_view can collapse that failure line. Per 093-S, evidence-integrity gaps are hard blockers for narrow-pilot promotion of this experiment.
<!-- END:problem-frame -->

## Options

<!-- BEGIN:options -->
A) Doc-only reconciliation: update the plan spec + note the detector shipped. REJECTED — leaves the real coverage gap open; evidence-loss risk persists; still blocks pilot promotion per 093-S. B) Close the coverage gap in policy.py with carefully-bounded added failure-signal patterns + positive AND negative controls, align the hook _EVIDENCE_LINE_PATTERNS and evidence_oracle.py failure-signal recognition with the same broadened set (defense-in-depth + measurement correctness), THEN reconcile the plan spec + capture explicit acceptance criteria and traceability. CHOSEN. C) Replace the enumerated patterns with a generic 'any error/failed/non-zero' heuristic. REJECTED — high false-positive rate would collapse compression coverage and corrupt the experiment's AUC savings measurement; the design deliberately uses precise, enumerated forms.
