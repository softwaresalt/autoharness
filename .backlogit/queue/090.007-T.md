## Description

<!-- BEGIN:description -->
Validate WorkSizingSnapshot.snapshot_boundary and AbsoluteOutcome exit-code coercion strictly (source: stash 4C4A8F0B, 435F201D).

Files (2): src/autoharness/telemetry/epoch.py, tests/test_telemetry_epoch.py

Current state (two related defects in the same file):
(1) WorkSizingSnapshot.__post_init__ (epoch.py:551-596) never validates snapshot_boundary against the public schema, which fixes it to const "pre_execution" (execution-epoch.schema.json:1408-1410); from_mapping (epoch.py:654) does str(data.get("snapshot_boundary", "pre_execution")), so an explicit null in incoming data becomes the literal string "None" instead of being rejected or defaulted safely.
(2) AbsoluteOutcome.from_mapping (epoch.py:504) does raw tuple(int(c) for c in codes) after _as_tuple (line 498), with no per-element type check, unlike the strict-type coercion pattern already used by _coerce_nonneg_metric (epoch.py:99-153, esp. 129-142) elsewhere in the same module -- a non-numeric/bool element raises a raw ValueError/TypeError instead of a clear EpochError, and int() also silently TRUNCATES a float (int(1.5) == 1), so a float slips through with no error yet violates the schema's integer-only exit-code contract.

TDD (red->green): add test_work_sizing_snapshot_rejects_null_snapshot_boundary (explicit null -> EpochError, not literal "None" string) and test_work_sizing_snapshot_rejects_invalid_snapshot_boundary_enum (unknown string -> EpochError) to test_telemetry_epoch.py; add test_absolute_outcome_from_mapping_rejects_non_numeric_exit_code (a bool, a string, AND a float such as 1.5 that int() would silently truncate to 1 -> each raises EpochError with an actionable message) mirroring the _coerce_nonneg_metric strict-type pattern. Confirm all three fail first. Then: add snapshot_boundary validation in WorkSizingSnapshot.__post_init__ / from_mapping raising EpochError on any value other than the schema const "pre_execution" (every other string, and null, is rejected -- exact const parity with execution-epoch.schema.json:1408-1410); add per-element strict-type validation in AbsoluteOutcome.from_mapping's exit-code tuple construction, following the _coerce_nonneg_metric pattern, raising EpochError instead of letting raw ValueError/TypeError propagate.
<!-- END:description -->

## Acceptance Criteria

<!-- BEGIN:acceptance-criteria -->
- snapshot_boundary set to anything other than the schema const "pre_execution" -- including null and any other string -- now raises EpochError instead of becoming the literal string "None".
