RELEASE DRY RUN A — build and package integrity. Runs BEFORE the PR.

STEP 0 (MANDATORY FIRST — do not skip): CLEAN dist/. Verified this session: dist/ currently contains STALE 1.4.11 artifacts (autoharness-1.4.11-py3-none-any.whl, autoharness-1.4.11.tar.gz). This was raised as P1-1 in plan review. If not cleaned:
  - `uvx twine check dist/*` validates the OLD artifacts and reports a MISLEADING PASS;
  - an isolated install from a dist/*.whl glob could install 1.4.11 while the operator believes 1.5.0 was verified.
That defeats the entire gate immediately before an irreversible publish.

STEPS:
1. Remove stale artifacts from dist/.
2. `uv build`
3. Confirm exactly two freshly-built artifacts exist, both carrying 1.5.0 in their filenames. FAIL if ANY non-1.5.0 artifact is present in dist/.
4. `uvx twine check dist/*`
5. Install the EXPLICITLY NAMED 1.5.0 wheel (never a glob) into an isolated environment — not the source tree.
6. Assert `autoharness version` outputs EXACTLY "1.5.0" AND the command exited zero.
7. Assert the installed distribution METADATA reports 1.5.0 (__init__.py prefers importlib.metadata.version(); a stale literal fallback would otherwise stay hidden).
8. Assert `autoharness home` resolves.
9. BUNDLED DATA — VERIFY EVERY DECLARED force-include DESTINATION, NOT JUST templates.
   CORRECTED after PR #422 review: pyproject.toml L35-L45 declares TEN force-include mappings, not one. A wheel could omit an entire shipped artifact family and still pass a templates-only check.
   Required destinations inside the wheel (each present, each directory NON-EMPTY, each readable from the ISOLATED install):
     templates                              -> autoharness/data/templates
     schemas                                -> autoharness/data/schemas
     .github/agents                         -> autoharness/data/.github/agents
     .github/skills                         -> autoharness/data/.github/skills
     .github/instructions                   -> autoharness/data/.github/instructions
     .github/prompts                        -> autoharness/data/.github/prompts
     .github/copilot-instructions.md        -> autoharness/data/.github/copilot-instructions.md
     .github/copilot-review-instructions.md -> autoharness/data/.github/copilot-review-instructions.md
     docs                                   -> autoharness/data/docs
     AGENTS.md                              -> autoharness/data/AGENTS.md
   PREFER deriving this list FROM pyproject.toml at run time rather than hard-coding it, so a future force-include addition cannot silently escape the gate.
   This whole surface is INVISIBLE to the test suite, which runs from the source tree via pythonpath = ["src"].
