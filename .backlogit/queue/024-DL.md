# Full-suite test-order/global-state pollution: bisect to a minimal reproducing pair, then fix at source

## Problem Frame

<!-- BEGIN:problem-frame -->
Five tests fail ONLY in a full-suite run; each passes in isolation, and all five pass when the three `tests/test_scope_containment_*` modules are excluded. Confirmed pre-existing on merge-base `b9d91b18` with the originating task's changes fully stashed out.

AFFECTED (victims):
1. `tests/test_gate_pipeline_topology_cli.py::PipelineTopologyStorageRootResolutionTests::test_backlog_only_workspace_succeeds` — subprocess `git init` exits 128 (ERROR, `check=True`)
2. `tests/test_gates_topology.py::FilesystemTopologyReadersTests::test_empty_queue_and_archive_dirs_pass_as_zero_shipments`
3. `tests/test_repo_root_artifacts.py::RepoRootTrackedJsonAllowlistTest::test_root_tracked_json_matches_allowlist`
4. `tests/test_telemetry_gitignore_template.py::MetricsGitignoreTests::test_git_check_ignore_matches_metrics_artifacts`
5. `tests/test_telemetry_gitignore_template.py::MetricsEmissionHardGateTests::test_emitted_metrics_artifacts_are_never_tracked` (ERROR, `check=True`)
Signature: 3 failures + 2 errors; the 2 errors are exactly the two `check=True` git-subprocess paths.

STAGE READ-ONLY STATIC FINDINGS (new evidence, narrows the hypothesis space):
- REFUTED — cwd rebinding: there is NO `os.chdir`, `monkeypatch.chdir`, or any `chdir(` call anywhere under `tests/`.
- REFUTED — environment leakage: there is NO bare `os.environ[...] = ...` assignment anywhere under `tests/`; the only `patch.dict(os.environ, ...)` uses are context-managed (`test_gate_pipeline_topology_cli.py:273`, `test_gate_dag_readiness_cli.py`), and no `mock.patch(...).start()` is left unstopped. `GIT_DIR`/`GIT_CONFIG*`/`HOME`/`TMPDIR` are never touched.
- REFUTED — working-tree writes by the suspected polluters: the three `test_scope_containment_*` modules perform no writes into the live working tree; their `tempfile` use is system-temp and context-managed.
- LEADING STRUCTURAL SUSPECT (58 sites): `tempfile.TemporaryDirectory(dir=Path.cwd())` creates temp trees INSIDE the live repository working tree — `test_gates_topology.py` (34), `test_backlog_root.py` (16), `test_gate_pipeline_topology_cli.py` (5), `test_gate_dag_readiness_cli.py` (3). Victims 1 and 2 live in two of those files, and victims 3/4/5 all shell out to `git` against the real repo root (`git ls-files`, `git check-ignore`, `git status`). This couples the suite to ambient process cwd and pollutes the working tree; on Windows, cleanup races and handle retention make it a credible carrier.
- The three suspected polluter modules are the suite's heaviest: they render every template pair through `_derive_template_variables`/`_render_template` and AST-parse sibling test modules.

CONCLUSION ON DIAGNOSABILITY: the exact causal predecessor is NOT determinable without EXECUTING the suite. Stage's role boundary forbids running build systems, test suites, or linters. Therefore the plan MUST front-load a bounded, protocol-driven empirical bisection executed by Ship, and MUST NOT ship a speculative fix.

SOURCE REFS (P-021 traceability): task 138.001-T; feature 138-F; shipment 146-S; PR #376 (reconciled from `N/A`, see notes); review-thread N/A (none exists).

## Options

<!-- BEGIN:options -->
(a) BLIND-HARDEN THE VICTIMS — add defensive setUp/tearDown (cwd snapshot/restore, env snapshot/restore, temp-dir isolation) to the five failing tests without identifying the polluter.

(b) BISECT FIRST, FIX AT SOURCE — run a bounded binary search over the suspected polluting module set to isolate a minimal reproducing pair, then remediate the polluting test's own state leakage.

(c) FORCE / PIN MODULE ORDER — serialise or pin execution order so the pollution never reaches the victims.

(d) MARK EXPECTED-FAILURE OR SKIP-ON-WINDOWS — accept the 5 as environment-specific and suppress them.

(e) WON'T-FIX — declare it a local dev-box artefact, since hosted CI is green.

## Chosen Direction

<!-- BEGIN:chosen-direction -->
CHOSEN: (b)+(a) SEQUENCED — BOUNDED EMPIRICAL BISECTION FIRST, then a targeted fix at the SOURCE of the pollution, plus two unconditional hygiene items and an AST-based structural regression guard. Explicitly REJECT (c) masking, (d) skipping, and (e) won't-fix.

WHY BISECT FIRST. Stage's static analysis REFUTED the two mechanisms the stash entry hypothesised ("cwd, env"), and can go no further without executing the suite — which is outside Stage's role boundary. A blind fix would therefore be a guess dressed as a remediation. The bisect is cheap (~8 rounds of a bounded re-run), deterministic, and produces the one artifact the fix needs: a MINIMAL REPRODUCING PAIR (polluter test ID -> victim test ID) plus the verbatim git stderr behind the exit-128.

BOUNDED DIAGNOSIS PROTOCOL (fits one 2h task; Ship executes, Stage does not):
1. Baseline on the CANONICAL gate (`$env:PYTHONPATH='src'; python -m unittest discover -s tests`, per `docs/compound/097-S-canonical-unittest-gate.md`). Capture the 5 IDs and, for each, the FULL stderr — especially the `git init` exit-128 message text.
2. Confirm the exclusion result: rerun with the three `test_scope_containment_*` modules excluded; expect green. If NOT green, the entry's premise is wrong and the task STOPS and returns to Stage.
3. Binary-search the polluting set: run {candidate subset of the three modules} + {the 5 affected tests} only. Halve by module, then by TestCase class, then by test method. <= 8 rounds.
4. Record the minimal reproducing pair and the observed mechanism verbatim.
5. HARD STOP: if the minimal pair is not isolated inside the time box, STOP and hand back to Stage with the narrowed candidate set. Do NOT proceed to a speculative fix. (Circuit-breaker discipline: no fourth attempt.)

THEN, remediation at the source of the confirmed pollution (shape specified once the pair is known; constrained to the polluting test's own setUp/tearDown or fixture scoping, NOT to weakening any of the 5 victims' assertions).

UNCONDITIONALLY CORRECT REGARDLESS OF THE BISECT RESULT (do these anyway):
U1. Remove ambient-cwd coupling: replace all 58 `tempfile.TemporaryDirectory(dir=Path.cwd())` sites with an explicit anchor. These create temp trees INSIDE the live working tree and make every one of those tests depend on ambient process cwd. Files: `test_gates_topology.py` (34), `test_backlog_root.py` (16), `test_gate_pipeline_topology_cli.py` (5), `test_gate_dag_readiness_cli.py` (3). NOTE: some of these tests may legitimately require the temp tree to be inside the repo (workspace-containment checks) — where that is true, anchor to `Path(__file__).resolve().parents[1]` (deterministic repo root) rather than `Path.cwd()` (ambient). This is a behaviour-preserving de-coupling, not a relocation.
U2. Make the two `check=True` git subprocess sites self-diagnosing: capture stdout/stderr and assert with the captured stderr in the failure message, so the next exit-128 names its own cause instead of surfacing as a bare CalledProcessError.
U3. AST-based structural regression guard forbidding NEW `TemporaryDirectory(dir=Path.cwd())` in `tests/`, per `docs/compound/2026-08-21-ast-based-structural-regression-guards-beat-line-regex.md` — a line-regex guard would be evaded by a multi-line call.

WHY NOT (c) FORCE ORDER. `unittest discover` order is already deterministic; pinning it proves nothing and preserves the latent defect for the first person who adds a module.
WHY NOT (d) SKIP/XFAIL ON WINDOWS. Windows IS the canonical local gate surface for this repository, and Ship's local build gate is a merge prerequisite (P-018). Marking them expected-failure converts a real gate defect into permanent invisible debt. Precedent `docs/compound/2026-08-15-checksum-drift-fix-correctly-surfaces-preexisting-self-hosted-customization.md`, applied in the inverse: do not bend the check to hide reality.
WHY NOT (e) WON'T-FIX. Five persistently-red tests have already contaminated the runtime-verification evidence of at least three consecutive shipments (146-S, 147-S and 145-S closure records each had to explain them away). That is a compounding evidence-integrity cost, not a cosmetic one.
<!-- END:chosen-direction -->

## Open Questions

<!-- BEGIN:open-questions -->
R1 (ACCEPTED UNCERTAINTY, mitigated by the protocol): the exact polluting predecessor is UNKNOWN at plan time and is not knowable within Stage's role boundary. Mitigation: task 1 is a bounded, protocol-driven bisect with an explicit HARD STOP and hand-back, so the uncertainty is time-boxed and cannot silently expand into speculative refactoring.

R2: U1 touches 58 call sites across 4 test modules. Even though each edit is mechanical, a wrong anchor can silently change what a test asserts — several of these tests exercise WORKSPACE-CONTAINMENT logic where "inside the repo" is semantically required. Each file must be reviewed for containment intent before its anchor is changed; anchor to the deterministic repo root, never relocate a containment test to system temp. This is the main reason this plan requires P-006 hardening.

R3: the fix must not weaken any of the five victim tests. `test_root_tracked_json_matches_allowlist` in particular is itself a regression guard (133-F/142-S) whose whole value is failing loudly; relaxing its allowlist or its assertion would destroy the guard while appearing to "fix" the suite.

R4: a Windows-only defect cannot be regression-guarded by hosted Linux CI. The regression guard must therefore be STRUCTURAL (U3, AST-based, platform-independent) rather than behavioural, or it will not run where the defect lives.

R5 (SCOPE GUARD): this deliberation authorises test-isolation work ONLY. If the bisect reveals the pollution originates in PRODUCTION code (a module-level cache or global in `src/autoharness/`), that is a DIFFERENT contract surface and must re-enter P-021 capture rather than being fixed inline. Stage's static scan found no such cache in `autoharness/backlog_root.py` or `autoharness/gates/topology.py`, but the scan was not exhaustive.

REQUIRES PLAN HARDENING: YES (P-006) — unknown root cause at plan time + a 58-site mechanical change across four test modules + a genuine masking hazard.
