# Repair P-021 contract-test loads of the archived 019-DL deliberation artifact (baseline suite-red prerequisite to 144-S)

## Problem Frame

<!-- BEGIN:problem-frame -->
The configured pytest suite is RED at branch HEAD `aea3b60a` before shipment 144-S begins, for a reason neither 144-S nor 145-S owns.

`tests/test_scope_containment_boundary_contract.py:127` and `tests/test_scope_containment_semantics_contract.py:137` each build a hardcoded path `<repo>/.backlogit/queue/019-DL.md` and `.read_text()` it inside `setUpClass`. The 019-DL deliberation artifact was ARCHIVED (merge `f72109e2`, PR #374) and now lives only at `.backlogit/archive/019-DL.md`. Verified read-only: `git cat-file -e origin/main:.backlogit/queue/019-DL.md` exits 128 (absent) while `git cat-file -e origin/main:.backlogit/archive/019-DL.md` exits 0 (present); the local worktree agrees. Because the read happens in `setUpClass`, the FileNotFoundError collapses BOTH modules' entire test classes, producing broad setup failures rather than a single targeted failure.

WHY THIS BLOCKS: Ship evaluates the full configured suite at each task's completion gate. With the baseline red, NO task in 144-S or 145-S can go green on its own merits — every task would fail a gate it did not break. This is an execution-blocking prerequisite, not a nice-to-have.

WHY IT IS NOT ABSORBED (P-021 C1 — FAILS):
* 144-S / `136-F` owns the `backlogit docs lint` + plan-frontmatter surface (docline lint restoration).
* 145-S / `137-F` owns the agent-template/dogfood paired-edit contract + stash-archive operation-naming surface.
* This defect lives on the P-021 scope-containment CONTRACT-TEST harness surface, specifically deliberation-artifact path resolution. That surface is in neither shipment's contract. Absorbing it into either would be a C1 violation, so it is captured (stash `7852CE0D`), deferred, and routed through normal intake into its own feature and its own prerequisite shipment.

ROOT CAUSE CLASS: backlog lifecycle drift. A test asserts against a live governance artifact by its CURRENT-AT-AUTHORING-TIME lifecycle location. The boundary module's own comment at line 128-129 admits this ("Still in queue (not yet archived) at the time this test was authored"), so the failure mode was foreseen and simply not guarded. Any future queue→archive transition of any swept artifact reproduces it.
<!-- END:problem-frame -->

## Options

<!-- BEGIN:options -->
OPTION A — Repoint both loads at the archive path.
Change the two literals to `.backlogit/archive/019-DL.md`.
+ Smallest possible diff; immediately green.
- Zero drift protection. Encodes a second lifecycle-volatile literal, so the identical defect returns on the next lifecycle move (and 019-DL's archive location is itself not terminal: the abandoned 138-S root migration `.backlogit`→`.backlog` would break it again).
- Leaves the failure mode undetected until the suite is next red for a reason nobody expected.
REJECTED as the sole change: it repairs the instance, not the class, and the operator explicitly asked for a regression assertion preventing future queue/archive lifecycle drift.

OPTION B — Shared lifecycle-stable resolver in the base contract module, plus a regression guard. [CHOSEN]
Add one helper to `tests/test_scope_containment_policy_contract.py` — the module both siblings ALREADY import from, so this rides the existing one-way dependency edge (011 → 013 → 012) and introduces no new import topology or cycle. The helper resolves the backlog root via the already-shipped, already-tested `autoharness.backlog_root.resolve_backlog_root` (importable because `pyproject.toml` sets `pythonpath = ["src"]`), then probes `queue/<id>.md` then `archive/<id>.md`, returning the first that exists and raising a descriptive error naming every probed path on a miss. Both sibling modules call it instead of hardcoding.
+ Repairs the class, not the instance: covers queue→archive drift AND the `.backlogit`→`.backlog` root axis for free, because `resolve_backlog_root` already implements backlogit's root precedence and its both-roots-present fail-closed rule.
+ Reuses shipped, tested code rather than inventing an abstraction.
+ Failure message names the probed paths, so the next drift is diagnosed in one read instead of a bare FileNotFoundError inside `setUpClass`.
- Adds a `tests` → `src/autoharness` import coupling that these three modules did not previously have.
  MITIGATION / why accepted: the coupling is to a narrow, public, independently-contract-tested helper (`tests/test_backlog_root.py` covers override precedence, both-roots-present, and symlink rejection); `pythonpath = ["src"]` already makes it a first-class test-time import; and the alternative — reimplementing root precedence locally in a test module — would be strictly worse duplication.

OPTION C — Generic backlog-path abstraction in `src/autoharness/` consumed by tests.
- Explicitly out of scope per operator instruction, and unwarranted: `resolve_backlog_root` ALREADY is that abstraction. Building another would widen blast radius into the shipped CLI distribution (a P-006 hardening trigger) to fix three lines in a test harness.
REJECTED.

OPTION D — Vendor a copy of 019-DL into `tests/fixtures/`.
- Defeats the purpose. These are universal negative-guard sweeps whose whole value is that they read the LIVE governance artifact; a frozen copy would pass while the real artifact drifted, converting a loud failure into a silent false green.
REJECTED as actively harmful.
