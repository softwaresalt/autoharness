Add `subagent_route_drift`. For each registry site (build_site_registry(...).sites: managed and workspace-authored agents enumerated from disk) compare the installed frontmatter model_family, model_provider, reasoning_effort, context_tier to the resolver's output. A workspace-authored agent has no default tier, so it resolves a route only when it has a binding; an unbound workspace-authored agent has nothing to compare and is skipped. Behavior depends on whether the workspace DECLARES BINDINGS (the opt-in): with bindings, a managed (manifest-rendered) agent that drifts fails closed and a (bound) workspace-authored agent produces one advisory warning (provenance split reused from frontmatter_conformity, 037-DL); without bindings, drift is reported only as non-blocking `info` lines (count plus at most 20 ids) and `ok` stays true. Every drift also yields a `refresh-route-frontmatter` migration proposal. The opt-in is `bindings` non-empty, NOT schema_version, so this workspace (1.2.0 after B5, no bindings) does not turn red over its 13 stale subagents (installed routes gpt-5.6-luna / claude-sonnet-5 with empty provider+effort, matching neither current tier1 nor tier2). Test scenarios: bindings + managed drift fails; bindings + bound workspace-authored drift (on-disk agent, no manifest entry) warns and does not change ok; an unbound workspace-authored agent is skipped; no bindings + drift is info only and ok stays true; matching frontmatter passes; proposals emitted; opt-in predicate tested in both directions.
