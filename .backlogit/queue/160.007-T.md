BRANCH (b) - no such mechanism exists:
- Materialize a TRACKED payload directory `plugin-payload/` from the resolved manifest, and repoint marketplace.json `source` from "." to that directory.
- `plugin-payload/` IS TRACKED AND COMMITTED. That is the entire point: a tracked directory is present in every consumer checkout, so `source` actually resolves. A `dist/plugin/`-style gitignored build-output path could never be fetched by a consumer and is prohibited.
- `plugin-payload/` IS THE PLUGIN CHANNEL'S GENERATED OUTPUT ROOT, NOT A CLASSIFIER INPUT (plan AC3d). It is declared in the manifest's `generated_output_roots` key by 160.003-T and is NOT an `include` rule in any channel. THIS IS LOAD-BEARING: if it were a plugin `include` input, the generator's own output would become its next run's input - run two would resolve `plugin-payload/**` as source and write it INSIDE `plugin-payload/`, giving `plugin-payload/plugin-payload/...`, and every further run would nest deeper. `generate --check` would then report drift that regenerating can NEVER clear, failing the release gate permanently. The resolver (160.004-T) removes every path under a declared output root from the tracked-path enumeration BEFORE classification, in all three channels, which is also what keeps the tree out of the wheel and the sdist as a derived duplicate.
- EXCLUSION FROM CLASSIFIER INPUT IS NOT EXCLUSION FROM PUBLICATION: the tree stays tracked, committed and consumer-fetchable, and remains the directory `source` points at.
- The materialization step MUST invoke the single generation command (160.014-T); it must not reimplement resolution, and it must NOT implement the self-exclusion itself - that belongs in the resolver so every other consumer of the resolver is protected too.
- Because `plugin-payload/` is both TRACKED and DERIVED, it inherits H1's generate-and-assert contract exactly as pyproject.toml and marketplace.json do: `generate --channel plugin --check` must detect drift between the committed tree and the manifest, and CI runs it.
- The release-path gate (160.015-T) must cover the plugin channel via `generate --channel all --check`, where `all` means wheel, sdist and plugin.

A trusted generator writing over a tracked file destroys committed content just as surely as an untrusted one; "it is a declared output root" describes the path ROLE, not the REVERSIBILITY of the write. The binding rule (plan H2, "Principle VII generation rule"):
  * PARTITION BEFORE WRITING. Every materialization run partitions its planned writes into CREATE (target absent and untracked), NO-OP (tracked, bytes byte-identical - destroys nothing, treated as CREATE-equivalent so idempotent regeneration does not trip the gate), OVERWRITE (tracked, bytes differ) and REMOVE (tracked, no longer resolved by the manifest). The generation command (160.014-T) computes and reports this partition and REFUSES TO PROCEED on a non-empty OVERWRITE-or-REMOVE set without approval.
  * A NON-EMPTY OVERWRITE-or-REMOVE SET REQUIRES FRESH LIVE OPERATOR APPROVAL obtained IN THE SESSION PERFORMING THE RUN over a channel THE AGENT CANNOT SYNTHESIZE (R-3) - INSIDE `plugin-payload/` exactly as anywhere else. Recorded pre-change bytes, backlog comments, this task text, prior-session approvals and any approval the agent could itself author are AUDIT EVIDENCE ONLY and can NEVER serve as that authorization. With no such channel available, HALT and do not perform the generation (R-4); do not downgrade, partially apply, or defer-and-proceed.
  * A RUN WHOSE OVERWRITE AND REMOVE SETS ARE BOTH EMPTY REQUIRES NO APPROVAL AND MUST NOT DEMAND ONE. The FIRST materialization of the tree is pure CREATE and is explicitly permitted unattended. Gating it would train reflexive approval and destroy the value of the gate on the runs that matter.
  * WHY THIS IS NOT MERELY PROCEDURAL: the first materialization is harmless, but EVERY SUBSEQUENT regeneration after a manifest change is OVERWRITE and/or REMOVE over tracked, committed payload content - and that is precisely the run in which a manifest mistake silently deletes payload files a consumer depends on. The cycle-3 wording exempted exactly that run.
