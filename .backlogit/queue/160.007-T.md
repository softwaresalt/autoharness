CONSUMER-FETCHABILITY IS A HARD CONSTRAINT ON EVERY BRANCH (AC3c, NEW IN CYCLE 2, FINDING 5): the `source` this task commits MUST resolve to a path a consumer can fetch from a repository checkout. `dist/.gitignore` contains `*`, so ANY path under dist/ is untracked, absent from every consumer checkout, and would make the plugin install fail outright. Pointing `source` at a gitignored or otherwise untracked path is PROHIBITED. This task must not assume unsupported marketplace behaviour or rely on an artifact that is never published.

BRANCH (a) - marketplace source supports an exclusion/allowlist mechanism:
- Wire the manifest-derived exclusions directly into `.github/plugin/marketplace.json`, GENERATED by `python -m build_support.payload generate --channel plugin`. The declaration is a derived artifact; hand edits are prohibited and detected by `generate --check`.
- `source` stays "." and is trivially fetchable; test_plugin_source_path_is_tracked_and_fetchable is satisfied by the repository root itself.

BRANCH (b) - no such mechanism exists (REPLACED IN CYCLE 2; the previous dist/plugin/ strategy is WITHDRAWN):
- Materialize a TRACKED payload directory `plugin-payload/` from the resolved manifest, and repoint marketplace.json `source` from "." to that directory.
- `plugin-payload/` IS TRACKED AND COMMITTED. That is the entire point: a tracked directory is present in every consumer checkout, so `source` actually resolves. The cycle-1 design pointed `source` at gitignored build output, which no consumer could ever fetch.
- The materialization step MUST invoke the single generation command (160.014-T); it must not reimplement resolution.
- Because `plugin-payload/` is both TRACKED and DERIVED, it inherits H1's generate-and-assert contract exactly as pyproject.toml and marketplace.json do: `generate --channel plugin --check` must detect drift between the committed tree and the manifest, and CI runs it. It is classified in the manifest (160.003-T) as INCLUDE-in-plugin / EXCLUDE-from-wheel-and-sdist so the payload is never shipped twice.
- The release-path gate (160.015-T) must cover the plugin channel via `generate --channel all --check`.

BRANCH (c) - neither mechanism is demonstrably supported: the spike HALTS TO THE OPERATOR. This task does not begin, and does not self-authorize an alternative delivery mechanism (release artifact, external installer, or any other) - that is a new decision requiring operator approval.
