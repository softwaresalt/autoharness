Implement the ONE deterministic generation/regeneration command that derives the static per-channel payload tables from the manifest, so `pyproject.toml` and `.github/plugin/marketplace.json` never become a second source of truth.

WHY THIS IS A SEPARATE TASK (Orchestrator review-fix cycle 1, findings 6 and 7): hardening decision H1 chose "generated-and-asserted" over a dynamic hatchling build hook. That decision makes the static channel tables DERIVED artifacts, which is only safe if regeneration is deterministic, single-pathed, and drift-detecting. That is a distinct deliverable from resolving the manifest, and folding it into the resolver task (160.004-T) pushed that task past the 2-hour rule.

BLOCKED BY 160.004-T: this command CONSUMES the resolver. It must not reimplement globbing, overlay merging, or classification.

THE COMMAND (exactly one, no alternatives):

    python -m build_support.payload generate --channel {wheel|plugin|all}
    python -m build_support.payload generate --channel all --check

- `generate` WRITES the derived tables: the hatchling include table for the wheel channel and the payload/source declaration for the plugin channel.
- `--check` re-derives and compares WITHOUT writing, exiting non-zero on any drift, and printing the drifting paths. This is the mode CI (160.015-T) and the composition tests call.
- Two output formats are produced from one resolution: TOML (pyproject build tables) and JSON (marketplace declaration). Serialization for both must round-trip through `--check` unchanged.

DETERMINISM REQUIREMENTS (all asserted by test):
- Byte-identical output across runs on an unchanged manifest. Running `generate` twice produces no diff.
- Stable sort order; no reliance on set or dict iteration order.
- No timestamps, no absolute paths, no host/user/environment values, no build counters embedded in output.
- Determinism must hold across operating systems: path separators are normalized to the forward-slash form both channel formats expect. A Windows run and a POSIX run of `generate` on the same manifest produce byte-identical output. Assert this explicitly - a packaging table that differs by platform reintroduces multiple truths through the back door.

SINGLE-PATH REQUIREMENT: there is exactly ONE generation path. Adding a second (a Makefile target, a shell wrapper, an inline CI snippet, or a test helper that re-derives) recreates the multiple-truths defect this task exists to prevent. CI and the tests must INVOKE this command, never reimplement it. A test asserts that no other module or workflow step derives a channel table.

HAND-EDIT PROTECTION: each derived table carries a generated-by header naming this exact command, so a human editing it is warned in place. `--check` is what mechanically detects the edit.

SAFETY MODE (SHIP-10 plan H2): careful + freeze-scope. Writes are confined to `build_support/` and `tests/`. This task builds the command but does NOT wire either channel - it must not commit generated content into pyproject.toml or marketplace.json (that is 160.006-T and 160.007-T). `src/autoharness/` is read-only (invariants I1/I2). `--check` is read-only by construction and must be safe to run against a dirty working tree. NO-PUBLISH. Full mode text: docs/plans/2026-09-03-minimal-copilot-plugin-payload-plan.md section Plan Hardening -> H2.

ACCEPTANCE: AC1 (manifest remains sole source of truth). `generate` is idempotent and byte-deterministic including cross-platform; `--check` detects drift and exits non-zero; exactly one generation path exists and a test asserts it.
