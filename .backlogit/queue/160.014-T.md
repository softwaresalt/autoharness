THE COMMAND (exactly one, no alternatives):

    python -m build_support.payload generate --channel {wheel|plugin|all}
    python -m build_support.payload generate --channel all --check

- The channel enum is CLOSED and has exactly TWO members - wheel and plugin - plus the aggregate `all`, which means wheel AND plugin. No third channel, and no channel-shaped string accepted outside the enum; an unrecognized channel FAILS CLOSED with a non-zero exit rather than defaulting. (Cycle 5, finding 1: the sdist was removed from the enum when that channel was de-scoped as a P-021 C1 expansion; evidence preserved in deferred entry 99818C6D. Re-adding it here is scope expansion and requires that entry to be deliberated first.)
- `generate` WRITES the derived tables: the hatchling include table for the wheel channel, and the payload/source declaration (and, under branch (b), the materialized tree) for the plugin channel. It accepts a target directory so it can write somewhere other than the repository files. THERE ARE TWO DISTINCT INVOCATION SHAPES AND CONFLATING THEM DELETES GATE A (clarified in cycle 7; the withdrawn wording "every test and `--check` invocation MUST use a declared ephemeral scratch target" collapsed them into one rule):
  (i) GENERATION TEST RUNS - WRITING runs. Every test that invokes `generate` MUST be given a target directory created UNDER THE PLAN'S SINGLE DECLARED WORKSPACE-CONTAINED RUN ROOT `dist/.autoharness-scratch/<run-id>/` (cycle 8, item 1 - this REPLACES the withdrawn `tempfile.TemporaryDirectory()`/OS-temporary-root form, which placed the target OUTSIDE the workspace where nothing in this repository can constrain, inspect, or reason about it). BINDING CONDITIONS, ALL FAIL-CLOSED: the run root's CANONICAL RESOLVED PATH must be a STRICT DESCENDANT of the workspace root, and a run that cannot prove containment ABORTS RATHER THAN WRITING; `<run-id>` is UNIQUE PER RUN so concurrent runs never collide; the path is NEVER derived from `TMPDIR`, `TEMP`, `TMP` or any other OS temporary-location environment variable; it is GITIGNORED by the existing `dist/.gitignore` (which contains `*`), so it can never dirty the working tree; and it is a declared `generated_output_roots` entry, so it is REMOVED FROM CLASSIFIER INPUT BEFORE MATCHING and from every manifest, and therefore carries NO include and NO exclude rule of its own. IT IS NOT AUTO-DELETED when the test finishes - bounded cleanup of this root is a SEPARATELY APPROVED DESTRUCTIVE ACTION, not a side effect of a test run. Such a run WRITES ONLY THERE and mutates NO repository file. (Plan AC3e's declared scratch-root list is authoritative and is NOT restated here.)
  (ii) `--check` - a NON-WRITING run, and therefore NOT given an ephemeral output target at all. It READS THE COMMITTED TARGETS - `pyproject.toml`'s wheel build table and `.github/plugin/marketplace.json`'s payload/source declaration, and under branch (b) the tracked `plugin-payload/` tree - renders the expected region TO MEMORY, and performs the CANONICAL BYTE COMPARISON specified below against those COMMITTED bytes read in BINARY mode. IT WRITES NOTHING, ANYWHERE, INCLUDING INTO AN EPHEMERAL ROOT. Directing `--check` at an ephemeral scratch target would compare freshly generated output against a freshly generated copy of itself - trivially equal, detecting NO drift - which would silently delete 160.015-T's Gate A while still reporting green. `--check` IS SAFE TO RUN AGAINST A DIRTY WORKING TREE precisely because it is read-only by construction.
- `--check` re-derives and compares WITHOUT writing, exiting non-zero on any drift and printing the drifting paths. This is the mode CI (160.015-T) and the composition tests call.
- Output formats produced from one resolution: TOML (the pyproject wheel build table) and JSON (the marketplace declaration) - TWO formats, not three (cycle 6, finding 16: the stale `all three formats` wording is withdrawn along with the third channel). Serialization for both must round-trip through `--check` unchanged.
- DETERMINISTIC RENDERING, STDLIB ONLY, NARROWLY SCOPED (cycle 6, finding 5). Python 3.10 - the floor in `requires-python` - has NO TOML WRITER in the standard library, and `tomllib` is read-only and 3.11+. DO NOT ADD tomli-w, toml, tomlkit, OR ANY OTHER SERIALIZER, and do not write a general TOML serializer: this command does not need to serialize arbitrary TOML, only ONE TABLE SHAPE.
  TOML: the emitted region is exactly a `[tool.hatch.build.targets.wheel.force-include]` table whose every entry is `"<source>" = "<destination>"`. No nested tables, arrays, non-string values, or inline tables. Lines are rendered as `"{source}" = "{destination}"` and SORTED BY THE SOURCE STRING using a plain code-point `sorted()` over `str`, never a locale-aware collation. ESCAPING IS ENFORCED BY REJECTION, NOT BY ESCAPING MACHINERY: the 1.0.0 schema constrains `src` and `dest` to a character class EXCLUDING the double-quote, backslash, control characters (U+0000-U+001F, U+007F) and any non-forward-slash path separator, so a manifest containing one is a SCHEMA VALIDATION FAILURE at 160.003-T/160.018-T and this renderer can never emit a string it cannot round-trip. ROUND-TRIP VERIFICATION IS MANDATORY: re-read the emitted region with `tomllib` on 3.11+, or with this command's own single-shape inverse line reader on 3.10, and assert the parsed mapping EQUALS the input mapping; failure is a HARD ERROR, not a warning.
  JSON: `json.dumps(obj, indent=2, sort_keys=True, ensure_ascii=False, separators=(",", ": "))` plus a single trailing newline. `sort_keys=True` is what makes key order independent of dict insertion order. Rewrite ONLY the payload/source declaration region and preserve every other committed key value verbatim (plan H2).
  BOTH FORMATS - BYTE CONTRACT (cycle 6, finding 17): UTF-8 WITHOUT BOM (written with `encoding="utf-8"`, `newline="\n"`; assert the emitted bytes do not begin with EF BB BF); LF ONLY on every platform, no CR anywhere in output; EVERY PATH IN OUTPUT USES FORWARD SLASHES, normalized ONCE at the resolver boundary via `PurePosixPath` rather than at each render site.
  `--check` COMPARES CANONICAL BYTES: render to memory, encode UTF-8, and compare against the committed file read in BINARY mode. It MUST NOT compare decoded text, normalize newlines before comparing, or strip a BOM - each of those lets a real byte-level drift pass as equal, which is precisely the drift the check exists to catch.

DESTRUCTIVE-WRITE PARTITION IS THIS COMMAND'S JOB (Constitution Principle VII; plan H2 "Principle VII generation rule"; added in extended review-fix cycle 4, finding 3). OVERWRITING OR REMOVING TRACKED CONTENT IS DESTRUCTIVE REGARDLESS OF THE DIRECTORY IT SITS IN, REGARDLESS OF WHETHER THE MANIFEST RESOLVES IT, AND REGARDLESS OF HOW TRUSTED THIS GENERATOR IS. Because this is the SINGLE generation path, the enforcement point belongs HERE - implementing it only in the plugin wiring task would leave every other caller of the generation path unprotected, which is the same error AC3d corrected by putting self-exclusion in the resolver rather than the generator. Required behaviour:
- BEFORE WRITING ANYTHING, partition the planned writes EXACTLY AS SPECIFIED IN PLAN AC3e. THE CLASS DEFINITIONS ARE NOT RESTATED HERE (cycle 6, finding 13). Plan AC3e is the SINGLE CANONICAL two-axis contract - destination axis first (the declared workspace-contained ephemeral scratch root vs. repository-scope), outcome axis second - and its class table is authoritative. This record previously restated a SIX-CLASS list which had already drifted from the plan's contract, and the cycle-3 FOUR-CLASS list (CREATE/NO-OP/OVERWRITE/REMOVE) survived in three places at once precisely because each place restated it. THE PLAN'S TABLE CARRIES EIGHT DISTINCT LABELS OVER EIGHT ROWS (cycle 8, item 5: the "seven classes" cardinal was WRONG AS COUNTED - the four EPHEMERAL_* labels plus CREATE, NO-OP, OVERWRITE and REMOVE are eight, and the stale seven created a P2 ambiguity about which label was supposedly absent). NO ROW AND NO CLASS IS ADDED BY THAT CORRECTION; only the count is fixed. THE APPROVAL SET IS EXACTLY OVERWRITE UNION REMOVE AT REPOSITORY SCOPE, per AC3e - unchanged. - TRACKED-NESS IS EVALUATED AGAINST THE TREE THE RUN EXECUTES IN, NEVER "AT THE BASELINE COMMIT" (cycle 6, finding 10). The withdrawn wording - tracked if `git ls-files --error-unmatch` resolves it AT THE BASELINE COMMIT recorded by 160.001-T - names an operation that DOES NOT EXIST: `git ls-files` reads the index and working tree and takes no commit argument. - UNTRACKED REPOSITORY CONTENT MUST NEVER BECOME SILENTLY PUBLISHABLE. A repository-scope CREATE leaves an UNTRACKED file, and an untracked file is absent from a consumer-fetchable checkout (AC3c). This command therefore MUST NOT resolve any payload member from an untracked path, and MUST fail closed if a resolved member is UNTRACKED IN THE TREE UNDER TEST (per the tracked-ness rule above, cycle 6 finding 10) - creating a file never promotes it into a payload; only committing does, and committing is a change the operator sees.

- THIS COMMAND COMPUTES AND REFUSES; IT DOES NOT ADJUDICATE APPROVAL (cycle 6, finding 7). That is impossible by definition: non-synthesizability means no signal the process can read is sufficient, since any file, env var, argument or backlog comment this command could check is one the agent could also write. Read literally it also DEADLOCKED 160.006-T and 160.007-T, whose entire purpose is a MANDATORY tracked overwrite of pyproject.toml and marketplace.json. THE GATE IS SPLIT ACROSS THE TWO LAYERS THAT CAN EACH HOLD THEIR HALF:

DETERMINISM REQUIREMENTS (all asserted by test):
- Byte-identical output across runs on an unchanged manifest. Running `generate` twice produces no diff.
- Stable sort order; no reliance on set or dict iteration order.
- No timestamps, no absolute paths, no host/user/environment values, no build counters embedded in output.
- Determinism must HOLD across operating systems: path separators normalized to the forward-slash form BOTH OUTPUT FORMATS expect - TWO formats, TOML and JSON, not three (cycle 6, finding 16: the stale `all three formats` wording survived the cycle-5 sdist de-scope). Normalization happens ONCE at the resolver boundary via PurePosixPath, not at each render site. A Windows run and a POSIX run of `generate` on the same manifest produce BYTE-IDENTICAL output - identical bytes, not merely equivalent text: UTF-8 with no BOM, LF-only terminators, forward slashes. Assert this explicitly - a packaging table that differs by platform reintroduces multiple truths through the back door.

SINGLE-PATH REQUIREMENT: there is exactly ONE generation path. Adding a second (a Makefile target, a shell wrapper, an inline CI snippet, or a test helper that re-derives) recreates the multiple-truths defect this task exists to prevent. CI and the tests must INVOKE this command, never reimplement it. test_only_one_generation_path_exists asserts that no other module or workflow step derives a channel table.

HAND-EDIT PROTECTION: each derived table carries a generated-by header naming this exact command, so a human editing it is warned in place. `--check` is what mechanically detects the edit.
