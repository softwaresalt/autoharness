Implement the ONE deterministic generation/regeneration command (T6) that derives the static per-channel payload tables from the manifest, so pyproject.toml and .github/plugin/marketplace.json never become a second source of truth.

WHY THIS IS A SEPARATE TASK: hardening decision H1 chose "generated-and-asserted" over a dynamic hatchling build hook. That decision makes the static channel tables DERIVED artifacts, which is only safe if regeneration is deterministic, single-pathed, and drift-detecting. That is a distinct deliverable from resolving the manifest, and folding it into the resolver task (160.004-T) pushes that task past the 2-hour rule.

BLOCKED BY 160.004-T: this command CONSUMES the resolver. It must not reimplement globbing, overlay merging, classification, or generated-output-root self-exclusion.

ALSO BLOCKED BY 160.002-T, THE BLOCKING SPIKE (edge added in extended review-fix cycle 4, finding 4). THIS COMMAND'S BEHAVIOUR IS BRANCH-DEPENDENT AND CANNOT BE BUILT BEFORE THE BRANCH IS KNOWN. Under branch (b) the plugin channel emits the payload/source declaration AND MATERIALIZES A TRACKED OUTPUT TREE; under branch (a) it emits a DECLARATION ONLY, no output root exists, and the destructive-write partition below is empty by construction. test_plugin_generation_is_idempotent is specifically about writing into a tracked output root that EXISTS ONLY UNDER BRANCH (b). Building the generator before 160.002-T resolves means either implementing both paths speculatively or discovering mid-task that the implemented path is the wrong one - the same failure the existing 160.007-T <- 160.002-T edge already prevents for the wiring task, left unencoded here through three cycles. NO CYCLE IS INTRODUCED: 160.002-T is a DAG root with no prerequisites, so it cannot be reachable from this task; the plan's published topological order already places T1 before T6, so this edge makes machine-explicit a constraint the order was honouring by luck rather than by rule.

GREEN RESPONSIBILITY. A task cannot own green for a state it is forbidden to create. This task's safety scope FORBIDS committing into pyproject.toml, marketplace.json or plugin-payload/, because those files belong to 160.006-T, 160.019-T and 160.007-T. Its green ownership is therefore confined to properties of the GENERATOR itself. THIS TASK OWNS GREEN FOR EXACTLY FOUR RED-FIRST CASES, all authored by 160.005-T:
- test_generate_emits_expected_tables_to_a_scratch_target (AC2c) - given the manifest, `generate` writes the expected content to a CALLER-SUPPLIED TARGET DIRECTORY, mutating NO repository file.
- test_generate_is_byte_deterministic_and_cross_platform (AC2c)
- test_only_one_generation_path_exists (AC2c)
- test_plugin_generation_is_idempotent (AC3d, AC2c) - running `generate --channel plugin` twice against the same manifest produces a byte-identical tree with no added nesting level, and a third run still produces no diff. This is the case that catches the recursive-output defect at the generator boundary rather than only at the resolver boundary.

IT DOES NOT OWN the committed-parity cases. Those are properties of the WIRING and are owned per channel by the task authorized to edit that channel's file: test_wheel_generated_table_matches_manifest -> 160.006-T; test_sdist_generated_table_matches_manifest -> 160.019-T; test_plugin_generated_declaration_matches_manifest and test_plugin_payload_conforms_to_the_selected_strategy (RENAMED in extended review-fix cycle 4, finding 6, from test_plugin_payload_tree_is_self_excluded_and_flat; the old name MUST NOT appear in the shipped suite, since 160.017-T's ledger bijection joins on the exact name) -> 160.007-T. This task's prohibition on committing generated content is absolute; it simply does not own any case that would require violating it. Each channel's parity case blocks on that channel's own wiring task.

THE COMMAND (exactly one, no alternatives):

    python -m build_support.payload generate --channel {wheel|sdist|plugin|all}
    python -m build_support.payload generate --channel all --check

- The channel enum is CLOSED and has exactly three members - wheel, sdist, plugin - plus the aggregate `all`, which means wheel AND sdist AND plugin. No fourth channel, and no channel-shaped string accepted outside the enum.
- `generate` WRITES the derived tables: the hatchling include table for the wheel channel, the include/exclude table for the sdist channel, and the payload/source declaration (and, under branch (b), the materialized tree) for the plugin channel. It accepts a target directory so it can write somewhere other than the repository files.
- `--check` re-derives and compares WITHOUT writing, exiting non-zero on any drift and printing the drifting paths. This is the mode CI (160.015-T) and the composition tests call.
- Output formats produced from one resolution: TOML (pyproject wheel and sdist build tables) and JSON (marketplace declaration). Serialization for all must round-trip through `--check` unchanged.

DESTRUCTIVE-WRITE PARTITION IS THIS COMMAND'S JOB (Constitution Principle VII; plan H2 "Principle VII generation rule"; added in extended review-fix cycle 4, finding 3). OVERWRITING OR REMOVING TRACKED CONTENT IS DESTRUCTIVE REGARDLESS OF THE DIRECTORY IT SITS IN, REGARDLESS OF WHETHER THE MANIFEST RESOLVES IT, AND REGARDLESS OF HOW TRUSTED THIS GENERATOR IS. Because this is the SINGLE generation path, the enforcement point belongs HERE - implementing it only in the plugin wiring task would leave every other caller of the generation path unprotected, which is the same error AC3d corrected by putting self-exclusion in the resolver rather than the generator. Required behaviour:
- BEFORE WRITING ANYTHING, partition the planned writes into CREATE (target path absent from the working tree AND untracked), NO-OP (tracked, and the bytes to be written are BYTE-IDENTICAL to the tracked content - destroys nothing, so treated as CREATE-equivalent; this is what keeps idempotent regeneration and test_plugin_generation_is_idempotent from tripping the gate on every run), OVERWRITE (tracked, bytes differ) and REMOVE (tracked, no longer resolved by the manifest).
- The command can REPORT that partition without writing, and REFUSES TO PROCEED when the OVERWRITE-or-REMOVE set is non-empty unless FRESH LIVE OPERATOR APPROVAL has been obtained in the session performing the run, over a channel THE AGENT CANNOT SYNTHESIZE (R-3). Standing, blanket, prior-session and inferred approvals, task text, and backlog comments are AUDIT EVIDENCE ONLY and can NEVER serve as that authorization. With no such channel available the command HALTS (R-4) rather than downgrading, partially applying, or deferring-and-proceeding.
- A RUN WHOSE OVERWRITE AND REMOVE SETS ARE BOTH EMPTY REQUIRES NO APPROVAL AND MUST NOT DEMAND ONE. Writing files that are absent and untracked creates content and destroys none; it is explicitly permitted unattended. Under BRANCH (a) this is ALWAYS the case - no output tree is materialized at all - so branch (a) MUST NOT prompt for approval. A false gate on the harmless path trains reflexive approval and devalues the gate on the branch-(b) regeneration that genuinely destroys tracked content.
- `--check` is READ-ONLY by construction and NEVER requires approval.

GENERATED OUTPUT ROOTS ARE THE RESOLVER'S JOB, NOT THIS COMMAND'S (AC3d): under branch (b), `plugin-payload/` is the plugin channel's declared output root. This command MUST NOT implement the self-exclusion itself - it consumes a resolver (160.004-T) that has already removed every path beneath a declared output root from the tracked-path enumeration, so every other consumer of the resolver is protected by the same rule. This command's obligation is to be IDEMPOTENT over that resolver: writing into the output root must never change what the next resolution returns. test_plugin_generation_is_idempotent is the assertion.

DETERMINISM REQUIREMENTS (all asserted by test):
- Byte-identical output across runs on an unchanged manifest. Running `generate` twice produces no diff.
- Stable sort order; no reliance on set or dict iteration order.
- No timestamps, no absolute paths, no host/user/environment values, no build counters embedded in output.
- Determinism must hold across operating systems: path separators normalized to the forward-slash form all three formats expect. A Windows run and a POSIX run of `generate` on the same manifest produce byte-identical output. Assert this explicitly - a packaging table that differs by platform reintroduces multiple truths through the back door.

SINGLE-PATH REQUIREMENT: there is exactly ONE generation path. Adding a second (a Makefile target, a shell wrapper, an inline CI snippet, or a test helper that re-derives) recreates the multiple-truths defect this task exists to prevent. CI and the tests must INVOKE this command, never reimplement it. test_only_one_generation_path_exists asserts that no other module or workflow step derives a channel table.

HAND-EDIT PROTECTION: each derived table carries a generated-by header naming this exact command, so a human editing it is warned in place. `--check` is what mechanically detects the edit.
