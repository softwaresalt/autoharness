Implement the ONE deterministic generation/regeneration command that derives the static per-channel payload tables from the manifest, so pyproject.toml and .github/plugin/marketplace.json never become a second source of truth.

WHY THIS IS A SEPARATE TASK: hardening decision H1 chose "generated-and-asserted" over a dynamic hatchling build hook. That decision makes the static channel tables DERIVED artifacts, which is only safe if regeneration is deterministic, single-pathed, and drift-detecting. That is a distinct deliverable from resolving the manifest, and folding it into the resolver task (160.004-T) pushed that task past the 2-hour rule.

BLOCKED BY 160.004-T: this command CONSUMES the resolver. It must not reimplement globbing, overlay merging, or classification.

GREEN RESPONSIBILITY (assigned by the RED-FIRST harness 160.005-T) - CORRECTED IN REVIEW-FIX CYCLE 2, FINDING 2. Cycle 1 made this task the green owner of test_generated_tables_match_manifest, a case asserting that the COMMITTED pyproject.toml and marketplace.json tables equal the derived tables - while this task's own safety scope FORBIDS committing into either file, because those files belong to 160.006-T, 160.019-T and 160.007-T. The task was required to reach a state it was forbidden to create, so it had NO ACHIEVABLE COMMITTED COMPLETION STATE. The case was conflating two different properties and is split along that seam. THIS TASK NOW OWNS GREEN FOR EXACTLY:
- test_generate_emits_expected_tables_to_a_scratch_target (AC2c) - a property of the GENERATOR: given the manifest, `generate` writes the expected content to a CALLER-SUPPLIED TARGET DIRECTORY, mutating NO repository file. Fully reachable inside this task's scope.
- test_generate_is_byte_deterministic_and_cross_platform (AC2c)
- test_only_one_generation_path_exists (AC2c)
IT DOES NOT OWN the committed-parity cases. Those are properties of the WIRING and are owned per channel by the task authorized to edit that channel's file: test_wheel_generated_table_matches_manifest -> 160.006-T; test_sdist_generated_table_matches_manifest -> 160.019-T; test_plugin_generated_declaration_matches_manifest -> 160.007-T. This task's prohibition on committing generated content is UNCHANGED; it simply no longer owns a case that required violating it. Downstream gating is preserved and sharpened - each channel's parity case now blocks on that channel's own wiring task rather than on one shared case.

THE COMMAND (exactly one, no alternatives):

    python -m build_support.payload generate --channel {wheel|sdist|plugin|all}
    python -m build_support.payload generate --channel all --check

- The channel enum is CLOSED and includes SDIST (added in cycle 2, finding 3). `all` means wheel AND sdist AND plugin.
- `generate` WRITES the derived tables: the hatchling include table for the wheel channel, the include/exclude table for the sdist channel, and the payload/source declaration for the plugin channel. It accepts a target directory so it can write somewhere other than the repository files.
- `--check` re-derives and compares WITHOUT writing, exiting non-zero on any drift and printing the drifting paths. This is the mode CI (160.015-T) and the composition tests call.
- Output formats produced from one resolution: TOML (pyproject wheel and sdist build tables) and JSON (marketplace declaration). Serialization for all must round-trip through `--check` unchanged.

DETERMINISM REQUIREMENTS (all asserted by test):
- Byte-identical output across runs on an unchanged manifest. Running `generate` twice produces no diff.
- Stable sort order; no reliance on set or dict iteration order.
- No timestamps, no absolute paths, no host/user/environment values, no build counters embedded in output.
- Determinism must hold across operating systems: path separators normalized to the forward-slash form all three formats expect. A Windows run and a POSIX run of `generate` on the same manifest produce byte-identical output. Assert this explicitly - a packaging table that differs by platform reintroduces multiple truths through the back door.

SINGLE-PATH REQUIREMENT: there is exactly ONE generation path. Adding a second (a Makefile target, a shell wrapper, an inline CI snippet, or a test helper that re-derives) recreates the multiple-truths defect this task exists to prevent. CI and the tests must INVOKE this command, never reimplement it. test_only_one_generation_path_exists asserts that no other module or workflow step derives a channel table.

HAND-EDIT PROTECTION: each derived table carries a generated-by header naming this exact command, so a human editing it is warned in place. `--check` is what mechanically detects the edit.

SAFETY MODE (SHIP-10 plan H2): careful + freeze-scope. Writes are confined to build_support/ and tests/. This task builds the command but does NOT wire any channel - it MUST NOT commit generated content into pyproject.toml (160.006-T wheel, 160.019-T sdist), marketplace.json or plugin-payload/ (160.007-T). src/autoharness/ is read-only (invariants I1/I2). `--check` is read-only by construction and must be safe to run against a dirty working tree. NO-PUBLISH. Full mode text: docs/plans/2026-09-03-minimal-copilot-plugin-payload-plan.md section Plan Hardening -> H2.

ACCEPTANCE: AC1, AC2c (manifest remains sole source of truth). `generate` is idempotent and byte-deterministic including cross-platform; it can emit to a scratch target without mutating any repository file; `--check` detects drift and exits non-zero; the channel enum covers all three channels; exactly one generation path exists and a test asserts it. The three RED-FIRST cases named above go red to green and the transitions are recorded for 160.017-T's ledger.
