<!-- BEGIN:description -->
Ship is the agent that actually performs fix cycles, so it carries the operative procedure. Add to Ship's review-fix and build/CI-fix loops:

1. Evaluate EVERY finding against the P-021 C1 same-contract-surface test before fixing it.
2. For out-of-scope findings, ALWAYS perform the C2 capture with the full six-field payload FIRST, then C3-resolve the original as far as possible without the expansion. The capture is Ship's ONLY write to the entry: every source ID known at capture is recorded at capture, every unavailable field is recorded as an explicit `N/A`, and Ship never edits the entry afterwards (the C5 carve-out grants creation only). Where a review thread exists, reference the deferred entry ID in the thread reply and then resolve the thread, and name it in the PR/closure residual-risk record. Where no review thread exists -- Ship's local review runs before PR creation, and build/CI findings have no thread even on an open PR -- mark the `review-thread ID` not applicable, record the ACTUAL PR number whenever a PR is already open (marking it not applicable only for a genuinely pre-PR finding), and reference the deferred entry ID in the task/run/closure residual-risk records instead; the reply and resolution steps are inapplicable, not skipped obligations.
3. Annotate the Stop Conditions review-fix row with C4: reaching the cycle limit does not authorize expansion; remaining findings are accepted as captured deferred entries, not as silently expanded fixes.

As written it forced Ship either to violate the step or to defer capture until a PR existed -- the latter directly contradicting C2's precondition-for-closing rule. The acceptance criteria now split the disposition into a thread-present path and a threadless path behind a common mandatory capture-first step, with path selection driven by whether a thread actually exists for the finding rather than by which loop raised it.
