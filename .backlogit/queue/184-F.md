Repair the Windows temp-directory teardown failure in tests/test_capability_pack_enforcement_verifier.py. After the authorized test-only synchronization repair 183.001-T landed as 622a41a1, the canonical suite (PYTHONPATH=src python -m unittest discover -s tests) failed TWICE at CapabilityPackEnforcementVerifierTests::test_orphaned_manifest_entry_without_pack_fails inside tempfile.TemporaryDirectory.__exit__ -> shutil.rmtree with PermissionError [WinError 32] (file in use by another process) / [WinError 5] (access denied). The failure is in teardown, not in any assertion: the module-level _run() helper (line ~114) wraps the whole fixture build and verify_workspace() call in a bare `with tempfile.TemporaryDirectory() as temp_dir:`, and on Windows a tree cannot be removed while any handle inside it is still open.

TEST-ONLY BY EVIDENCE: a read-only concurrency review of the production verifier path (src/autoharness/verify_workspace.py, capability_pack_enforcement targeted check) found NO production file-handle leak. src/ MUST NOT be modified under this feature unless later execution evidence disproves that finding, in which case the work STOPS and returns to Stage.

AUTHORIZED REPAIR: a bounded retry at the temp-workspace teardown site - catch PermissionError whose winerror is 32 or 5, retry removal a small fixed number of times with a short bounded backoff, and RE-RAISE the final exception once the bound is exhausted. PROHIBITED: ignore_cleanup_errors=True, shutil.rmtree(ignore_errors=True), any unbounded or swallowing retry (they convert a real defect into invisible residue and permanently suppress the WinError 5 access-denied signal); any production/src change; any change to another test module; adding a `dir=Path.cwd()` anchor to TemporaryDirectory (tests/test_test_suite_isolation_contract.py guards against reintroducing that pattern under tests/, per docs/closure/149-S-141-F-post-merge-closure.md).
