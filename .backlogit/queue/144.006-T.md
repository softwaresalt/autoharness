## Part 1 — `src/autoharness/gates/topology.py:200` `_run_git`

Currently `check=False` and `return ""` on nonzero exit: a git INFRASTRUCTURE failure is laundered into "no branch" -> `detached_head` -> `BRANCH_MISMATCH` -> `exit_code == 1`. Victims #1 and #2 assert `exit_code == 0` and therefore fail with a FALSE DOMAIN DIAGNOSIS. Same anti-pattern as `docs/compound/2026-08-08-shell-pipeline-exit-status-masking-in-version-probes.md` (a failing probe's exit status discarded while partial stdout is still consumed).

**A3 (BINDING) — strictly additive and schema-safe:**

**A3R (BINDING, cycle 3) — expected absence is NOT invocation failure.**

The original A3 bound the diagnostic to fire on ANY nonzero exit. Verified against the ACTUAL call sites in `src/autoharness/gates/topology.py`:

```
L571  _run_git(["git","--no-pager","branch","--show-current"], ...)
L574  _run_git(["git","--no-pager","symbolic-ref","--quiet","--short",
               "refs/remotes/origin/HEAD"], ...)
L583  _run_git(["git","--no-pager","worktree","list","--porcelain"], ...)
```

`git symbolic-ref --quiet` exits **1** when the ref does not exist, and `--quiet` means exactly "do not print an error, just exit nonzero". That is the DESIGNED way to ask whether `refs/remotes/origin/HEAD` exists. In any clone where `origin/HEAD` is unset, exit 1 is the NORMAL, EXPECTED answer and `default_branch()` correctly falls through to its next rung.

Under A3 as written that ordinary path would populate `git_invocation_error` on EVERY run — making A3's own binding claim ("absent whenever every git invocation succeeded") FALSE in routine operation and turning the diagnostic from signal into noise at the exact site it was added to clarify. And because `--quiet` suppresses stderr, the key would be populated with the EMPTY STRING: a present-but-meaningless diagnostic.

`_run_git` therefore gains a caller-declared expected-absence set:

```python
def _run_git(argv: list[str], cwd: Path,
             expected_absence_codes: frozenset[int] = frozenset()) -> str:
```

- Add ONE new key, `details['git_invocation_error']`, carrying the captured stderr.
- It is populated **ONLY** when the exit code is nonzero **AND NOT** in `expected_absence_codes`.
- It is **ABSENT** (key not present at all) whenever every git invocation either succeeded or returned a declared expected-absence code — so the success-path `details` payload is BYTE-IDENTICAL to today.
- It is **NEVER** populated with an empty string. If an unexpected nonzero exit produced no stderr, record the exit code instead, so a present key is always meaningful.
- Exhaustive call-site declarations:
  - `branch --show-current` -> `frozenset()` (exit 0 even on detached HEAD, which reports empty stdout; any nonzero is a real failure)
  - `symbolic-ref --quiet --short refs/remotes/origin/HEAD` -> `frozenset({1})`
  - `worktree list --porcelain` -> `frozenset()`
- Additional required tests: expected-absence exit 1 at the `symbolic-ref` site produces **NO** `git_invocation_error` key and the identical verdict as today; an unexpected exit (e.g. 128) at the same site **DOES** populate it; a no-stderr unexpected exit records the exit code rather than `""`.
- It never replaces, renames, or reorders an existing key.
- `_run_git`'s return contract is UNCHANGED: still `""` on nonzero exit, so the gate's token and exit code are IDENTICAL on every path.
- Add a **verdict-equality test**: for a simulated nonzero git exit, `result.exit_code`, `check.token`, and EVERY pre-existing `details` key equal the pre-change behavior, AND the new key carries the captured stderr.
- **Re-run the consumer grep at THIS task's head** and record the result: `scripts/ci-topology-check.sh` and `tests/test_ci_topology_check_entrypoint.py` for whole-`details` equality or strict-key consumption. If ANY consumer compares exactly, route the diagnostic to stderr logging only and DROP the `details` key.

Pre-verified at plan-review time (review finding N1, informational only, NOT a substitute for the grep above): `scripts/ci-topology-check.sh` has zero `details` references; `tests/test_ci_topology_check_entrypoint.py` has zero; every `details` assertion in `tests/test_gates_topology.py` is an individual key lookup (`['current_branch']`, `['default_branch']`, `['detached_head']`, `['resolved_via_ci_env_fallback']`, `['default_branch_resolved_via_ci_env_fallback']`), never whole-dict equality; there is no JSON schema for topology output under `schemas/`.
