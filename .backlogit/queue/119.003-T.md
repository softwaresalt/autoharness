SIZE: M. COMPLEXITY: medium. (Two independent axes; also emitted as structured backlog fields.) Shipment 2 (P0). Create src/autoharness/supervise/session.py implementing the explicit session state machine: INIT -> LOCKING -> BOOTSTRAPPING -> PREFLIGHT -> RESOLVING -> LAUNCHING -> RUNNING -> {CANCELLING | RESTARTING | DRAINING} -> {EXITED | FAILED | REFUSED | CANCELLED}. THE TERMINAL SET IS EXACTLY THESE FOUR STATES (operator ruling, 2026-08-12): EXITED, FAILED, REFUSED and CANCELLED. CANCELLED IS A DISTINCT FOURTH TERMINAL STATE, not an alias of EXITED - an operator-cancelled session MUST be distinguishable from a normally-completed one in the terminal state itself, not only via exit code or journal, for the same reason REFUSED is already distinct from FAILED: a deliberate policy outcome is neither an error nor a normal completion. THIS SUPERSEDES the earlier three-state terminal set, which omitted CANCELLED and contradicted the plan diagram and outcome table. The legal-transition table is DATA, not control flow. FAIL CLOSED (H2): any transition absent from the table raises ErrorKind.ILLEGAL_TRANSITION - there are no implicit transitions and no permissive fallback. DRAINING IS THE SOLE TERMINAL GATEWAY (F18/F22 ruling, strengthened from 'only path from RUNNING'): EVERY path from ANY post-LOCKING phase to ANY terminal state routes through DRAINING. There is no CANCELLING -> EXITED edge, no direct failure edge from BOOTSTRAPPING / PREFLIGHT / RESOLVING / LAUNCHING / RUNNING / RESTARTING to FAILED, and no terminal edge that skips it. DRAINING ALWAYS flushes the journal, RELEASES THE LOCK via the idempotent 118.005-T release contract, and reaps the child - which is what guarantees that a failure anywhere after LOCKING can never strand the workspace lock and force the operator into --force-unlock (F22). CANCELLATION IS LEGAL FROM EVERY POST-LOCKING PHASE (F23): BOOTSTRAPPING, PREFLIGHT, RESOLVING, LAUNCHING, RUNNING and RESTARTING each carry a transition to CANCELLING, and CANCELLING transitions ONLY to DRAINING. REFUSED (lock contention) is a DISTINCT terminal state from FAILED, because a contended workspace is a policy outcome, not an error; REFUSED is ALSO THE SINGLE DOCUMENTED EXCEPTION to the DRAINING gateway, reachable only from LOCKING BEFORE a lock is acquired, so there is nothing to release. CANCELLATION TERMINATES IN CANCELLED, NEVER IN EXITED: the full path is <post-LOCKING phase> -> CANCELLING -> DRAINING -> CANCELLED, and DRAINING is entered BEFORE the terminal state so that child termination, journal flush and lock release have all COMPLETED before CANCELLED is reported. THERE IS NO CANCELLING -> CANCELLED EDGE: a direct transition bypassing DRAINING is ILLEGAL and MUST raise ErrorKind.ILLEGAL_TRANSITION, exactly as CANCELLING -> EXITED does. NORMAL CHILD COMPLETION terminates in EXITED via ... -> DRAINING -> EXITED; failure paths terminate in FAILED via DRAINING; refusal terminates in REFUSED from LOCKING. REQUIRED TESTS FOR THIS RULING: (i) a cancellation run ends in CANCELLED and a normal-completion run ends in EXITED, asserted as DIFFERENT terminal values so the two outcomes cannot be conflated; (ii) the CANCELLING -> CANCELLED transition is ABSENT from the table and attempting it raises ILLEGAL_TRANSITION - a negative control, not a comment; (iii) the existing graph-property test (plan Rule 4) covers CANCELLED as it does every other terminal, asserting NO terminal state is reachable except through DRAINING save the documented REFUSED exception, so the no-bypass guarantee is proven by graph property rather than by enumerating the paths anyone happened to think of. Every transition emits exactly one SessionPhaseChanged event, using the event contract defined in the shared core module (118.003-T contracts.py); this module does NOT import or depend on the 119.004-T event bus, which is what removes the F19 circular dependency. Pure module: no I/O, no spawning, no threads - it is driven by the orchestrator. Tests enumerate the full transition table, assert every illegal transition raises, and assert terminal states are absorbing. MANDATORY GRAPH-PROPERTY TEST (F18/F22, not a hand-enumerated list): search the transition graph and assert that for EVERY post-LOCKING phase, EVERY path to EVERY terminal state passes through DRAINING, and that every such path releases the lock exactly once. A hand-written list of paths is insufficient - the defect being prevented is an edge nobody thought to enumerate.
