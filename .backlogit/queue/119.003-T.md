SIZE: M. COMPLEXITY: medium. (Two independent axes; also emitted as structured backlog fields.) Shipment 2 (P0). Create src/autoharness/supervise/session.py implementing the explicit session state machine: INIT -> LOCKING -> BOOTSTRAPPING -> PREFLIGHT -> RESOLVING -> LAUNCHING -> RUNNING -> {CANCELLING | RESTARTING | DRAINING} -> {EXITED | FAILED | REFUSED}. The legal-transition table is DATA, not control flow. FAIL CLOSED (H2): any transition absent from the table raises ErrorKind.ILLEGAL_TRANSITION - there are no implicit transitions and no permissive fallback. DRAINING IS THE SOLE TERMINAL GATEWAY (F18/F22 ruling, strengthened from 'only path from RUNNING'): EVERY path from ANY post-LOCKING phase to ANY terminal state routes through DRAINING. There is no CANCELLING -> EXITED edge, no direct failure edge from BOOTSTRAPPING / PREFLIGHT / RESOLVING / LAUNCHING / RUNNING / RESTARTING to FAILED, and no terminal edge that skips it. DRAINING ALWAYS flushes the journal, RELEASES THE LOCK via the idempotent 118.005-T release contract, and reaps the child - which is what guarantees that a failure anywhere after LOCKING can never strand the workspace lock and force the operator into --force-unlock (F22). CANCELLATION IS LEGAL FROM EVERY POST-LOCKING PHASE (F23): BOOTSTRAPPING, PREFLIGHT, RESOLVING, LAUNCHING, RUNNING and RESTARTING each carry a transition to CANCELLING, and CANCELLING transitions ONLY to DRAINING. REFUSED (lock contention) is a DISTINCT terminal state from FAILED, because a contended workspace is a policy outcome, not an error. Every transition emits exactly one SessionPhaseChanged event, using the event contract defined in the shared core module (118.003-T contracts.py); this module does NOT import or depend on the 119.004-T event bus, which is what removes the F19 circular dependency. Pure module: no I/O, no spawning, no threads - it is driven by the orchestrator. Tests enumerate the full transition table, assert every illegal transition raises, and assert terminal states are absorbing. MANDATORY GRAPH-PROPERTY TEST (F18/F22, not a hand-enumerated list): search the transition graph and assert that for EVERY post-LOCKING phase, EVERY path to EVERY terminal state passes through DRAINING, and that every such path releases the lock exactly once. A hand-written list of paths is insufficient - the defect being prevented is an edge nobody thought to enumerate.
