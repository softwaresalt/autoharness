Package and install only the minimum runtime file set for the two IN-SCOPE autoharness distribution channels - the WHEEL and the COPILOT PLUGIN - driven by a single declarative allowlist manifest and enforced by a fail-closed composition test.

PROBLEM (measured at commit 1c50b0a8be6ca71dfeacf8cf15b6514b11d988da; corrected in review-fix cycle 5, finding 2 - the earlier framing implied every channel ships the whole repository, which is FALSE for the wheel):
- THE PLUGIN CHANNEL SHIPS THE WHOLE REPOSITORY. `.github/plugin/marketplace.json` declares `source: "."`, which resolves to the repository root - 3,238 tracked files / ~18 MB - including `.backlogit/` (2,110 files, 65% of all tracked files, this workspace's own backlog records with no runtime role), `tests/`, `experiments/` and `references/`.
- THE WHEEL DOES NOT. Its `[tool.hatch.build.targets.wheel.force-include]` table already lists ONLY templates, schemas, four `.github/` subtrees, both copilot instruction files, docs, and AGENTS.md, plus `packages = ["src/autoharness"]`. `.backlogit/`, `tests/`, `experiments/` and `references/` are ALREADY ABSENT from it. The wheel's defects are narrower and specific: it OVER-INCLUDES all 642 `docs/` files (~6.9 MB of provably dead weight), and it OMITS parts of the required runtime set - `.github/policies/**` (carrying workflow-policies.md, referenced by installed agents) and `scripts/**` (whose members are referenced by installed skills).

EVIDENCE: `verify_workspace.py` resolves every `docs/*` path against `workspace_path` (the target workspace), never the packaged data dir - so the wheel's 6.9 MB docs force-include is provably dead weight. Skill references to `docs/compound|plans|memory|decisions|closure` are target-workspace OUTPUT destinations, not engine payload ("referenced != required payload").

DECISION: an explicit allowlist manifest as the single source of truth for the CLOSED TWO-CHANNEL SET {wheel, plugin}; allowlist-by-default fails closed, denylist fails open. Projected plugin payload 3,238 -> ~350 files, ~18 MB -> ~3 MB (a PROJECTION, to be replaced by measured per-channel figures).

THIRD CHANNEL DEFERRED, NOT DENIED (review-fix cycle 5, finding 1 - a P-021 C1 scope correction). The Python SOURCE DISTRIBUTION is a THIRD published channel DISCOVERED DURING PLAN REVIEW, not part of the deliberated source request E9E5E6CC, which is the Copilot plugin installer payload. Its `[tool.hatch.build.targets.sdist]` table declares only `core-metadata-version = "2.4"`, so hatchling's default sweep publishes essentially the whole source tree to PyPI and, via `dist/*`, to the GitHub release - a real and larger disclosure than the plugin's. It nonetheless shares NEITHER the plugin's allowlist mechanism NOR its failure mode, so absorbing it here would have been scope expansion. It is captured IN FULL, with its measured evidence, in DEFERRED STASH ENTRY 99818C6D (kind bug, priority high, requires deliberation). THE WHEEL IS NOT DEFERRED WITH IT: the wheel shares the plugin request's allowlist mechanism, the same `_DATA_DIR`/`templates`/`schemas` payload contract, and the same over-inclusion defect, so it is genuinely coupled to the deliberated request. Task 160.019-T, which had wired the sdist, is RETIRED and ARCHIVED at `.backlogit/archive/160.019-T.md`.

Preserves install, update, verification, and cross-environment behavior. Target workspaces receive only generated output, never autoharness engine files.
