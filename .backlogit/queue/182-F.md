BOOTSTRAP (P0). Install the actor that policies P-002 and P-004 already name, WITHOUT assuming that actor exists and WITHOUT depending on any code-bearing shipment. WHY THIS FEATURE EXISTS SEPARATELY FROM 181-F. 181-F/187-S delivered BOTH the installed actor AND the Ship pre-task lifecycle automation that invokes it, while itself declaring depends_on 184-S. That is a bootstrap deadlock on two independent axes: (1) 187-S's own tasks write Python under src/, so P-004 requires a confirmed red phase and P-002 requires a harness-ready label before Ship may claim them, and the only declared producer of that label is the actor 187-S itself outputs - it must consume its own output before producing it; and (2) 184-S is code-bearing and needs the same absent actor. Reversing the 187-S->184-S edge repairs axis 2 ONLY and leaves the self-bootstrap of axis 1 intact, which is why edge reversal was rejected.

THE SPLIT. THIS FEATURE INSTALLS THE ACTOR ONLY - it generates .github/skills/harness-architect/SKILL.md from its authoritative template. NO Python module, NO agent-lifecycle edit, NO installed-mirror edit, NO policy edit. 181-F/187-S KEEPS THE AUTOMATION - the harness-surface resolver, the Ship pre-task lifecycle phase, and the HARNESS_READY/NO_HARNESS state contract - which become ordinary harness-backed implementation tasks once a real installed actor exists.

NOT A WAIVER. P-004's precondition is MECHANICAL AND ACTOR-INDEPENDENT: py_compile exits 0 AND unittest discover exits non-zero with expected failure markers. The skill file is the PROCEDURE SPECIFICATION; the commands are the EVIDENCE. During bootstrap the procedure is executed directly from templates/skills/harness-architect/SKILL.md.tmpl, which is complete and self-contained (posture selection, harness generation, Step 5.1 compilation check, Step 5.2 red-phase check, Step 6 harness-ready labelling). No gate is suspended, no severity lowered, no evidence assumed, nothing skipped. A waiver produces LESS evidence than the policy demands; this produces EXACTLY the evidence the policy demands, once. NO waiver, NO force flag, NO policy edit, NO operator exemption note exists anywhere on this path.

ONE-TIME BOUNDARY ON FOUR SIMULTANEOUS AXES: SCOPE - exactly the tasks of 188-S/182-F, not inheritable; COUNT - exercised exactly once, by 182.002-T; DELIVERABLE - only .github/skills/harness-architect/SKILL.md from its existing template; EXPIRY - terminated by 182.004-T emitting HARNESS_ARCHITECT_INSTALLED. It is also NOT RE-ENTERABLE: installing the actor destroys the condition (actor absence) that justified the authority, so a re-run of this unit routes through the installed skill.
