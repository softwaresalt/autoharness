WHY THIS FEATURE EXISTS SEPARATELY FROM 181-F. 181-F/187-S delivered BOTH the installed actor AND the Ship pre-task lifecycle automation that invokes it, while itself declaring depends_on 184-S. That is a bootstrap deadlock on two independent axes: (1) 187-S's own tasks write Python under src/, so P-004 requires a confirmed red phase and P-002 requires a harness-ready label before Ship may claim them, and the only declared producer of that label is the actor 187-S itself outputs - it must consume its own output before producing it; and (2) 184-S is code-bearing and needs the same absent actor. Reversing the 187-S->184-S edge repairs axis 2 ONLY and leaves the self-bootstrap of axis 1 intact, which is why edge reversal was rejected.

THE SPLIT. THIS FEATURE INSTALLS THE ACTOR ONLY - it generates .github/skills/harness-architect/SKILL.md from its authoritative template AND registers that file and its checksum in .autoharness/harness-manifest.yaml in the SAME commit (decision D11).
