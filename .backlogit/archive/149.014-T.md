<!-- BEGIN:acceptance-criteria -->
* **INV-1**: the on-disk report artifact is asserted to be a **flat list with no edge/topology data** — derive-never-persist for the graph itself is verified against the written file, not merely against the type signature.
* Non-overwrite asserted at the same epoch key.
* Stale `head_sha` -> `insufficient_evidence`, asserted NOT a reused `passed`.
* Changed `tool_version_dims` -> `insufficient_evidence`, asserted NOT a reused `passed`.
* Results carry the canonical `status` field only — no independent outcome field appears in the serialized report (D-9).
* No network access.
<!-- END:acceptance-criteria -->

<!-- BEGIN:description -->
Plan unit **U10b**. Create `tests/test_detectors_report.py`.

**4 scenarios**:

1. **Report shape** — the written report is a flat list of node results with **no edge/topology data** of any kind (INV-1 / Law 1).
2. **Non-overwrite** — a second run at the same epoch key does **not** overwrite the existing report.
3. **Stale HEAD** — a result whose `head_sha` differs from current HEAD is `insufficient_evidence`, never a reused `passed`.
4. **Changed tool versions** — a result whose declared `tool_version_dims` changed is `insufficient_evidence`, never a reused `passed`.

**Gate command (Q5)**: `PYTHONPATH=src python -m unittest discover -s tests`
<!-- END:description -->

<!-- BEGIN:implementation-notes -->
**Depends on U7.**

**Split provenance**: this unit and U10c were carved out of the original U10, which after the cycle-1 corrections would have carried **8 scenarios across 2 files** — breaching the plan's max-4-scenario granularity budget and the 2-hour rule. U10 keeps the assembler scenarios; this unit owns report shape and freshness *semantics*; U10c owns epoch-key *identity* (determinism, stale siblings, concurrency).

The division is deliberate: freshness **semantics** (what a stale result must report) and epoch **identity** (which file is the current one) are separate concerns that fail for different reasons, so keeping them in separate suites keeps each failure diagnosable.
