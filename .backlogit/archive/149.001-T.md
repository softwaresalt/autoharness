Define NodeSpec/Evidence/NodeResult frozen dataclasses with ONE canonical `status` field carrying the closed 8-value outcome vocabulary (no independent `verdict` field) and report-only exit mapping. Domain: code. Files: 2.

<!-- BEGIN:acceptance-criteria -->
* All three dataclasses frozen, with `to_dict()` matching the `CheckResult`/`GateResult`/`TopologyResult` convention.
* **ONE canonical outcome field.** `NodeResult.status` carries the full 8-value vocabulary. There is **NO independent `verdict` field** — asserted by checking `verdict` is absent from `dataclasses.fields(NodeResult)` and absent from `to_dict()` keys.
* **Contradictory state is UNREPRESENTABLE**: no constructor path, no `dataclasses.replace` path, and no deserialization path can produce a result whose outcome disagrees with itself. There is only one stored outcome field, so there is nothing to disagree with.
* If a `verdict` alias is provided at all it is a **read-only `@property` returning `self.status`** — no setter, no constructor argument, no field, and NOT serialized.
* Status vocabulary is exactly the 8 named values — a 9th FAILS the suite (contract-freeze, verification step 1). This is what stops S2-S10 widening the contract silently.
* `waived` is declared but **unreachable** in S1 (no waiver engine) and asserted unreachable.
* `mode` is constructor-fixed to `report_only`; `NodeSpec` exposes no setter.
* **Status -> exit mapping reads `status` ONLY**: 0 for everything except `invalid` -> 2. No consumer branches on any alias.
<!-- END:acceptance-criteria -->

<!-- BEGIN:implementation-notes -->
**Decision D-1**: `NodeResult` **mirrors** `CheckResult` rather than subclassing it. `CheckResult` is a frozen dataclass in a 96 KB high-traffic module; mirroring avoids coupling the detector package to topology's import graph while keeping D5's 'reuse unchanged' intent.

**Decision D-9 (PR #414 cycle-1 correction, thread PRRT_kwDORzpWpM6dGx_H)**: the earlier draft of this task defined **two independent outcome fields** — `status` inherited from the `CheckResult` shape, plus a new `verdict` carrying the 8-value vocabulary — with **no invariant between them**. A result could serialize as `status="passed"` with `verdict="failed"`, leaving exit mapping and every downstream consumer ambiguous about which field is authoritative.

This is now collapsed to ONE canonical field, for three converging reasons:

1. **The governing D5 text says so.** `031-DL` D5 reads: *"Reuses `CheckResult{name,status,token,message,details}` and `TopologyResult` exit-code semantics unchanged; the extension is [...] additional statuses."* D5 describes a **widened vocabulary on the existing `status` field**, not a second parallel field. The two-field draft diverged from its own governing decision.
2. **It is already compatible.** `CheckResult.status` is an unconstrained `str` (`src/autoharness/gates/topology.py:130-142`), and existing consumers branch on `.status` directly (e.g. `check.status in ("blocked", "retry_required")` at `topology.py:180`). Widening the vocabulary of that one field needs no new field and breaks nothing.
3. **Now is the only cheap moment.** S1 is the FIRST shipment to define `NodeResult`; no consumer exists yet. Since S2-S10 all bind to this contract, collapsing the field before first ship is strictly cheaper than after — deferring would guarantee a breaking change later.

**If a compatibility alias is wanted**, it MUST be derived and non-independent: a read-only `@property` returning `self.status`, with no setter, no constructor argument, not a dataclass field, and **absent from `to_dict()`**. That makes contradiction structurally unrepresentable rather than merely tested-against.

**Decision D-6**: `waived` is in the vocabulary but unreachable — keeps the vocabulary closed and stable for S10 without importing waiver authority into S1 (split (c)).

Architecture Strategist P1: contract stability is the real risk since S2-S10 all depend on this. Mitigated by the contract-freeze test and by the monitoring trigger — if S2's first detector needs a contract change, that is the RK1 signal arriving late.

Add no field S1 does not itself exercise, except `waived`.

**Coupled tasks** that must read the canonical `status` only: U5 (149.005-T) sets `blocked_upstream`; U6 (149.006-T) validator outcomes; U7 (149.007-T) serialization; U8 (149.008-T) exit mapping; U9 (149.009-T) contract assertions; U11 (149.011-T) CLI acceptance.
