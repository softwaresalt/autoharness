Registry loader: schema-validate the detectors block, resolve producer/validator refs under a strict autoharness.detectors namespace allow-list, build NodeSpec objects. Any defect yields invalid/exit 2. Domain: code. Files: 1.

<!-- BEGIN:acceptance-criteria -->
* **SECURITY (P0 containment — this is the gating criterion)**: `producer.ref` / `validator.ref` MUST resolve **inside the `autoharness.detectors` package namespace**. Any ref outside it is a **registry defect -> `invalid` -> exit 2, NEVER imported**. Asserted in U9.
* **`producer.kind: command` is NOT implemented in S1**. A registry declaring `kind: command` yields `invalid`. No subprocess is ever spawned by this shipment.
* Every listed defect class yields `invalid` and a partial run is impossible.
* Absent registry -> zero nodes, exit 0.
* `mode: blocking` rejected at load even if it somehow passed schema.
<!-- END:acceptance-criteria -->

<!-- BEGIN:description -->
Plan unit **U3**. Create `src/autoharness/detectors/registry.py`.

Load and schema-validate the `detectors` block; resolve `producer.ref` / `validator.ref` to importable callables; build `NodeSpec` objects.

**Validation failures produce `invalid` (exit 2), never a partial run**:
* schema violation
* unknown or unimportable ref
* duplicate `node_id`
* malformed `node_id`
* `mode: blocking`
* `depends_on` naming an unknown node

A **missing/absent** registry is NOT a defect — it yields zero nodes and exit 0.

**Execution posture**: test-first.
<!-- END:description -->
