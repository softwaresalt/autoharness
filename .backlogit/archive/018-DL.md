# Adopt backlogit .backlog storage root across the autoharness product surface

## Problem Frame

<!-- BEGIN:problem-frame -->
backlogit 1.9.0 resolves the external blocker recorded on BED0DDED. Verified read-only against C:\Source\GitHub\backlogit at v1.9.0 (HEAD 39528a41; NOT mutated): workspaceRootCandidates = {'.backlog', '.backlogit'} gives .backlog-first discovery precedence with legacy fallback; BACKLOGIT_WORKSPACE_DIR provides an explicit override; ResolveStorageRoot fails closed with AmbiguousWorkspaceRootError when BOTH directories exist (both-exist safe detection); migrate --workspace-dir renames a legacy .backlogit workspace to .backlog with --dry-run and --rollback; init now creates .backlog. Every element of the recorded unblocker has landed, so the silent-backlog-state-SPLIT hazard that forced the 2026-08-07 and 2026-08-09 deferrals no longer applies. The remaining work is the autoharness-side FOLLOWER surface: ~29 hardcoded '.backlogit' references across schemas (3), templates (4), .github instructions/agents (7), scripts (1), src/autoharness/cli.py (1) and docs (13), plus the .autoharness/backlog-registry.yaml 'directory' default.
<!-- END:problem-frame -->

## Options

<!-- BEGIN:options -->
1. NO-OP / keep deferring. Rejected: the recorded unblocker has demonstrably landed, and continuing to emit .backlogit-only guidance makes autoharness the sole remaining source of contract drift. 2. BIG-BANG RENAME: flip every literal to .backlog and migrate this repository's own .backlogit directory in one shipment. Rejected: mutating the live backlog storage root during a dark-factory run would move the very files the pipeline is reading and writing, and a mid-run failure has no safe recovery. 3. DIRECTORY-AGNOSTIC FOLLOWER (chosen): make the autoharness product surface accept BOTH roots with .backlog-first precedence, mirror upstream both-exist fail-closed detection, default NEW installs to .backlog, and leave this repository's own storage-root migration as a separate operator-gated step that is explicitly OUT of dark-mode automation.
<!-- END:options -->

## Chosen Direction

<!-- BEGIN:chosen-direction -->
Option 3. Treat the directory name as resolved data, not a literal. (a) Introduce a single shared resolution helper in src/autoharness that mirrors upstream precedence exactly -- BACKLOGIT_WORKSPACE_DIR override, then .backlog, then .backlogit -- and fails closed when both exist rather than silently picking one. (b) Update schemas so backlog-tool-registry, harness-config and workspace-profile accept and prefer .backlog while still validating legacy .backlogit values. (c) Update templates, instruction templates, agent templates, CI topology scripts and docs to stop asserting a single hardcoded root, and to name .backlog as the default for new installs. (d) Give tune-harness a drift rule that DETECTS and REPORTS a legacy-rooted target workspace and points at backlogit migrate --workspace-dir, but never performs the rename itself. (e) EXPLICITLY EXCLUDE migrating autoharness's own .backlogit directory: that is a separate operator-gated action, must not run under dark mode, and must not be added to any shipment in this chain.
<!-- END:chosen-direction -->
