Create the final verification matrix, fixtures, and operator runbook for the complete Plan 3 system. Cover local-only, remote-only, interleaved local/remote, restart handoff, PTY slash behavior, ACP routing, model/permission/MCP controls, automatic updates, auth failures/account mismatch, stable API discovery, and unavailable Copilot/Dev Tunnel/MCP/ACP prerequisites. Re-assert security/privacy boundaries and compatibility with shipped Plan 2 V1.

<!-- BEGIN:acceptance-criteria -->
- Browser tests launch the real Gradio app on loopback and interact through Playwright locators, browser-visible state, and actual named API/network operations; direct callback invocation alone does not satisfy this task.
- Hermetic Playwright tests use deterministic local fake broker, PTY, ACP, identity, approval, event, and prerequisite adapters while retaining the real Gradio presentation and browser runtime.
- Browser scenarios cover authenticated remote access, valid account binding, wrong-account rejection, stale/session/workspace binding rejection, stable API discovery/version mismatch, automatic polling or push updates without Tail-button repetition, local+remote interleaved control, PTY /yolo and /mcp show or explicit equivalent behavior, model/permission/MCP controls, ACP request/response and agent-request flows, local-approval-required states, reconnect/restart handoff, error/degraded states, tunnel loss, and responsive/usable layouts at defined viewport sizes.
- Browser assertions prove no arbitrary shell/browser terminal, no private chain-of-thought, bounded/redacted output, metadata-only operator-text audit, and clear capability-unavailable messaging.
- The live-validation matrix is separate from hermetic CI and explicitly requires: optional Gradio extra, Node.js, Playwright package and installed browser binaries, a runnable Copilot CLI binary, authenticated Microsoft Dev Tunnel CLI/account, the target account/principal configuration, actual MCP servers, and an ACP endpoint/client SDK. Missing prerequisites produce BLOCKED or NOT_RUN evidence and are never reported as passing live validation.
- Automated non-browser tests still cover broker contracts, PTY/ACP adapters, authorization, input arbitration, cursor semantics, and error classification; all implementation work follows red -> implementation -> green ordering.
<!-- END:acceptance-criteria -->

<!-- BEGIN:description -->
Create the final verification matrix, fixtures, and operator runbook using TDD-first sequencing. The first implementation step is to write failing Playwright tests against the actual launched Gradio Web UI; only then implement the broker/API/UI behavior needed to make them pass.
<!-- END:description -->

<!-- BEGIN:implementation-notes -->
Use a stable Playwright configuration with deterministic base URL, browser install/version pinning, bounded startup/teardown, trace/video capture only on failure, and no external credentials in hermetic tests. Provide a local fixture mode that starts Gradio with fake adapters and an explicit live mode that is opt-in, authenticated, and excluded from default CI. The test report must distinguish hermetic PASS, live PASS, BLOCKED, and NOT_RUN. Do not claim that Dev Tunnel/Copilot/ACP/MCP end-to-end tests ran when those prerequisites are absent.
