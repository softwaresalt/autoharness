SIZE: M. COMPLEXITY: high. (Two independent axes; also emitted as structured backlog fields.) Shipment 2 (P0). Create src/autoharness/supervise/process_pty.py implementing PtyChildProcess behind the IDENTICAL ChildProcess Protocol fixed by 119.001-T: ConPTY on Windows via an OPTIONAL pywinpty extra, stdlib pty on POSIX. BACKEND ROLES AFTER THE F29 RULING: inherited stdio (119.001-T) is the DEFAULT for interactive launches and preserves terminal attachment; PTY is the OPT-IN backend for sessions that need BOTH terminal semantics AND capturable output, and is the ONLY supported way to journal ChildOutput without downgrading the terminal to pipes; the pipe backend remains the CI/test path so the base install stays dependency-light. PTY is never required for an ordinary interactive launch. GUARDED IMPORT: when the optional extra is absent or the platform backend fails to initialize, DEGRADE TO INHERITED STDIO - never to pipes - with a recorded warning, so a missing PTY extra costs OUTPUT CAPTURE but NEVER TERMINAL ATTACHMENT (F29). Degrading to pipes here would silently convert an interactive session to non-TTY, which is the exact failure the F29 ruling forbids. Never a hard failure, and never a silent substitution: a requested-but-unavailable PTY must always surface the warning (H2). Exit-status fidelity is asserted on this backend too, over the same {0,1,2,42,130} table. H8 DE-RISKING (CORRECTED 2026-08-12 BY THE P1-A RULING - THE PRIOR "SHIP PIPE-ONLY" FALLBACK IS REMOVED AND IS PROHIBITED): scope is exactly ONE class behind an already-fixed Protocol. If ConPTY/pywinpty integration exceeds the 2-hour box, the documented fallback is to DEFER THE PTY BACKEND and ship WITHOUT it - the default interactive path remains INHERITED STDIO from 119.001-T, which preserves terminal attachment - and re-file PTY as a follow-up. SHIPPING PIPE-ONLY IS EXPLICITLY PROHIBITED as a de-risking outcome: pipes are the CI/test path only, and making them the interactive path would convert an interactive session to non-TTY, which is exactly the failure F29 forbids. THE DE-RISKING FALLBACK MAY NEVER RELAX THE F29 CONTRACT - a scheduling pressure is not a licence to change observable interactive behaviour. Where capture/control genuinely requires a PTY and no supported PTY is available, FAIL CLOSED BEFORE LAUNCH rather than substituting piped stdio; inherited stdio is used only where the defined contract permits it (an ordinary interactive launch, which never required PTY). JOURNALING IS INDEPENDENT OF TERMINAL ATTACHMENT: supervisor lifecycle and structured events are journaled separately via 119.005-T and MUST NOT require replacing terminal attachment with pipes; where ChildOutput capture is consequently unavailable, the declared ChildOutputUnavailable(reason=inherited-stdio) marker is written instead (F29). No downstream task is blocked on PTY.
