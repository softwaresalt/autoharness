**LAYER 3 — regression guard.**

Plan: `docs/plans/2026-08-22-git-config-env-containment-plan.md` Task 4. Amendments A1, **A1R**, **R5R**, R4 BINDING.

## Deliverable

A NEW test class in the EXISTING module `tests/test_test_suite_isolation_contract.py`, following that module's established shape (AST visitor + pinned allowlist + non-vacuity positive and negative cases + `path:line` failure message).

## Guard

Recursively over every `*.py` under `tests/`, an `ast.NodeVisitor` flags:

- any call to `patch.dict` / `mock.patch.dict` / `unittest.mock.patch.dict` whose first argument is `os.environ` (attribute access) or the string literal `'os.environ'`;
- any call to `os.environ.clear()` / `environ.clear()`.

**AST-structural, NOT a line regex** — per `docs/compound/2026-08-21-ast-based-structural-regression-guards-beat-line-regex.md`. It must match regardless of line wrapping, argument ordering, context-manager vs. decorator form, or import alias. A regex only encodes the textual shapes its author anticipated; this is the exact whack-a-mole failure that learning documents.

## A1R (BINDING) — the allowlist is EMPTY; `_env_patch.py` is NOT exempt

The earlier version pinned `ENV_MUTATION_ALLOWLIST` to `frozenset({"_env_patch.py"})`. **That is withdrawn.**

The guard forbids only the **destructive** forms above. `tests/_env_patch.py` implements **targeted set/delete** (`os.environ[k] = v`, `del os.environ[k]`), which the guard does **not** forbid — so the helper needs **NO EXEMPTION AT ALL**.

The original justification ("the helper is the one legitimate place the underlying primitives may appear") conflated *the primitives the helper uses* with *the forms the guard forbids*. They are disjoint sets.

Worse, a path exemption would make the single file most likely to reintroduce the defect the ONE FILE in which the destructive forms are **permitted** — inverting the guard's entire purpose.

Therefore:

- **`ENV_MUTATION_ALLOWLIST = frozenset()`** — EMPTY, pinned, asserted exactly, with **no** path exemption for `_env_patch.py` or anything else.
- `tests/_env_patch.py` is scanned by the guard **on equal terms** with every other module and must contain **ZERO** forbidden forms.

## R5R (BINDING) — naming, and the negative case that makes an empty allowlist workable

`tests/test_test_suite_isolation_contract.py` ALREADY defines `ALLOWLIST` (pinned `frozenset()`) for the cwd-anchored-tempdir guard, asserted by `test_allowlist_is_exactly_expected`. A second guard in the same module invites a future editor to relax the wrong one.

- The new allowlist is named **`ENV_MUTATION_ALLOWLIST`**, asserted exactly by its own **`test_env_mutation_allowlist_is_exactly_expected`**.
- The existing `ALLOWLIST` and `test_allowlist_is_exactly_expected` are left **BYTE-IDENTICAL** (covered by AIG-1 as an untouched-assertion check).
- Because the allowlist is empty, the guard MUST be able to tell targeted set/delete apart from the forbidden forms. The negative non-vacuity case below is therefore **MANDATORY**, not optional — without it the empty allowlist is unworkable.

## Required companion tests

- `test_env_mutation_allowlist_is_exactly_expected` — pins `ENV_MUTATION_ALLOWLIST` to `frozenset()` so it cannot silently grow into an escape hatch.
- Non-vacuity POSITIVE: a synthetic source string using EACH forbidden shape is detected — context-manager form, decorator form (`@patch.dict(os.environ, ...)`), aliased import, multi-line/split-argument call, string-literal `'os.environ'` first argument, and `os.environ.clear()`.
- Non-vacuity NEGATIVE (**mandatory, R5R**): `patched_environ(...)`, `patch.dict(some_other_dict, ...)`, **`os.environ[k] = v`**, and **`del os.environ[k]`** are NOT flagged.
- The failure message NAMES every offending `path:line`.

**Alias-resolution approach (structural, not literal-name matching).** Rather than matching the literal spelling `patch.dict`/`mock.patch.dict` textually, a small `_ImportAliasCollector` walks every `Import`/`ImportFrom` node anywhere in the module (not just top-level) to build `alias_map: local_name -> canonical_dotted_origin` (e.g. `from unittest.mock import patch as p` binds `p -> "unittest.mock.patch"`; `import unittest.mock as um` binds `um -> "unittest.mock"`). `_resolve_dotted(expr, alias_map)` then resolves any `Name`/`Attribute` chain to its canonical dotted string, substituting each name's tracked origin (falling back to the literal name when untracked, which is what lets the guard's own synthetic non-vacuity samples exercise the forbidden shapes without a full import preamble). A call is flagged when: (a) the resolved callee ends with `"patch.dict"` AND its first positional argument resolves to `"os.environ"` (attribute-chain, through any alias of `os`) or is the string literal `"os.environ"`; OR (b) the callee is `<expr>.clear()` where `<expr>` resolves to `"os.environ"`.

**Non-vacuity POSITIVE (`test_guard_detects_every_known_offending_shape`).** A single synthetic source string carries all 7 required shapes — decorator form, context-manager form, aliased-import form (`patch as p`), module-alias form (`unittest.mock as um`), multi-line/split-argument form, string-literal `'os.environ'` first-argument form, and `os.environ.clear()` — each marked with a `# OFFENSE` comment. The test derives the expected offending-line set by scanning the sample text for that marker (not hardcoded line numbers, so the test is robust to incidental reformatting) and asserts `sorted(visitor.offending_lines) == expected`, plus a sanity assertion that exactly 7 markers are present. This test also discharges the acceptance criterion "guard provably fails if a migrated site is reverted" — every shape in the sample is exactly what a reverted 144.003-T site looks like, demonstrated via synthetic source rather than reverting committed code.

**Non-vacuity NEGATIVE (`test_guard_ignores_authorized_forms`, R5R MANDATORY).** A second synthetic source string confirms `patched_environ(...)`, `patch.dict(some_other_dict, ...)` (a dict that is not `os.environ`), `os.environ['X'] = '1'`, and `del os.environ['X']` are never flagged — `visitor.offending_lines == []`.

**R5R naming.** New allowlist is `ENV_MUTATION_ALLOWLIST`, pinned by its own `test_env_mutation_allowlist_is_exactly_expected` (asserts `== frozenset()`), kept fully distinct from the pre-existing `ALLOWLIST`/`test_allowlist_is_exactly_expected` pair (untouched, confirmed above).
