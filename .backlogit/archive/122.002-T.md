title: Define PTY and ACP adapter interfaces with explicit protocol semantics
updated_at: 2026-08-14T23:46:36.1847607Z

Create replaceable adapter interfaces and test doubles for native interactive PTY and ACP sessions. Specify which controls are PTY-native slash-command mappings versus ACP message/protocol mappings. ACP must negotiate capabilities and route typed requests/responses; it must never receive slash text as a guessed substitute. Adapters report unsupported prerequisites explicitly.

<!-- BEGIN:acceptance-criteria -->
PTY adapter exposes native interactive input and an allowlisted slash-command mapping contract; ACP adapter exposes typed request/response/event methods for model, permission, MCP, prompt, approval, and agent-request capabilities; no ACP path forwards raw slash text; fake adapters cover supported, unsupported, malformed, timeout, and protocol-mismatch outcomes; imported base installation remains ACP/Gradio independent.
<!-- END:acceptance-criteria -->

<!-- BEGIN:description -->
Adapter boundary only; do not implement broad runtime control behavior in this task.
<!-- END:description -->

<!-- BEGIN:implementation-notes -->
Keep Copilot CLI/ACP as the external runtime. The adapter owns transport/protocol translation; broker owns policy and authorization.
