SIZE: M. COMPLEXITY: medium. (Two independent axes; also emitted as structured backlog fields.) Shipment 1 (P0). Create src/autoharness/supervise/{__init__.py,result.py,errors.py,contracts.py}. result.py defines ONE typed SupervisorResult envelope with fields status, exit_code, data, messages, warnings, artifacts and a .to_dict(); it WRAPS existing result shapes and never rewrites them. errors.py defines ONE AutoharnessError base carrying a machine-readable `kind` (enum), the supervisor error taxonomy, and a SINGLE machine-readable exit-code contract table from which the CLI adapter derives its exit codes, so agent prose depending on exit codes cannot drift. contracts.py IS THE SHARED SUPERVISOR CORE CONTRACT MODULE, added by the F19/F21 ruling to fix two ordering defects. It defines (a) the STABLE EVENT NAME AND PAYLOAD CATALOG - SessionPhaseChanged, SidecarProbed, CopilotResolved, ChildSpawned, ChildOutput, ChildOutputUnavailable, ChildExited, ApprovalRequested, ApprovalResolved, CancelRequested, RestartScheduled, RestartExhausted, JournalCheckpoint - and (b) the APPROVAL REQUEST/RESPONSE TYPES (kind, summary, options, default, timeout, resolution, resolved_by), and (c) THE TYPED, EXHAUSTIVE GATED-ACTION CATALOG/REGISTRY - THIS TASK IS ITS SOLE PRODUCER (P1-3 ruling, 2026-08-12; previously 120.004-T CONSUMED a catalog that no task was obliged to create, so the DAG could mark this task fully satisfied while the artifact its consumer requires did not exist - structurally the same defect class as F21, a guarantee stated but made nobody's obligation). The catalog is a TYPED REGISTRY, not a bare string list: each entry carries a STABLE ACTION IDENTIFIER that is part of the module's public contract and MUST NOT be renamed silently once shipped, plus the metadata the approval service needs to render and resolve a request without inventing policy of its own - at minimum a human-readable summary, the permitted options, the TIMEOUT, and a FALLBACK POLICY (see below). It is DECLARED ONCE HERE AND NOWHERE ELSE: no downstream task may define a second list, and duplication is itself a defect. THE SET IS FROZEN AND ENUMERATED BY IDENTIFIER, NOT MERELY REQUIRED TO BE NON-EMPTY (ruling B, 2026-08-12 - "non-empty" was VACUOUS: a one-entry registry satisfied both this task and 120.004-T''s exhaustive-dispatch criterion while omitting real gated behavior, so omission passed the suite instead of failing it). THE FROZEN INITIAL SET IS EXACTLY THESE TWO IDENTIFIERS, derived by a BOUNDED INVENTORY of every action that the 118.*, 119.* and 120.* task contracts explicitly mark destructive, approval-required or operator-confirmed: (1) `session_restart` - 119.006-T: "a restart requires BOTH remaining budget AND explicit operator confirmation"; FALLBACK POLICY = USE_SAFE_DEFAULT(DECLINE_RESTART), because the restart budget already DEFAULTS TO 0, so declining is the documented safe posture and is not an invented value. (2) `force_unlock` - 118.006-T: a stale record "is NEVER silently reclaimed: it requires an explicit operator --force-unlock", exposed by the 120.006-T CLI option contract; FALLBACK POLICY = REFUSE, because 118.006-T already requires refusal on a live holder and on indeterminate liveness, and NO safe automatic value exists for destroying another holder''s lock record. THE INVENTORY IS DELIBERATELY CLOSED TO EXISTING PLAN-1 OBLIGATIONS: speculative future actions MUST NOT be added here, and any NEW gated action introduced by a later task MUST be added to this catalog in the same change that introduces it - that is precisely what the equality tests below force. EXHAUSTIVENESS IS ENFORCED HERE, NOT ONLY DOWNSTREAM: this task''s tests assert EXACT SET EQUALITY between the frozen expected identifier set above and the identifiers actually exported by the catalog - not a subset, not a non-empty check, so BOTH an omitted action AND an unannounced addition FAIL - that every entry has a unique stable identifier, complete required metadata and exactly one fallback-policy variant, and that the registry is CLOSED - lookup of an unregistered identifier RAISES rather than returning a permissive default - so an unknown gated action FAILS CLOSED at the contract boundary itself. THE FALLBACK POLICY IS A TAGGED UNION WITH EXACTLY TWO VARIANTS (ruling C, 2026-08-12, superseding the earlier requirement that EVERY entry carry a safe-default VALUE, which contradicted 120.005-T''s documented "REFUSED where no safe default exists" path and could only have been satisfied by INVENTING A BOGUS DEFAULT): `USE_SAFE_DEFAULT(reference/value)` names the option to select when no human answers, and `REFUSE` denies the action outright. EVERY ENTRY MUST CHOOSE EXACTLY ONE VARIANT; there is no third state and no absent/None policy. WHERE NO SAFE DEFAULT EXISTS, `REFUSE` IS THE REQUIRED FAIL-CLOSED OUTCOME AND NO PLACEHOLDER DEFAULT MAY BE FABRICATED. A test asserts both variants are representable and that a policy-less entry is rejected at construction. THIS TASK IS NOT DONE UNTIL THE CATALOG IS DEFINED AND EXPORTED FROM contracts.py, because 120.004-T's approval-wiring acceptance criteria are unsatisfiable without it, and satisfying them by editing this already-completed upstream task would be out of scope. Note the SHARED-CONTRACT AVAILABILITY RULE: this module is upstream of both the orchestrator and the approval service, so the catalog is importable by each WITHOUT either depending on the other - which is what keeps the dependency direction 120.004-T -> 120.005-T intact rather than inverted. PRODUCERS AND CONSUMERS BOTH DEPEND ON THIS MODULE AND NEVER ON EACH OTHER: 119.003-T emits SessionPhaseChanged against this catalog WITHOUT depending on the 119.004-T bus, which removes the F19 dependency cycle; and 120.005-T implements the console approval channel against a contract that already exists upstream. THE FURTHER CLAIM PREVIOUSLY MADE HERE - that this placement means "the approval path is no longer orderable out of the runtime (F21)" - IS WITHDRAWN AND REMOVED (P1-C ruling, 2026-08-12, following F32/F33).
