# docs/compound `source` value semantics: correct the single provenance-string outlier and ratchet the conformance check from non-emptiness to value shape

## Problem Frame

<!-- BEGIN:problem-frame -->
Exactly ONE file in `docs/compound/` carries a `source` value that is a shipment/feature/PR provenance string rather than the document's own repo-relative path.

STAGE MEASUREMENT (read-only, this session, 2026-08-23): `docs/compound/` now holds **75** markdown files (up from the 73 measured at 025-DL time). Full-frontmatter parse:
- **74/75** carry a self-referential `source` matching `docs/compound/<filename>.md`.
- **1/75** does not: `docs/compound/2026-08-09-next-eligible-detail-scoping-and-vacuous-tiebreak-tests.md` carries `source: "123-S / 115-F (PR #323 Copilot review)"`.
- `doc_type` is `learning` on that file and corpus-wide; the corpus passes `backlogit docs lint` and the structural contract test AS WRITTEN.
The entry's premise is therefore CONFIRMED AND EXACT, and it is still live at HEAD `259ddeb1`.

DECISIVE EVIDENCE THE ENTRY DID NOT HAVE — THE AUTHORING CONTRACT IS ALREADY NORMATIVE ON THIS POINT. `templates/skills/compound/SKILL.md.tmpl` (Phase 3, landed by 140.002-T under 025-DL's chosen direction) states verbatim:

  "`source` is this document's own repo-relative path — the same path the \"Output\" section above already describes. It is never a description of where the *problem* came from; it is the location of the learnings file itself."

So this is NOT an open design question about what `source` should mean. autoharness's own already-merged authoring contract answers it, and the outlier is a CONFORMANCE VIOLATION against that contract — not a stylistic preference and not an "unrelated key" exemption.

THE SAME TEMPLATE ALSO NAMES THE CORRECT HOME FOR THE DISPLACED VALUE. Phase 3's frontmatter block already models a `citations` key, and the Quality Criteria section states its purpose: "Citations make it possible to trace the learning back to the work that produced it." `"123-S / 115-F (PR #323 Copilot review)"` is precisely that. The outlier file has `title`, `date`, `source`, `tags`, `doc_type` and NO `citations` key.

WHY THE GAP SURVIVED. The structural guard `tests/test_docs_compound_frontmatter_contract.py::test_all_compound_docs_have_source_and_doc_type` asserts only NON-EMPTINESS (`if not source_value: missing_source.append(rel)`). A truthful-looking but semantically wrong value passes. The Quality Criteria line in the template mirrors that weaker framing ("`source` and `doc_type` are present and non-empty"), so the checkable criterion is strictly weaker than the normative prose eight lines above it.

SOURCE REFS (P-021 traceability, carried from the entry): task 140.001-T (whose AC3 verbatim-preservation rule created the asymmetry); feature 140-F; shipment 148-S; PR: N/A (genuinely pre-PR — surfaced during Ship's local report-only review before PR creation); review-thread ID: N/A (no thread exists). Predecessor deliberation: 025-DL. Predecessor closure record: `docs/closure/148-S-140-F-post-merge-closure.md` (feature_pr 387, closure_pr 388).
<!-- END:problem-frame -->

## Options

<!-- BEGIN:options -->
(a) HAND-CORRECT `source` ONLY — rewrite the one file's `source` to its own repo-relative path and drop the provenance string.

(b) EXEMPT AND DOCUMENT — leave the value, record an explicit exemption for this file, and leave the test at non-emptiness.

(c) CORRECT + RELOCATE + RATCHET — rewrite `source` to the self-referential path, preserve the provenance string VERBATIM by relocating it into the contract-designated `citations` key, and ratchet BOTH checkable surfaces (the structural test and the template's Quality Criteria line) from non-emptiness to a value-shape rule.

(d) DEFER AS EXTERNAL — treat `source` semantics as backlogit/docline-owned per the 90F2A9F8 / 84D8E6AB / 3C7AAC71 precedent.

(e) RE-OPEN 025-DL / 140-F and fold the correction into that feature's contract surface.

(f) WON'T-FIX — cosmetic; corpus already passes lint and the structural test.
<!-- END:options -->

## Chosen Direction

<!-- BEGIN:chosen-direction -->
CHOSEN: (c) CORRECT + RELOCATE + RATCHET. Reject (a), (b), (d), (e) and (f).

DISPOSITION OF THE OPERATOR'S EXPLICIT QUESTION — DOES THIS JOIN 025-DL'S DOCLINE CONTRACT SURFACE?
**SAME CONTRACT SURFACE, SEPARATE AND SUCCESSOR FEATURE. It does NOT merge into 025-DL.**
- SAME SURFACE: the artifacts are identical to 025-DL's — the `docs/compound/` corpus frontmatter, `templates/skills/compound/SKILL.md.tmpl`, and `tests/test_docs_compound_frontmatter_contract.py`. This is the completion of the `source` conformance story 025-DL opened, one semantic layer deeper (VALUE shape, where 025-DL covered KEY presence).
- SEPARATE FEATURE: 025-DL's chosen direction was fully executed and closed. A shipped-and-archived feature cannot absorb new work, and re-opening it would rewrite a closed acceptance record. So this lands as a NEW feature that CITES 025-DL/140-F/148-S as predecessor. That is exactly why (e) is rejected.

PRIOR ACCEPTANCE-CONTRACT CONSTRAINTS — PRESERVED EXPLICITLY (this is the load-bearing part of the decision):
1. **140.001-T AC3 (verbatim preservation) IS NOT VIOLATED AND IS NOT AMENDED.** AC3 bound what 140.001-T was authorized to do: add only the missing keys and leave every pre-existing key byte-identical. 140.001-T satisfied AC3 and merged. AC3 is a SCOPE CONSTRAINT ON A COMPLETED CHANGE, not a standing prohibition on the repository ever correcting a value again. This work does not re-run, re-open, re-evaluate, or retroactively reinterpret 140.001-T; it proceeds under a NEW, separately planned and separately reviewed authorization. The entry's own P-021 C1 reasoning — that rewriting the value THEN would have contravened AC3 — was CORRECT AT THAT TIME and is the precise reason the finding was deferred rather than fixed inline. Deferral worked as designed; this deliberation is its intended discharge.
2. **NO INFORMATION IS DESTROYED.** The provenance string `"123-S / 115-F (PR #323 Copilot review)"` is preserved VERBATIM, moved into `citations`, the key the authoring contract already designates for exactly this data. This converts the change from value-destroying to value-relocating and removes the only substantive objection to (a). (a) is therefore rejected as strictly worse than (c) at identical cost.
3. **025-DL R5 (consumer safety) CARRIES FORWARD**: no existing frontmatter key may be removed and no key ordering may be disturbed beyond the single `source` value rewrite plus the `citations` addition. `title`, `date`, `tags`, `doc_type` survive verbatim.
4. **025-DL R4 (proven body invariance) CARRIES FORWARD**: acceptance must PROVE via `git diff` that the change is confined to the frontmatter block; zero body bytes change.
5. **025-DL R3 (path scope) CARRIES FORWARD**: scope is `docs/compound/` and nothing else. `docs/decisions/`, `plans/`, `reviews/`, `closure/`, `spikes/`, `research/`, `design-docs/`, `product-specs/` are in docline scope and may carry the same class of gap; that remains a SEPARATE surface and widening into it is a P-021 scope breach.
6. **025-DL R6 (width isolation, P-003) CARRIES FORWARD**: corpus data, test surface, and template family are three distinct surfaces and MUST be three distinct tasks. Do not combine them.

WHY (b) EXEMPT IS REJECTED. An exemption would enshrine, in the learnings corpus itself, that `source` means two different things depending on which file you read — while the authoring contract says in normative prose that it means exactly one. The corpus is the Step 1.8 learnings-retrieval substrate; a field whose meaning is file-dependent is a retrieval hazard, not a cosmetic one. An exemption is also strictly more machinery than the fix: it requires an allowlist, a rationale record, and permanent maintenance, versus a one-value edit.

WHY (d) EXTERNAL IS REJECTED. 025-DL already adjudicated this exact boundary and the reasoning transfers unchanged: 90F2A9F8 / 3C7AAC71 / B57F9E24 are defects in backlogit's OWN BEHAVIOUR, changeable only in backlogit's repository on backlogit's release schedule. This is a value in autoharness's own corpus, violating autoharness's own already-merged authoring contract, fixable today by autoharness alone. Classifying a self-closable gap as external is how a gate becomes decorative — 025-DL's phrase, applied here unchanged.

WHY (f) WON'T-FIX IS REJECTED. The cost is not the one wrong value; it is that the guard cannot see it. `test_all_compound_docs_have_source_and_doc_type` reports 75/75 GREEN on a corpus that contains a known violation. That is a false-green structural guard, and the same class of evidence-integrity defect the 146-F "success-shaped evidence loss" work upstream exists to close. Leaving it in place guarantees silent recurrence: the next author who copies a neighbouring file's shape is unconstrained by anything executable.

WHY THE RATCHET IS THE DURABLE HALF, AND WHY IT IS TWO EDITS NOT ONE. The normative prose (Phase 3) and the checkable criterion (Quality Criteria: "present and non-empty") disagree in strength within a single template file, and the Python guard mirrors the weaker one. Fixing only the data leaves both weak surfaces intact. Fixing only the test leaves an authoring template that still tells a human the weaker rule. Both must move to value shape, in their own width-isolated tasks.

NOTABLY OUT OF SCOPE — NO NEW TEMPLATE CONTRACT IS AUTHORED. Phase 3 already states the self-referential rule normatively. The template task is a one-line RATCHET of the existing Quality Criteria bullet to match prose that is already there — NOT a new contract, NOT a redefinition, and NOT a re-litigation of 140.002-T. This bounds the template-family blast radius to a single bullet.

## Open Questions

<!-- BEGIN:open-questions -->
R1 (VALUE-SHAPE PREDICATE — MUST BE PINNED IN THE TEST TASK): the assertion is `source`, with surrounding quotes stripped, EQUALS the file's repo-relative path in POSIX form (`docs/compound/<...>.md`). It MUST be derived from the file's actual location, never hard-coded to a flat `docs/compound/` prefix: `templates/skills/compound/SKILL.md.tmpl` Phase 3 models `source: "{{DOCS_COMPOUND}}/{category}/{slug}-{YYYY-MM-DD}.md"`, i.e. a CATEGORY SUBDIRECTORY is a legal future shape. A predicate that assumes a flat directory would become a false failure the day the first category subdirectory is created. Derive from `path.relative_to(repo_root).as_posix()`.

R2 (RATCHET MUST NOT WEAKEN THE EXISTING GUARD): the current test also enforces non-emptiness and a `*.md`-only scope (`test_no_non_markdown_assets_are_in_scope`, amendment C2), and treats a YAML null (`source: null` / `source: ~`), a comment-only value (`source: # missing`), and an empty string as empty. The value-shape assertion must be ADDITIVE. Every one of those existing behaviours must still fail after the ratchet. Deleting or relaxing any of them to make the new assertion simpler destroys a working guard while appearing to strengthen it (the R3 hazard 024-DL recorded, in its own domain).

R3 (`doc_type` IS EXPLICITLY NOT RATCHETED): this deliberation authorises a value-shape assertion on `source` ONLY. `doc_type` remains a non-emptiness check. Its correct value is resolved through the template's three-rung capability-neutral authority order (tooling operation -> configured path map -> directory convention), and pinning a literal `learning` in a repo-side test would hard-code rung 3 and contradict amendment C3's capability-neutral design. Extending the ratchet to `doc_type` is a SEPARATE decision requiring its own deliberation.

R4 (ORDERING DEVIATES FROM TEST-FIRST, DELIBERATELY): the ratcheted test would be RED against the current corpus, so the ordering is corpus-fix FIRST, then test ratchet, then template ratchet. This deviates from the repo's usual RED-harness-first precedent (e.g. 144.001-T) and does so on purpose: with only ONE known violation and an exactly-measured baseline (74/75 conforming), a RED intermediate commit would break the canonical local gate mid-shipment for zero diagnostic gain. The test task's acceptance MUST therefore independently demonstrate the assertion's DISCRIMINATING POWER — prove it fails on a deliberately wrong value — so it is not merely green-by-construction.

R5 (CORPUS DRIFT DURING EXECUTION): the corpus grew 73 -> 75 between 025-DL (2026-08-21) and this deliberation (2026-08-23) — roughly one new learning per day. The corpus-fix task must RE-MEASURE at execution time rather than trusting the 74/75 baseline recorded here. If re-measurement finds MORE than one non-conforming file, that is a materially different finding: fix the single known outlier, and return the additional files to Stage as a new P-021 capture rather than silently widening scope.

R6 (SCOPE GUARD): this authorises `docs/compound/` only. If the ratcheted predicate turns out to be desirable for other docline-scoped directories, that is a different contract surface and must re-enter P-021 capture. Do not widen the test's glob.

REQUIRES PLAN HARDENING: **NO** — considered, not defaulted. Blast radius is one corpus file (frontmatter only, body-invariant, git-revertible), one test file, and one prose bullet in one template file. No schemas, no CLI distribution, no multiple template families. `templates/skills/compound/SKILL.md.tmpl` has NO installed dogfood counterpart under `.github/skills/` (which holds only `install-harness`, `tune-harness`, `verify-harness`, `workspace-discovery`) and NO entry in `.autoharness/harness-manifest.yaml` — independently re-verified this session — so there is no paired-edit obligation and no checksum churn. This matches 025-DL's hardening determination, which held through execution.
