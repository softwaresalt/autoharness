Phase 1 of the deferred DAG-visibility follow-up from spike 001-SP (stash 33CC445C). Add a READ-ONLY reporting command that surfaces the ready-set (LIVE QUEUED shipments whose every predecessor has reached a genuine no-longer-blocking terminal closure — completed with valid `shipped`/`done` closure; a `queued` OR `active` predecessor is UNFINISHED and BLOCKS, an `active` shipment is in-progress work and is NOT terminal/non-blocking; `abandoned`/malformed/unknown predecessor states are FAIL-CLOSED and never treated as terminal-ready; and the ready-set itself contains ONLY live `queued` candidates — never an `active`/`shipped`/`abandoned`/`archived` shipment even if dependency-free), the critical path, and downstream dependents over backlogit's EXISTING shipment-blocks DAG. No scheduler, no mutation, no parallelism. Reuses the shipment-blocks graph reader already present in src/autoharness/gates/topology.py (shipped via 109-F).

IMPL-PLAN (impl-plan; source of truth = spike 001-SP Phase 1):
- Surface: extend the existing gate family. New read-only function in gates/topology.py computing ready-set + critical path + downstream dependents from the same backlogit shipment-blocks graph the topology gate already reads (READY-SET DEFINITION: the ready-set is the LIVE QUEUED shipments (status == `queued`) whose EVERY predecessor block has reached a genuine no-longer-blocking terminal closure — a predecessor counts as finished ONLY when it is completed with valid `shipped`/`done` closure. A `queued` OR `active` predecessor is UNFINISHED and BLOCKS its dependent (an `active` shipment is in-progress work — NOT a terminal state and NOT non-blocking). A predecessor in an `abandoned`, malformed, or unknown state follows the EXISTING FAIL-CLOSED semantics — treated as still-blocking / not-ready, never casually treated as terminal-ready. Separately, the ready-set itself contains ONLY live `queued` candidates: a shipment that is `active`, `shipped`, `abandoned`, or `archived` is NEVER a ready candidate even when dependency-free); new `autoharness gate dag-readiness [--json]` subcommand in cli.py dispatch + GATE_USAGE.
