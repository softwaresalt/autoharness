'critical path' defined as the LONGEST CHAIN in the blocks DAG by NODE COUNT (shipments are not time-weighted) — documented in the function docstring (review P2-1). 3. Ready-set is defined as LIVE QUEUED shipments ONLY (status == `queued`) whose EVERY predecessor block has reached a genuine no-longer-blocking terminal closure — a predecessor counts as finished ONLY when completed with valid `shipped`/`done` closure. Separately, a shipment that is `active`, `shipped`, `abandoned`, or `archived` is NEVER in the ready-set even when it has no blocks / is dependency-free, and a `queued` shipment with any unfinished predecessor is excluded (review P2-3). 4. Unit tests cover: empty graph, single node, linear chain, branch/merge, a cycle-guard, AND ready-set status filtering — a dependency-free shipment that is `active`/`shipped`/`abandoned`/`archived` is EXCLUDED from the ready-set while a dependency-free LIVE `queued` shipment is INCLUDED; AND predecessor-finished filtering — a LIVE `queued` dependent whose predecessor is `active` is EXCLUDED (REGRESSION: active predecessor blocks queued dependent — an `active` predecessor is unfinished, NOT terminal-ready), a LIVE `queued` dependent whose predecessor is still `queued` is EXCLUDED, a LIVE `queued` dependent whose every predecessor is completed with valid `shipped`/`done` closure is INCLUDED, and a predecessor in an `abandoned`/malformed/unknown state keeps the dependent EXCLUDED (fail-closed) — cycle detection is OWNED and performed by THIS new read-only DAG-readiness analyzer/algorithm; the reused gates/topology.py shipment-blocks reader is used ONLY for data access (graph read) and does NOT itself detect cycles.
