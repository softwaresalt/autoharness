Stage deliberation resolving stash DDBF283E and EB23D1B9. DDBF283E: the Step 0(c) pre-mutation evidence mechanism planned for 163.004-T proves pre-existence with fields the agent itself writes (collection_completed_at, HEAD SHA, manifest list), so a byte-identical post-hoc reconstruction that backdates the timestamp satisfies every clause of the check — a gate no illegitimate state can fail, the dual of the 15A02E21 gate no legitimate state could satisfy. EB23D1B9: that prerequisite is not encoded in 171-S's claim-eligibility graph, which blocks only on 169-S. DECIDED: adopt an engine-written append-only ordering proof (O4). Step 0(c) appends a PRECASCADE_EVIDENCE_ANCHOR event carrying the evidence record's sha256 to .backlogit/logs/{shipment_id}.jsonl via backlogit's append operation; the engine — not the agent — writes the timestamp, actor, and append position, and the cascade mutation later appends its own shipment_status_changed/commit_tracked/archived events to the same file, so ordering is proved by relative append position in an engine-owned file. Verified against live data: engine authorship confirmed in 150-S/151-S/152-S logs; logs survive archival ON THE LOCAL FILESYSTEM so the proof outlives the mutation it proves for a reviewer working in the closing workspace; and .backlogit/logs/159-S.jsonl demonstrably contains no anchor before archived, making the real failure case mechanically detectable. collection_completed_at is demoted to corroborating metadata. Four separately labelled, independently failing halt tokens (EVIDENCE_MISSING, EVIDENCE_STALE, ANCHOR_MISSING, ANCHOR_NOT_PRE_MUTATION). Rejected: RFC 3161 external timestamps (injects a network dependency into a fail-closed irreversible close path, converting an integrity control into an availability outage); git-commit ancestry as primary (would make the gate unsatisfiable in legitimate states — the 15A02E21 mistake — retained as an optional corroborating field); skill-maintained hash chain (agent owns the chain, self-reported at one remove). CONTAINMENT: revise 171-S in place rather than create a predecessor shipment, because a predecessor would edit the identical Step 0(c) paragraphs 171-S's U2 edits, adding a third contender to a region already contended by 169-S and reproducing the two-independent-restatements drift that produced 15A02E21. No Python source change; no new units; no change to 169-S/161-F or 170-S/162-F scope; 856B6770 disposition untouched; no retroactive-compliance claim for 159-S. Revises plan U1a/U1b/U1c/U2/U3 and tasks 163.001-T, 163.002-T, 163.003-T, 163.004-T, 163.005-T. Threat model stated explicitly: the target is tamper-EVIDENT and out-of-protocol, not tamper-proof — no purely local mechanism resists an operator with shell access, and the design goal is to make the reconstruction path unreachable through the agent's normal tool surface. (1) FALSE GIT-STATE PREMISE CORRECTED. The AMENDMENT D-7 / R1-11 block above justifies the durability split with "the anchor is durable and auditable LOCALLY but invisible to a fresh-clone reviewer" because ".backlogit/logs/ is covered by a workspace .gitignore rule", and instructs an unconditional force-add past that rule. THE L1/L2 CONCLUSION SURVIVES - repository publication is genuinely a separate concern from local retention and still deserves separate naming - but the MECHANISM is now CONDITIONAL on the path's tracking state: CASE A already tracked, commit its mutation NORMALLY; CASE B untracked and not ignored, ordinary git add; CASE C untracked and ignored, git add -f bounded to that ONE shipment log.
