<!-- BEGIN:description -->
Add size-based rollover on write with a NO-REPLACE atomic generation claim, preserving the sink best-effort concurrent-writer contract. When the active segment reaches _MAX_SEGMENT_BYTES (module constant), seal it to max(existing sealed generation)+1 using an operation that FAILS rather than clobbers if that generation name already exists -- os.link(active, sealed_gen_N) then unlink active, or an O_EXCL / Win32 CreateFileW CREATE_NEW claim of the sealed name, or rename-to-unique-then-verify. On collision (another writer already claimed gen-N), the loser re-reads max(existing sealed generation) and RETRIES with the next generation, so a concurrent rollover can NEVER overwrite or lose an already-sealed segment -- WITHOUT a global lock. Then create a fresh active segment; an oversized single record (encoded line > threshold) is still written INTACT as one line to its own segment (never split). Writer model (PR #249 round 3, DEFINITIVE -- Option A): the sink is a best-effort concurrent-writer-safe mirror (cli.py:934/1003 telemetry record is a second public writer entry point; jsonl_sink.py:96-104 and :161-171 document concurrent writers as safe/benign-by-design), with SQLite authoritative and duplicate/late lines reconciled on read. Therefore sealed segments are NOT claimed immutable: a writer that opened the active fd before rollover may land a late O_APPEND in the just-sealed segment -- acceptable under contract, reconciled on read, NOT a correctness violation and NOT fixed with a writer-drain lock (which the sink deliberately avoids). Default _MAX_SEGMENT_BYTES is large enough that the existing suite never rolls; tests patch the constant to a low value. Depends on 095.001-T. Files: src/autoharness/telemetry/jsonl_sink.py, tests/test_telemetry_jsonl_sink.py. <=3 files, <=5 functions, <=4 test scenarios. TDD.
<!-- END:description -->

<!-- BEGIN:acceptance-criteria -->
With a patched low threshold, appending past _MAX_SEGMENT_BYTES rolls over: the prior active segment is sealed under the next generation name and a fresh active segment is created. Simultaneous destination-collision: when two writers pick the same next generation, the no-replace claim forces one to retry the next generation; BOTH sealed segments are preserved with zero whole-segment loss (no rename/create ever clobbers an existing sealed segment). With the default (high) threshold, existing small-scale writes stay single-segment and existing behavior is preserved, including the existing multi-thread line-integrity test. An oversized single record larger than the threshold is written intact to its own segment. Cross-segment replay from 095.001-T continues to hold after a rollover. No sealed-segment byte-immutability is claimed: a late line landing in a sealed segment after rollover is acceptable under the best-effort-mirror contract and is reconciled on read (covered by 095.004-T). No global write lock is introduced.
