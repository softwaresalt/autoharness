# P-015 / shipment-reconcile cascade-close `archived_ids` post-condition: replace false full-set equality with a two-set allowed/required gate

## Problem Frame

<!-- BEGIN:problem-frame -->
PROBLEM
autoharness's shipped contract text asserts a SAFETY INVARIANT THAT IS FALSE against the engine it governs.

`templates/policies/workflow-policies.md.tmpl` (P-015, fully-covered-root exception item 7, L444) states that the cascade `ship_shipment` operation "returns them in its `archived_ids` result exactly as it does newly-archived members, so the `shipment-reconcile` skill's post-condition exact-match check against the full manifest remains unchanged and must never be relaxed to exclude them."

`templates/skills/shipment-reconcile/SKILL.md.tmpl` step 3 (L600-604) implements that as a FULL-SET EQUALITY gate: `archived_ids` must contain "exactly the manifest's task items, every qualifying feature member, and the shipment record itself - nothing more, nothing less", and L562-567 pins it as evaluated "against the manifest's full item set, never against 'members newly archived by this call'", and "must never be relaxed."

That claim is FALSE. It makes the fail-closed gate itself the defect: any cascade close whose manifest contains a truly `status: archived` task is required to HALT with a spurious P-005 violation, even though the engine behaved correctly and the persisted final state is correct.

OBSERVED
Shipment 154-S / feature 146-F cascade close on backlogit 1.10.1-0.20260823032255-b07729386a31: `archived_ids` omitted pre-archived TASK manifest members while still listing the feature (146-F) and the shipment record (154-S). The closure was nonetheless recorded READY, and a compound-learning "operating rule" was written to rationalize it. PR #405 Copilot review threads PRRT_kwDORzpWpM6bj72w and PRRT_kwDORzpWpM6bj72- correctly flagged that BOTH the READY verdict AND that operating rule bypass a documented gate whose own text says it must never be relaxed. So the live situation is worse than a stale doc: shipped contract text and shipped practice actively disagree, and the disagreement was resolved in favor of undocumented practice.

EVIDENCE REVIEWED THIS SESSION (read-only; no new behavioral spike commissioned, per the entry's explicit non-goal)

1. ENGINE SOURCE (authoritative, C:\Source\GitHub\backlogit @ b0772938, READ-ONLY):
   - `internal/core/shipment_lifecycle.go` `archiveItems()` L1122-1139: iterates candidates, and `if item.Status == models.StatusArchived { continue }` - the item is SKIPPED and, critically, is NOT appended to the returned `archived` slice. That slice becomes `ArchivedIDs` (L670, L709).
   - Candidate collection L799: `if feature.Status != models.StatusArchived { candidates = append(...) }`; L808: descendants with `item.Status == models.StatusArchived` are `continue`d.
   CONCLUSION: `archived_ids` is, by construction, THE SET OF ARTIFACTS ACTUALLY TRANSITIONED TO ARCHIVED DURING THAT INVOCATION - a transition log, not a manifest echo. A truly pre-archived artifact has no transition to report and is therefore correctly absent. This is longstanding, deliberate, and correct.

2. WHY THE FEATURE STILL APPEARS: the explicit covering feature is temporarily moved to `done` and re-archived within the invocation, so at the L799 filter its status is `done`, not `archived` - a GENUINE transition inside the call. Hence the asymmetry actually observed on 154-S (feature + shipment present, pre-archived tasks absent) is fully explained by correct engine behavior.

3. THE SPIKE THAT MANUFACTURED THE FALSE INVARIANT: `docs/spikes/2026-08-18-cascade-close-pre-archived-member-behavior.md` reports all three arms returning byte-identical `archived_ids` including "members archived before the call" (L65-79), and explicitly concludes that adjusting the exact-match post-condition is "not required and would be actively harmful" (L111-115). ITS METHOD WAS INVALID: it produced its "pre-archived" arms with `move --status done`, which RELOCATES the record but leaves declared `status: done`. Against the L1130 guard, `done != archived`, so those artifacts WERE archived by the call and DID legitimately appear in `archived_ids`. The spike therefore never once exercised a true `status: archived` input; all three arms were, at the guard that matters, the control arm. Its central invariant was never tested, only assumed.

4. THE 1.10.1-REGRESSION HYPOTHESIS IS REFUTED. `docs/compound/2026-08-23-cascade-close-archived-ids-omits-pre-archived-tasks-on-1101.md` blames a version regression. The skip guard is unconditional in the shipped source and the behavior it produces is the documented intent; the observation is normal semantics meeting a false expectation, not a regression.

WHY THIS MUST BE FIXED IN AUTOHARNESS, NOT UPSTREAM
Primary ownership is autoharness's contract text, which mis-specifies a correct external API. A backlogit documentation/test follow-up is OPTIONAL and NON-BLOCKING. No engine change is warranted or requested.

BLAST RADIUS
Every future cascade close, for both Stage and Ship, runs this gate. Left as-is it produces false P-005 halts on legitimate closures - which trains agents and operators to override the gate, which is precisely the failure already observed on 154-S. A safety gate that must routinely be overridden is worse than no gate, because the override habit generalizes to the cases the gate exists to catch.

## Options

<!-- BEGIN:options -->
OPTION A - RELAX TO A SUBSET CHECK (`archived_ids - allowed_ids == empty` only)
Accept any subset of allowed artifacts; drop any completeness requirement.
+ Trivially removes the false failure; smallest edit.
- DESTROYS the gate's actual value. A cascade that silently archived NOTHING, or archived only the shipment record while leaving every task open, would PASS. The gate's whole purpose is detecting incomplete/incorrect cascade execution. This trades a false-positive problem for a false-negative one, on a fail-closed safety control. REJECTED.

OPTION B - KEEP FULL-SET EQUALITY, PRE-NORMALIZE BY RE-ARCHIVING
Before invoking cascade, force every pre-archived member back to a non-archived state so the invocation transitions all of them and the full-set equality holds.
+ Preserves existing contract text verbatim.
- Requires MUTATING correct, already-final artifacts purely to satisfy a checker; re-stamps shipment provenance onto artifacts belonging to earlier shipments (exactly what backlogit's own 129.001-T guard at L1091-1096 deliberately prevents). Fights the engine to preserve a false claim. REJECTED.

OPTION C - TWO-SET ALLOWED/REQUIRED GATE (SELECTED)
Snapshot DECLARED STATUS pre-close, then evaluate two independent set relations:
  - `allowed_ids` = manifest tasks + qualifying feature members + the shipment record
  - `required_ids` = allowed artifacts NOT truly `status: archived` in the pre-close snapshot
  - FAIL if `archived_ids - allowed_ids` is non-empty  (out-of-scope mutation - unchanged strength)
  - FAIL if `required_ids - archived_ids` is non-empty  (incomplete cascade - unchanged strength)
  - An already-archived allowed member MAY be included or omitted without failing.
+ Retains BOTH safety properties at full strength: nothing outside scope may be touched; nothing that had to be archived may be skipped. It removes ONLY the one assertion that was false - that artifacts with no transition to perform must nonetheless be reported as transitioned.
+ Tolerance is derived from a SNAPSHOT OF DECLARED STATUS, so it is scoped exactly to artifacts that genuinely had nothing to do - not a blanket allowance.
+ Robust to which engine sub-path ran: it does not encode the feature-via-done detail, so a future engine change to that detail cannot silently invalidate the contract.
SELECTED.

OPTION D - DERIVE STATE FROM DIRECTORY LOCATION
Treat presence in `archive/` as archived.
- This is the EXACT defect that invalidated the 2026-08-18 spike: `move --status done` puts a record in `archive/` with `status: done`, which the engine does NOT treat as archived. Location and declared status are different facts. Adopting location would rebuild the original error into the fix. REJECTED - and this rejection is itself a required regression test.
<!-- END:options -->

## Chosen Direction

<!-- BEGIN:chosen-direction -->
SELECTED: OPTION C - two-set allowed/required gate, keyed on a pre-close snapshot of DECLARED STATUS.

NORMATIVE CONTRACT (to be implemented verbatim)
1. Pre-close snapshot records each manifest member's DECLARED `status` field. "Truly archived" means declared `status: archived`. Directory location alone is NEVER sufficient - a record in `archive/` bearing `status: done` is NOT truly archived.
2. `allowed_ids` = manifest task items + qualifying feature members + the shipment record.
3. `required_ids` = allowed artifacts NOT truly `status: archived` in the pre-close snapshot.
4. FAIL when `archived_ids - allowed_ids` is non-empty -> `HALT - cascade archived unexpected artifact {id}` + P-005. (Unexpected/out-of-scope detection PRESERVED at full strength.)
5. FAIL when `required_ids - archived_ids` is non-empty -> `HALT - cascade did not archive required artifact {id}` + P-005. (Completeness PRESERVED.)
6. An already-archived allowed member MAY be present or absent in `archived_ids`; neither outcome fails the gate.
7. PRESERVED UNCHANGED: persisted-final-state verification, `returned_ids` empty check, parent_id-preservation against the Step 0(b) snapshot, shipment-status verification, protected-set rules (which retain NO pre-archived exemption), and the no-substitution rule.

RATIONALE
`archived_ids` is a TRANSITION LOG, not a manifest echo. The old gate asked the engine to report work it correctly did not do. Option C asks the two questions actually worth asking - "did you touch anything you shouldn't have?" and "did you skip anything you had to do?" - and asks neither about artifacts that had nothing to do. Fail-closed strength is preserved on both axes; only the false assertion is removed.

- The 154-S closure artifact is KEPT INTACT as historical evidence; add a forward cross-reference only. Changelog gets a NEW correction entry; history is not rewritten.
