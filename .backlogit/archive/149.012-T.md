Resolve and validate every user-controlled Git ref before it reaches git, closing the argument-injection surface in discover_modified_files, and resolve at the gate.check() boundary so shipped callers keep working. Domain: code (security). Files: 2.

<!-- BEGIN:acceptance-criteria -->
* `resolve_commit_ref(ref)` runs `git rev-parse --verify --end-of-options <ref>^{commit}` and returns the resolved SHA **only** if it matches `^[0-9a-f]{40}$`; otherwise returns `None`.
* **Option-like refs are never treated as options.** `--output=/tmp/x`, `--upload-pack=...`, and any leading-dash value resolve to `None`. `--end-of-options` forces git to interpret the value as a ref.
* **No side effect on rejection**: resolution writes no file, mutates nothing, and does not invoke `git diff`.
* `discover_modified_files` accepts **only** validated full hex SHAs for `base`/`head`, and additionally uses `--end-of-options` / `--` separators internally as a backstop, so the module is safe even if a future caller forgets to pre-resolve.
* Applies to **every** user-controlled ref — head as well as base.
* Read-only: the resolver performs no repository mutation.
* **PRODUCTION CALLERS *ARE* AFFECTED — cycle-2 claim RETRACTED (D-17, cycle-3
  thread `PRRT_kwDORzpWpM6dVfzg`)**. `gate.py::check` declares
  **`head: str = "HEAD"`** (`gates/gate.py:65`) and forwards `base`/`head`
  **unresolved** into `discover_fn(base, head, cwd=cwd)` (`gates/gate.py:77`).
  The shipped `autoharness gate check` command reaches that default
  (`cli.py:290` -> `cli.py:400-405`), so a hex-only discovery contract breaks a
  **released command**.
* **`gate.py::check` resolves at the boundary**: it resolves `base` and `head`
  through `resolve_commit_ref` and passes only validated 40-hex SHAs into
  `discover_fn`. An unresolvable or option-like ref is rejected there with the
  invalid-input class, **no `git diff` invocation and no file written**.
* **Resolution sits AFTER the disabled/no-gates early return** — `check()` must
  still return an empty report for `check(GatesConfig(enabled=False), base="main")`
  without resolving anything (pinned by `tests/test_gates_gate.py:86`).
* **Symbolic-ref tolerance is NOT restored inside `discover_modified_files`** —
  re-rejected in cycle 3 for the same reason as cycle 2: it reopens the D-12
  hole. The ref->SHA conversion moves *up* to the boundary.
* **BREAKING FOR SYMBOLIC-REF CALLERS — characterized, not accidental** (PR #414
  cycle-2 correction, thread `PRRT_kwDORzpWpM6dVQdY`): `discover_modified_files`
  no longer accepts symbolic refs (`main`, `HEAD`, `HEAD~1`, branch/tag names).
  Callers MUST pre-resolve through `resolve_commit_ref`. Symbolic-ref resolution
  is **not** removed from the system — it moves **up** into the resolver, which is
  the single place allowed to talk to `git rev-parse`.
* **The existing suites are re-characterized, not silently broken**:
  `tests/test_gates_discovery.py` calls `discover_modified_files("main", "HEAD", ...)`
  at lines **32, 40, 49** and asserts the exact pre-change argv
  `["git", "diff", "--name-only", "main...HEAD"]` at line **45**. All four
  assertions fail under this unit's contract. Additionally
  `tests/test_gates_gate.py::test_check_uses_injected_discover` asserts the
  injected discover receives `base == "main"`, which the D-17 boundary resolution
  changes. Both files are updated in **U8c (`149.013-T`)**, which owns the tests
  domain (width isolation). **This unit MUST NOT be marked complete while
  `PYTHONPATH=src python -m unittest discover -s tests` is red on either file.**

<!-- BEGIN:description -->
Plan unit **U8b**. Edit `src/autoharness/gates/discovery.py` **and** `src/autoharness/gates/gate.py`.

**The vulnerability being closed**: `discover_modified_files` currently builds

```python
argv = ["git", "diff", "--name-only", f"{base}...{head}"]
```

(`src/autoharness/gates/discovery.py:61`) with **no option terminator**. Because `base` is user-controlled via `--base`, a value of `--output=/tmp/x` produces the argument `--output=/tmp/x...HEAD`, which `git diff` parses as its **`--output=<file>` option and writes a file** — directly contradicting this gate's read-only guarantee.

**Add** `resolve_commit_ref(ref) -> str | None`:

1. Run `git rev-parse --verify --end-of-options <ref>^{commit}`.
2. Accept the result **only** if it matches `^[0-9a-f]{40}$`.
3. Return `None` for anything else — unresolvable, ambiguous, or option-like.

**Harden** `discover_modified_files` itself: assert `base`/`head` are validated full hex SHAs, and add `--end-of-options` / `--` separators. This is defence in depth — the resolver is the primary control, this is the backstop.

**Execution posture**: test-first. Tested by U8c (option-like, invalid, symbolic, full-SHA pass-through).

<!-- BEGIN:implementation-notes -->
**Decision D-12 (PR #414 cycle-1 correction, thread PRRT_kwDORzpWpM6dGx_a).**

**No dependencies** — this is a self-contained hardening of an existing module and does not need the detector contract. It is therefore schedulable FIRST in the serial order and unblocks both U4 (149.004-T) and U8 (149.008-T).

**Why a separate unit from U8**: U8 is width-isolated to the CLI (`src/autoharness/cli.py`, Files: 1). The resolver belongs in `gates/discovery.py` beside the vulnerable call, and it must protect **every** caller of discovery — not just the CLI path. Splitting keeps both units single-file and single-domain.

**Relationship to D-7**: D-7 already required resolving the base ref before calling `discover_modified_files`, but for a *correctness* reason — `discover_modified_files` never raises and returns `[]` on failure, so 'no files changed' and 'git broken' are indistinguishable (the FC1 trap). D-12 adds the *security* reason. One resolver satisfies both, which is why U4's applicability context also depends on this unit.

**Pre-existing-surface caution (CORRECTED in cycle 2, thread `PRRT_kwDORzpWpM6dVQdY`)**:
this is the one genuinely pre-existing shipped function touched by this shipment,
and the cycle-1 draft understated the blast radius. Two separate claims must be
kept apart:

* `--end-of-options` / `--` constrain only **option parsing** and cannot change
  the meaning of an already-valid ref. That part of the cycle-1 claim stands.
* The **input contract** does change: asserting `base`/`head` are validated
  40-hex SHAs **rejects symbolic refs at the call boundary**. The cycle-1 claim
  that "existing callers ... so observable diff output is unchanged" was true only
  of the single **production** caller (`gates/gate.py:77`); it was **false** of
  `tests/test_gates_discovery.py`, which passes `"main"`/`"HEAD"` directly and
  pins the exact old argv.

Consequence: the canonical unittest gate (Q5) fails on that file unless it is
updated. It is listed in **U8c**'s scope for that reason. Retaining symbolic-ref
compatibility inside `discover_modified_files` was considered and **rejected** —
it would reopen the very hole D-12 closes by letting unvalidated ref text reach
`git diff` again.
