# 33CC445C Phase 2 — deterministic next-eligible resumption ADVISORY over the shipped dag-readiness substrate

## Problem Frame

<!-- BEGIN:problem-frame -->
Phase 1 of 33CC445C shipped as 110-F / 117-S (both archived; `autoharness gate dag-readiness`). It reports a lexicographically-sorted `ready_set`, a `critical_path`, and `downstream_dependents`. VERIFIED GAP (read-only, this session): there is NO deterministic single-cursor answer to "what is the one thing to pick up right now?" — `ready_set` is a SET that may hold 0, 1, or N candidates with no documented selection rule, and it deliberately ignores in-flight `active` work entirely (an `active` shipment is never a ready candidate). After a crash, restart, or context loss, an operator/Orchestrator reading `ready_set` alone can wrongly conclude that a NEW shipment should be started while an `active` shipment is still in flight — the exact failure mode P-001 single-active exists to prevent. Grep confirms NO existing `next_eligible`/`NextEligible` implementation in autoharness (src/, docs/, templates/, .github/) and NONE in external backlogit 1.8.0 (HEAD fd8d2c9d, internal/ scanned read-only), so this is non-duplicative and not upstream-owned. TENSION TO RESOLVE: docs/dag-readiness-gate.md states a PERMANENT NON-GOAL that the gate will never "Select or execute a 'next' shipment automatically." Any Phase 2 must be reconciled with that sentence rather than silently contradicting it.
<!-- END:problem-frame -->

## Options

<!-- BEGIN:options -->
OPTION A — Do nothing; leave Phase 2 deferred indefinitely. Pro: zero risk, honors the literal non-goal sentence. Con: leaves the verified resumption ambiguity permanently unaddressed; the operator has now explicitly granted authority to evaluate/stage this phase; `ready_set` alone remains actively misleading after a crash because it hides in-flight `active` work.

OPTION B — Full scheduler / auto-claim: compute the next shipment and claim/activate it. REJECTED OUTRIGHT. Directly violates P-001 (at-most-one-active), P-016 (single worktree), P-009/P-014 (Stage/Ship role separation and no self-authorized promotion), and the gate's stated permanent non-goal. Not considered further.

OPTION C — Advisory-only deterministic resumption cursor (CHOSEN). A pure, read-only analyzer + additive CLI field that answers "what single shipment should be picked up next?" as a RECOMMENDATION that performs no claim, no activation, and no mutation of any kind. Resolution order is resumption-first: (1) exactly one `active` shipment => THAT is the cursor (resume in-flight work; never recommend starting new); (2) zero `active` => the deterministic first element of the existing `ready_set` under a documented, stable two-key tie-break; (3) more than one `active` (a P-001 anomaly) => fail closed, emit null + anomaly reason, defer to the pipeline-topology gate; (4) cycle detected, DEGRADED backlog, or ambiguous live+archive provenance => null, never fabricate a cursor. Pro: reuses `compute_dag_readiness` and `FilesystemTopologyReaders` wholesale (composability), is strictly additive to an existing JSON payload (interoperability), materially improves crash/restart reliability, and is small enough to keep the whole feature inside three width-isolated ~2h tasks (simplicity). Con: requires an explicit, careful documentation reconciliation of the existing permanent-non-goal sentence.

OPTION D — Option C but tie-break on `critical_path` membership. Rejected as gratuitous complexity: `critical_path` is a longest-chain-by-node-count artifact whose own tie-break is already lexical, so keying off it would layer one arbitrary tie-break on another. The chosen key (`downstream_dependents` fan-out) is already computed by the same call, is directly meaningful ("unblocks the most work"), and needs no new graph traversal.

OPTION E — Fold the cursor into the existing `--json` payload unconditionally with no opt-in flag. Deferred to the plan: the additive-field-plus-opt-in-flag question is an implementation detail, but the payload MUST remain backward compatible either way.
<!-- END:options -->

## Chosen Direction

<!-- BEGIN:chosen-direction -->
OPTION C — advisory-only deterministic resumption cursor, harvested as a bounded three-task feature.

RECONCILIATION OF THE STATED PERMANENT NON-GOAL: the non-goal sentence in docs/dag-readiness-gate.md is preserved verbatim in force and NARROWED IN WORDING ONLY where it is genuinely ambiguous. The prohibited behavior is AUTOMATIC selection-for-execution — claiming, activating, or executing a shipment without an explicit human/Ship decision. Emitting a deterministic, read-only RECOMMENDATION that a human or the Orchestrator must still act on explicitly is categorically different and does not weaken P-001/P-016: no shipment is claimed, no shipment is activated, no worktree or branch is created, and Ship's authority to claim is untouched. The documentation task MUST make this distinction explicit rather than deleting or quietly softening the non-goal.

DETERMINISTIC TIE-BREAK (documented, stable, total): among `ready_set` candidates sort by (1) DESCENDING count of transitive `downstream_dependents` — prefer the candidate that unblocks the most downstream work; then (2) ASCENDING shipment id as the total-order fallback. Because shipment ids are unique, the second key makes the order total, so the cursor is never ambiguous and never depends on filesystem or dict iteration order.

FAIL-CLOSED POSTURE (inherits compound learning 2026-08-07-copilot-review-fix-introduces-new-filter-bug): enumerate the full shipment set UNFILTERED, check for anomalies (multi-active, cycle, DEGRADED, ambiguous live+archive provenance) FIRST on the unfiltered result, and only THEN partition to candidates. Never add an early narrowing filter that could hide the anomaly the cursor exists to surface. Every anomaly path yields `next_eligible: null` WITH a populated machine-readable reason — never a silently empty result and never a fabricated cursor.

SCOPE FLOOR (minimal composable substrate): analyzer + CLI field + docs ONLY. Explicitly NOT in scope — no agent-template weaving, no installed dogfood mirror refresh, no schema change, no new gate family, no exit-code change, no backlogit/external change.
<!-- END:chosen-direction -->

## Open Questions

<!-- BEGIN:open-questions -->
(1) Opt-in flag vs. unconditional additive field — RESOLVED IN PLAN, not blocking: either is acceptable provided existing `--json` consumers keep working and the human-readable report gains at most one line. (2) Should the cursor ever be emitted when `status == "degraded"`? NO — resolved: DEGRADED means the graph was never read, so any cursor would be fabricated; emit null with the degraded reason. (3) Should a multi-active anomaly cause a non-zero exit? NO — resolved: dag-readiness has no BLOCK verdict by design and the pipeline-topology gate already owns the P-001 BLOCK; changing exit codes here would break the Phase 1 contract. (4) Should Orchestrator/Stage/Ship agent templates be woven to consult the cursor? DEFERRED OUT OF SCOPE — weaving would pull in the installed dogfood mirror refresh burden (the 111.007-T lesson) and broaden width for no reliability gain in this increment; re-triage only after the cursor has shipped and proven stable. (5) 33CC445C DISPOSITION: with Phase 2 harvested here, the tracker carries no remaining unconsumed content and becomes fully consumed; it is archived at Step 5.6. Parallel-safe multi-worktree execution remains a PERMANENT NON-GOAL under P-001/P-016 and is NOT resurrected by this deliberation.
