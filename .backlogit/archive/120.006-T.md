SIZE: M. COMPLEXITY: medium. (Two independent axes; also emitted as structured backlog fields.) Shipment 3 (P1). Add a `run` top-level command to src/autoharness/cli.py and a matching console entry point, following the repository's existing hand-rolled parsing style (no argparse, no click/typer). The adapter is STRICTLY parse argv -> call supervise.app.run_session() -> render human or --json -> sys.exit(result.exit_code). NO POLICY IN THE ADAPTER: no config loading, no pass/fail definition, no verdict mutation, no audit-log authorship, no telemetry classification, and no synthesis of any outcome the service cannot produce. Exit codes are DERIVED from the single machine-readable contract table, never hardcoded at the call site. If a supervisor ToolTelemetryEvent is ever emitted it is emitted BY THE SERVICE with tool_surface supplied by this adapter - never synthesized in cli.py. F25 RULING - THE COMPLETE, STABLE OPTION CONTRACT IS DEFINED HERE, AND THIS IS THE ONLY SURFACE THAT EXPOSES IT: `autoharness run [--json] [--force-unlock] [--max-restarts N] [--pty | --no-pty] [--session-id ID] [-- <verbatim child argv>]`. Each option maps to exactly one run_session() parameter: --json selects the machine-readable renderer; --force-unlock is the ONLY reachable remedy for a stale workspace lock (118.006-T) and MUST be exposed here or that remedy does not exist for the operator; --max-restarts N sets the restart budget whose DEFAULT REMAINS 0 (119.006-T); --pty/--no-pty selects the opt-in PTY capture backend (119.002-T), with INHERITED STDIO as the default when neither is given (F29); everything after `--` is forwarded VERBATIM and never re-parsed. The contract is STABLE - adding, renaming or removing an option is a documented contract change - and 120.008-T publishes it as operator-facing documentation. ADDITIVE ONLY: the existing 10 top-level / 17 leaf command paths are unchanged, and no existing CLI test is modified. Tests cover human and --json rendering, exit-code propagation for each error kind, and - for EVERY option in the contract above - BOTH that it parses AND that it is FORWARDED to run_session() with the expected value. Parsing alone is explicitly insufficient evidence that an option is reachable: F25 was precisely a case where operator controls were specified elsewhere and never exposed.

F34 CONSEQUENCE FOR --force-unlock (2026-08-11, operator-accepted ruling; propagated here because this task OWNS the operator-facing remedy). Under the GUARD/RECORD split now specified in 118.005-T/118.006-T, --force-unlock is genuinely REACHABLE: cleanup acquires the stable never-deleted GUARD lock and repairs only the separate RECORD file. Under the superseded exclusive-create (`O_CREAT|O_EXCL`) backend it was NOT reachable - a stale lock meant the path already existed, so cleanup could never acquire the primitive and the remedy would have refused unconditionally, leaving the workspace strandable with no recovery path at all. This adapter MUST NOT re-implement, weaken, or work around that contract: it exposes the flag and forwards it, and ALL exclusion, liveness, refusal and repair policy stays in supervise/locking.py (zero policy in the adapter). ADDITIONAL ACCEPTANCE CRITERION: assert that --force-unlock is FORWARDED to run_session() AND that a REFUSED force-unlock (live holder present) propagates the distinct REFUSED outcome and its exit code verbatim - the adapter MUST NOT convert a refusal into a success, a generic failure, or a retry. This criterion MUST execute on both Windows and POSIX.
