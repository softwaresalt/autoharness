<!-- BEGIN:acceptance-criteria -->
* The ownership reader consumes `target_shipment_id` from the shared gate domain-input established by 109.002-T; it never substitutes the currently claimed shipment for an explicit target.
* SHIPMENT-SCOPED / PRE-CLAIM: load the explicitly selected target shipment read-only even when no shipment is currently claimed, derive its expected `feat/{slug}` or `chore/{slug}` branch from that target's title, and evaluate ownership against THAT target.
* Three mutually-exclusive target-scoped cases resolve unambiguously: matching target shipment branch -> BRANCH_OK; default branch -> create-eligible for the target; any other branch -> BRANCH_MISMATCH fail-closed. A branch matching some different claimed shipment does not satisfy the selected target.
* Agent shipment-scoped mode with missing/empty/unresolvable `target_shipment_id` is INVALID (exit 2) under 109.002-T; the ownership check is never silently skipped.
* NON-SHIPMENT HOOK/CI: consume the centrally resolved ambient target (currently-claimed shipment, then current-branch slug) when one resolves and apply the same target-scoped ownership cases. Only when no ambient target resolves is the target-ownership check existence-guarded/skipped so ordinary no-claim git work is not blocked; target-independent A2/A3b checks still run fail-closed.
* Reader is read-only and injectable.
<!-- END:acceptance-criteria -->

<!-- BEGIN:description -->
[Shipment A / core] Implement the P-011 three-case branch ownership check against the gate domain-input's `target_shipment_id`. In shipment-scoped mode, read the explicitly selected shipment before claim, derive the expected branch slug from that target shipment's title, and validate the current branch against that target regardless of whether any shipment is currently claimed. In ambient hook/CI mode, apply the same check when central target resolution yields a shipment; reserve no-target existence-guard behavior strictly for ambient mode when no target resolves.
