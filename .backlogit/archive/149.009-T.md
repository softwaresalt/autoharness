<!-- BEGIN:acceptance-criteria -->
* **P0 SECURITY ENFORCEMENT — the gating assertion**: a ref pointing OUTSIDE the `autoharness.detectors` namespace yields `invalid` and is **NEVER imported**. This test is what makes the plan-review PASS verdict valid; without it the arbitrary-import P0 is unmitigated.
* **D-9 CANONICAL-FIELD CONTRACT**: `verdict` is absent from `dataclasses.fields(NodeResult)` and absent from `to_dict()` keys; any `verdict` property always equals `status`; **no constructor, `dataclasses.replace`, or deserialization path can produce a contradictory outcome pair**. Contradiction must be unrepresentable, not merely unobserved.
* A registry declaring `producer.kind: command` yields `invalid` (not implemented in S1).
* Contract-freeze test fails if a 9th status value is added — this is what stops S2-S10 widening the contract silently.
* FC1 test asserts the outcome is `insufficient_evidence` and explicitly asserts it is NOT `not_applicable`.
* **FC1 IS AN ENGINE-LAYER TEST (D-14, cycle-2 thread `PRRT_kwDORzpWpM6dVQdQ`)**: it drives the applicability engine **directly**, with a context that cannot be built from *already-validated* input — unreadable manifest, missing profile, or an internally-derived base that fails to resolve. It MUST NOT be written as a CLI test with an unsafe/unresolvable `--base`: that input exits **2** at the CLI boundary before the engine is reached (U8/U8b/U8c), so such a test would contradict U11 and could never pass alongside it.
* Back-compat: config with no `detectors` block validates, yields zero nodes, exit 0.
* No network access.
<!-- END:acceptance-criteria -->
