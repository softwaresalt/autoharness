## Description

<!-- BEGIN:description -->
Stabilize the non-context telemetry record path so identical retries are digest-stable (source: stash A7DBF981).

Files (2): src/autoharness/cli.py, tests/test_telemetry_record_cli.py

Current state: the non-context telemetry record path (cli.py:945-952) validates only epoch_id via _validate_record_epoch_id (cli.py:820-840). When timestamp is omitted, ExecutionEpoch.from_mapping (epoch.py:822-823) leaves the dataclass default field(default_factory=_utc_now_iso) (epoch.py:700) to stamp a fresh wall-clock value on every call, so an intended idempotent retry produces a different payload_digest and is rejected as conflict_rejected instead of recognized as idempotent_replay.

TDD (red->green): add test_record_rejects_missing_timestamp_without_context (payload omitting timestamp on the non-context path now raises EpochError / exits 2, mirroring test_record_rejects_missing_epoch_id_without_context at line 108), test_record_replays_idempotently_with_explicit_timestamp_without_context (same payload with explicit timestamp, recorded twice, yields created then idempotent_replay), and test_record_rejects_malformed_timestamp_without_context (a nonblank but malformed timestamp such as "not-a-date" raises EpochError / exits 2 rather than being accepted on write and later silently dropped by the reader). Confirm all three fail first. Then add a _validate_record_timestamp(value) helper beside _validate_record_epoch_id in cli.py, called at cli.py:951 alongside the existing non-context epoch_id validation, raising EpochError with an actionable message when timestamp is None/blank OR is a nonblank value that is not a valid ISO-8601 instant -- mirroring the reader's write/read parity check (reader.py:45-50: datetime.fromisoformat(value.replace("Z","+00:00"))) so a malformed timestamp fails closed on write instead of being persisted and later silently skipped by the reader's _validate_record_timestamp (reader.py:35-50).
