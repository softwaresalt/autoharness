<!-- BEGIN:acceptance-criteria -->
* **RK1 FALSIFICATION GATE — this is a gate, not a metric.** If `ART-01` re-detects **NONE** of the listed historical defects, **HALT the shipment and ESCALATE to the operator** for the Option A (independent gates) reconsideration. This does NOT authorize proceeding with a weaker claim. This is a designed early exit, not a formality.
* **INV-6**: the shipped registry contains **exactly one** node. A second detector FAILS this test — structural enforcement of the S1/S2 boundary.
* **INV-7**: `.backlogit/**` content and mtimes unchanged after a run (zero backlogit mutation, Q9).
* **Exit-code invariance sweep**: across every fixture the only observed exit codes are **0 and 2**. Any 1 or 3 is a HARD STOP.
* Exit 0 asserted while `ART-01` reports `failed` (report-only guarantee).
* **D-12 / FC1 LAYER BOUNDARY — this suite must not contradict U8/U8b/U8c**
  (PR #414 cycle-2 correction, thread `PRRT_kwDORzpWpM6dVQdQ`). Exactly one
  outcome is correct per layer, and the two are never asserted for the same input:
  * **CLI boundary** (`--base` is user-controlled): an unsafe or unresolvable ref
    is rejected **before discovery** with **exit 2 and no side effect** — the
    contract stated in U8 (`149.008-T`), implemented in U8b (`149.012-T`), and
    security-tested in U8c (`149.013-T`). **This suite asserts that.**
  * **Applicability-engine FC1** (`149.004-T`): a context that cannot be built
    from **already-validated** input — unreadable manifest, missing profile, or an
    internally-derived base that fails to resolve — yields `insufficient_evidence`
    for every node, explicitly NOT `not_applicable`. That is asserted in **U9
    (`149.009-T`) scenario 4**, and is **out of scope for this suite**.
  * The CLI path can never reach FC1 with bad user input, because it exits 2
    first. An `insufficient_evidence`-at-exit-0 assertion for a bad `--base` would
    make U11 and U8/U8c mutually unsatisfiable.
* No network access anywhere in this suite.
<!-- END:acceptance-criteria -->
