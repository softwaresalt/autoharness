# verify-workspace template-variable derivation must conform to the install-harness resolution contract (62 unresolved variables)

## Problem Frame

<!-- BEGIN:problem-frame -->
`autoharness.verify_workspace._derive_template_variables` is a SECOND implementation of a variable-resolution contract whose single source of truth is `.github/skills/install-harness/SKILL.md` (variable resolution tables, lines ~380-453). It has drifted from that contract.

MEASURED BY STAGE (read-only, this workspace, from the committed staging report `.autoharness/staging/verify-workspace-report.json`):
- 83 unresolved `{{...}}` placeholder OCCURRENCES spanning 62 DISTINCT variables across 10 staged files.
- Distribution: `.autoharness/config.yaml` 45; `.github/agents/_orchestrator.agent.md` 15; `escalation-protocol.instructions.md` 6; `copilot-instructions.md` 4; `constitution.instructions.md` 4; `graphtor-docs.instructions.md` 2; `AGENTS.md` 2; `start.ps1` 2; `start.sh` 2; `github-pr-automation.instructions.md` 1.
- `{{DEFAULT_BRANCH}}` alone accounts for 12 occurrences.
- This is MATERIALLY LARGER than the stash entry's own measurement (4 template pairs / 21 occurrences). The entry under-scoped the defect.

VARIABLE FAMILIES (62 distinct):
1. Model-routing/escalation (~30): MODEL_ROUTING_TIER1/2/3, TIER_1/2/3_{FAMILY,PROVIDER,REASONING_EFFORT}, ORCHESTRATOR_*, STAGE_*, SHIP_*, STAGE_ESCALATION_*, SHIP_ESCALATION_*, LEGACY_ESCALATION_*, ESCALATION_*, ANCHOR_REVIEW_*.
2. Install shape (~10): INSTALL_PRESET, PRIMARY_STACK_PACK, STACK_PACKS_YAML, INSTALL_LAYERS_YAML, CAPABILITY_PACKS_YAML, HARNESS_OVERRIDES_YAML, ENABLED_SIDECARS_{YAML,SH,PS1}, COPILOT_CLI_ARGS_{YAML,SH,PS1}.
3. Profile-derived (7): LANGUAGE_VERSION, LANGUAGE_NOTES, LINTER, FORMATTER, FORMAT_CHECK_COMMAND, ERROR_PATTERN, DOC_COMMENT_STYLE.
4. Misc config (~8): DEFAULT_BRANCH, STRICT_SAFETY_ENABLED, CONTINUOUS_LEARNING_{CAPTURE_HOOKS,ENVIRONMENT_ADAPTER,PROMOTION_THRESHOLD}, GRAPHTOR_SOURCES_PATH, GRAPHTOR_BINARY_PATH.

AUTHORITY EVIDENCE (bears directly on option (c)):
- `_derive_template_variables` + `_render_template` ARE the renderer behind `autoharness verify-workspace`, which writes the full staged harness to `.autoharness/staging/` (verify_workspace.py:4196 derive, :4339 render, :4058 staging root). That staging tree is the refresh/re-install surface.
- The SAME module treats unresolved placeholders as hard errors in targeted artifact checks: `errors.append("unresolved template placeholders: " + ...)` at verify_workspace.py:3494-3497 and :3689-3692, and `_scan_manifest_scalar_placeholders` emits BLOCKERS.
- The renderer is additionally load-bearing for the P-021/137-F parity contract: `tests/test_scope_containment_policy_contract.py` imports `_derive_template_variables`/`_render_template` (module level) and asserts byte-identity of the four clean template/dogfood pairs (`test_clean_pairs_are_byte_identical_via_render_template`, line 630).
- Repository contract (`.github/copilot-instructions.md`): "Unresolved variables in output files indicate an installation error."

SOURCE REFS (P-021 traceability, carried forward): origin stash 6D62077C; spike `docs/decisions/2026-08-20-template-dogfood-render-parity-spike.md` finding F5; feature 137-F; shipment 145-S; PR N/A (pre-PR Stage discovery); review-thread N/A.
<!-- END:problem-frame -->

## Options

<!-- BEGIN:options -->
(a) MISSING DERIVATION LOGIC — close the coverage gap in `_derive_template_variables`, conforming per-variable to the install-harness SKILL.md resolution table.

(b) INTENTIONALLY OPTIONAL — declare the missing variables optional and document them as such; leave the placeholders.

(c) RENDERER NOT AUTHORITATIVE — declare `verify_workspace`'s renderer not the install-time renderer, therefore not authoritative for parity or install correctness; retroactively reinterpret the 137-F parity contract.

(d) HYBRID (a)+(bounded b) — close the derivation gap for every variable that has a documented resolution source, AND explicitly derive-to-EMPTY-STRING (present in the map, value "") for the variables the SKILL.md documents as intentionally inert-when-unset. Zero unresolved tokens either way.

(e) NO ACTION — classify as acceptable baseline noise.
<!-- END:options -->

## Chosen Direction

<!-- BEGIN:chosen-direction -->
CHOSEN: (d) HYBRID — close the derivation gap against the install-harness SKILL.md resolution table as the single source of truth, with an explicit per-variable classification into RESOLVED-FROM-SOURCE vs DERIVE-TO-EMPTY-STRING. Target state: `autoharness verify-workspace --workspace .` reports ZERO unresolved placeholders in the staged tree.

WHY NOT (c) — REJECTED ON EVIDENCE. The claim "verify_workspace's renderer is not the install-time renderer" is falsified: it is the renderer for the `verify-workspace` staging tree (the refresh/re-install surface), it already raises unresolved placeholders as ERRORS in its own targeted checks (verify_workspace.py:3494, :3689), and it is imported directly by the P-021 parity contract test to prove byte-identity of four template/dogfood pairs. Adopting (c) would silently retire an existing enforced gate and retroactively weaken the 137-F parity contract on the strength of a defect in the thing being measured. Precedent `docs/compound/2026-08-15-checksum-drift-fix-correctly-surfaces-preexisting-self-hosted-customization.md` is directly on point in the inverse direction: when a check flags reality, fix reality or describe it accurately — do not disable the check.

WHY NOT (a) ALONE. The SKILL.md contract explicitly documents `{{STAGE_ESCALATION_*}}`, `{{SHIP_ESCALATION_*}}` and `{{LEGACY_ESCALATION_*}}` as RAW, NOT-resolved, intentionally EMPTY-by-default values that render an inert all-empty block, and warns (Copilot review round 3, PR #316) that substituting the acting-role-collapsed `{{ESCALATION_*}}` value into those raw slots reproduces the H2 flat+nested ambiguity. For those variables the CORRECT derivation is the empty string, not a config value. A naive "resolve everything" fix would inject a nested-only override into the flat block on re-render — a correctness regression, not a fix.

WHY NOT (b) ALONE. `{{DEFAULT_BRANCH}}` (12 occurrences), the tier1/2/3 and orchestrator/stage/ship route fields, `{{INSTALL_PRESET}}` and `{{PRIMARY_STACK_PACK}}` all have plainly present values in `.autoharness/config.yaml` and `.autoharness/workspace-profile.yaml`. Absent derivation of a present value is a defect, not optionality.

WHY NOT (e). The repository's own contract classifies unresolved output variables as an installation error, and 45 of the 83 occurrences are in the staged `.autoharness/config.yaml` — i.e. precisely the round-trip surface that prior learning `docs/compound/2026-05-05-harness-config-round-trip-requirement.md` identifies as the place where lost variables silently revert to defaults on the next install/tune.

BINDING CONSTRAINTS ON THE FIX:
C1. `.github/skills/install-harness/SKILL.md` resolution tables are the SINGLE SOURCE OF TRUTH. `_derive_template_variables` conforms to them; it does not invent resolution sources not documented there.
C2. Resolution order is CONFIG-FIRST, DETECTION-AS-FALLBACK (prior learning `docs/compound/2026-05-05-resolution-order-config-first-not-detection-first.md`). Do not invert.
C3. Preserve the PROSE-ONLY vs RAW-STORAGE split for escalation variables. `{{ESCALATION_*}}` (collapsed, resolved) renders prose only; `{{LEGACY_ESCALATION_*}}`/`{{STAGE_ESCALATION_*}}`/`{{SHIP_ESCALATION_*}}` are raw pass-through and MUST derive to "" when unset.
C4. Every variable newly derived must round-trip through `templates/harness-config.yaml.tmpl` where the SKILL.md table says it is stored (round-trip learning above).
C5. No behavioural change to `_render_template` itself (pure `{{VAR}}` substitution).
C6. `.autoharness/harness-manifest.yaml` checksums must be refreshed atomically with any regenerated artifact.
<!-- END:chosen-direction -->

## Open Questions

<!-- BEGIN:open-questions -->
R1 (HIGH, must be measured before implementation): closing the derivation gap CHANGES RENDERED BYTES. `tests/test_scope_containment_policy_contract.py::test_clean_pairs_are_byte_identical_via_render_template` asserts byte identity for the four CLEAN template/dogfood pairs. If any newly-derived variable appears in a clean pair, that pair's render changes and the P-021/137-F parity contract test breaks. The implementation MUST begin by measuring, per variable, which staged artifacts change — and must either leave the clean pairs byte-identical or update both sides of the pair plus the manifest checksum in the same change. This is the primary reason this plan requires P-006 hardening.

R2: 62 variables is far past a single 2-hour task. Decomposition MUST be by RESOLUTION SOURCE (model-routing/escalation | install-shape | profile-derived | misc-config), not by file, so each task owns one coherent resolution rule set.

R3: `LINT_COMMAND` derives to the empty string and `FORMAT_CHECK_COMMAND` is absent from the map entirely, yet the installed dogfood copies carry literal values ("# no format check command configured", `markdownlint "**/*.md"`). `.autoharness/workspace-profile.yaml` has `lint.command: ""` and `format.command: ""`. OPEN: is the truthful derivation the empty string (faithful to the profile) or the documented literal default from the SKILL.md table? RESOLUTION FOR PLANNING: use the SKILL.md documented default where one exists; otherwise derive to "" — never invent a value. Do not backfill the workspace profile as part of this work (that is a different surface).

R4: the four `.autoharness/config.yaml`-family variables that are YAML BLOCKS (`STACK_PACKS_YAML`, `INSTALL_LAYERS_YAML`, `CAPABILITY_PACKS_YAML`, `HARNESS_OVERRIDES_YAML`, `ENABLED_SIDECARS_*`, `COPILOT_CLI_ARGS_*`) require structural rendering (YAML array / shell array / PowerShell array), not scalar substitution. Indentation and quoting correctness is a real failure mode inside `_render_template`'s pure string substitution model.

R5: `{{GRAPHTOR_SOURCES_PATH}}`/`{{GRAPHTOR_BINARY_PATH}}` are documented in SKILL.md as the only pack producing a workspace-specific installed file requiring discovery before rendering; `.autoharness/workspace-profile.yaml` records `graphtor_docs.binary_path: null` while `sources_path` is set. Derivation must tolerate the null.

R6 (SCOPE GUARD): this deliberation does NOT authorise the F3/F4(2) SEMANTIC PROSE DRIFT reconciliation that the 6D62077C spike explicitly excluded (~1,200 lines of bidirectional normative drift). Any implementation that finds itself editing normative agent prose has left scope and must stop and re-enter P-021 capture.

REQUIRES PLAN HARDENING: YES (P-006) — elevated blast radius (CLI/install correctness + config round-trip + multiple template families + a live P-021 contract test).
