## Deliverable (A1/R4 — flat module, NO new package, NO `__init__.py`)

`tests/_env_patch.py` exporting:

```python
@contextlib.contextmanager
def patched_environ(**overrides: str | None) -> Iterator[None]:
    """Set/delete only the named keys; restore only those keys on exit.

    A value of ``None`` deletes the key for the duration of the block.
    Restoration is by targeted diff: keys absent before are deleted, keys
    present before are re-set to their prior value. ``os.environ.clear()``
    is NEVER called, so untouched variables are never removed and re-added
    and therefore never destroyed by the Win32 empty-value-delete behavior.
    """
```

The module name does NOT match the `test*.py` discovery pattern, so it is never collected as a test module. Imported as `from _env_patch import patched_environ`.

**FORBIDDEN:** `tests/__init__.py`, `tests/conftest.py`, or a `tests/support/` package. The original plan text said `tests/support/env_patch.py`; A1/R4 supersede it.

## A4 (BINDING) — reject empty-string overrides UNIFORMLY

`patched_environ(X="")` would itself invoke the Win32 empty-value delete this task exists to avoid, producing a helper correct on Linux and broken on Windows. Raise `ValueError` on ANY override whose value is `""`, **on every platform** (no platform branch), before any mutation, with a message directing the author to pass `None` to delete or a real value to set.

## A5 (BINDING) — fail closed at ENTRY on an empty prior value

If a caller overrides a key whose current value is `""` (exactly `GIT_CONFIG_VALUE_2`'s shape), faithful restore is impossible on Windows and the helper would reintroduce the defect through its own restore path. At ENTRY, before any mutation, inspect the prior value of every key about to be touched; raise `RuntimeError` naming the key if any prior value is `""`. Entry-time failure means nothing is mutated yet — no torn state.

## Required property tests (in `tests/test_environ_restore_contract.py`)

1. Restores a pre-existing key to its exact prior value.
2. Deletes a key that did not exist before the block.
3. Restores a key that existed before and was deleted (`None`) inside the block.
4. Re-entrant / nestable without cross-talk.
5. Exception-safe: restoration happens on exception and the exception propagates unchanged.
6. **Non-destruction (A11 topology, BINDING):** an untouched variable whose value is `""` is still visible to a spawned child process after the block exits. This is `144.001-T` test 1 re-pointed at the helper via the `fixed` variant of the L0/L1/L2 topology — L0 seeds the blank sentinel through an EXPLICIT env block, L1 verifies inheritance, runs `patched_environ(...)` instead of the bare `patch.dict`, and re-probes. It must go GREEN on Windows here. The blank is NEVER seeded by in-process assignment (that call is itself the destructive operation).
7. **No-op equivalence:** `patched_environ()` with zero overrides leaves a spawned child's serialized `os.environ` byte-identical.
8. A4: `ValueError` raised on the current platform, before any mutation, `os.environ` unchanged after the raise.
9. A5: `RuntimeError` raised at entry, before any mutation, message names the offending key, `os.environ` unchanged.
