Mandatory 114-S closure pre-activation fix (Defect 1). Replace the illusory internal post-claim self-retry (re-reads shipment state twice with no intervening claim, so real delayed/failed claims deterministically hit CLAIM_VERIFY_FAILED) with an explicit read-only retry-required outcome contract (CLAIM_NOT_OBSERVED; exit non-zero, non-blocked). A stateless read-only detector CANNOT distinguish a delayed claim from a failed claim on the post-claim snapshot -- both present identically as target `queued` + zero active -- so that indistinguishable first snapshot MUST consistently emit CLAIM_NOT_OBSERVED (retry-required, non-blocked) WITHOUT classifying delayed vs failed. Terminal CLAIM_VERIFY_FAILED is emitted ONLY for genuinely ambiguous snapshots the gate CAN discriminate: an inconsistent snapshot (SHIPMENT_STATE_INCONSISTENT), two-or-more-active, or a mismatched single active. ALL failure/exhaustion classification for the indistinguishable case is owned by 109.017-T (after its one bounded double-claim-guarded retry, a second CLAIM_NOT_OBSERVED becomes terminal CLAIM_VERIFY_FAILED; actual ambiguous states remain terminal immediately). Gate stays a pure detector and never claims (P-001/P-016). Ship's external claim-retry-and-recall loop drives convergence. Repair the misleading unit test whose fake reader silently advances its snapshot; add a genuinely-delayed-claim test (queued+zero-active -> CLAIM_NOT_OBSERVED, not a false pass and not premature terminal) and ambiguity tests (inconsistent / two-or-more-active / mismatched-single -> terminal CLAIM_VERIFY_FAILED). Do NOT add a producer test requiring terminal CLAIM_VERIFY_FAILED for a queued+zero-active first snapshot -- that classification is owned and tested by 109.017-T.
