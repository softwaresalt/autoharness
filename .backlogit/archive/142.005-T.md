## RULE FOR EMPTY PROFILE FIELDS (023-DL R3, amendment B4)
Use the SKILL.md documented default where one exists; otherwise derive to the EMPTY STRING. **Never invent a value.**

`.autoharness/workspace-profile.yaml` currently records `lint.command: ""`, `lint.tool: ""`, `format.command: ""`, `format.tool: ""`. The installed dogfood copies contain literals (`"# no format check command configured"`, `markdownlint "**/*.md"`). **Amendment B4: "observed in the current dogfood copy" is a FORBIDDEN provenance.** Hardcoding those observed literals would make the derivation lie about a workspace whose profile genuinely has no linter.

`GRAPHTOR_BINARY_PATH` must tolerate the `null` currently recorded in the workspace profile (`graphtor_docs.binary_path: null`) — and **`null`/absent does NOT mean empty**. Per SKILL.md row 875 and the prose at line 1088, an absent or null `graphtor_docs.binary_path` resolves through an ORDERED FALLBACK CHAIN: (1) `graphtor` on PATH (`which graphtor`); (2) `.graphtor/bin/graphtor-docs.exe` or `.graphtor/bin/graphtor-docs`; (3) final default `graphtor` (assumes PATH). The chain therefore ALWAYS yields a non-empty value. This is a DOCUMENTED-DEFAULT case under the "use the SKILL.md documented default where one exists" rule above, NOT a candidate for the empty-string branch — and SKILL.md line 881 independently requires `GRAPHTOR_BINARY_PATH` to be fully resolved in installed output. (Corrected in review-fix cycle 1.)
