Add one shared helper in src/autoharness that resolves the backlog storage root, mirroring backlogit 1.9.0 precedence EXACTLY: BACKLOGIT_WORKSPACE_DIR (validated), then .backlog, then .backlogit. When both roots exist it MUST report and halt, mirroring upstream AmbiguousWorkspaceRootError. It MUST NOT merge, copy, delete, or rename either directory, and MUST NOT fall through to the candidate scan when an explicit override names a missing directory. Autoharness MUST NOT invent a competing directory-name config key or env var (H8). EXCLUSION (H5, verbatim): this task MUST NOT run 'backlogit migrate --workspace-dir', MUST NOT rename this repository's .backlogit directory, and MUST NOT change .autoharness/backlog-registry.yaml's directory value. That migration is operator-gated and must never run under dark-mode automation. CONSUMER SCOPE (PR #339 Copilot review, comment 3788712397): this task ALSO routes the single functional in-repo Python consumer through the new helper -- src/autoharness/gates/topology.py:372 (FilesystemTopologyReaders.backlog_dir), reached via src/autoharness/cli.py:1063 (pipeline-topology) and src/autoharness/cli.py:1186 (DAG-readiness) -- and adds regression tests asserting both CLI gate paths succeed on a .backlog-only workspace. Without this, a .backlog-only workspace still fails both gates with 'backlog directory is unavailable' after the resolver ships. Size/complexity re-assessed and HELD at M/medium: the incremental delta is one constructor assignment plus tests, well inside the 2-hour envelope. CLI ERROR-CONTRACT PRESERVATION (PR #342 Copilot review, comment 3789100773): wiring the resolver into FilesystemTopologyReaders must NOT change the failure path of either call site. Verified: src/autoharness/cli.py:1186 constructs the reader OUTSIDE the try: at line 1187, so only list_shipments() is covered by the BacklogUnavailableError handler that emits the documented non-fatal 'degraded' payload (lines 1189-1211); and src/autoharness/cli.py:1063 constructs the reader as an argument to topology.evaluate(), before evaluate can produce its structured BLOCK result. A resolver raise at construction time (both-roots ambiguity, or an explicit override naming a missing directory) would therefore escape as an unhandled traceback on BOTH paths. REQUIRED: defer or translate resolution so these contracts are preserved -- prefer resolving lazily at first use and surfacing failures as the existing topology.BacklogUnavailableError, which both call sites already handle, rather than raising from __init__. REQUIRED REGRESSIONS: cover all three cases on both CLI paths -- (a) .backlog-only success, (b) both-roots ambiguity, (c) invalid/missing explicit override -- asserting the pipeline-topology path still returns its structured gate result and the DAG-readiness path still returns the non-fatal degraded payload, never a traceback. Size/complexity re-assessed and HELD at M/medium: deferred resolution reuses the already-handled BacklogUnavailableError contract, so the delta stays a lazy accessor plus table-driven tests.
