PREREQUISITE to 144-S and 145-S. Ship currently treats the shipment manifest as its executable task set: `.github/agents/_ship.agent.md` Step 2 says "For each task in the shipment/feature: 1. Claim: Move the task to active", with no status filter, no `pre-archived` classification, and no `shipment-reconcile mode: pre` intake step. After the closure-membership correction at HEAD e88a8d62, manifests 144-S and 145-S correctly contain superseded, archived children (136.001-T, 137.005-T, 137.006-T) so that `classify_shipment_close_path` returns the cascade verdict for P-015. Those two purposes now conflict: the membership that makes closure valid makes execution invalid, and Ship would attempt to reactivate or hard-fail on an archived task marked `*** SUPERSEDED - NOT EXECUTABLE - DO NOT SCHEDULE ***`.

This feature makes both Ship contracts (the installed dogfood agent AND the template) derive the executable task set from live task records - keeping only `queued`/`active` - and explicitly exclude `pre-archived` manifest members, while leaving every manifest byte-for-byte unchanged.

Constraints (non-negotiable): do NOT weaken closure membership; do NOT unarchive or reactivate superseded tasks; refresh the `.autoharness/harness-manifest.yaml` checksum for `.github/agents/_ship.agent.md` atomically with the instruction edit; keep template/dogfood parity; introduce no new template `{{VARIABLE}}`.

Sequencing: this shipment contains only newly created queued items and therefore has NO pre-archived manifest members of its own, so it executes safely under the current unfixed contract. Chain: 146-S -> this shipment -> 144-S -> 145-S. A MANDATORY post-merge reload of `main` agent instructions is required before 144-S begins.

Acceptance (feature level):
1. Both Ship contract files declare the executable-set derivation with an exhaustive status rule (keep queued/active; skip-and-report archived as `pre_archived_skipped`; report `done` separately as `already_done`; any other/missing/unreadable status is a fail-closed halt).
2. Artifact-type filtering (`-T` only, covering feature resolved via `parent_id`) precedes any status read.
3. A `pre-archived` member is stated to be expected and tolerated, never a halt.
4. An empty executable set over a non-empty manifest halts and reports; it never advances to build/PR and never triggers a closure path.
5. The Step 0.5 item 1a `SHIPMENT_STATE_INCONSISTENT` early-warning is unchanged and still runs strictly before the derivation.
6. `.autoharness/harness-manifest.yaml` checksum for the installed agent matches the LF-normalized committed blob, with an appended provenance note.
7. A discriminating regression module pins the execution contract in both files.
8. No manifest, backlog record, or archived task is mutated.
