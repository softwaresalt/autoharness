Files (2): src/autoharness/verify_workspace.py, tests/test_verify_workspace_subagent_route_drift.py (new). Add `subagent_route_drift`. For each registry site (build_site_registry(...).sites: managed (rendered and community) and workspace-authored agents enumerated from disk) compare the installed frontmatter model_family, model_provider, reasoning_effort, context_tier to the ROUTE THE RENDERER WRITES for that site, read through B6a's `_expected_site_route(...)` from `_compose_site_route_variables(...)` (208.007-T) with the same inputs the two render seams pass (base variables, model_routing, config_authoritative, overrides, the registry), and NEVER from raw resolver output: the resolver has no config.overrides layer, so a correctly rendered agent using an explicit TIER_<N>_* override, bound OR unbound, would otherwise be reported as drift and fail closed (PR #513 thread PRRT_kwDORzpWpM6rmyoz). B7 contains no derivation of its own, so renderer and drift check cannot diverge. The branches are the same two explicit ones as 040-DL D4: UNBOUND managed agent (rendered or community) = the expectation is the site default tier's TIER_<N>_* from the composed map (the base map, overrides included); an unbound MANAGED-COMMUNITY agent resolves its template default tier exactly as an unbound managed-rendered agent does and is compared, never skipped (PR #513 thread PRRT_kwDORzpWpM6rmKbh). BOUND managed agent with a resolved default tier = the binding's route with explicit overrides on top (the site default tier is not consulted). WORKSPACE-AUTHORED agent = no default tier and no template, so it resolves a route only when bound, and the expectation is then the resolver's bound route (no override can name it); drift is one advisory warning (provenance split reused from frontmatter_conformity, 037-DL); an unbound workspace-authored agent has nothing to compare and is skipped. UNBOUND managed agent whose default tier is UNRESOLVED (SiteRegistry.unresolved) is not silently skipped: it cannot resolve a route, so the verdict follows the drift opt-in as ROUTING_SITE_DEFAULT_UNRESOLVED: <id>: <reason> (a verify-level code, not a resolver code). BOUND managed agent whose default tier is UNRESOLVED (PR #513 thread PRRT_kwDORzpWpM6rmyoO) is REJECTED with ROUTING_BINDING_UNRESOLVED_SITE: <id>: <reason> whatever its installed frontmatter says: B6a cannot apply its binding (no TIER_<N>_* overlay target, or no readable template), so reinstall or community rendering could restore a different route; the site is never compared, never passes, and yields no refresh-route-frontmatter proposal (nothing can render it); a bound site whose binding does not resolve (resolver error) is likewise never compared and B7 reports the resolver's code. B6 (208.008-T) already rejects both configs; B7 repeats the rejection so it cannot pass a site the renderer cannot compose even when run on its own. Behavior depends on whether the workspace DECLARES BINDINGS (the opt-in): with bindings, a managed agent (manifest-rendered or community) that drifts fails closed, an unbound managed agent whose default tier is unresolved fails closed, and a bound-and-unrenderable site fails as above; without bindings (so no site can be bound), drift and unresolved defaults are reported only as non-blocking `info` lines (count plus at most 20 ids) and `ok` stays true. Every drift also yields a refresh-route-frontmatter migration proposal. The opt-in is `bindings` non-empty, NOT schema_version, so this workspace (1.2.0 after B5, no bindings) does not turn red over its 13 stale subagents (installed routes gpt-5.6-luna / claude-sonnet-5 with empty provider+effort, matching neither current tier1 nor tier2; the dogfood config has overrides: {} so the composed expectation equals the base tier values). Test scenarios (one parametrized fixture builder, the B2/B6a style): MATRIX class {managed-rendered, managed-community} x {unbound, bound} x {frontmatter matches the expected route, drifted} x {bindings declared, none declared}: a match passes and appears in the compared set (a community agent is never skipped), drift fails closed when bindings are declared and is info only otherwise. TARGETED: (1) a bound workspace-authored agent (on-disk, no manifest entry) with drift warns and does not change ok, an unbound workspace-authored agent is skipped; (2) EXPLICIT OVERRIDE: a bound agent whose frontmatter carries an explicit TIER_<N>_* override value passes, the same agent carrying the raw binding value (override ignored) fails closed, an UNBOUND agent rendered with an override passes (no false drift), and a frontmatter that differs from the composed expectation while an override is present still fails closed; (3) BOUND BRANCH: a bound tier that leaves provider, effort or context_tier empty while the agent's template default tier supplies them: frontmatter with the empty values passes, frontmatter carrying the default tier's values fails closed; (4) UNRESOLVED DEFAULT (community template_path naming a missing file, and a template with no tier placeholder): unbound plus bindings declared fails with ROUTING_SITE_DEFAULT_UNRESOLVED naming the reason, no bindings declared is one info line and ok stays true, BOUND fails with ROUTING_BINDING_UNRESOLVED_SITE even when the installed frontmatter equals the binding's route values and emits no refresh proposal, and a bound site whose binding does not resolve fails with the resolver's code and is never compared; (5) REINSTALL ROUND TRIP: write the B6a render output (the staged render for a bound managed-rendered agent, the reinstall-community candidate for a bound managed-community agent, each with and without an override) as the installed file: B7 passes, change one frontmatter route field: it fails closed; (6) proposals are emitted for each drift, the opt-in predicate (bindings non-empty) is tested in both directions, info output is bounded (count plus at most 20 ids); (7) a non-authoritative config: the expectation is the same manifest-first base map the render uses (no false drift).
