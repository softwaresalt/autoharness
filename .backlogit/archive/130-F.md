Make it structurally impossible for a Stage or Ship agent following its instructions literally to write a schema-invalid backlogit checkpoint. Root cause of quarantined checkpoint-20260817-234318.json (stash E0B80A6C): backlogit applies V1 validation and auto-populates created_at/updated_at/status ONLY when the payload declares schema_version=1; a payload omitting it is written through unvalidated and fails later at checkpoint get, during recovery. Two defective surfaces: (A) four agent-template write sites (_stage.agent.md.tmpl:773,780; _ship.agent.md.tmpl:956,970) plus backlogit.instructions.md.tmpl:129 enumerate fields but never require schema_version or context nesting; (B) the installed dogfood mirrors .github/agents/_stage.agent.md and _ship.agent.md contain NO structured checkpoint-write guidance at all while backlogit_create_checkpoint is an exposed MCP tool - the proximate cause of the actual failure. Fix publishes one canonical Checkpoint Payload Contract in the backlogit overlay instruction and adds a short mandatory minimum plus pointer at each write site. Predecessor of 138-S: the migration's own hardening H7 directs Ship to take a resumption checkpoint before 129.005-T while MCP tools are unavailable, which is exactly the checkpoint this contract protects.
