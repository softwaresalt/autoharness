Plan docs/plans/2026-10-11-model-routing-resolver-single-source-plan.md unit A2a (RA4a). Files (2): src/autoharness/model_routing_yaml.py (new), tests/test_model_routing_yaml.py (new). WHY: yaml.safe_load erases anchors, aliases and merge keys, so the CLI (A4) and verify-workspace (R1-B B6) would otherwise accept a configuration that 040-DL D2/D9 forbid; the rule must run on the RAW YAML TEXT before loading, in ONE function used by both (it lands in R1-A because A4 is its first consumer and 215-S blocks on 214-S, so B6 sees it already shipped). It is a separate module because it imports yaml, which the pure model_routing.py import allowlist forbids. Implement check_model_routing_yaml(raw_text: str, schema_version: str | None) -> YamlGuardResult(errors: tuple[str, ...], warnings: tuple[str, ...], parse_error: str | None). Walk the yaml.parse EVENT STREAM (not safe_load) and flag, anywhere in the value of the top-level model_routing key: a node carrying an anchor, an alias event, and a merge key (a plain unquoted << scalar in mapping-key position; a quoted "<<" key is an ordinary string). Constructs outside model_routing are ignored. Severity follows the declared schema_version parsed as dotted integers: below 1.2.0 the findings are warnings (a 1.1.0 config with aliases is NOT rejected: D2 scopes the prohibition to 1.2.0); at or above 1.2.0, or when the version is missing or unparsable, they are errors (fail closed). Message form: ROUTING_ANCHOR_UNSUPPORTED: <anchor|alias|merge_key> at line N (document order, 1-based). A YAML syntax error sets parse_error and never raises. Pure over text: no filesystem, environment, subprocess or network access. Test scenarios (every call under the A2 forbid_io() guard, tests/_resolver_purity_guard.py): an anchor definition, an alias and a merge key under model_routing each flagged with kind and line; an anchor on a sequence node; flow and block styles; errors at 1.2.0, with a missing version and with an unparsable version; warnings (not errors) at 1.1.0, 1.0.0 and 0.9.0; anchors and aliases outside model_routing ignored; a quoted "<<" key and & or * inside a string or a comment not flagged; the baseline-shaped document (undefined aliases) reports the aliases without raising; broken YAML sets parse_error without raising; empty text yields no findings; the module imports standalone. Stash traceability: BF66F08B; 040-DL D2, D5, D9; PR #513 thread PRRT_kwDORzpWpM6rkjEC. Gate: PYTHONPATH=src python -m unittest discover -s tests.
