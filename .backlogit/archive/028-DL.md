# PR-review convergence: finding-ledger + epoch + monotone measure, with the DAG as diagnostic layer (not the convergence layer)

## Problem Frame

<!-- BEGIN:problem-frame -->
INTENT: make issue-resolution convergence during the PR review cycle MEASURABLE and OBSERVABLE, so a review loop can be shown to be converging, stalled, or diverging rather than being terminated by operator fatigue.

OPERATOR HYPOTHESIS UNDER TEST: "record DAG nodes in backlogit's SQLite DB to track issue-resolution convergence during the PR review cycle, because DAG work items relate naturally to code/documentation implementation."

VERDICT ON THE HYPOTHESIS: the INSTINCT is right and materially advances this entry (it re-aims at PR review, where node identity is externally solved), but the ARCHITECTURE as literally stated is wrong on three counts, and a DAG alone cannot deliver the stated intent.

CENTRAL FINDING (why a naive DAG is insufficient): the observed non-termination is NOT state revisitation, so a visited-set/cycle detector would NEVER fire. Evidence: docs/compound/2026-08-16-...-mechanical-consequence-judgment.md states "fixing one finding often surfaces a new, real finding on the very next pass (either a mirror bug in the same fix, or a consequence of the fix itself)"; docs/compound/093-S-review-loop-convergence.md records 13 rounds where the final pass fixed 4 deferred + 5 new findings and STILL surfaced 2 more genuine hard blockers. Every node is genuinely NEW. The process is not looping -- it is a non-terminating productive descent under a regenerating external oracle.

Acyclicity implies termination ONLY over a FINITE, FIXED node set. Here the node set is generated on demand by Copilot as a function of the current HEAD, so it is unbounded. Termination therefore requires a WELL-FOUNDED MONOTONE MEASURE that strictly decreases, which acyclicity does not provide. Conflating "acyclic" with "terminating" is the precise naive-DAG error.

SECOND ERROR -- four distinct graphs are being collided into one: (1) the work-item dependency DAG (backlogit item_deps, dep_type=blocks, 488 edges) ALREADY EXISTS, is markdown-sourced, and already has a reader in `autoharness gate dag-readiness` with cycle detection, ready-set, critical path and transitive closure; (2) a review-finding/evidence graph does NOT exist -- and is the only one of the four where node IDENTITY is already solved, because GitHub assigns stable review-thread node IDs; (3) the reasoning-state graph, whose identity problem is the unsolved blocker that stalled this entry across four prior triages; (4) execution/event history, which already exists as backlogit item_log_entries (append-only, FTS-indexed) and src/autoharness/telemetry/ -- and which is a SEQUENCE, not a graph.

THIRD ERROR -- the storage target is disposable. .github/instructions/backlogit.instructions.md states: "Treat backlogit's markdown files as the current-state source of truth, its query index as a disposable cache." backlogit_sync_index rehydrates SQLite from markdown (963 items rehydrated this session). Convergence records written ONLY to that SQLite are destroyed by the next sync. Writing them there is a data-loss architecture unless the ownership contract is deliberately changed, which is a separate and much larger decision.

BINDING PRIOR CONSTRAINT: the 2026-08-16 spike's F5 (no consumer => write-only emission => the APPEARANCE of reliability) and F4 (prose-only bounds mean an emission contract edits every agent's behavioural contract surface) both remain in force and constrain any proposal here.
<!-- END:problem-frame -->

## Options

<!-- BEGIN:options -->
OPTION A -- Reasoning-state visited-set/DAG (the original 34AAF1C7 framing). REJECTED for this use case. Requires solving reasoning-state identity, unanswerable from static evidence across four prior triages, and would not fire on the observed failures because every finding is a new node.

OPTION B -- Work-item DAG extension (add convergence nodes to backlogit item_deps). REJECTED. Conflates plan-time sequencing semantics ("must ship after") with runtime evidence semantics ("was raised, then superseded"). Would pollute the existing dag-readiness ready-set/critical-path contract, which has a documented permanent no-scheduler NON-GOAL.

OPTION C -- DAG nodes in backlogit SQLite (operator hypothesis, literal form). REJECTED AS STATED. Disposable-cache violation (see problem frame). Also requires backlogit to learn what a "Copilot review finding" is, embedding harness policy in the backlog tool.

OPTION D -- Finding ledger + state machine, no graph. Nodes = review findings keyed on GitHub thread node ID; per-finding lifecycle open -> fixed | declined | deferred(P-021 C2 capture) | superseded. Convergence = all findings terminal. STRONG but cannot explain WHY a loop is not converging, and cannot detect fix-A-regresses-B thrash.

OPTION E -- Event log + materialized graph (append-only rounds + derived view). Strong on replay/recovery and matches the existing telemetry precedent, but is the heaviest option and presumes the model is already validated.

OPTION F -- HYBRID (RECOMMENDED): ledger + epoch + monotone measure as the CONVERGENCE layer, with DAG edges as a DIAGNOSTIC layer. Findings are pinned to HEAD-keyed rounds (epochs), which makes new-vs-carried-over computable; a monotone measure over new_findings_per_round is the actual termination witness; and typed edges (supersedes, regression_of, caused_by) explain WHY the measure is not decreasing. SCC/cycle detection over regression_of catches the one genuine cycle that CAN occur here (fix A breaks B, fix B breaks A) -- which is exactly where a graph earns its keep and where the operator's DAG instinct is correct.

OPTION G -- Retrospective-only analyzer, no persistence at all (MVE). Read GitHub's already-existing review history for past PRs and test whether the model can separate pathological from healthy loops. Cheapest possible falsification.
<!-- END:options -->

## Chosen Direction

<!-- BEGIN:chosen-direction -->
CHOSEN: OPTION G as the immediate next step (a now-executable spike), staging toward OPTION F. NOT harvested; NOT planned; no shipment created.

THE ARCHITECTURAL SUMMARY IN ONE LINE: ledger + epoch + measure delivers TERMINATION; the DAG delivers EXPLANATION. The operator's DAG is the diagnostic layer, not the convergence layer. That is the answer to "is this a naive DAG that misses other mechanisms?" -- yes, and the missing mechanisms are the epoch pinning, the monotone measure, and the disposition state machine.

THE UNLOCK THAT DISSOLVES THE FOUR-SESSION BLOCKER: the 2026-08-15 annotation deferred this entry because "answering reasoning-state identity requires observing instrumented agent runs... no such instrumentation exists in this workspace." For the PR-REVIEW framing that blocker DOES NOT APPLY. GitHub already holds, retrospectively, the complete round-by-round review history of every PR this harness has ever shipped, with stable thread node IDs supplying the node identity that reasoning states could not. No instrumentation needs to be built to answer the question. This is the substantive change the operator's re-aiming produced.

MINIMUM VIABLE EXPERIMENT: a read-only, report-only `autoharness gate review-convergence <pr> --repo <slug>` analyzer. Derives HEAD-keyed rounds from GraphQL review threads (the same query surface src/autoharness/gates/copilot_review.py already uses), classifies each thread per round as new/carried/resolved, and emits the new_findings_per_round series plus a verdict CONVERGING | STALLED | DIVERGING | INSUFFICIENT_DATA. Always exits 0 in v0.

WHY THIS SLICE SURVIVES THE PRIOR SPIKE'S OBJECTIONS: it ships the READER first and only (answers F5 -- it is pure read-side, there is nothing write-only about it); it changes NO agent-contract prose (dodges F4's multi-family blast radius entirely); it changes NO backlogit schema and writes NOTHING to the disposable SQLite cache; and it is report-only, so it does not govern when any agent stops (dodges the standing authority-expansion safety note).

FALSIFICATION TEST (the gate on everything downstream): run the analyzer retrospectively against PR #229 (13 rounds), PR #325 (15+ rounds, the motivating case), PR #328 (5 rounds), PR #348 (7 rounds), and at least two healthy PRs with 0-1 rounds. It MUST classify the pathological PRs as DIVERGING or STALLED and the healthy ones as CONVERGING, using only data GitHub already holds. IF IT CANNOT SEPARATE THEM RETROSPECTIVELY, THE WHOLE CONVERGENCE MODEL IS FALSIFIED AND THIS ENTRY SHOULD BE CLOSED RATHER THAN STAGED FURTHER -- cheaply, and before any persistence, schema, or policy work is authorized.

STAGED PATH (each phase gated on the prior phase's evidence): Phase 1 = the MVE analyzer above (Stage-ownable spike, read-only). Phase 2 (ONLY if Phase 1 separates the populations) = persist the finding ledger as markdown-backed sections on the existing backlogit `-R` review artifact type (13 already exist) plus append-only item_log_entries, and add supersedes/regression_of diagnostic edges with SCC detection. Phase 3 (ONLY with EXPLICIT OPERATOR CONSENT, because it is authority-expanding) = allow a DIVERGING verdict to block, binding into P-018/P-021.

CROSS-REPO INTERFACE CONTRACT (so neither side embeds the other's policy): backlogit owns GENERIC persistence and query ONLY -- it must never learn what a "Copilot review finding" is, nor what "convergence" means, nor own a threshold. autoharness/harness owns the finding schema, the disposition state machine, the measure, the thresholds, the verdict enum, and the P-018/P-021 policy binding, in src/autoharness/gates/ alongside the existing copilot_review.py. The harness reads and writes ONLY through backlogit's public MCP/CLI operations (append_comment, item log entries, markdown sections) and NEVER by direct SQLite writes. Notably the MVE requires ZERO backlogit change, which is itself evidence the boundary is drawn correctly.

WHAT A DAG ALONE CANNOT GUARANTEE (the mechanisms the naive framing misses): TERMINATION (needs a well-founded decreasing measure, not acyclicity); PROGRESS (needs monotonicity over rounds); FIXED POINT (needs an idempotence check -- a review pass over unchanged HEAD yielding no new findings); ORACLE STABILITY (Copilot is nondeterministic, so any fixed point is probabilistic, not logical); FREEDOM FROM THRASH (needs causal/regression edges -- the one place the DAG genuinely helps); and SCOPE DISCIPLINE (P-021 C1: a finding can be genuine AND legitimately out of scope, so the model must record DISPOSITION, not merely resolution -- "unresolved" and "not converged" are different predicates).

DISPOSITION OF THE STASH ENTRY: REFINED and LINKED to this deliberation. NOT archived, NOT harvested, NOT split this session. It remains spike-first, but its blocker has changed from "unanswerable without instrumentation that does not exist" to "answerable now by retrospective analysis of existing GitHub history."

## Open Questions

<!-- BEGIN:open-questions -->
REQUIRING OPERATOR AUTHORITY (Stage cannot self-authorize any of these):

Q1 (HARD GATE, authority-expanding) -- May a convergence verdict EVER block a merge? Phase 3 only. The standing safety note across three prior triages reserves any mechanism that GOVERNS when agents stop reasoning for explicit operator consent, and spike finding F6 showed the ENFORCING variant is the valuable half. Phases 1-2 deliberately do not touch this.

Q2 -- Is DIVERGING always pathological? docs/compound/093-S states "fresh containment/safety-critical code invites deep, iterative scrutiny." A genuinely deep review of novel safety-critical code may legitimately diverge. If so the verdict must remain advisory for that class, and the classifier needs a novelty/criticality input it does not currently have.

Q3 -- Cross-repo sequencing. Does backlogit get ANY change at all, or does the harness stay entirely within markdown-backed `-R` artifacts and item_log_entries? The MVE needs none; Phase 2 might want a `regression_of` link type (backlogit currently supports related_to, duplicate_of, informs, supersedes, spike_ref). Adding it is a backlogit-repo change requiring separate authorization.

Q4 -- Should the stash entry be SPLIT? This deliberation retires "duplicate-state detection over reasoning states" as the wrong frame for the PR-review use case, but reasoning-state identity remains a genuinely separate, still-unsolved concern. Recommend a logical split into (a) PR-review convergence [now executable] and (b) reasoning-state identity [still blocked]. NOT executed this session -- splitting a tracker is an operator-visible reclassification.

OPEN TECHNICAL RISKS / FAILURE MODES (to be resolved BY the MVE, not before it):

R1 -- Thread-ID instability. If Copilot re-posts a materially identical finding as a NEW thread node ID after a push, carried-over detection silently breaks and every round looks like new findings. Fallback secondary identity: (path, normalized rule/message hash). The MVE will expose whether this is real.

R2 -- Docs-only pushes re-trigger review. 093-S records round 11 as "a docs/backlog-only tracking commit with zero source changes" that still triggered a fresh Copilot round. Rounds must be classified by whether HEAD touched reviewable paths, or the round count is inflated with no code delta.

R3 -- Suppressed/body-only findings are invisible. The 128-S closure records "4 suppressed-only (review-body text, no thread)". Any thread-based measure systematically undercounts these.

R4 -- Oracle nondeterminism. The same HEAD can yield different findings, so single-round comparisons are unsound; the measure must be taken over a window (3 rounds proposed) rather than pairwise.

R5 -- gate_evidence is a snapshot, not a history. The existing table (354 rows; PRIMARY KEY on item_id, columns gate_status/evidence_sha/head_sha) is overwritten per item, so it CANNOT carry a round series. Its head_sha column is nevertheless the correct HEAD-pinning precedent to imitate.

R6 -- Recovery/replay and idempotency are unaddressed in Phase 1 by design. Phase 2 must define stale-round handling, re-analysis idempotency, and schema versioning before any persistence lands.
