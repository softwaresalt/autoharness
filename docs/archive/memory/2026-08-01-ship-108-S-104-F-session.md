## Reusable lessons (see compound doc for full detail)

- A `must_contain`-style whole-file substring check only proves a token is
  *present somewhere*, never that it's present at the *specific site* whose
  invariant it's meant to guard. Any FOUNDATION_ASSERTIONS-style check whose
  safety property depends on placement (not just presence) needs a windowed/
  scoped check instead.
- "Falsy or empty" is not "wrong type": `is None or == ""` lets `False`, `42`,
  `[]`, `{}` all slip through. Prefer `not isinstance(x, str) or not
  x.strip()` for any field whose only valid shape is a non-empty string.
- Hosted Copilot review re-arms on every HEAD advance and can surface new
  findings on a fix commit that itself introduced a narrower bug — budget for
  at least 2 hosted-review rounds on any PR that adds new fail-closed
  verifier checks.
