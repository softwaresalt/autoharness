## Key learnings / cross-references

- See `docs/compound/2026-08-08-state-vs-call-outcome-conflation-in-telemetry-mapping.md`
  for the generalizable pattern: a subsystem's own reported state (or a
  completion-time field, or a field absent from the wire) must never be
  conflated with the calling operation's own outcome/timing/provenance when
  mapping pack telemetry onto `ToolTelemetryEvent`.
- CI flakiness triage: before assuming a failing check requires a code fix,
  confirm the PR's actual diff could plausibly have caused it (`git diff
  --name-only`); a doc-only PR failing a concurrency test in unrelated test
  infrastructure is a strong signal to retry, not remediate.
- Dirty-worktree isolation via labeled `git stash push -u` with precise
  pathspecs continues to be the correct Ship pattern for carrying forward
  operator-owned content while excluding unrelated in-flight work for a
  successor shipment — now a 5th precedent occurrence (117-S, 114-S, 098-S,
  059-S, **120-S**).
