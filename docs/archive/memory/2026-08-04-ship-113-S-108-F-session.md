## Key Learnings

- The move-vs-archive gap is now a 4-time-recurring pattern
  (`109-S`, `111-S`, `112-S`, `113-S`). Reading a file's physical location
  under `.backlogit/archive/` is never sufficient evidence that the
  explicit `archive` transition (status: archived + archived_status +
  archived_from) has occurred — only an explicit per-item `status:` field
  read confirms it. This should be hardened into a scripted, unconditional
  pre-flight step rather than relying on narrative compound-doc recall.
- Defense-in-depth re-verification of every current-HEAD gate (not trusting
  prior-session state) is cheap relative to the risk of a stale merge on an
  unattended dark-mode-adjacent resume; no drift was found here, but the
  full re-check is the correct default regardless.
- `082-F`'s `informs` link to `108-F` is not a parent/child relationship —
  archiving `108-F` does not and must not cascade to `082-F`. This
  distinction matters for the protected-set computation during safe-close.
