## Key Learnings / Cross-References

- `docs/compound/2026-08-12-verify-hosted-review-findings-against-frozen-task-spec.md`
  — **corrected lesson** (this document's own text below is left as
  originally written, for the historical record; the corrected version
  is authoritative): checking a hosted-review finding against the frozen
  spec is necessary but not sufficient — this session did exactly that
  and still produced 2 wrong dismissals, because what was checked was a
  *paraphrase* of each Copilot comment, not its exact text. **The exact,
  literal review-comment text must be captured (`gh api .../pulls/N/comments`)
  before comparing it against the spec** — a paraphrase can silently
  substitute a more-obviously-wrong straw-man suggestion for what was
  actually said, letting an accurate spec citation still produce the
  wrong verdict. (Original, pre-correction phrasing, retained for
  context: "verify hosted review findings against frozen
  acceptance-criteria text before fixing or dismissing, especially on
  tasks whose spec deliberately forbids a 'natural-looking' code shape."
  This is still true but incomplete — see above.)
- Cross-reference: `docs/compound/114-S-109-F-copilot-review-fix-patterns.md`
  for the suppressed-vs-active-comment distinction (reused, not
  re-derived, this session).
- Cross-reference: `docs/compound/2026-08-12-close-path-decisions-must-use-the-classifier-not-summarized-prose.md`
  (from `127-S`) — the close-path classifier discipline was reapplied
  here without needing re-derivation, confirming the classifier
  generalizes cleanly to a second shipment.
