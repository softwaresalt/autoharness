## Decisions Made

1. **Diagnosed the single unresolved Copilot thread** (`schemas/harness-config.schema.json:608`)
   as a schema-versioning-discipline violation: PR #316 added new
   `additionalProperties:false` nested `stage.escalation`/`ship.escalation`
   properties plus an H2 `not` ambiguity constraint to BOTH the root schema
   AND the already-published `schemas/harness-config/1.0.0.schema.json`
   mirror, without bumping `schema_version`/`current_version` — making the
   string `1.0.0` mean two different contracts.
2. **Chose the tool-telemetry-event v1.0->v1.1 precedent (commit `6da2f55b`)
   as the exact fix template**: restore the old mirror byte-identical,
   publish a new versioned mirror for the additive change, bump
   `current_version`/`known_versions`, no forced `CONTRACT_MIGRATIONS` entry
   for a purely additive bump.
3. **Deliberately did not add a `CONTRACT_MIGRATIONS["config"]` entry** —
   confirmed via code inspection and `tests/test_verify_workspace.py:1053`
   that this would break the existing `migration_proposals == []` assertion
   for a workspace at schema_version 1.0.0.
4. **Bumped the dogfood `.autoharness/config.yaml`'s own `schema_version` to
   1.1.0** alongside the template default — a judgment call (not explicitly
   requested by the Copilot comment or the operator), inferred from
   convention (harness-manifest.yaml already tracks its own contract at
   current version). Flagged as a judgment call in the closure artifact.
5. **Recomputed the harness-manifest.yaml checksum from the LF-normalized
   git blob** (`git cat-file blob :.autoharness/config.yaml`), not the raw
   CRLF working-tree bytes — confirmed `core.autocrlf: true` normalizes
   CRLF->LF on staging, matching the convention already established for
   this checksum field.
6. **Used `-F` (typed field), not `-f` (string field), for `gh api graphql
   query=@file`** — `-f` fails to honor the `@filename` file-read
   convention in this environment/gh version (2.81.0), producing a
   `DIR_SIGN "@"` parse error.
7. **Best-effort Copilot re-review request**: no MCP `request_copilot_review`
   tool was available in this session, and `gh api .../requested_reviewers`
   for the Copilot bot identity did not register as a formal review request
   (confirmed empty `reviewRequests` afterward, matching the documented
   unreliability of GitHub CLI reviewer flags for Copilot's special
   identity). Fell back to polling (2-minute wait) per the documented
   back-off schedule — Copilot's auto-review-on-push behavior (already
   engaged on this PR from 4 prior rounds) completed the review without an
   explicit re-request succeeding.
8. **Safe-closed 121-S and archived 113-F** following the exact 119-S

## Key Learnings

See the new compound-learning doc,
`docs/compound/2026-08-08-schema-mirror-mutated-in-place-without-version-bump.md`,
for the generalizable pattern: a schema-behavior change applied uniformly
across "the schema files" for a contract with published versioned mirrors
silently redefines an already-published version unless the old mirror is
deliberately excluded and the version is bumped instead. This is the
**second** occurrence of this exact bug class (first: `6da2f55b`,
tool-telemetry-event v1.0->v1.1) — a "mirror preserved unchanged" regression
test should be added in the same PR that first introduces a versioned schema
contract, not retroactively after a second review catch.
