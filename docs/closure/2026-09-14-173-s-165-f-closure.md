## Summary of Change

PR #450 ships feature `165-F` (10 tasks, `165.001-T`..`165.012-T`;
`165.007-T`/`165.010-T` pre-archived, not part of this shipment's executable
set) for shipment `173-S`: replaces the pipeline-topology `pre_claim` gate's
numeric-adjacency predecessor heuristic with a DAG-authoritative, four-state
predecessor derivation engine driven by explicit `blocks` edges in backlog
data, adds a read-only `audit_sequencing` phase, aligns `dag-readiness`
advisory output with `pre_claim`'s authoritative derivation, surfaces
predecessor provenance/audit rendering in the CLI, and adds an at-most-once
bootstrap-grant consumption surface for documented pre-claim gate bypass
scenarios.

The 11-persona review gate found zero unresolved P0/P1 findings (all fixed
in commit `38c3baa4` or confirmed as already-decided design per the staging
plan). The initial CI run then surfaced two genuine cross-platform bugs in
the new bootstrap-grant consumption code (never exercised on POSIX during
Windows-only local development), fixed in commits `1ae5c894`/`b17cc530`.

Four subsequent rounds of automatic hosted Copilot review (re-arming on
every push) then surfaced 7 more genuine, in-scope bugs across the same
bootstrap-grant/pipeline-topology consumption surface: two symlink-following
reads with no containment check (`9a87d745`), a grant-scoping gap that could
bypass evaluation of undeclared blocking predecessors (`1bfa41ea`), a
missing directory-fsync durability guarantee and a pathname-based scan that
discarded an already-established containment guarantee (`d9958ee4`), and a
missing mode/phase authority-boundary check plus a symlink-following
force-audit-log append (`408ae4a2`). All 7 were fixed in the commit they
were found in, each with a new regression test, validated on both Windows
and native POSIX (WSL). Two further findings were process/hygiene items
(a stale PR-body readiness reference, and the already-fixed-but-never-
auto-resolved `BoDd` thread), both closed by replying to and resolving their
threads plus updating the PR body.

A fifth round, triggered by the pre-merge closure-artifact commit itself
(a docs-only push still re-arms hosted Copilot review), surfaced one more
genuine bug in the same family: `load_bootstrap_grant()` verified only the
final `{shipment_id}.yaml` path component for a symlink, never the
intermediate `.autoharness`/`bootstrap-grants` directory components, so a
crafted workspace could still redirect the grant read to an arbitrary
external file via a swapped intermediate directory. Fixed in commit
`1dac0613` by adding `_read_bytes_no_follow_walked()` (a read-only
counterpart to `append_no_follow()`, walking every directory component
with the same no-follow discipline before opening the final file) and
using it from `load_bootstrap_grant()`. Round 5 also flagged a second,
process-only finding: this same closure artifact's own "Merge Readiness
Gate Status" section had hardcoded a specific HEAD that the closure-doc
commit itself had already made stale; fixed by rewriting that section to
defer to the PR body's live readiness block instead of asserting a fixed
HEAD (see the current "Merge Readiness Gate Status" section below). All 8
review rounds' genuine findings are now fixed; Copilot review-thread
resolution for round 5 is tracked live via
`autoharness gate copilot-review 450 --enforcement auto --json` and the
PR body -- see those for the authoritative current state.

One out-of-scope, pre-existing CI finding was captured per P-021 as a new
stash entry (`EB9CB9E8`, a flaky telemetry-sink test with zero diff in that
file across this PR's range); one further out-of-scope finding was reused
from an existing prior-shipment entry (`24A85BF8`, same flaky-test root
cause as a 159-S capture). No out-of-scope finding was fixed in-cycle.

## Invariants to Preserve

* The `pipeline-topology` gate's `pre_claim` phase must continue to fail
  closed (BLOCK, never a silent PASS) on every ambiguous, malformed, or
  containment-violating filesystem condition encountered while evaluating or
  claiming a bootstrap grant.
* `--bootstrap-grant-invocation` must remain usable only in its documented
  agent-consumable, pre-claim-only scope (`--mode agent --phase pre_claim`).
* The bootstrap-grant consumption record's durable at-most-once guarantee
  (a claimed label can never be silently reused or reset by editing the
  grant) must hold on both the POSIX and Windows claim strategies.
* The pipeline-topology force-audit log must be appended to only via a
  containment-checked, no-follow path -- never a plain pathname-based
  append that could follow a symlinked directory or file.
* Every bootstrap-grant read (not only the final `{shipment_id}.yaml`
  file) must verify each intermediate directory component is not a
  symlink/reparse point before traversal -- a check at the final
  component alone is insufficient.
* No `{{VARIABLE}}` placeholder may remain unresolved in any installed
  mirror touched by this shipment.
