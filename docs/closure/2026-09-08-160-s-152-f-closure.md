# 160-S / 152-F Operational Closure (pre-merge) -- SHIP-2 Release and CI Pipeline Fail-Closed Gates

## Summary of Change

PR #439 ("SHIP-2: Release and CI pipeline fail-closed gates (160-S)") closes
3 tasks (`152.001-T`, `152.002-T`, `152.003-T`) under feature `152-F`. The
PyPI pre-publish probe used by `.github/workflows/release.yml` previously
treated any HTTP 2xx response as proof the target version was already
published, with no host, body, or version validation -- an unattended re-tag
could silently smoke-test and release around pre-existing artifacts. This
shipment extracts the inline heredoc probe into an importable, hermetically
testable module (`build_support/pypi_probe.py`, `152.002-T`), hardens it to
validate the resolved response host, decode/validate the JSON body, and
require an exact version match, changing the CLI's already-published outcome
from a silent exit 0 to a fail-closed exit 2 with an explicit remedy message
(`152.001-T`), and adds an end-to-end push-context test plus an AST-based
static guard to `tests/test_gates_topology.py` for the unrelated
`GITHUB_HEAD_REF` ambient-empty-string convention (`152.003-T`). This
artifact was originally created to record **pre-merge** readiness while PR
#439 was open against `main`. It has since been updated, post-merge, on the
`post-merge/160-s-closure` branch (never on `main` directly, per the
Post-Merge Branch Protocol) to record the finalized merge: PR #439 merged
via a two-parent merge commit `12b2d4a36f0cdcd9a07aa2cfc13b372cea2ef386`
(parents `bb003791c0448c614c3c96f62cfb6ffbc898e938` and reviewed HEAD
`3549e03b07f9e67751169c30d953ed69f14a3356`), confirmed present in
`origin/main` history, following explicit operator approval scoped to this
PR.

## Evidence Currency Model

Rounds 5 and 6 of PR #439 review each found this artifact citing a stale
HEAD and "fixed" it by rewriting a `reviewed_head` field to name the PR's
then-current HEAD. Each such refresh was itself a new commit, so the value
it wrote was already stale the instant the refresh commit was created: a
committed file cannot truthfully assert it covers the commit that
introduces it, and every subsequent SHA-refresh commit invalidates itself
the same way, without end. This section replaces that self-referential
pattern instead of extending it with a seventh refresh.

This artifact now distinguishes two kinds of commit on this branch:

* **Code-affecting commits** change `build_support/`, `tests/`, or
  workflow behavior and require fresh CI/build/test evidence. The
  frontmatter `last_code_affecting_head` names the most recent such commit
  (`373a24ea777bd19aa11c54fe655c99b34c8bb8e2`, PR #439 review round 4). This
  value is stable across evidence-only/docs-only commits -- including this
  one -- and is updated only when a future commit actually changes reviewed
  code.
* **Evidence-only/docs-only commits** (rounds 5, 6, and this round-7
  correction) update this artifact's own prose to reflect that the PR's
  current HEAD has advanced, without changing any reviewed code. Such a
  commit necessarily post-dates itself, so this artifact never claims to be
  "reviewed at" or "P-018-satisfied at" its own commit or any later one; it
  makes no current-HEAD readiness claim at all.
* The PR's **current** HEAD, its live required-check state, and the live
  P-018 Copilot-review gate verdict are authoritative only in two places
  that stay current without a commit: the PR #439 body's `## Local Review
  Readiness` block (updated in place after each push) and the
  `autoharness gate copilot-review 439 --enforcement auto` command, run at
  merge time. This committed artifact records only the observed
  review/CI state for the named `last_code_affecting_head`, plus the one
  currently-open condition above -- never a readiness or P-018 assertion
  for a HEAD that necessarily post-dates this file.

## Invariants to Preserve

* The probe reports `PRESENT` (and the CLI exits 2) only when the response's
  resolved host is `pypi.org` (after redirects, including on the 404 path),
  the body decodes as JSON, and the decoded body names the exact requested
  version. Any other well-formed-but-wrong-identity response is a transport
  or integrity error, never silent success.
* `skip-existing: true` remains on the publish step as declared defense in
  depth; it is not the primary fail-closed mechanism.
* No change to the pinned publish action SHA, the release workflow's
  trigger, permissions, or secret handling (binding H3).
* Every `patched_environ(GITHUB_HEAD_REF=...)` call site in
  `tests/test_gates_topology.py` remains preceded by
  `_clear_ambient_github_head_ref()` (enforced by the AST guard added in
  `152.003-T`, now also covering `except`/`case` blocks after review-fix
  `2686f786`).
