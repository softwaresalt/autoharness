## Key Decision / Learning: PR #434 Copilot-Review Circuit Breaker

An earlier PR in this shipment's lifecycle, #434
(`chore/stage-159-s-checkpoint-resolution`, "chore(backlog): publish 159-S
checkpoint waiver", merged `05bbfc2f` at reviewed HEAD `2e4c2e59`), tripped
the universal 3-attempt circuit breaker on `autoharness gate
copilot-review 434` -- all three polls returned `WAITING_FOR_REVIEW`
(Copilot review enabled but not yet complete for that HEAD). The Orchestrator
correctly halted rather than issuing a fourth poll or bypassing the P-018
gate, and the breaker's own record noted the correct remediation: wait for an
operator-visible Copilot review before any further readiness check. That
guidance was followed -- PR #434 subsequently received and satisfied Copilot
review before this session merged its follow-on, PR #435.

**Learning**: the 3-attempt circuit breaker on `gate copilot-review` behaves
as designed under genuine review latency (not a gate defect) -- Copilot
review completion is asynchronous and a bounded poll-and-halt is the correct
non-negotiable response, not a signal to add a longer bespoke wait loop
inside the gate itself.
