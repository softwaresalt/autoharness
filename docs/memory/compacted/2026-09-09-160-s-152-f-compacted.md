## Key learnings

* A PR's own commits can pre-archive manifest tasks/feature (queue→archive
  file moves) while leaving their `status` field as `done` rather than
  `archived`, and leaving the shipment record itself un-archived. The
  official classifier (`classify_shipment_close_path`) and the cascade
  two-set gate both key off **declared status**, not file location, so this
  is handled correctly: pre-moved-but-`done` artifacts are still
  unconditionally `required_ids` and get archived by the cascade call.
* When the merged commit's tree is identical to the reviewed-HEAD tree
  (clean fast-forward-style merge), `git checkout main` after merge does
  not touch any working-tree file — safe to switch branches without
  stashing while preserving unrelated dirty/untracked artifacts
  byte-for-byte (verified here via SHA-256 hash comparison).
* Post-merge closure work (backlog archival, closure-artifact finalization,
  this compaction) was performed on `post-merge/160-s-closure`, branched
  from `main` before any closure commit — never directly on `main`.
