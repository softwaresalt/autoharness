## Key learnings (durable)

1. **Aggregate/rollup checks over an untyped manifest items list must filter
   by `artifact_type` before computing the aggregate.** This is the second
   occurrence of the same pitfall in this repo's claim-integrity family
   (first: Ship agent's Unit B `SHIPMENT_STATE_INCONSISTENT` scan, `106-S`;
   now: `shipment-reconcile` pre-mode's new record-status classification,
   `109-S`). Design the filter in from the start; don't rely on review to
   catch it a second time.
2. **Declining a valid-but-broader review finding requires citing the exact
   approved-plan Scope-Boundary text**, not a vague "out of scope" — and
   explicitly confirming (by checking `git show main:...`) that the
   behavior being declined predates the current diff, so the decline
   rationale is factually grounded rather than asserted.
3. **A Copilot finding that would require a new backlog item to properly
   track cannot be implemented mid-session by Ship (P-010 role boundary)** —
   the correct disposition is: fix what's in scope, decline the rest with
   rationale, and record it as an explicit residual-risk note in the PR body
   and closure artifact for Stage triage.
