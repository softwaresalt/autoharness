## Key lessons (see full memory in `docs/archive/memory/` for detail)

1. Reuse existing verification-check resolution logic for derivation
   (shared helpers keep both surfaces from diverging).
2. A fallback chain must apply the SAME terminal default across every
   function in the chain, not just the innermost one (tier-own-default bug).
3. "Never invent a value" sometimes means leaving a genuine unresolved gap
   detectable, not defaulting to an empty string that looks like a valid
   answer (DEFAULT_BRANCH bug).
4. CI checkout environments (e.g. `actions/checkout`) may lack local git
   refs that work fine in a full local clone; always verify resolution
   chains against actual CI output.
5. JSON/YAML quoting is not shell quoting -- array-literal variables spliced
   into generated scripts need the target shell's own escaping rules
   (single-quote literals), or configured data becomes executable code.
6. Don't literally copy the one concrete example given for an otherwise-
   generic fallback case; give it its own branch or write neutral prose.
