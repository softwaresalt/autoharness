## Cycle 1 (2026-08-28) — four in-scope findings, plan hardened to 15 tasks

Four unresolved Copilot review threads against the `149-F` plan, all
classified in-scope (P-021 C1) and none deferred:

- **D-9**: one canonical `status` field on `CheckResult`; any `verdict` is a
  derived read-only property absent from `to_dict()` — contradiction between
  outcome fields made unrepresentable.
- **D-10**: pointer + versioned schema are one atomic contract; detector
  validation runs against the versioned document.
- **D-11**: report freshness/identity key becomes `<head_sha>-<fingerprint>`,
  fingerprint = SHA-256[:16] over canonical JSON of registry version, schema
  version, and sorted resolved `tool_version_dims` — collapsing freshness and
  identity into one predicate.
- **D-12**: user-supplied git refs resolved via
  `git rev-parse --verify --end-of-options <ref>^{commit}`, validated against
  `^[0-9a-f]{40}$`, rejected with exit 2 and no side effect.

Task count grew 11 -> 15 (three splits forced by the plan's own granularity
budget, not by added scope). New invariants INV-7/8/9; new risks RK10-RK13.

## Cycle 2 (2026-08-28) — five in-scope findings, no-clobber publication

Five further Copilot threads against PR #414, all classified in-scope, zero
deferred:

- **D-13 (no-clobber report publication)**: `os.replace` forbidden
  throughout — publication uses an exclusive-claim + atomic-publish protocol
  (temp file -> fsync -> `os.link` or `O_CREAT|O_EXCL` fallback);
  `FileExistsError` is treated as success (existing file untouched). Retracts
  cycle-1's premise that same-key payloads are deterministic (`provenance.
  produced_at` is wall-clock, so they are not) — `os.replace` would have been
  a last-writer-wins overwrite of immutable evidence.
- **D-14 (one correct outcome per layer)**: unsafe/unresolvable user ref text
  -> exit 2 at the CLI (no `git diff`, no report); an unbuildable context from
  already-validated input -> `insufficient_evidence` at the applicability
  engine. New invariants INV-10 (published report immutable by construction),
  INV-11 (exactly one correct outcome per layer).
- A reviewer suggestion to change `031-DL`'s corpus count ("Nine" -> ten) was
  deliberately **not followed** and recorded as such: the count was correct;
  only the tracker's provenance label needed clarifying.
- Verified shipment membership counts for the Orchestrator's PR-body refresh:
  `156-S` = 9 members, `157-S` = 16 members (23 total implementation tasks,
  25 total members).

Plan review verdict both cycles: `decision: PASS`. Final task count 15,
unchanged from cycle-1's post-split total. Stage claimed nothing, pushed
nothing, replied to no thread, and invoked no Ship at either cycle (P-010).
