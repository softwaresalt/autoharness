## Key learnings (durable)

1. **A `must_contain`-style whole-file substring check only proves token
   presence, never placement.** Any check whose safety property depends on
   *where* a token sits (not just that it exists somewhere in the file) needs
   a windowed/scoped check — e.g. requiring the token to appear specifically
   between two narrower anchor tokens — to defeat a "delete the real thing,
   leave a summary that mentions the same tokens" attack.
2. **"Falsy or empty" is not "wrong type."** `x is None or x.strip() == ""`
   lets `False`, `42`, `[]`, `{}` all slip through un-flagged. Prefer
   `not isinstance(x, str) or not x.strip()` for any field whose only valid
   shape is a non-empty string — especially unschema-backed raw-YAML reads
   (e.g. frontmatter parsed from installed `.md` files) where a JSON Schema
   isn't independently enforcing the type.
3. **Schema-backed vs. non-schema-backed validation matters when deciding
   where to add a type-check.** If a field already has `"type": "string"` in
   an enforced JSON Schema (e.g. `harness-config.schema.json`), a duplicate
   runtime type-check is redundant; the fix belongs only at the unschema'd
   read site (frontmatter-from-Markdown), not both.
4. **Hosted Copilot review re-arms on every HEAD advance and can surface new
   findings on a fix commit that itself introduces a narrower bug.** Budget
   for at least 2 hosted-review rounds on any PR that adds new fail-closed
   verifier checks; never trust an old `SATISFIED` verdict after a new push —
   re-request and poll fresh.
5. **Plan/backlog reference repointing after archiving a plan is asymmetric.**
   Live/active artifacts (an active feature record, a durable compound-learning
   doc) should repoint to the new decided-plan; historical/archived artifacts
   (an already-archived duplicate feature, a dated Stage session-memory
   snapshot) should repoint to the archived original-plan path, preserving
   what was true for the reader at that point in time.
