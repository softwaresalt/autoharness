## E10. OPERATOR TAG INSTRUCTION

No agent created a tag. Tagging and publishing is an operator-only action.

### Prerequisites

1. The release pull request is merged to `main`.
2. `git checkout main` then `git pull`.
3. `git status` shows a clean working tree.
4. `git rev-parse HEAD` equals the merge commit recorded in the **Merge commit** section below (`<MERGE_SHA>`).
5. `git tag -l v1.6.0` prints nothing and `git ls-remote --tags origin v1.6.0` prints nothing.
6. `PYTHONPATH=src python -m unittest tests.test_version_consistency` passes and `pyproject.toml` has
   `version = "1.6.0"`.

### Commands

```powershell
git tag -a v1.6.0 <MERGE_SHA> -m "autoharness 1.6.0"
git push origin v1.6.0
```

Push only that one tag. Do not use `git push --tags`.

### Verification

1. `git tag -v v1.6.0` (when tags are signed) or `git show v1.6.0` shows an annotated tag on `<MERGE_SHA>`.
2. Watch the Release workflow: `gh run list --workflow release.yml --limit 1`, then `gh run watch <run-id>`.
   Every step must pass, including the tag-equals-version check and the PyPI smoke test.
3. Confirm the release on PyPI: `python -m pip index versions autoharness` lists `1.6.0`, or open
   `https://pypi.org/project/autoharness/1.6.0/`.
4. Confirm the GitHub release `v1.6.0` carries the extracted changelog notes and both distributions.
