## Who this is for

Operators of a workspace that has an autoharness 1.5.0 harness installed, especially one that uses a backlogit
backlog, the agent-engram pack, or both. This guide changes only your workspace and its CI. It never asks you
or an agent to modify the backlogit or engram repositories.

## 1. Reinstall or tune

1. Upgrade the global install to 1.6.0 (see [Installation](../installation.md)) and confirm with
   `autoharness version`.
2. In the target workspace run tune-harness (see [Tuning Guide](../tuning-guide.md)). Review the proposals
   before applying; tuning is non-destructive and backs up first.
3. Expect drift in these installed artifacts: workflow-policies, the Stage, Ship and Orchestrator agents,
   the `shipment-reconcile`, `operational-closure`, `harness-architect` and `build-feature` skills, the
   `circuit-breaker`, `agent-engram` and backlog instructions, and the backlogit registry.
4. Run `autoharness verify-workspace --workspace .` and resolve any failure.

## 2. Harness-config contract path: 1.1.0 to 1.2.0 to 1.3.0

The harness-config contract moved in two steps after `1.1.0`. The current version is `1.3.0`
(`current_version` in `src/autoharness/schema_contracts.py`).

| Version | Change | Action |
|---|---|---|
| `1.1.0` | Nested per-role escalation, `context_tier`. | None; stays valid and resolves identically. |
| `1.2.0` | Optional `model_routing.routes` catalog and `bindings` map; unknown `model_routing` keys and YAML anchors, aliases or merge keys are rejected. | Bump `schema_version` to `1.2.0` only to use `routes` or `bindings` (see the Route Catalog and Site Bindings section of the [Tuning Guide](../tuning-guide.md)). |
| `1.3.0` (current) | The retired `agent-intercom` pack leaves the `capability_packs` enum. | Remove the retired pack from `capability_packs`, then bump `schema_version` to `1.3.0`. |

The workspace profile and the harness manifest remain at `1.1.0`; do not bump them for this release. A config
pinned to an older published mirror keeps validating against that untouched mirror.

## 3. agent-intercom removal tolerance

The `agent-intercom` pack, overlay instruction, registry entry, profile block and verify assertions are gone.
Installers and deploy wrappers that are asked for the pack print `RETIRED_PACK: agent-intercom ignored` and
continue. After tuning, delete the stale `agent-intercom.instructions.md` and `agent_intercom` profile block from
your workspace if tune-harness reports them as orphaned.

## 4. agent-engram and P-002.8 (claim-marker consumption)

P-002.8 is opt-in and off by default, so nothing changes until you enable it. It needs a backlogit that produces
the `custom_fields.scheduler_baseline_claim` marker (producer `scheduler-baseline-marker/v1`) in the engram-driven
Ship flow. To enable it:

1. Confirm your backlogit produces that marker. Without such a backlogit, leave the feature off.
2. Set `features.scheduler_baseline_claim: true` in the backlogit registry.
3. Run tune-harness so the Ship agent and workflow-policies carry the Step 3 and Step 4.1 behavior.

Details and the operator-only follow-up are in [claim-marker-consumption.md](../claim-marker-consumption.md).

## 5. CI pin

Change any CI or tooling pin from `autoharness==1.5.0` to `autoharness==1.6.0`, for example
`uv tool run --from "autoharness==1.6.0" autoharness verify-workspace --workspace .`. The version appears on PyPI only after
the operator publishes the `v1.6.0` tag.

## 6. Remove engram local workarounds

If your workspace carries local workarounds for the engram issues tracked as 140-F, 7DE66A04 and 1AD161B8,
remove them after tuning and verifying. The `agent-engram` instruction now names only registered tools
(`query_graph` with `operation` of `neighborhood`, `find_path` or `transitive_closure`), and pack assertions are
conditional on enabled packs.

## 7. Backlogit engine line

backlogit `1.11` is verified for cascade close (P-015). `1.12` is verified only after the probe in
[engine-line-verification.md](../engine-line-verification.md); until then it is `UNVERIFIED` and selects
SAFE_CLOSE. Do not widen the verified set by version number alone.

## 8. Behavior changes to expect (G1 to G4)

* **G1**: engram graph traversal uses `query_graph`; no Cypher-style wording remains.
* **G2**: backlogit CLI operations are first-class peers of MCP; P-012 reports `TOOL_OK: {operation} via {mcp or cli}`.
  `cascade-close` runs use `--detach` with `--poll`, or an attached run with a sufficient declared wait.
* **G3**: documentation-only tasks may take the `harness-verification-gated` route checked by
  `autoharness harness docs-only-check`; see [gates-reference.md](../gates-reference.md).
* **G4**: `verify-workspace` no longer fails a workspace for lacking an optional pack's content.

## Verify

Run `autoharness verify-workspace --workspace .` and your usual quality gates. A clean result with no unresolved template
variables and no cross-reference failures means the upgrade is complete.
