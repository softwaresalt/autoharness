## Summary

autoharness 1.6.0 follows 1.5.0. The authoritative, per-entry record is the `1.6.0` section of
[CHANGELOG.md](../../CHANGELOG.md); this page groups the changes by what an operator needs to know. To adopt them
in an installed workspace, follow the [upgrade guide](1.6.0-upgrade-guide.md).

## Behavior changes by group

### G1: agent-engram guidance

The `agent-engram` instruction names only tools the engram server registers. Graph traversal uses `query_graph`
with an `operation` of `neighborhood`, `find_path`, or `transitive_closure`. Re-run tune-harness to refresh the
installed instruction.

### G2: backlog CLI is a first-class peer of MCP

The backlogit registry declares `cli_command` for hook polling and acknowledgement, comments, memory save,
shipment add, stash edit and get, deliberate, and the metadata operations. P-012 treats every declared MCP or CLI
surface as an equal supported surface and reports `TOOL_OK`, `TOOL_DEGRADED`, or `TOOL_UNAVAILABLE`.
`log_telemetry` stays MCP-only and `dispose_shipment` stays unregistered until backlogit ships it.

### G3: verification-gated docs-only route

A documentation-only task may carry `harness-verification-gated` instead of `harness-ready`. Ship records a
start-SHA baseline and proves completion with the offline `autoharness harness docs-only-check`; any ambiguity
fails closed to the code route or a halt. See the docs-only section of
[gates-reference.md](../gates-reference.md).

### G4: pack-conditional assertions

`verify-workspace` checks pack-specific content only when the pack is enabled, so workspaces without
`agent-engram` or `backlogit` verify cleanly.

## Engine line

backlogit `1.11` is the only verified cascade engine-semantics line. Any other line, including `1.12`, is
`UNVERIFIED` and selects SAFE_CLOSE until the probe in
[engine-line-verification.md](../engine-line-verification.md) passes. See also the
[compatibility matrix](../backlogit-compatibility-matrix.md).

## Schema contracts

The harness-config contract is at `1.3.0` (`current_version` in `src/autoharness/schema_contracts.py`); the
published `0.9.0` through `1.2.0` mirrors stay byte-identical. The workspace profile and harness manifest
contracts remain at `1.1.0`.

## Release process

The `v1.6.0` tag is created and pushed by the operator only, after the release PR merges. See the OPERATOR TAG
